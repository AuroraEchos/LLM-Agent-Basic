## 我的答案

三者优化的是不同层次的开销：**CUDA Graph 减少重复提交工作流的 CPU/driver 启动开销；Kernel Fusion 减少 kernel 次数和中间张量的显存读写；算子/图编译根据形状与硬件生成、选择并组合更高效的代码**。

### 一、CUDA Graph：把重复的 launch 序列录下来重放

传统 eager 执行中，CPU 要逐个向 GPU 提交 kernel。Decode 每一步包含许多执行很短的小 kernel，单次 launch 的固定开销和 CPU-GPU 间隙可能占明显比例。

CUDA Graph 将 kernel、memcpy 及依赖关系先 capture/instantiate，之后重复 replay 整张图，把许多逐算子提交成本变成一次图启动。NVIDIA 的 [CUDA Graph 文档](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html)也强调：创建和实例化的成本可预先支付，重复启动时只保留较小开销。

适合：执行拓扑稳定、shape 相对固定、会重复很多次的 Decode。限制包括：

- 通常需要稳定的内存地址与可捕获操作，会额外保留 graph buffer；
- batch、序列数和 shape 高度动态时，可能要为多个 bucket 分别 capture；
- 动态控制流、CPU 操作或某些通信/分配会导致 capture 失败或 graph break；
- 首次预热和实例化较慢，因此要区分冷启动和稳态性能。

### 二、Kernel Fusion：少启动、少搬运

未融合时，一个典型序列可能是：

```text
读 X → 加 bias → 写中间结果
读中间结果 → 激活函数 → 再写回
读中间结果 → residual add → 输出
```

融合 kernel 可以在寄存器或 shared memory 中连续完成 bias、activation、residual 等操作，避免反复写回 HBM。收益来自：

1. kernel launch 数减少；
2. 中间张量分配减少；
3. HBM 读写减少，提高算术强度；
4. 可联合调度线程、向量化和 Tensor Core epilogue。

常见例子有 fused RMSNorm、RoPE、QKV projection、bias+GELU/SwiGLU、residual+norm，以及融合 Attention。边界是融合过大可能增加寄存器压力、降低 occupancy，动态分支也可能让一个通用融合 kernel 比专用 kernel 更慢。

### 三、算子编译：从计算图生成适配实现

以 `torch.compile`、TorchInductor、Triton、XLA 或 TensorRT 为例，编译器会捕获计算图，做常量折叠、死代码消除、layout 传播、算子融合、内存规划，并针对具体 dtype、shape 和 GPU 选择 tile、并行方式或 autotune kernel。PyTorch 的 [`torch.compile` 文档](https://docs.pytorch.org/docs/stable/generated/torch.compile)也提供动态 shape、autotune、epilogue fusion 和 CUDA Graph 等选项。

收益通常在重复执行足够多次后体现：

\[
T_{total}=T_{compile}+N\cdot T_{compiled}
\]

只有当节省的 \(N(T_{eager}-T_{compiled})\) 大于编译与预热成本时才值得。在线服务需要提前 warmup 常见 shape，并缓存编译产物。

### 四、三者的关系

它们可以叠加：编译器先把多个算子融合成少量高效 kernel，再把稳定的 kernel 序列 capture 成 CUDA Graph。也不能混为一谈：Graph replay 不会自动让单个低效 kernel 变快；Fusion 也不能消除剩余 kernel 的全部 host launch；编译则可能负责自动完成部分 fusion 和 graph 化。

### 五、工程验证

- 用 profiler 比较 kernel 数量、kernel 间空洞、HBM traffic 和单算子耗时；
- 分别测试 Prefill 与 Decode、不同 batch/context bucket；
- 报告首次编译、首次请求和预热后稳态三种延迟；
- 检查 graph break、recompile 次数、额外显存和数值误差；
- 对动态输入保留 eager/fallback 路径，避免罕见 shape 触发长时间编译。

### 面试简答版

CUDA Graph 把固定的 kernel 与 memcpy 依赖序列预先实例化并重复 replay，主要降低 Decode 中大量小 kernel 的 CPU/driver launch 开销；Kernel Fusion 把 bias、激活、norm、residual 等操作合到一个 kernel，减少启动次数和中间张量的 HBM 读写；算子编译捕获计算图，根据 dtype、shape 和硬件做融合、布局、内存规划和 autotune。它们可以叠加，但要考虑动态 shape、graph break、额外显存、编译与预热成本，并分别测冷启动和稳态收益。
