> **问题：** 模型服务中的 Replication、Sharding 和 Disaggregation 分别解决什么问题？

## 我的答案

这三个词分别回答三个问题：**Replication 是“要多少份完整服务”，Sharding 是“一份服务如何跨设备切开”，Disaggregation 是“不同阶段是否由不同资源池完成”**。

### 一、Replication：复制完整实例

Replication 为同一个模型建立多个可独立处理请求的副本，前面放负载均衡器。一个“副本”也可能内部包含多张 TP/PP GPU，不一定等于单卡。

它主要解决：

- 总请求吞吐的水平扩展；
- 故障容忍、滚动升级和多可用区部署；
- 按流量弹性扩缩容以及多租户隔离。

代价是每个副本都重复保存模型权重，并且 KV Cache、prefix cache 通常彼此独立。若路由器不理解会话或前缀，相同前缀被送到不同副本会降低命中率；扩容也可能受权重加载和预热时间限制。

### 二、Sharding：切开同一个逻辑实例

Sharding 将无法或不适合放在单卡上的资源拆到多设备，例如：

- 用 TP 按张量维切权重；
- 用 PP 按层切权重；
- 用 EP 按专家切 MoE 权重；
- 用 CP 按序列切上下文或 KV Cache。

它主要解决单卡显存容量、单请求算力和超大模型/长上下文可部署性。代价是请求必须跨 shard 协同，一张卡或一条链路变慢都可能拖慢整个实例；集合通信、拓扑放置和并行度会直接影响 TPOT 与 P99。

因此 Sharding 的目标首先可能是“放得下”，其次才是“跑得快”。把一个本来能高效运行在单卡的模型盲目切到很多卡，可能因通信增加而更慢。

### 三、Disaggregation：拆开生命周期或执行阶段

Disaggregation 不只是把一层切开，而是让不同类型的工作进入不同资源池。例如：

- Prefill 池负责长 Prompt 的并行计算，Decode 池负责逐 token 生成；
- GPU 保存热 KV，CPU/DRAM/NVMe 保存冷 KV；
- tokenizer、视觉 encoder、retriever 和 LLM decoder 分开扩容；
- routing/control plane 与实际模型 worker 分离。

它主要解决不同阶段资源特征不一致和相互干扰的问题。例如 Prefill 计算密集且影响 TTFT，Decode 更偏显存带宽并决定 TPOT；拆开后可分别选择 GPU 型号、并行度、batch 策略和扩容比例。

代价是必须传输中间状态，增加网络带宽、序列化、排队、失败恢复和调度复杂度。最典型的是 P/D 分离要把 KV Cache 从 Prefill worker 交给 Decode worker，若传输时间高于隔离带来的收益，系统反而变慢。

### 四、三者可以同时存在

例如一个生产集群可能是：

```text
入口路由
├── 3 个 Prefill replica       ← Replication
│   └── 每个 replica 用 TP=4   ← Sharding
└── 8 个 Decode replica        ← Replication + P/D Disaggregation
    └── 每个 replica 用 TP=2   ← Sharding
```

所以它们不是互斥选项。一个副本可以由多个 shard 组成，不同阶段又可以放在不同的副本池里。

### 五、工程选型指标

- Replication：看到达率、单副本服务率、排队时间、缓存亲和性、故障和扩容时间。
- Sharding：看模型/KV 是否放得下、通信占比、拓扑、单请求延迟和每实例吞吐。
- Disaggregation：看阶段间资源不匹配程度、中间状态字节数、网络带宽、排队与独立扩容收益。

还要防止一个常见误区：GPU 利用率高不等于服务更好。最终应以 TTFT、TPOT、端到端 P99、goodput（满足 SLO 的吞吐）、可用性和成本判断。

### 面试简答版

Replication 是复制完整的逻辑服务实例，用负载均衡扩吞吐、可用性和弹性，但会重复权重并割裂 KV/prefix cache。Sharding 是把一个实例的模型、专家或上下文切到多卡，解决单卡放不下和单请求算力问题，但引入关键路径通信。Disaggregation 是把 Prefill/Decode 或 encoder/decoder 等不同阶段放到独立资源池，解决资源特征不一致和相互干扰，但要付出中间状态传输与调度成本。生产中三者常组合：多个副本，每个副本内部多卡分片，同时 P/D 又分别成池。
