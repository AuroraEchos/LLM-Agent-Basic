> **问题：** 模型量化的基本目标是什么，Weight、Activation 和 KV Cache 量化有何区别？

## 我的答案

模型量化把高精度实数张量映射到更少 bit 的离散表示，目标是在可接受质量损失下减少存储、显存带宽、通信和计算成本。它不是单纯“模型文件变小”：只有推理硬件与 kernel 真正支持相应低精度运算，压缩才会转化为吞吐或延迟收益。

典型仿射量化：

$$
q=\operatorname{clip}\left(\operatorname{round}(x/s)+z,q_{min},q_{max}\right)
$$

反量化：

$$
\hat x=s(q-z)
$$

$s$ 是 scale，$z$ 是 zero point。误差来自舍入、裁剪和 scale/zero-point有限精度。

### Weight Quantization

权重是静态的，可离线统计并量化一次。常见配置：

- W8A8：权重和激活 INT8；
- W4A16：权重 INT4，激活 FP16/BF16；
- weight-only GPTQ/AWQ/NF4 等。

主要收益：

- 模型文件和常驻显存减少；
- Decode 每步读取全模型权重的 HBM 流量下降；
- 同一 GPU 可放更大模型或更多副本；
- 若有 INT4/INT8 Tensor Core或融合反量化 GEMM，可加速计算。

权重量化参数可用 per-channel/per-group scale，离线成本可接受。挑战是 outlier、Embedding/LM Head/小层敏感，以及 group scale/packing 元数据。W4A16 常在 GEMM 中边读压缩权重边反量化；如果 kernel 先完整解压到 FP16，峰值内存和速度收益会大打折扣。

### Activation Quantization

Activation 随输入、token、层和时间动态变化，无法像权重一样永久量化一次。需要运行时计算或使用校准得到的 scale：

- static activation quantization：校准集确定固定范围；
- dynamic/per-token quantization：每个 token/batch 在线求 scale；
- per-tensor/per-channel/group 等粒度。

收益是减少层间 activation 带宽、通信，并让 W8A8/W4A4 使用真正的低精度矩阵乘。难点是 activation outlier 与输入分布漂移；在线求 amax/scale 也有 reduction、同步和 kernel 开销。

训练中 activation 还要用于 backward，其量化远比只做推理更敏感。部署时 W4A16 表示“只压权重”，activation 仍是 16-bit，不能宣称全计算 4-bit。

### KV Cache Quantization

KV Cache 是推理时按层、按 token 生成并长期保存的 activation 子集。它与普通 activation 的区别是：

- 随 context 和并发持续线性增长；
- 每个 Decode step 都会反复读取全部历史 cache；
- 新 token KV 需在线量化并追加；
- 误差会影响后续所有 Attention，而非只经过一层；
- scale/zero-point 必须随 cache block/token 一起存储和分页。

量化主体从 BF16 2 bytes 降到 INT8 1 byte或INT4约0.5 byte，可提高最大并发并降低长上下文 Decode 带宽。Key 误差改变 attention logits/排序，Value 误差改变聚合结果，两者可能使用不同位宽、粒度或让 recent window 保持高精度。

### 三者对比

| 维度 | Weight | Activation | KV Cache |
|---|---|---|---|
| 生成时间 | 训练后固定 | 每次 forward动态产生 | Prefill/Decode逐 token产生并持久化 |
| 首要收益 | 权重容量与读取带宽 | 算子/层间带宽与低精度 GEMM | 长上下文容量、并发和Decode带宽 |
| Scale 可得性 | 离线充分优化 | 静态校准或在线统计 | 在线、随 token/block保存 |
| 主要难点 | 敏感权重/outlier | 输入依赖与动态范围 | 误差长期累积、元数据/分页 |

### 质量与性能评估

量化误差不应只用 weight MSE 判断。需要比较：validation perplexity、中文/代码/数学/长上下文任务、结构化输出、logit KL 和极端输入。性能需测模型加载显存、峰值显存、TTFT、TPOT、tokens/s、最大并发和功耗。

低 bit 可能让模型更小却更慢：反量化、scale加载、shape不适配、batch太小或硬件不支持，都可能使 kernel退化。量化格式还必须与推理引擎、TP sharding和序列长度一起选。

### 面试简答版

量化用低 bit 离散值和 scale/zero-point近似实数，目标是省容量、带宽、通信和计算，同时控制质量损失。Weight 是静态的，适合离线 per-channel/group量化，主要省模型显存和Decode权重带宽；Activation 随输入变化，要静态校准或在线 per-token scale，决定能否用真正 W8A8/W4A4计算；KV Cache 是长期保存的动态激活，量化主要省长上下文显存和每步KV读取带宽，但误差会持续影响后续 Attention。最终必须用目标硬件 kernel和任务质量端到端验证。
