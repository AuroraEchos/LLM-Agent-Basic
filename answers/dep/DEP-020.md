## 我的答案

Prefill-Decode Disaggregation（P/D 分离）把请求的两个阶段交给不同 worker 池：Prefill worker 处理完整 Prompt 并生成首 token 及 KV Cache，随后把 KV 交给 Decode worker，后者继续逐 token 生成。

### 一、为什么值得拆分

两个阶段的负载特征不同：

- **Prefill** 一次处理许多输入 token，矩阵较大、并行度高，通常更偏计算密集，主要影响 TTFT；
- **Decode** 每一步只增加一个 token，需要反复读取权重和历史 KV，通常更偏显存带宽与调度延迟，主要影响 TPOT/ITL。

混合调度时，突然到来的长 Prompt 可能占用大量计算资源，阻塞正在 Decode 的交互请求；反过来，大量 Decode 序列也会挤压 Prefill，使 TTFT 增大。

### 二、主要收益

1. **隔离干扰**：长 Prefill 不再直接打断延迟敏感的 Decode，可改善 TPOT 和尾延迟。
2. **独立扩容**：输入 token 激增就扩 Prefill 池，长回答变多就扩 Decode 池，不必按固定比例复制整套实例。
3. **分别调优**：Prefill 可用较大 chunk、较高 TP 或计算型 GPU；Decode 可用更适合低延迟/高带宽的配置和连续批处理。
4. **提高 goodput**：即使理论总 tokens/s 未必大幅提高，满足 TTFT 与 TPOT SLO 的请求数可能增加。
5. **故障与优先级隔离**：可为不同阶段设置队列、限流、抢占和降级策略。

### 三、核心成本：KV Cache 传输

对常规 Transformer，一条长度为 \(T\) 的请求，其 KV 字节数可粗略估为：

\[
M_{KV}=2L T n_{kv}d_hb
\]

其中 \(L\) 为层数，2 表示 K 和 V，\(n_{kv}\) 为 KV 头数，\(d_h\) 为头维度，\(b\) 为每元素字节数。batch 大小不为 1 时再乘 batch。MHA 的 \(n_{kv}=n_h\)，GQA/MQA 会显著减少传输量。

理想传输时间下界约为：

\[
t_{transfer}\geq \frac{M_{KV}}{B_{effective}}+t_{setup}
\]

但实际还包括跨卡读取、协议封装、拓扑绕行、接收端写入、同步和排队。若是长上下文、低带宽网络，KV 交接可能抵消 P/D 分离收益。可用 RDMA、GPU Direct、分块流式传输、KV 量化或让 P/D 共处高速互联域来降低成本。

### 四、最难的是调度，不是“拆两个服务”

- **何时交接**：Prefill 是一次完成、chunked prefill，还是边算边传；首 token 在哪一侧采样。
- **Decode worker 选择**：不仅看空闲 GPU，还要看 KV 可用空间、预测输出长度、已有 batch 形状、网络距离和租户优先级。
- **背压**：Prefill 生产 KV 过快而 Decode 消化不了时，继续接收会导致队列和显存爆炸，必须 admission control。
- **负载预测**：输入长度已知，输出长度未知；池比例需根据 token 到达率和在线 TPOT 动态调整。
- **缓存亲和性**：已有 prefix KV 在哪个 Prefill 节点、会话历史在何处，会影响路由和传输量。
- **生命周期一致性**：请求取消、超时或 Decode worker 故障后，发送端和接收端都要正确回收 KV block，避免泄漏或重复释放。
- **并行布局匹配**：P、D 两侧 TP/PP 度数或 KV 布局不同，可能需要重排、切片或聚合 KV。

### 五、什么时候不一定适合

- 小模型、短 Prompt、低并发时，单体部署简单且交接成本占比更低；
- P/D 比例稳定、混部调度已经能很好隔离，独立资源池可能降低共享带来的统计复用；
- 网络慢或跨可用区传 KV，额外延迟与故障面可能不可接受；
- 流量太小，两个资源池都难以形成有效 batch，GPU 利用率反而下降。

因此应至少对比三种基线：混合 continuous batching、chunked prefill 混部、真正 P/D 分离。报告 TTFT、TPOT、E2E P99、KV 网络吞吐、GPU 显存、goodput 和每请求成本，并覆盖输入/输出长度变化与突发流量。

### 面试简答版

P/D 分离利用了两个阶段的差异：Prefill 处理整段 Prompt，偏计算密集并决定 TTFT；Decode 逐 token 读取权重和 KV，偏带宽与调度延迟并决定 TPOT。收益是隔离长 Prompt 对 Decode 的干扰、分别扩容和调优资源池，从而提高满足 SLO 的 goodput。主要成本是把大小约为 \(2LTn_{kv}d_hb\) 的 KV Cache 传给 Decode，以及由此产生的网络、排队、背压、缓存亲和性、KV 生命周期和并行布局转换问题。短请求、低并发或慢网络下不一定划算，必须和 chunked prefill 混部方案做同负载压测。
