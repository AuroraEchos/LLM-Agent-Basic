> **问题：** Tensor Parallelism 与 Pipeline Parallelism 在推理中的通信模式有何不同？

## 我的答案

两者都用于让单卡放不下或单卡太慢的模型跨卡推理，但切分维度不同：**Tensor Parallelism（TP）切一个层内部的张量，Pipeline Parallelism（PP）切不同层**。因此通信频率和形态也不同。

### 一、Tensor Parallelism：层内高频集合通信

以 Transformer 的线性层为例，可把权重按列或按行切到多张卡。每张卡计算局部矩阵乘，然后通过 `All-Reduce`、`All-Gather` 或 `Reduce-Scatter` 合成下一步所需结果。

例如把输出维度切分：

\[
Y=[XW_1, XW_2,\ldots,XW_p]
\]

各卡能独立得到部分输出，后续若需要完整激活就做 All-Gather；若把输入维度切分，则局部结果满足：

\[
Y=\sum_{i=1}^{p}X_iW_i
\]

需要用 All-Reduce 或 Reduce-Scatter 汇总。注意力的头和 MLP 中间维度也常按类似方式切分。

特点是：

- 几乎每个 Transformer 层都会通信，单次消息相对较小但频率很高；
- 每个 token 的 Decode 也要重复这些集合通信，因此对通信延迟尤其敏感；
- 更适合同一节点内 NVLink/NVSwitch 等高带宽、低延迟互联；
- TP 增大后，每卡计算下降，但通信占比上升，存在明显的收益拐点。

### 二、Pipeline Parallelism：层间低频点对点通信

PP 把连续层分成多个 stage，例如 GPU 0 放第 1～20 层，GPU 1 放第 21～40 层。stage 边界只需把激活从前一阶段 `Send` 到后一阶段 `Recv`，权重不必在每层集合通信。

其特点是：

- 通信次数大致与 stage 边界有关，而不是与每层都相关；
- 主要传输激活，通信通常是相邻 stage 的点对点 Send/Recv；
- 对互联带宽的压力可能比大 TP 小，因此更适合跨节点，但会出现流水线气泡；
- 只有足够多的并发请求或 micro-batch 才容易填满各 stage。

若有 \(p\) 个 stage、\(m\) 个 micro-batch，经典流水线中气泡比例可粗略理解为：

\[
\text{bubble fraction}\approx\frac{p-1}{m+p-1}
\]

推理并不完全等同于训练：自回归 Decode 的每个请求一次只向前推进一个 token，低并发时很难用大量 micro-batch 掩盖气泡；而且请求输出长度不一会造成 stage 间负载不均。

### 三、对推理指标的不同影响

| 维度 | TP | PP |
|---|---|---|
| 切分位置 | 单层内部 | 层与层之间 |
| 主要通信 | All-Reduce / All-Gather / Reduce-Scatter | 相邻 stage 的 Send/Recv |
| 通信频率 | 每层、每 token，高频 | 每个 stage 边界，较低频 |
| 互联要求 | 极度依赖低延迟高带宽 | 相对更能容忍跨节点互联 |
| 主要风险 | 集合通信吞噬计算收益 | 气泡、stage 不均衡、调度复杂 |
| 典型用途 | 降低单请求延迟、层内并行 | 模型跨节点放置、降低单卡权重占用 |

Prefill 的矩阵乘规模大，计算更容易覆盖部分通信；Decode 每步计算较小，TP 集合通信与 PP 调度延迟都更突出。因此不能只按“几张卡”选择并行度，应分别压测 TTFT 和 TPOT。

### 四、实际通常是混合并行

例如 16 张 GPU、每节点 8 卡，可以节点内做 TP=8，两个节点做 PP=2：TP 的高频集合通信留在 NVLink 域内，跨节点只传 stage 激活。选择时还要考虑层数能否整除、MoE 专家分布、KV Cache、量化 kernel 和故障域。

### 面试简答版

TP 是层内切张量，每层通常都要 All-Reduce、All-Gather 或 Reduce-Scatter，通信高频且 Decode 每个 token 都发生，所以更依赖节点内 NVLink/NVSwitch；它可以并行计算同一层并降低单请求延迟。PP 是按层切 stage，主要在 stage 边界点对点传激活，通信频率较低、较适合跨节点，但需要足够并发或 micro-batch 填流水线，否则有气泡。生产中常用“节点内 TP、节点间 PP”的混合方案，并分别按 TTFT、TPOT 和吞吐压测。
