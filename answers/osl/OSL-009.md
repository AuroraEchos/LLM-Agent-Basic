## 我的答案

**Namespace 改变进程“能看到什么/自己是谁”，cgroup 控制一组进程“能用多少、如何分配和统计资源”**。容器通常是这两类内核机制加 rootfs、capabilities、seccomp、网络与运行时配置的组合，不是单独一种内核对象。

### Namespace：隔离视图

Linux 常见 namespace 包括：

- PID：进程号视图及 namespace 内 PID 1；
- mount：挂载点/文件系统视图；
- network：网卡、地址、路由、端口、netfilter 等网络栈；
- UTS：hostname/domain name；
- IPC：System V IPC/POSIX message queue；
- user：UID/GID 映射和 capability 范围，是 rootless 容器关键；
- cgroup：看到的 cgroup 路径视图；time namespace 还可隔离部分时钟。

namespace 通过 `clone/unshare/setns` 创建或加入，可嵌套；它隔离资源视图，但不自动限制 CPU/内存，也不等于安全沙箱。

### cgroup：分组、限制、保护和计量

cgroup v2 以统一层级组织进程，控制器按层级分配资源。典型接口包括 CPU weight/quota、`memory.high/max` 与 OOM 事件、`io.weight/max`、`pids.max`、cpuset 等。它能限制/计量 CPU、内存、I/O、进程数并提供 pressure/events，但资源语义各不相同：CPU quota 常表现为 throttling，内存 hard limit 可能触发 cgroup OOM，不能把二者理解成“给容器一台固定大小机器”。

容器进程仍共享宿主内核。namespace/cgroup 配置错误、过多 capability、可写宿主 socket/device、特权容器或内核漏洞都可能破坏隔离；需要 rootless/user namespace、drop capabilities、seccomp/LSM、只读挂载和镜像供应链等纵深防御。VM 有独立 guest kernel，通常隔离边界更强但开销/运维模型不同。

GPU 要额外说明：device 可见性只决定能否访问设备，普通 cgroup 并不自动提供完整 GPU 显存/算力公平隔离；还需驱动、MIG/MPS、设备插件和应用调度配合。容器内排障也要同时看 namespace 内指标、cgroup limit/throttle/OOM 和宿主全局压力。

### 面试简答版

Namespace 隔离进程看到的 PID、mount、network、UTS、IPC、user 等视图；cgroup 把进程按层级组织，并对 CPU、内存、I/O、pids 等做分配、限制和统计。容器是 namespace + cgroup + rootfs + capabilities/seccomp/网络配置的组合，仍共享宿主内核，不等同 VM。CPU quota 会 throttle，memory limit 可能 cgroup OOM；GPU 还需驱动/MIG/调度器，不能只靠普通 cgroup 宣称完整隔离。
