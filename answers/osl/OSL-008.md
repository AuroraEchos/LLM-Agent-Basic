## 我的答案

Linux 传统权限由 owner、group、others 三组 `rwx` 位组成，并结合文件所有者、进程的有效 UID/GID 与附加组判断。

- 对普通文件：`r` 读内容，`w` 改内容，`x` 执行。
- 对目录：`r` 列出名字，`w` 创建/删除目录项，`x` 穿越并访问已知名字。删除文件主要取决于父目录权限，不只看文件本身。
- setuid/setgid/sticky、POSIX ACL、SELinux/AppArmor、mount option 和 capabilities 还会进一步影响结果；`chmod 777` 不是通用修复。

`umask` 是**屏蔽新建对象的权限位**，不是简单十进制相减。应用请求的 mode 与 umask 取按位屏蔽：

$$mode_{effective}=mode_{requested}\ \&\ \sim umask$$

普通文件常从 `0666` 请求、目录从 `0777` 请求；`umask 027` 常得到文件 `0640`、目录 `0750`。应用显式 mode、ACL 默认项等会让最终结果更复杂，应以 `stat/getfacl` 验证。

### 模型与密钥的最小权限

- 服务使用独立、不可登录的 UID/GID，不以 root 跑推理；只授予所需目录和设备能力。
- 模型权重通常只读，例如由模型组读、服务写禁用；缓存/临时/输出目录单独可写，避免通过漏洞篡改已审核权重。
- 密钥文件只给服务账号读（常见 `0600` 或受控 group `0640`），父目录限制遍历；不要提交 Git、烘进镜像层、写日志/命令行。优先由 secret manager 以短期凭据、受限文件/fd 注入并支持轮换。
- 环境变量虽然方便，也可能通过 debug dump、子进程继承或错误日志泄漏；必须限制可见性并在启动后尽量缩小传播。
- 下载模型用 TLS、固定可信来源和 digest/signature 校验；临时文件采用安全创建与原子 rename，防 symlink/race。

容器内的 UID 仍会映射到宿主/volume 权限；只读 rootfs、drop capabilities、no-new-privileges、seccomp 和 user namespace 是额外纵深防御，不替代文件权限。轮换时先让新凭据可用、原子切换，再吊销旧值，并确认长连接/进程内缓存是否刷新。

### 面试简答版

Linux 权限按 owner/group/others 的 rwx 判断；目录的 x 是穿越，w 控制目录项，因此删除不只看文件权限。umask 用 `requested & ~umask` 屏蔽新建权限，例如 027 常得到文件 640、目录 750。模型服务应使用独立非 root 账号，权重只读、缓存目录单独可写，密钥用 600/受控 640 与受限父目录，不进 Git/镜像/日志；再结合 ACL、MAC、只读挂载、capability 和 secret manager 做最小权限与轮换。
