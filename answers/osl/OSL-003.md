## 我的答案

Linux 内核把可调度实体统一表示为 task，核心结构是 `task_struct`。传统“进程”和“线程”不是两套完全不同的内核对象：创建 task 时通过 `clone` 类标志选择是否共享地址空间、文件描述符表、信号处理等资源。

- 一个线程组共享进程级资源；线程组 ID（通常就是主线程 PID）代表进程，各线程有独立 TID、寄存器、内核栈和调度状态。
- `/proc/<pid>/task/<tid>` 可观察各线程；`ps -eLf` 或 `top -H` 可看线程级状态。
- `fork` 产生新的 task 与资源视图，地址空间通常先 copy-on-write；`exec` 用新程序映像替换当前进程映像，不创建新 PID。

### 文件描述符的层次

fd 是进程 fd table 中的一个小整数索引，不是文件本身：

```text
process fd number
  -> fd table entry
  -> open file description（当前 offset、status flags、引用计数）
  -> inode/dentry、pipe、socket 等内核对象
```

`dup` 或 `fork` 后的多个 fd 可以指向同一个 open file description，因此共享文件 offset/status；但 fd 自身的 `FD_CLOEXEC` 等 descriptor flag 是每个表项的。`close(fd)` 只移除一个引用，仍被其他 fd、进程或内核持有的对象不会立刻销毁。忘记 close 会耗尽 `RLIMIT_NOFILE`，表现为 `EMFILE`。

### 为什么 Socket 也是 fd

`socket()` 创建内核 socket 对象并返回 fd。Linux VFS/文件接口把不同内核对象统一成“可通过 fd 引用并调用一组操作”的抽象，所以 socket 能用于 `read/write`、`close`、`fcntl`、`poll/epoll`；socket 特有能力则由 `send/recv`、`bind`、`listen`、`accept` 等调用提供。

“everything is a file”是接口统一的口诀，不代表 socket 在磁盘上、支持 seek，或所有 fd 都有普通文件语义。pipe、eventfd、设备也可用 fd 表示，但可用操作和错误不同。多线程共享 fd table 时，一线程关闭/复用 fd 可能与另一线程 I/O 竞态；事件循环还要在注销 epoll 后正确关闭，并注意 accept 出的新 socket 是新的 fd。

### 面试简答版

Linux 用 `task_struct` 表示可调度 task，线程是共享地址空间、fd table 等资源的一组 task，各自有 TID 和调度上下文。fd 是进程表中的整数索引，指向 open file description，再关联 inode、pipe 或 socket；dup/fork 可能共享 offset，close 只释放一个引用。Socket 通过同一 fd/VFS 抽象支持 read/write/close/poll，但它不是磁盘文件，也不一定支持 seek，网络特有操作仍用 socket 系统调用。
