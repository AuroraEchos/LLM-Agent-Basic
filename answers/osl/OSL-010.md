> **问题：** `P1` Load Average、CPU Utilization、IO Wait 和 Context Switch 应如何结合判断系统瓶颈？
>
> **分类：** 操作系统与 Linux
>
> **来源：** [ENGINEERING_FOUNDATIONS_PATCH.md](../../ENGINEERING_FOUNDATIONS_PATCH.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

四个指标分别描述队列、时间占比和调度活动，必须结合 CPU 核数、趋势与工作负载解释。

### 指标含义

- **Load Average** 是 1/5/15 分钟的指数平滑负载。在 Linux 中大致统计可运行任务以及不可中断睡眠（常见 `D` 状态）的任务数量，不是 CPU 百分比。8 核机器 load 8 可能接近满载，也可能是大量 I/O D-state；容器里看到的值还可能是宿主视角。
- **CPU Utilization** 是采样区间 CPU 时间分布：user、system、idle、iowait、steal 等。总利用率高只表示 CPU 忙，函数热点需 profiler；单核打满时整机 8 核可能仅显示约 12.5%。
- **I/O wait** 表示 CPU 空闲且存在未完成 I/O 的一类时间记账。高值常提示存储路径值得查，但低 iowait 不能排除 I/O 瓶颈：有其他 runnable 工作时 CPU 不空闲，指标就未必记成 iowait。
- **Context Switch** 是 CPU 从一个 task 切到另一个，有 voluntary（主动阻塞/让出）和 involuntary（抢占）等。高 switch rate 可能来自高并发 I/O，是正常现象；若伴随低有效吞吐、高 system CPU、run queue 和延迟，则可能是线程过多、锁竞争或时间片抖动。

### 组合判断

| 现象 | 可能方向 | 进一步证据 |
|---|---|---|
| load/每核高，user CPU 高，run queue 长 | CPU 计算饱和 | `mpstat -P ALL`、`pidstat -u`、perf/profile、cgroup throttled |
| load 高，CPU 不高，D-state/iowait 高 | 块设备/NFS 等 I/O 等待 | `vmstat`、`iostat -xz` 的 latency/queue/util、PSI io、进程 wchan |
| CPU 利用不高但延迟高，context switch/锁等待高 | 线程/锁/调度问题 | `pidstat -w`、线程栈、off-CPU profile、run queue |
| steal 高 | 虚拟化宿主争用 | 云监控/宿主指标，不能只优化应用 |
| cgroup CPU throttle 高但宿主 idle | 容器 quota 瓶颈 | `cpu.stat`、quota/period；宿主总体 CPU 会掩盖它 |

排查顺序可用 USE 方法：对 CPU、内存、磁盘、网络逐项看 utilization、saturation、errors；再将资源指标与请求 p50/p95/p99、吞吐和队列年龄同时间轴关联。瞬时平均会掩盖尖峰，1 分钟 load 也不是即时 run queue；需要秒级历史与压力实验验证因果。

### 面试简答版

Load average 是 runnable 加 Linux 不可中断睡眠任务的平滑数量，要除以/对照核数，不能等同 CPU%；CPU utilization 看 user/system/idle/iowait/steal 时间；iowait 高提示 I/O，但低值不能排除 I/O；context switch 高只有伴随 system CPU、长队列和低吞吐才说明调度/锁抖动。CPU 高+run queue 长查计算热点，load 高但 CPU 低+D-state/iowait 高查存储，容器还要查 cgroup throttling/OOM/PSI，并把资源指标与业务尾延迟对齐。
