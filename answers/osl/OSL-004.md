## 我的答案

### 1. Page Cache 与 Buffer Cache

Linux 用 page cache 缓存文件内容。普通 buffered read 命中时可从内存返回；未命中触发存储 I/O 后把页放入缓存。普通 write 通常先修改 page cache 并标记 dirty，内核稍后 writeback，所以 `write()` 成功不等于数据已落到持久介质；需要相应持久性时使用 `fsync/fdatasync`，还要考虑目录项、设备缓存和文件系统语义。

历史上 buffer cache 更强调块设备块/文件系统元数据缓存；现代 Linux 中数据缓存已与 page cache 大体统一，但 buffer head 等结构仍可管理块映射和元数据。面试中不宜说成两块完全独立、重复缓存文件内容的区域。

缓存占用“available memory”通常不是泄漏：在内存压力下，干净文件页可回收；`free` 的 `available` 往往比单看 `free` 更有意义。重复读取模型权重可能受 page cache 加速，多进程映射同一文件还可共享物理文件页。

### 2. Swap

Swap 为匿名内存等提供后备存储，让冷页可从 RAM 换出，为活跃页腾空间。它能缓解突发压力，但磁盘远慢于 RAM，持续换入换出会产生 thrashing 和巨大尾延迟。没有 swap 并不等于不会 OOM；有 swap 也不是容量规划替代品。模型服务要结合 `vmstat` 的 swap in/out、major faults、PSI 与 cgroup memory events 判断压力，而非看到 swap 已使用就断言正在抖动。

### 3. 内存映射文件

`mmap` 把文件区间映射到虚拟地址，访问时通过 page fault 按需装入 page cache，省去显式 read 循环，并可让内核按访问模式预读/回收：

- `MAP_SHARED` 修改可反映到文件/其他共享映射，持久化时仍需正确的 `msync/fsync` 语义；
- `MAP_PRIVATE` 是 copy-on-write，修改形成私有页，不写回原文件。

mmap 不保证零缺页、零复制或一定更快。随机访问大文件可能造成 page-fault storm；截断正在映射的文件可能触发 `SIGBUS`；地址空间映射很大也不等于 RSS 同样大。`O_DIRECT` 可绕过 page cache，适合应用自带缓存且满足对齐等约束的场景，但小型随机 I/O 未必获益。

### 面试简答版

Page cache 缓存文件页，使读命中走内存、写先变 dirty 后异步回写；write 成功不等于持久化，需要按语义 fsync。现代 Linux 的文件数据缓存和传统 buffer cache 大体统一。Swap 把冷匿名页移出 RAM，可缓冲压力但持续 swap 会抖动。mmap 通过缺页把文件页映射进地址空间，`MAP_SHARED` 可共享/写回，`MAP_PRIVATE` 用 COW；它仍依赖 page cache、可能 major fault，也不保证一定更快。判断性能要结合 cache hit、dirty/writeback、fault、swap I/O 和 PSI。
