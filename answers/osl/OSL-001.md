## 我的答案

每个进程看到的是自己的**虚拟地址空间**。CPU 的 MMU 按页表把虚拟页映射到物理页；某段地址已分配，并不表示它已占用同等大小的 RAM，页面可能尚未因缺页真正装入、被共享、换出，或只有地址范围被保留。

典型用户态布局（具体顺序、地址和方向依 ABI、链接器、内核及 ASLR 而变）包括：

- **代码段 `.text`**：机器指令，通常可读可执行、不可写；共享库的代码页可被多个进程共享。
- **只读数据**：字符串常量、只读全局数据等。
- **数据段 `.data` / `.bss`**：已初始化与零初始化的全局/静态变量；BSS 不需要在可执行文件中保存整块零数据。
- **堆**：动态分配对象。传统上可由 `brk` 扩展，但现代 allocator 对大块内存也常用 `mmap`；“堆一定连续向上增长”只是简化模型。
- **内存映射区**：共享库、可执行文件、普通文件映射、匿名映射、共享内存以及 allocator 的大块映射。`mmap` 可把文件页按需映射进地址空间。
- **栈**：函数调用帧、返回信息和部分局部变量。每个线程有自己的用户栈，大小受限制，并带保护页；大对象或深递归可能栈溢出。
- 还可能有 vDSO/vvar、线程本地存储、内核为进程暴露的特殊映射等。内核地址空间通常受权限保护，用户态不能直接访问。

### 栈、堆和映射的主要差别

栈的生命周期通常随函数调用自动管理，分配释放快但容量有限；堆由 allocator 管理，适合跨作用域、大小动态的对象，但会有元数据、碎片和缓存；`mmap` 以页为粒度创建独立映射，适合大块、文件、共享或特殊权限内存，建立/销毁映射本身也有系统调用和页表成本。

Python 对象通常位于解释器/allocator 管理的堆或匿名映射中，局部变量的 Python 名称并不意味着整个对象在 C 栈上。PyTorch/NumPy 数据还可能位于 native heap、共享内存、pinned memory 或 GPU 显存，单看进程某个“heap”段不足以解释总内存。

排查可读 `/proc/<pid>/maps` 看映射范围与权限，`smaps`/`smaps_rollup` 看 RSS、PSS、private/shared 和匿名/文件页。`VSZ` 是虚拟地址规模，`RSS` 是当前驻留物理内存，PSS 按共享比例分摊；三者不能混为“真实独占内存”。

### 面试简答版

进程拥有独立虚拟地址空间，常见区域有代码/只读数据、data/BSS、堆、mmap 区、每线程栈和共享库。栈随调用自动管理、快但有大小限制；堆由 allocator 管动态对象；mmap 用页映射文件或匿名内存。虚拟地址已分配不等于页面已驻留 RAM，映射还可能共享或换出。Linux 可用 `/proc/pid/maps`、`smaps` 区分 VSZ、RSS、PSS；Python/张量内存也不一定只出现在传统 heap 段。
