> **问题：** LoRA 应作用于 Q、K、V、O 还是 FFN，如何通过实验判断？

## 我的答案

没有一个对所有任务都最优的固定位置。直观上，Q/K 更多影响“看哪里”，V/O 影响“取出和写回什么”，FFN 影响 token 内的特征变换与知识表达。应该结合任务变化类型，并通过控制参数量的消融判断。

### 一、各位置可能影响什么

#### Q 与 K

注意力分数来自：

\[
S=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}+M\right)
\]

给 Q/K 加 LoRA 可以改变 token 间匹配与注意力路由，适合需要调整上下文选择、长依赖或跨模态对齐的任务。K 会进入 KV Cache；如果每请求动态切 adapter，需要确认 runtime 如何处理 adapter 变化与缓存一致性。

#### V 与 O

\[
H=\operatorname{Attention}(Q,K,V),\qquad Y=HW_O
\]

V 改变被聚合的信息表示，O 改变多头结果如何投影回 residual stream。Q/V 是 LoRA 早期常见的参数高效基线；加入 O 往往能增强输出表示适配。不能因为“Q/V 经典”就默认对所有现代架构充分。

#### FFN

以 SwiGLU 为例：

\[
\operatorname{FFN}(x)=W_{down}\left(\operatorname{SiLU}(W_{gate}x)\odot W_{up}x\right)
\]

`gate/up/down` 通常占 Transformer 大量参数，参与每个 token 的非线性特征变换。领域知识、风格、代码和复杂能力迁移可能从 FFN LoRA 获益；代价是 adapter 参数与计算明显增加。

### 二、参数量不能忽略

给某线性层 \(W\in\mathbb R^{d_{out}\times d_{in}}\) 加 rank \(r\) 的 LoRA，参数为：

\[
r(d_{in}+d_{out})
\]

因此“Attention+FFN 比 Q/V 好”可能只是因为它用了更多可训练参数。GQA/MQA 中 Q、K、V 投影形状还不同，K/V 的 LoRA 参数不一定与 Q 相同。比较前应从模型 config 和实际 module shape 计算总参数。

### 三、推荐的分层消融

在相同 base、数据、训练 token 和评测下构建：

1. `Q + V`：低成本经典基线；
2. `Q + K + V + O`：完整 Attention；
3. `FFN only`：只测 token 内变换贡献；
4. `QKVO + FFN`：所有主要线性层；
5. 必要时测 `O only`、`down only` 或任务相关 projector。

每组至少报告：

- 总可训练参数和 adapter 文件大小；
- 任务主指标及难度/长度/领域切片；
- 通用能力和安全能力回退；
- 训练显存、tokens/s、推理是否合并以及多 LoRA 服务代价。

为了分清覆盖范围和参数量，可做两种实验：

- **固定 rank**：回答“扩大 module 范围的整体收益”；
- **固定总参数量**：给 module 更多的一组降低 rank，回答“参数放在哪里效率最高”。

### 四、怎样根据结果选择

- Q/V 已达到目标且差距很小：选择更小 adapter，便于多租户服务；
- 加 K/O 明显改善长上下文或对齐任务：保留完整 Attention；
- FFN only 或加入 FFN 对领域能力提升显著：说明仅调整注意力路由不够；
- 全 linear 训练 loss 更低但验证下降：可能容量过大或数据不足，应降 rank、加正则或改善数据；
- 某层组梯度范数长期接近零：检查 target 命中、量化/冻结配置和实现，而不是立即判定该 module 无用。

还可查看各 adapter 的梯度范数、\(\|BA\|/\|W\|\)、奇异值谱和层间分布辅助解释，但最终仍以独立验证集和线上指标裁决。

### 面试简答版

Q/K 主要改变注意力匹配和“看哪里”，V/O 改变聚合内容与写回 residual 的表示，FFN 的 gate/up/down 负责 token 内非线性特征变换，常对领域与能力迁移重要。Q/V 是低成本基线，但现代 LLM 上 Attention 全投影或所有 linear 可能更强。实验应依次比较 QV、QKVO、FFN only、QKVO+FFN，并同时做固定 rank和固定总参数量两套对照，因为 module 更多本身就增加参数。最后按任务切片、遗忘、显存、adapter 大小和多 LoRA 部署成本选择。
