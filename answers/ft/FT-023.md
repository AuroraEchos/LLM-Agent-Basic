> **问题：** 如何判断微调是在注入知识、改变风格，还是学习新的任务能力？

## 我的答案

这三种变化会混在最终准确率中，不能仅凭“微调后答对了”判断。需要把**内容是否见过、任务规则是否见过、输出风格是否受控**设计成正交变量，并用反事实和跨模板评测拆分。

### 一、先定义三类目标

- **知识注入**：模型在无外部上下文时，能回忆训练前未知的事实、术语或实体关系；
- **风格改变**：事实与解题能力基本不变，但语气、长度、结构、术语、拒答或品牌表达改变；
- **新任务能力**：模型学会一种映射、算法、工具协议或决策规则，并能迁移到未见内容，而非记住训练答案。

SFT 还可能只是**激活基座已有潜在能力**。因此“训练前做不到、训练后做到”也不自动证明模型内部产生了全新算法。

### 二、用二维/三维对照集拆解

构建如下因子：

| 维度 | 已见 | 未见 |
|---|---|---|
| 事实/实体 | 训练中出现的知识 | 时间外或严格隔离的新知识 |
| 任务规则 | 训练过的任务形式 | 新模板、新组合或新规则 |
| 风格 | 目标风格 | 中性/其他风格指令 |

然后做交叉测试：

- 已见事实 + 新问法：检验知识是否超越原句记忆；
- 未见事实 + 已见规则：检验任务能力泛化；
- 已见内容 + 指定不同风格：检验风格是否可条件控制；
- 新事实 + 新实例但同算法：检验规则迁移，而不是答案记忆。

所有 Test 必须按实体、题目家族、来源和模板与训练隔离。

### 三、如何判断知识注入

1. 微调前先测并剔除 base 已会的事实，或记录概率基线；
2. 微调后做多种语义改写、反向问题、组合关系和干扰选项；
3. 检查训练事实能否跨上下文稳定回忆，而非复述邻近文本；
4. 用冲突事实/时间切片测试更新和旧知识干扰；
5. 同时观察未训练相关事实是否被错误外推。

如果只对训练句式有效，更多是记忆；若能在新关系组合中正确使用，才有更强的知识内化证据。对于频繁更新、需要引用和可删除的知识，RAG 通常比写入参数更可控。

### 四、如何判断风格改变

- 固定同一组问题与参考事实，只改变“用目标风格/中性风格”条件；
- 用盲评或 style classifier 测语气、结构、长度、术语和品牌规范；
- 同时用事实正确率、代码测试等确保内容能力没被风格分数掩盖；
- 检查目标风格是否无条件泄漏到不该使用的场景。

若所有问题都变得更长或总用固定开头，这可能只是表面模板模仿，不是稳健的可控风格。

### 五、如何判断新任务能力

以工具调用为例，不能只测训练过的城市或 API 参数。应在未见实体、参数组合、工具错误、调用顺序和新自然语言表达上测试 schema 与执行成功率。代码/数学则用新生成且可执行验证的实例，必要时按难度外推。

可以比较：

- 只给自然语言任务说明的 in-context baseline；
- SFT 后零样本表现；
- 打乱输入—答案配对或只保留风格的数据消融；
- 同数据量的知识-only、style-only、task-demonstration-only 训练。

若正确率仅在内容重叠样本上提升，倾向记忆；若未见内容上也遵循新规则，才支持任务能力提升。

### 六、归因注意事项

- 训练数据中知识、风格和任务示范常相关，要人工构建反事实数据打破相关性；
- judge 可能偏爱目标风格或长答案，应使用执行器与独立内容指标；
- 不同 checkpoint 的能力变化轨迹也有信息：风格通常很快改变，复杂能力可能需要更多覆盖，但这只是线索，不是证明；
- 参数探针、LoRA 范数和 embedding 可帮助分析，但行为归因最终要靠干预与独立测试。

### 面试简答版

我会把事实内容、任务规则和输出风格做正交对照。知识注入要在训练前未知的事实上，经过改写、反向询问和关系组合仍能闭卷回答；只复现原句是记忆。风格改变用相同问题比较目标/中性风格，同时保持事实或执行正确率，并检查风格是否错误泄漏。新任务能力必须在未见实体、模板、参数组合和难度上仍遵循规则，用代码测试、工具执行等验证。再通过 knowledge-only、style-only、task-only 数据消融和固定 token budget 归因。
