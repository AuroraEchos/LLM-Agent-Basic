> **问题：** Adapter、Prefix Tuning、Prompt Tuning 和 LoRA 有何差异？
>
> **分类：** SFT 与参数高效微调
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

四者都是 Parameter-Efficient Fine-Tuning（PEFT），共同点是冻结大部分基座参数；区别在于**新增参数放在哪里、如何影响前向、是否占用序列/KV，以及能否合并进原权重**。

### 一、结构对比

| 方法 | 新增参数位置 | 如何影响模型 | 典型额外参数 | 主要推理代价 |
|---|---|---|---:|---|
| Adapter | 每层 Attention/FFN 后插瓶颈网络 | 对 hidden state 做非线性残差变换 | 约 \(O(Ldr)\) | 每层新增串行算子 |
| Prefix Tuning | 每层 Attention 的虚拟 K/V 前缀 | 所有 token 都可注意一组可学习前缀 | 约 \(O(2Lpd)\) | KV/Attention 长度增加 |
| Prompt Tuning | 输入 embedding 前的软 token | 仅在输入层加入可学习提示向量 | \(O(pd)\) | 占上下文，Attention 稍增 |
| LoRA | 线性层权重旁的低秩分支 | 学习 \(\Delta W=BA\) | \(O(r(d_{in}+d_{out}))\) / 层 | 可动态分支，也可合并 |

其中 \(L\) 为层数，\(d\) 为 hidden size，\(r\) 为瓶颈/低秩维度，\(p\) 为虚拟 token 数。实际参数量取决于具体实现与 target modules。

### 二、Adapter：在层内增加小网络

经典 bottleneck adapter 可写为：

\[
h'=h+W_{up}\,\sigma(W_{down}h)
\]

其中先降维再升维。它具有非线性，表达能力强，任务模块边界清楚；但它位于每层主路径上，通常增加串行 kernel 和 latency，也不容易像线性 LoRA 那样无条件代数合并到单个原权重中。

### 三、Prefix Tuning：每一层都有可学习虚拟 KV

Prefix Tuning 不修改原 token，而是为每层 Attention 注入长度为 \(p\) 的可学习 key/value：

\[
K'=[K_{prefix};K],\qquad V'=[V_{prefix};V]
\]

它能直接引导各层注意力，参数量较小；但每个请求都要携带 prefix KV，实际 Attention 长度变为 \(T+p\)，消耗 KV Cache、带宽和计算。多租户切 prefix 也需管理每层缓存。

### 四、Prompt Tuning：只学习输入层软提示

Prompt Tuning 在 token embedding 前拼接 \(p\) 个连续可训练向量：

\[
H_0=[P;E(x)]
\]

它参数最少、制品很小、实现简单，但控制信号只从输入层逐层传播，也占用上下文窗口。模型越小或任务分布差异越大时，纯软提示可能表达能力不足；而且 learned prompt 向量不可直接解释为自然语言。

### 五、LoRA：在线性权重空间学习低秩更新

LoRA 对选中的 Q/K/V/O 或 FFN 线性层使用：

\[
y=W_0x+\frac{\alpha}{r}BAx
\]

它不增加序列长度，容量和作用范围容易通过 rank 与 target modules 调节。高精度 base 上可合并为 \(W_0+\alpha/r\cdot BA\)，消除分支开销；多任务服务则可保持动态 adapter。量化模型合并需要重新量化，并非无损。

### 六、如何选择

- 追求当前 LLM 生态兼容、质量/成本平衡和多 LoRA 服务：通常先选 LoRA/QLoRA。
- 需要每层非线性任务模块，且能接受额外串行延迟：考虑 bottleneck Adapter。
- 极少参数、超大模型、任务主要可由软上下文引导：尝试 Prompt Tuning。
- 希望各层 Attention 都获得显式任务条件：Prefix Tuning 比仅输入层 Prompt Tuning 更强，但要核算 KV 与长上下文代价。

应在相同数据、训练 token 和可训练参数预算下比较主指标、通用能力遗忘、峰值显存、TTFT/TPOT、制品大小与多租户切换成本。参数少不代表延迟一定低，新增 token 和串行小算子都可能比参数量显示得更昂贵。

### 面试简答版

Adapter 在每层插入降维—非线性—升维的小网络，表达强但增加串行推理算子；Prefix Tuning 为每层 Attention 学习虚拟 K/V，能直接影响各层，但会增加 KV Cache 和有效序列长度；Prompt Tuning 只在输入 embedding 前学习少量软 token，参数最少但控制能力相对弱，也占上下文；LoRA 在线性层旁学习低秩权重更新，不增加序列长度，高精度下还能合并。选择时不能只比参数量，还要比较任务质量、KV/上下文、TTFT/TPOT 和多租户切换成本。
