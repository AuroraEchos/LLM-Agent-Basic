## 我的答案

多 LoRA 系统包含两个层面：离线决定 adapter 如何组合，在线决定请求路由到哪个 adapter 并高效加载。它的前提是所有 adapter 与同一个 base revision、模型结构和模板协议兼容。

### 一、多个 Adapter 如何组合

若第 \(j\) 个 LoRA 的增量为：

\[
\Delta W_j=s_jB_jA_j
\]

最直接的线性组合是：

\[
W'=W_0+\sum_{j=1}^{m}\lambda_j\Delta W_j
\]

可在离线将加权增量 merge，也可运行时计算多个分支。把多个 rank-r adapter 拼接，可构成最高 rank 约为 \(mr\) 的等价增量，但参数与计算也累加。

组合并不保证能力相加：两个 adapter 可能修改相同方向、缩放不同或行为冲突，负权重/大权重还可能使输出偏离训练分布。每种组合都应在目标、通用、安全和格式集重新评估。更复杂的 Adapter Fusion/learned router 可以按层或 token 学权重，但它本身需要训练和版本管理。

### 二、路由策略

- **显式路由**：请求携带 `adapter_id`，适合租户定制和确定性任务；
- **规则路由**：按产品、语言、领域、工具或权限选择；
- **分类器/LLM 路由**：先预测任务，再选 adapter；要评估错路由、额外延迟和 fallback；
- **级联**：默认走通用 adapter，低置信或高价值请求升级到专用 adapter；
- **组合路由**：同时启用风格+领域 adapter，但需预先验证允许的组合矩阵。

路由结果应写入 trace，支持离线复盘。安全/权限不能只靠语义分类器，租户可用的 adapter 需要服务端 ACL。

### 三、热切换和高效服务

共享 base 常驻 GPU，把 adapter 分成：

```text
GPU 热缓存 → CPU pinned-memory 缓存 → 对象存储冷层
```

按热度预取和 LRU/LFU 淘汰；加载过程异步，但请求只有在完整校验 adapter 后才能执行。batch 内请求使用不同 adapter 时，runtime 可按 adapter 分组 GEMM，或用支持 heterogeneous LoRA 的 kernel，避免把 batch 全拆成单请求。

关键约束是：**同一个生成序列中不能随意中途更换 adapter 并继续复用旧 KV Cache。** 之前的 K/V 和 hidden states 是旧 adapter 下产生的，换 adapter 后函数已改变；安全做法是保持 sequence-level adapter affinity，若必须切换则重算受影响前缀。

### 四、兼容性与版本元组

每个 adapter 制品至少记录：

- `adapter_id`、语义版本、状态（draft/canary/prod/retired）；
- base model 的不可变 hash/revision，而不只是模型名字；
- tokenizer、special token、Chat Template、tool schema 版本；
- target modules、rank、alpha/scaling、dropout、DoRA/rsLoRA 等变体；
- dtype、量化 base 配置、训练代码 commit 和 PEFT/runtime 版本；
- 数据 manifest、评测报告、许可证、签名与 checksum。

加载时做 shape、module name、base hash 和 checksum 校验；不兼容就 fail closed。不能把为 `model-v1` 训练的 adapter 静默挂到同名但权重已更新的 `model-v2`。

### 五、发布、灰度与回滚

1. 离线通过质量、安全、格式和 merge/dynamic 一致性测试；
2. 预加载到小流量 canary worker，按 adapter 版本比较 SLO 与业务指标；
3. 路由配置和 adapter 制品分开版本化，但发布记录要绑定二者；
4. 使用 immutable artifact，新版本新 ID，不覆盖正在运行的文件；
5. 保留上一稳定版和一键回滚，drain 旧请求后再卸载；
6. 监控加载失败、cache hit、adapter 数/rank 对 TPOT、OOM 和错路由率的影响。

### 六、安全边界

第三方 adapter 等同于模型代码/权重供应链的一部分。只允许受信来源，做签名、扫描、大小/rank 限额，禁止任意路径加载；租户间 cache key 和日志隔离。某个 adapter 可能破坏 base 的安全对齐，因此每个 adapter 及常用组合都需独立红队测试。

### 面试简答版

多个 LoRA 可把增量按 \(W_0+\sum_j\lambda_jB_jA_j\) 线性组合或离线 merge，但能力不保证线性相加，组合也要回归。在线可由请求 ID、规则或分类器路由，base 常驻 GPU，adapter 用 GPU/CPU/对象存储分层缓存并对异构 batch 做 grouped kernel。一个生成序列应固定 adapter；中途切换会使旧 KV 与新模型不一致。版本必须绑定 base hash、tokenizer/template、target modules、rank/scaling、量化和数据评测，并用不可变制品、灰度、ACL、签名与可回滚发布。
