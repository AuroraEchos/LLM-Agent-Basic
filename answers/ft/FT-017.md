## 我的答案

三种问题可能同时发生，但概念不同：**灾难性遗忘是旧能力下降，过拟合是训练数据表现继续变好而未见数据变差，格式退化是输出协议、角色或停止行为被破坏**。只看总体 SFT loss 无法区分它们。

### 一、如何发现

#### 灾难性遗忘

在微调前后用同一套冻结评测比较：

- 通用知识、推理、代码、多语言和安全能力；
- 目标领域外任务与原模型典型能力；
- perplexity 或 next-token loss 在通用 held-out corpus 上的变化；
- 不同 checkpoint 的能力曲线，而不只看最终模型。

若目标任务提升，但多个旧能力桶稳定下降，才有证据称为遗忘。目标数据与旧任务分布冲突、全参更新幅度过大是常见原因。

#### 过拟合

- train loss 持续下降，validation loss/任务指标停止提升或恶化；
- 训练样本轻微改写就答不好，或能复述训练答案中的独特片段；
- 同模板验证集很好，换表达、实体和难度后明显下降；
- 多个随机种子波动大，少数样本对结果影响异常大。

要保证 validation 在语义和模板上与 train 真正隔离，否则泄漏会伪装成“没有过拟合”。

#### 格式退化

单独统计机器可验证指标：JSON/schema parse rate、tool call 参数通过率、角色串台率、EOS/stop 正确率、额外前后缀率、代码编译率和多轮协议成功率。格式退化有时总体语义分数变化不大，却会直接让生产链路失败。

### 二、共同根因

- 学习率过大、epoch 过多或数据量过小；
- 目标数据重复、风格单一，长答案在 token-level loss 中权重过高；
- 通用数据和安全数据被完全移除；
- Chat Template、Loss Mask、EOS 或工具协议错误；
- 合成 teacher 的固定口吻、冗长偏好和错误被放大；
- 训练只以目标域 loss 选 checkpoint，没有多目标回归门槛。

### 三、缓解灾难性遗忘

1. 混入经过筛选的通用 replay 数据、安全数据和旧任务示范；
2. 降低学习率、训练步数和可训练范围，先用 LoRA 等 PEFT 建基线；
3. 对参考模型增加 KL/L2-SP 等保持约束：

\[
\mathcal L=\mathcal L_{SFT}+\lambda
D_{KL}(p_\theta(\cdot|x)\|p_{ref}(\cdot|x))
\]

4. 使用分层采样，防止大领域数据淹没少数通用能力；
5. 以“目标提升且旧能力不跌破阈值”的 Pareto 准则选 checkpoint。

KL 约束太强也会阻止领域适配，因此 \(\lambda\) 要做消融。

### 四、缓解过拟合

- 语义去重、提高数据质量和表达多样性，而不只是增加模板改写；
- early stopping、减少 epoch、降低 rank/target modules，必要时增加 dropout/weight decay；
- 按样本归一化或限制超长回答权重，避免少数长样本主导；
- 用执行器、扰动集、跨模板集和时间外数据评估泛化；
- hard-example mining 时保留难度梯度，避免只训练极难且噪声大的样本。

### 五、缓解格式退化

- 训练、评测、部署共用同一 tokenizer、Chat Template 与 tool schema；
- 精确标注 assistant/tool-call/结束 token 的 Loss Mask；
- 增加合法格式、错误恢复、工具失败和多轮边界样本，而非只加最简单 happy path；
- 对 JSON、代码、SQL 用 parser/compiler/test 做数据过滤和 checkpoint 验收；
- 必要时在推理端配合 grammar/constrained decoding，但它不能替代模型语义训练。

### 六、工程闭环

每隔固定有效 target tokens 保存 checkpoint，并生成三条曲线：目标能力、保留能力、协议成功率。上线前设置硬门槛，例如目标指标提升、通用关键集下降不超过容忍值、tool parse rate 不低于基线。灰度时按模型/模板/adapter 版本监控 bad case，并能一键回滚。

### 面试简答版

灾难性遗忘看微调前后通用和旧任务能力是否下降；过拟合看 train 与真正语义隔离的 validation 是否出现 gap，以及扰动后能否泛化；格式退化则用 JSON/tool parse、EOS、角色串台、代码编译等协议指标发现。缓解上，遗忘用通用 replay、较小学习率/可训练范围和 KL 保持；过拟合用去重、多样数据、early stopping、正则和按样本权重；格式问题要统一模板、修正逐 token mask，并用 parser/执行器验收。checkpoint 应按目标能力、保留能力和格式成功率共同选择。
