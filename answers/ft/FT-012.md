> **问题：** LoRA 合并进基础权重后是否完全没有推理开销，量化模型上有什么例外？

## 我的答案

对普通 FP32/BF16/FP16 权重，LoRA 可以先计算：

\[
W_{merged}=W_0+\frac{\alpha}{r}BA
\]

再用一次普通线性层完成前向。此时从计算图角度看，确实消除了 LoRA 分支的两次小矩阵乘和相关 kernel launch；但“完全没有任何代价”仍不严谨，尤其在量化模型上通常不能无损直接相加。

### 一、高精度权重上的结论

未合并时：

\[
y=W_0x+sB(Ax)
\]

合并后：

\[
y=W_{merged}x
\]

代数上两者等价，因此合并后：

- 不再需要 adapter 分支的额外 GEMM、读参数和 kernel launch；
- 主权重形状不变，单请求推理路径与普通线性层相同；
- 不再方便按请求切换 adapter；每个任务若都预合并，需要保存一整份模型；
- merge 有一次性计算和保存成本，也会受到目标 dtype 舍入误差影响；
- 若存在 tied weights、分布式 shard 或 tensor parallel，必须在正确布局中合并。

所以更准确的说法是：**合并后基本没有 LoRA 分支的稳态算子开销，但会牺牲多 adapter 灵活性并承担制品与数值处理成本。**

### 二、量化权重为什么例外

设量化基座表示为：

\[
W_q=s_q(q-z)
\]

LoRA 增量 \(sBA\) 通常是 BF16/FP16。量化整数张量 `q` 不能直接精确加上浮点低秩增量，常见处理只有两类。

#### 方案 1：运行时保留两条分支

```text
dequantized base matmul + LoRA matmul
```

这样保持 adapter 可切换，也较接近训练时的量化基座，但 LoRA 分支依然有额外读写与 kernel；batch 很小或 adapter 很多时开销更明显。

#### 方案 2：反量化、合并、再量化

\[
\widehat W=\operatorname{Quantize}
\left(\operatorname{Dequantize}(W_q)+sBA\right)
\]

部署时恢复单一量化矩阵乘，但重新量化会带来新的舍入与 clipping 误差。原 GPTQ/AWQ 的 scale、zero point、分组和校准结论是针对旧权重的，合并后权重分布变化，直接沿用旧参数不一定最优，最好重新量化并做任务回归。

### 三、QLoRA 的额外细节

QLoRA 的 adapter 是在“冻结的 4-bit 基座反量化到计算 dtype”的前向上训练的。部署可选择：

- 原 4-bit base + adapter 动态计算；
- 合并到高精度原始 base，再部署高精度模型；
- 合并后重新做 4-bit 量化。

三种路径的函数并不保证逐位相同。特别是把 adapter 直接合并到未量化原始 base，base 的量化误差背景发生了变化；有时质量更好，有时会偏离训练分布，必须实测。

### 四、还要考虑多 Adapter 服务

如果每个请求使用不同 LoRA，预合并意味着为每个 adapter 复制完整基座，通常得不偿失。生产 runtime 会保留共享 base，并对 batch 中不同 adapter 做分组或融合 kernel。此时不能宣称“LoRA 零推理开销”，应实测 adapter 数、rank、batch composition、cache 命中下的 TTFT 与 TPOT。

### 面试简答版

在 BF16/FP16 等高精度模型上，可把 \(W_0+\alpha/r\cdot BA\) 预先合并成同形状权重，稳态前向只剩原线性层，基本消除了 LoRA 分支算子开销，但失去动态切换 adapter 的能力。量化权重不能精确直接加浮点增量：要么保留量化 base 和 LoRA 两条运行时分支，仍有开销；要么先反量化、合并再量化，会产生新的量化误差，GPTQ/AWQ scale 也可能需要重校准。QLoRA 合并到原始高精度 base 或重新量化都应单独回归质量。
