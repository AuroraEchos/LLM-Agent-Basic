## 我的答案

四种来源都能构建 SFT 数据，但风险结构不同：人工标注主要受成本和一致性限制；模型蒸馏会继承 teacher；开源数据的核心是来源、许可证和污染；Self-Instruct 则容易产生自举偏差和同质化。生产数据集通常混合使用，而不是押注单一来源。

### 一、人工标注

优势是可以针对业务规则、复杂边界和真实失败案例精细设计，还能追责和复核。主要风险有：

- 标注成本高、速度慢，导致覆盖面不足；
- 指南含糊时，标注员之间标准不一致；
- 专业任务由非专家标注，答案表面流畅但事实错误；
- 标注员迎合示例模板，形成单一风格和长度偏差；
- 接触有害内容带来标注员身心风险；
- 原始业务数据中可能含个人信息、商业秘密或访问越权。

治理措施包括详细 rubric、培训与资格测试、双标/仲裁、golden questions、inter-annotator agreement、专家抽检、脱敏和最小权限。不能只看标注“完成率”。

### 二、模型蒸馏数据

这里指用强 teacher 为 Prompt 生成回答、推理过程或工具轨迹，再训练 student。它便宜、可扩展，还能统一格式，但风险包括：

- teacher 的幻觉、偏见、过度拒答和错误推理被批量复制；
- student 学到 teacher 的口吻和长度偏好，输出同质化；
- teacher 能力构成上限，稀有错误因批量生成被放大；
- Prompt 过于简单时，只是在复制 teacher 的常见表面行为；
- 使用第三方模型输出可能受服务条款、训练用途限制和数据保留政策影响；
- teacher 输出可能无意复现 benchmark 或受版权保护内容。

应使用执行器、规则、多个 judge、teacher disagreement 和人工抽检过滤；保留生成模型、Prompt、采样参数与验证结果，避免无法追溯。

### 三、开源数据

开源不等于可以任意用于商业训练。常见风险是：

- 许可证缺失、互相冲突，或数据内容本身并非发布者有权授权；
- 含个人信息、仇恨、有害内容、密钥和恶意 Prompt；
- 数据重复、格式混乱、答案过时或质量不明；
- 训练集、验证集和公开 benchmark 相互污染；
- 多个“不同数据集”其实来自同一上游，混合后重复计权；
- 原模型生成的数据没有标明 provenance，可能违反下游使用条件。

需要数据卡、许可证审查、来源血缘、内容扫描、语义去重、benchmark contamination 检测和版本固定。删除请求也要求能从样本追溯到制品。

### 四、Self-Instruct

Self-Instruct 用种子任务引导模型生成新指令、输入与答案，再过滤后回灌。它能低成本扩任务覆盖，但有典型的自举风险：

- 种子集的领域和风格偏差被不断放大；
- 模型倾向生成自己最熟悉的简单任务，表面数量大但语义重复；
- 指令看似新颖，答案却错误、不可解或与约束冲突；
- 同一模型既出题又答题，缺少独立校验；
- 多轮自训练可能缩窄分布，降低多样性，形成 model collapse；
- 过滤器若也是同源模型，会与生成器共享盲点。

可用多样化人工种子、任务聚类和去重、难度控制、不同模型交叉验证、可执行任务验证，并限制合成数据占比。高风险领域仍需专家审核。

### 五、混合与验收

一个稳妥的组合是：真实线上 bad case 和人工数据定义目标边界，开源数据提供广度，teacher 蒸馏扩展高质量示范，Self-Instruct 补长尾任务。每条样本都保留 `source / license / generator / verifier / quality / version`，按来源设置采样权重。

评估时不仅看总体正确率，还要按数据来源切片。如果去掉某一来源后效果几乎不变，说明其边际价值有限；如果模型在该来源的训练风格上很好、真实线上却无提升，则可能发生了分布错配。

### 面试简答版

人工标注的风险是昂贵、覆盖有限和标注标准不一致；模型蒸馏会批量继承 teacher 的幻觉、偏见、风格和使用条款风险；开源数据重点防许可证、隐私、上游重复、低质量和 benchmark 污染；Self-Instruct 容易放大种子偏差，生成同质简单任务，并因生成器与验证器共享盲点导致自举错误。我的做法是混合来源、保留完整 provenance，用规则/执行器/异源模型与人工分层验证，并通过按来源消融判断真实边际价值。
