## 我的答案

定位时先排除评测链路变化，再判断下降发生在什么 checkpoint、哪些能力桶，最后用最小对照实验区分数据、优化强度和实现错误。不能一看到下降就直接“混更多通用数据”，否则可能掩盖真正的模板或 Loss Mask bug。

### 一、第一步：确认是模型退化而非评测漂移

用同一个 base checkpoint 重跑新旧评测管线，核对：

- tokenizer、Chat Template、BOS/EOS、stop tokens；
- system prompt、few-shot、generation 参数和最大长度；
- 量化、推理框架、模型 revision 与 adapter 是否正确加载；
- 数据集版本、答案解析器、judge/prompt 版本和随机种子；
- 是否因输出更短/更长触发 parser 或截断。

若 base 在新管线也下降，先修评测，不能归因于微调。

### 二、按切片定位下降形态

比较 base 与每个训练 checkpoint，而不只比较最终模型：

- 语言、领域、长度、任务、难度和安全切片；
- 生成能力、选择题、代码执行、格式和拒答分别看；
- 目标任务提升与通用下降从第几步同时出现；
- train/validation loss、梯度范数、参数更新范数与输出长度变化。

若第一批更新就骤降，怀疑学习率、mask、模板或数据严重冲突；若随 epoch 缓慢下降，更像过度训练和分布遗忘；只在格式解析下降则优先检查协议。

### 三、数据侧审计

1. **混合比例**：领域/拒答/长推理是否压倒通用数据；看实际 target tokens，而非文件条数。
2. **质量与冲突**：错误答案、teacher 偏见、同 Prompt 矛盾响应、过时知识和错误拒答。
3. **重复与长度**：少数模板或长答案是否因重复/token 数获得过大权重。
4. **语言和风格**：单一语言、固定开头、极端简洁/冗长是否改变通用输出分布。
5. **Loss Mask**：是否误对 user/system/tool result 计算 loss，assistant/EOS 是否漏训或错位。
6. **切分泄漏**：Validation 太接近 Train，错误地选择了过拟合 checkpoint。

可做 source leave-one-out：每次去掉一个数据源，以小 token budget 重训，观察哪一来源触发回退；也可只训练少量人工高质量集，判断问题是数据规模还是配置。

### 四、训练配置审计

- 学习率、warmup、scheduler、epoch 与 global target-token batch；
- 全参/LoRA/QLoRA、rank、alpha、dropout、target modules；
- weight decay 是否误用于 norm/bias/LoRA，gradient clipping 是否在正确位置；
- 混合精度溢出、loss scaling、量化 compute dtype 和梯度异常；
- gradient accumulation、packing、sequence truncation 是否改变样本权重；
- 冻结规则是否正确，embedding/LM head 是否被意外训练；
- 分布式训练是否漏同步、恢复 checkpoint 后 sampler/scheduler 是否错位。

检查每层 \(\|\Delta W\|/\|W\|\)、LoRA 范数和梯度分布。某层更新异常大是定位信号，但不能仅凭范数断定因果。

### 五、最小消融矩阵

固定数据子集和训练 token，至少比较：

| 实验 | 目的 |
|---|---|
| 当前配置复现 | 确认问题稳定存在 |
| 学习率降 2～10 倍 | 判断更新过猛 |
| 步数/epoch 减半 | 判断过度训练 |
| LoRA 缩小 rank/target | 判断可训练范围过大 |
| 修正 mask/template | 排查协议实现 |
| 加通用 replay | 判断分布遗忘 |
| 去掉可疑数据源 | 判断数据冲突 |
| 加 KL 保持 | 判断约束是否有效 |

一次只改变一个主要因素；多个随机种子验证小差异。若时间有限，先跑小模型/短训练进行方向筛选，再在目标模型复核。

### 六、修复与上线门槛

常见修复是降低学习率/步数、提高数据质量和多样性、平衡 target-token 混合、使用 PEFT、加入通用 replay 或对 reference 加 KL。格式问题则优先统一模板、mask 和 EOS。

最终按 Pareto 选 checkpoint：目标指标达到增益，同时通用、安全、格式和成本不跌破硬门槛。上线采用灰度和 adapter/base 一键回滚，保留每次数据与配置变更的因果记录。

### 面试简答版

我先用同一 base 重跑新旧评测，排除模板、generation、parser、数据版本和 adapter 加载漂移。然后比较各 checkpoint 的任务/语言/长度/格式切片：首步骤降通常怀疑学习率、mask 或模板，随 epoch 缓慢下降更像遗忘。数据侧检查实际 target-token 配比、冲突、重复、长答案和错误 mask；配置侧检查学习率、步数、rank/target、冻结、精度和 packing。最后用降学习率、减步数、去可疑源、加 replay/KL 等单变量小规模消融定位，并按目标提升与通用保留的 Pareto 门槛选模型。
