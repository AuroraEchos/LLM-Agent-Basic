## 我的答案

正确的切分单位通常不是“数据行”，而是能产生相关性的上游单位，例如**同一文档、用户、会话、题目家族、代码仓库、模板种子或时间窗口**。先随机逐行切分再去重，往往已经把近重复和语义改写泄漏到多个集合。

### 一、三个集合各自用途

- **Train**：用于梯度更新和数据采样调试；
- **Validation**：用于超参数、early stopping、checkpoint、模板和数据配比选择；
- **Test**：只在方案冻结后做最终一次或少量审计，不能反复据此改模型。

如果团队看了 Test 结果后继续调整，它实际上已变成 Validation，应再建立未触碰的 Test。对高频迭代可保留内部开发集、冻结回归集和最终盲测集多层结构。

### 二、正确顺序：治理后按组切分

```text
收集与溯源
→ 规范化
→ 精确/近似/语义去重与聚类
→ 按 group/source/time 切分
→ 集合间污染扫描
→ 冻结 manifest
```

规范化可统一 Unicode、空白、大小写、HTML、代码格式和模板壳，但要保留原始 ID。先形成 duplicate/semantic cluster，再把整个 cluster 分到同一个集合，避免同一内容的不同改写跨集合。

### 三、防止三类泄漏

#### 1. 精确与近重复泄漏

- 对规范化文本做 hash 查重；
- 用 MinHash/LSH、SimHash、n-gram containment 检测局部复制；
- 长文要按文档和片段两级查重，因为测试题可能只复制训练文档的一段；
- 代码按 token/AST、仓库和 commit lineage 检查，而不只比较字符串。

#### 2. 指令模板泄漏

若先用 20 个模板批量生成题目，再随机切行，那么 Test 可能只是替换实体的同一模板。应按 `template_id / seed_prompt / generator_batch / task_family` 分组切分，并额外建立未见模板评测。

例如：

```text
训练：把 {城市A} 到 {城市B} 的距离转为公里
测试：把北京到上海的距离转为公里
```

实体不同不代表独立；推理结构和答案程序完全相同。

#### 3. 语义泄漏

同一事实、题目或代码 bug 可有不同表述。用 embedding 聚类、检索相似度、LLM pair judge 辅助筛查，并对高相似边界样本人工复核。对数学题可抽取规范化表达式/答案，对 QA 可用实体—关系—答案三元组，对工具任务比较调用轨迹。

### 四、选择合理的切分维度

- 客服/个性化：按 user/account 切，验证新用户泛化；
- 多轮对话：整段 conversation 不可拆开；
- 文档 QA/RAG：按 source document 或站点切；
- 代码：按 repository/project 切，必要时按时间切；
- 新闻/知识更新：使用时间外切分，Test 时间晚于 Train；
- 合成数据：按 seed、teacher prompt 和生成批次切；
- 医疗等主体数据：同一患者所有记录只能在一个集合。

可同时构建 IID validation 和 OOD/temporal test，分别衡量同分布优化与真实迁移。

### 五、避免 Benchmark Contamination

- 将公开 benchmark 题目、答案及常见改写加入 denylist/reference index；
- 在原始数据、生成 Prompt、teacher 输出和最终 packed tokens 多阶段扫描；
- 不只搜索题目全文，还搜索独特短语、答案、代码测试和翻译版本；
- 公开数据版本与 benchmark 版本都要锁定，因为后续版本可能互相收录；
- 对无法确认来源但高度相似的样本，宁可隔离到 quarantine，不进入训练。

### 六、可复现与审计

保存每条样本的稳定 ID、source、license、group、cluster、split、时间、hash、生成器与过滤版本；用 manifest 固定集合，并禁止训练管线根据 Test 内容做数据过滤之外的优化。每次数据更新重新输出集合交叉相似度分布和高相似样本清单。

### 面试简答版

我不会按数据行直接随机切分，而是先规范化和做精确、近似、语义去重，形成文档/用户/会话/题目家族/模板种子等 group，再让整个 group 只进入一个集合。模板生成数据按 template ID、seed 和生成批次隔离；代码按仓库，RAG 按源文档，时效知识按时间切。切分后再用 hash、MinHash、embedding 检索和领域结构检查集合间污染。Validation 用于调参，Test 在方案冻结后使用；如果根据 Test 反复改模型，就必须建立新的盲测集。
