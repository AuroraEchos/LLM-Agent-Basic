## 我的答案

这些超参数应围绕三个量选择：**有效 target token 数、更新步数和验证曲线**。SFT 数据长度差异很大，只说“3 个 Epoch、Batch Size 32”而不说明 token、packing、梯度累积和并行度，信息是不完整的。

### 一、学习率

学习率取决于全参还是 PEFT、模型规模、数据量、global batch、optimizer 和 target modules。

- 全量 SFT 改动所有权重，通常从较小量级试起，例如 \(10^{-6}\) 到数个 \(10^{-5}\)；
- LoRA/Adapter 只训练少量参数，可从 \(10^{-5}\) 到数个 \(10^{-4}\) 搜索；
- 这些只是常见数量级起点，不是公式。小数据、高 rank、QLoRA 数值敏感时仍可能需要更低学习率。

用短 pilot run 做对数网格搜索，观察 loss 下降速度、梯度范数、目标验证集和遗忘集。学习率过高表现为 loss spike、格式崩坏和旧能力快速下降；过低则训练 loss 几乎不动或预算内未收敛。

通常保留少量 warmup，再线性/cosine decay；数据很小、总 step 很少时，warmup 比例不能机械照搬预训练设置。

### 二、Epoch 与训练步数

Epoch 是数据被重复的次数：

\[
\text{steps/epoch}=\left\lceil
\frac{N_{samples}}{B_{micro}\cdot G\cdot D}
\right\rceil
\]

其中 \(G\) 为梯度累积步数、\(D\) 为 data-parallel world size。但变长序列下更应记录每个 step 和全程的有效 target tokens。

- 小而高质量的数据通常会看到多次，但重复越多越易过拟合；
- 大规模多样数据可能不到一个完整 epoch 就已达到 token budget；
- 每隔固定 target tokens 评估，验证指标饱和或保留能力下降时 early stop；
- 不同数据源可用不同采样次数，避免“大来源样本多”自动决定训练目标。

### 三、Batch Size

有效样本 batch 为：

\[
B_{global}=B_{micro}\times G\times D
\]

但每个 batch 的 token 数可能差十倍以上，所以还要报告：

\[
T_{batch}=\sum_i T_i^{nonpad}
\]

实际 runtime 常按最大 token budget 动态组 batch。micro-batch 由激活显存决定，gradient accumulation 用于达到所需 global token batch。更大 batch 降低梯度噪声、提高吞吐，但更新步数变少，可能降低泛化；学习率与 batch 的线性缩放在 SFT 上不是必然成立，需要实测。

使用 length bucketing 和 packing 减少 padding，但 packing 时保证样本边界、position 和 Loss Mask 正确。

### 四、序列长度

先统计 tokenized 后的输入、目标和总长度分布，再按业务选择，而不是直接使用模型宣称的最大上下文。

- 长度覆盖应包含目标流量的关键分位数和关键长尾；
- 训练长度越长，Attention/activation 显存和计算增长越大，吞吐下降；
- 对超长样本可截断、分块、摘要或单独长上下文阶段，但不能从 role/tool JSON 中间截断；
- 若线上需要长上下文，只有短 SFT 可能导致位置外行为和格式不稳定；
- 使用 RoPE scaling 等扩窗必须确认模型、数据和推理配置一致。

截断后统计有效 assistant token 比例；只剩 Prompt、没有 target 的样本不应参与 SFT。

### 五、保存与选择策略

按固定 optimizer steps 容易在变长 batch 下对应不同 token 数，更稳妥的是按有效 target tokens 或固定 wall-clock 配合评估保存。checkpoint 至少保存：

- 模型或 adapter 权重；
- optimizer、scheduler、gradient scaler；
- 当前 step/epoch、data sampler 和 RNG state；
- tokenizer、Chat Template、special tokens、LoRA/量化配置；
- 数据 manifest、代码版本和评测结果。

保留 `last` 用于恢复、若干时间点用于分析、`best` 用于部署候选；best 应由目标能力、通用保留、安全与格式成功率的综合门槛选择，不能只看最低 train loss。为控制磁盘可轮转旧 checkpoint，但最终制品及其可追溯状态必须保留。

### 六、推荐实验顺序

1. 固定高质量小数据和模型，先搜学习率；
2. 用验证曲线确定大致 token/epoch 预算；
3. 在显存允许下调 micro-batch、packing 与 gradient accumulation，提高吞吐；
4. 单独做序列长度课程和长上下文回归；
5. 最后用完整数据复训，并按多目标门槛选 checkpoint。

### 面试简答版

我会围绕有效 target tokens 和验证曲线选超参数。全参 SFT 学习率通常比 LoRA 小一个数量级左右，但只把常见范围当搜索起点；Epoch 由验证饱和和遗忘决定，不机械固定；global batch 等于 micro-batch×累积×DP，但变长数据还必须报告 non-padding token batch。序列长度依据业务分布和显存选择，截断不能破坏角色/工具边界。checkpoint 按固定有效 token 定期保存，并包含 optimizer、RNG、sampler、tokenizer/template 和数据版本；部署模型按目标、保留、安全和格式指标共同选择。
