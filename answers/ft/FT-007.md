> **问题：** 全量微调、LoRA 和 QLoRA 应如何选择？
>
> **分类：** SFT 与参数高效微调
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

三者的主要区别是基座权重是否训练、以什么精度驻留。**全量微调更新所有权重；LoRA 冻结通常为 BF16/FP16 的基座，只训练低秩增量；QLoRA 再把冻结基座以 4-bit 保存，反向梯度穿过反量化计算到 LoRA adapter。**

### 一、对比

| 维度 | 全量微调 | LoRA | QLoRA |
|---|---|---|---|
| 基座权重 | 可训练 | 冻结，通常 BF16/FP16 | 冻结，通常 4-bit |
| 可训练参数 | 全部参数 | 低秩 adapter | 低秩 adapter |
| 梯度/优化器状态 | 全模型 | 仅 adapter | 仅 adapter |
| 显存 | 最高 | 中等 | 最低 |
| 能力上限/自由度 | 最高 | 通常接近，但受低秩与 target 限制 | 还叠加量化误差 |
| 多任务存储 | 每任务一整份模型 | 共享 base，每任务小 adapter | 共享量化 base，每任务小 adapter |
| 训练速度 | 取决于分布式规模 | 通常较省通信和优化器开销 | 显存省，但反量化 kernel 不保证更快 |

LoRA 的原始思想是冻结预训练权重并注入低秩可训练矩阵，见 [LoRA 论文](https://arxiv.org/abs/2106.09685)。QLoRA 使用 4-bit NormalFloat、double quantization 和 paged optimizer 等技术降低训练显存，见 [QLoRA 论文](https://arxiv.org/abs/2305.14314)。

### 二、什么时候选全量微调

适合：

- 有足够算力和大规模、高质量数据；
- 领域或语言分布与基座差异很大，需要广泛修改模型表征；
- 要做 continued pretraining、深度能力迁移，或 LoRA 消融已显示明显上限；
- 最终只部署一个统一模型，不需要频繁切换许多 adapter。

代价不仅是保存一份权重，还包括梯度、优化器一阶/二阶状态、master weights 和分布式通信，显存可远超参数本身。训练数据较少时也更容易灾难性遗忘或过拟合。

### 三、什么时候选 LoRA

LoRA 通常是 SFT 的首选基线：

- 显存和多机通信预算有限，但可以加载完整精度冻结基座；
- 需要为多个租户/任务保存和热切换小 adapter；
- 希望快速迭代，并保留原 base 以便回滚；
- 任务变化具有较低的内在维度，低秩增量足够表达。

LoRA 只减少可训练参数、梯度和优化器状态，并不自动消除基座权重、激活和 Attention 的显存；长上下文训练仍可能被 activation 主导。推理时可以动态加载 adapter，也可把增量 merge 到 base，合并后通常不增加额外矩阵乘，但失去便捷切换能力。

### 四、什么时候选 QLoRA

当完整 BF16/FP16 base 都难以放入现有 GPU 时，QLoRA 很合适。它让更大模型可在有限硬件上 SFT，尤其适合实验、单机和多 adapter 场景。

边界是：

- 4-bit base 带来量化误差，敏感任务可能低于 BF16 LoRA 或全参微调；
- 训练计算通常仍以 BF16/FP16 进行，需要反量化，显存省不等于训练一定更快；
- 不同 GPU、量化类型和 kernel 支持会影响速度与稳定性；
- optimizer 虽小，但 activation 在长序列下仍可能占主要显存；
- 部署时要明确是 adapter + 4-bit base、合并到高精度 base，还是合并后重新量化；三者质量和速度不同。

### 五、决策流程

1. 固定数据、模板和评测，先用 LoRA/QLoRA 建低成本基线。
2. 显存不足以加载高精度 base，先选 QLoRA；能加载则比较 BF16 LoRA 的质量与吞吐。
3. 对 rank、target modules 做小规模消融；若提升已饱和，再增加数据质量，而非只增 rank。
4. 若 LoRA 在关键指标持续低于目标，且排除数据与超参数问题，再用相同 token budget 做全量微调对照。
5. 同时比较训练总成本、通用能力遗忘、制品大小和实际部署方式。

### 面试简答版

全量微调更新所有参数，表达自由度最高，但要保存全模型梯度与优化器状态，算力、显存和遗忘风险都最大，适合大规模高质量数据和深度领域迁移。LoRA 冻结高精度 base，只训练低秩增量，通常是 SFT 的首选基线，便于多任务保存和切换，但激活与 base 权重仍占显存。QLoRA 再把冻结 base 以 4-bit 保存，反向只更新 LoRA，适合显存紧张时训练更大模型，但有量化误差和反量化 kernel 成本。最终要在相同数据与 token budget 下比较质量、遗忘、训练成本和部署方式。
