## 我的答案

指令微调数据的逻辑单位通常是一段“消息序列”，而不是简单的两个字符串。字段设计要能完整表达角色、内容、工具协议和样本元数据；Loss Mask 则要明确哪些内容是条件，哪些内容是希望模型学会生成的目标。

### 一、常见字段

最基础格式可以是：

```json
{
  "messages": [
    {"role": "system", "content": "你是一个严谨的助手。"},
    {"role": "user", "content": "解释什么是过拟合。"},
    {"role": "assistant", "content": "过拟合是……"}
  ],
  "id": "sample-001",
  "source": "human",
  "language": "zh",
  "quality_score": 0.95
}
```

复杂 Agent 数据还可能包含：

- `tool_calls`：工具名与 JSON 参数；
- `tool` message：工具返回结果以及与 call 的关联 ID；
- 多模态内容：文本、图片、音频的占位符或引用；
- `weight`、`task`、`domain`、`license`、`split` 等采样与治理元数据；
- 安全标签、是否拒答、生成模型版本、人工修订轨迹。

元数据不一定送进模型，但用于去重、过滤、分层采样、评估切分和数据追溯。

### 二、从消息到 token

训练前必须用与推理一致的 Chat Template 将消息序列化，例如：

```text
<|system|>你是一个严谨的助手。<|eot|>
<|user|>解释什么是过拟合。<|eot|>
<|assistant|>过拟合是……<|eot|>
```

随后 tokenizer 得到 `input_ids`、`attention_mask`、`position_ids` 和 `labels`。Causal LM 的标签通常是输入向左错一位的 next token 目标；实现中常把不计 loss 的标签位置设为 `-100`，由交叉熵忽略。

### 三、哪些 token 计算损失

常见的 assistant-only SFT 规则是：

| token 区域 | 是否计算 loss | 原因 |
|---|---:|---|
| system 指令 | 否 | 是条件，不希望模型把它当回复复述 |
| user 消息 | 否 | 是输入条件 |
| assistant 内容 | 是 | 希望模型学习生成 |
| assistant 发出的 tool call | 是 | 它是模型动作 |
| tool 返回结果 | 否 | 是外部环境观测，不是模型生成 |
| assistant 的结束 token | 通常是 | 教会模型在正确位置停止 |
| padding | 否 | 只为 batch 对齐 |

若角色 token 属于 assistant 输出协议，例如 assistant header 应由模型预测，则也可以计算 loss；具体边界必须和推理时 prompt 截止位置一致。

损失可写为：

\[
\mathcal L=-\frac{1}{\sum_t m_t}\sum_t m_t\log p_\theta(x_{t+1}|x_{\le t})
\]

需要特别注意 mask 与 label 的 shift：mask 标的是“被预测 token”还是“输入位置”，错一位会让模型学习预测 user/assistant 边界之外的 token。

### 四、并非永远只训 assistant

有些 continued pretraining 风格、completion-only 或小规模领域适配会对整段文本计算 loss；也有人给不同角色或样本设置 loss weight。但这样会让模型花容量预测用户输入，可能加强模板复读或角色混淆。是否采用应通过消融决定，并把策略写入数据版本。

多轮数据可以对每一轮 assistant 都算 loss，也可以只训最后一轮。前者监督 token 更多，后者可避免早期回复作为固定上下文时重复计权。工具轨迹中还应决定是否训练 reasoning/analysis；若生产不希望暴露隐式推理，就不能未经设计地把它作为可生成目标。

### 五、必须做的单元测试

- decode `input_ids`，逐 token 可视化 `labels != -100` 的区域；
- 检查 assistant 首 token、tool call、结束 token 和 padding 边界；
- 验证截断后没有只剩输入而零有效 label 的样本；
- packing 时不让后一条样本看到前一条样本，或明确接受这种拼接语义；
- 统计每个样本有效 target token 数，防止空答案和超长回答主导训练。

### 面试简答版

SFT 数据通常用 messages 表示 system、user、assistant，Agent 数据还包含 tool call、tool result、call ID，以及来源、质量、领域等治理元数据。消息必须用与推理一致的 Chat Template 序列化。常见 assistant-only loss 中，system、user、tool result 和 padding 只作为条件，labels 设为 -100；assistant 内容、模型发出的 tool call 以及通常的结束 token 计算交叉熵。最容易出错的是 mask 与 next-token label 错位、角色边界和截断，所以应逐 token 可视化 loss 区域并做单元测试。
