## 我的答案

以 Switch Transformer 的 Top-1 思路为例，在一个含 $T$ 个 token、$N$ 个专家的 routing group 中，定义：

$$f_i=\frac{1}{T}\sum_{t=1}^{T}\mathbf 1[\arg\max_j p_{t,j}=i],\qquad
P_i=\frac{1}{T}\sum_{t=1}^{T}p_{t,i}$$

$f_i$ 是专家 $i$ 实际收到 token 的硬比例，$P_i$ 是 Router 分给它的平均软概率。典型辅助损失为：

$$L_{balance}=\alpha N\sum_{i=1}^{N}f_iP_i$$

当硬负载和软概率都接近 $1/N$ 时该项较小。硬计数 $f_i$ 本身不可微，但把它视作当前路由统计量后，梯度可通过 $P_i$ 推动 Router 降低热门专家的概率、提高冷门专家的概率。Top-K 实现可把硬计数按 $KT$ 归一化；不同论文的分组粒度、系数和公式会变化，核心都是同时约束“实际分配”和“概率质量”。

训练总损失一般写作：

$$L=L_{task}+L_{balance}+\lambda_zL_z$$

其中 z-loss 可抑制 Router logits 过大，避免 softmax 数值和训练不稳定。

### 辅助损失的副作用

- **梯度干扰**：主任务想按语义非均匀路由，均衡项却推动均匀分配；系数过大可能损害语言建模质量或专家专门化。
- **粒度偏差**：在很小的微批次、单序列或单设备上要求均匀，可能把自然的数据偏斜误判成问题；跨设备统计又增加通信。
- **超参数敏感**：系数太小压不住塌缩，太大则 Router 为“完成指标”而牺牲主任务。
- **只平衡不保证专门化**：所有专家 token 数相等，不代表它们学到了不同且有价值的能力。

工程上我会同时做 loss 系数扫描、下游/困惑度评测和按层负载观测，不能只看 auxiliary loss 下降。还要确认统计范围是 token、sequence、rank 还是全局，否则同一个公式含义不同。

### 面试简答版

经典做法同时计算每个专家的硬 token 占比 $f_i$ 和平均软路由概率 $P_i$，加入 $\alpha N\sum_i f_iP_i$。硬选择不可微，但梯度通过 $P_i$ 调整 Router，使热门专家降概率、冷门专家升概率。它能防塌缩，却可能与主任务语义路由冲突，并对系数和统计粒度敏感；均衡也不等于专门化，所以必须联合看主任务质量、负载、溢出和专家差异。
