## 我的答案

长上下文不是改一个 `max_position_embeddings` 就完成，而是四层共同扩展。

### 1. 位置编码

RoPE 模型超出训练长度会遇到相位外推问题，可用 position interpolation、NTK-aware scaling、YaRN 等重新映射频率/位置，并通过长序列继续训练校准。ALiBi 等相对偏置也有不同外推性质。仅修改 RoPE base 往往能“跑起来”，不保证远距离依赖质量。

### 2. 训练数据与目标

模型必须见过足够的长序列及真正跨远距离的依赖，包括长文档、代码仓库、多文档问答和长指令。常采用从短到长的 curriculum 或 continual pretraining，再做长上下文 SFT。只把无关短文本拼成长序列，token 数够了但学习不到跨段检索、引用和状态跟踪；还要控制 document boundary、packing 污染和长样本稀缺。

### 3. 注意力与模型结构

精确 full attention 的分数计算随长度约为 $O(L^2)$，可用 FlashAttention 降中间显存但不改变二次计算量；sliding-window、block/local+sparse/global attention、检索压缩、线性 Attention 或 SSM 可改变计算结构，但可能牺牲任意 token 间直接交互。GQA/MLA 和 KV 量化主要降低生成时缓存，不等于解决 prefill 的全部二次计算。

### 4. 系统并行与内存

把序列切到多设备做 Context Parallel/Ring Attention，分块传递 K/V 并在线 softmax；配合 activation checkpointing、sequence parallel、分布式 FlashAttention、paged KV cache、prefix cache 和 prefill/decode 分离。通信能否被块计算覆盖、负载是否均衡，决定理论长度能否转成实际吞吐。

验收要同时测可接受长度、困惑度、远近位置检索、多跳/聚合、长代码与真实业务任务，并按 needle 深度和上下文长度分层。长窗口只是容量声明，effective context 才是能力。

### 面试简答版

扩长上下文要四层协同：位置编码用 RoPE 插值/频率缩放并继续训练；数据侧提供真实长依赖和长指令；模型侧用 FlashAttention、稀疏/滑窗或新序列结构控制计算，并用 GQA/MLA 降 KV；系统侧用 Context Parallel/Ring Attention、checkpoint 和分页 KV 分摊内存。只改最大长度只能让输入被接受，必须用不同位置、长度和多跳真实任务验证有效利用。
