> **问题：** MoE 的总参数量、激活参数量和单 token FLOPs 应如何区分？

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

三者描述的是不同维度，不能互换：

- **总参数量（total parameters）**：模型中全部可学习参数，包括共享层和所有专家。它决定 checkpoint 大小、全量权重存储及训练时参数/优化器状态的总体规模。
- **激活参数量（activated parameters）**：一次 token 前向实际经过的共享参数，加上各 MoE 层被选中的 Top-K 专家参数。它更接近单 token 的稀疏计算路径，但不是严格的算力单位。
- **token FLOPs**：处理一个 token 实际执行的浮点运算次数。它还包含 Attention、Router、Norm、输出头等计算，并受序列长度、训练/推理阶段、算子实现影响。

假设每层有 8 个大小相同的专家、每个 token 选 2 个，则专家部分的激活参数大约是总专家参数的 $2/8$；但模型的共享 Attention、共享/常驻专家和其他层仍全部参与。因此不能直接说“总参数 100B、激活 25B，所以 FLOPs 一定是 dense 25B 的 FLOPs”。更准确的粗略表达是：对以矩阵乘为主的 FFN，计算量通常与所经过的参数量近似成正比；这是估算，不是恒等式。

### 为什么参数稀疏不一定带来同等墙钟收益

1. Router 和 token 重排有额外开销；Expert Parallelism 常需两次 All-to-All。
2. 每个专家拿到的小批量可能很小，GEMM 利用率不如大 dense FFN。
3. 最慢专家/设备决定 collective 完成时间，负载长尾会拖慢整层。
4. 推理 prefill 的 Attention 仍随上下文增长；decode 还受 KV Cache 带宽约束。
5. 总权重即使每次只激活一部分，仍要放在一组设备的显存/内存里，或付出加载代价。

所以比较模型成本时至少要同时给出：总参数、每 token 激活参数、训练/推理 FLOPs、序列长度、精度、batch、吞吐和硬件拓扑。模型报告里的“37B activated parameters”主要说明稀疏路径规模，不等价于该模型像普通 37B dense 模型一样部署。

### 面试简答版

总参数量回答“模型一共有多大”，决定存储和全量状态；激活参数量回答“一个 token 经过哪些权重”；token FLOPs 才回答“实际做了多少运算”。MoE 用较大的总参数换取较小的激活路径，但 FLOPs 还含 Attention 等共享计算，实际延迟又含 Router、All-to-All、负载不均和小 GEMM 开销，因此不能仅凭激活参数量推断吞吐或显存需求。
