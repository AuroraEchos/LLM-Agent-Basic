## 我的答案

DeepSeekMoE 的目标是让专家学习更聚焦、彼此更少重叠，核心有两点：细粒度专家分割和 shared expert isolation。

### 细粒度分割

假设传统 MoE 有 $N$ 个专家、每 token 激活 $K$ 个。把每个大专家切成 $m$ 个较小专家后，得到 $mN$ 个专家，同时激活约 $mK$ 个小专家；若每个小专家规模约为原来的 $1/m$，专家部分的激活参数与计算可大致保持不变。

它的价值不只是“专家更多”，而是组合更灵活。传统 Top-2 只能从较粗的大模块中选两个，细粒度方案能为一个 token 组合多个更小的知识单元，使不同 token 共享其中一部分能力、同时在另一部分分化。组合数增大只是表达潜力，并不自动证明质量提升。

### Shared expert isolation

再把若干专家设为始终激活的 shared experts，专门承接公共知识，避免每个 routed expert 重复学习相同基础模式；其余 routed experts 更专注于差异化知识。DeepSeekMoE 论文正是把这两点作为提升 expert specialization 的主要策略。

### 工程边界

- 专家越小，每专家 token batch 越小，GEMM 利用率可能下降；
- 激活的小专家数量增加，会增加路由元数据、dispatch 和 All-to-All 消息；
- 更多专家使负载均衡、容量和拓扑放置更复杂；
- “细粒度”应在相同激活参数/FLOPs下比较，否则提升可能只是更多计算；
- 专门化要通过消融、专家相似度、路由分布和下游性能验证，不能用直觉命名代替证据。

因此这是模型结构与系统实现的共同设计：算法上获得更灵活的专家组合，系统上必须用 grouped GEMM、通信重叠和稳定均衡把碎片化开销压住。

### 面试简答版

DeepSeekMoE 把 $N$ 个大专家细分成 $mN$ 个小专家，并把 Top-K 相应扩成约 Top-$mK$，从而在近似激活计算下获得更灵活的知识单元组合；同时隔离 shared experts 承接公共知识，减少 routed experts 的重复。代价是小 GEMM、更多路由与通信以及更难的负载均衡，所以必须在等计算预算下做消融，不能把更多组合数直接等同于更强能力。
