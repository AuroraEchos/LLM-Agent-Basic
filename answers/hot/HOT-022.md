> **问题：** Model Soup、Task Arithmetic、TIES-Merging 和 DARE 等模型合并方法有哪些适用条件？
>
> **分类：** MoE、推理模型与前沿方向

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

模型合并是在不重新联合训练或少量校准的前提下，把多个 checkpoint 的能力组合进一套权重。前提通常是模型**同架构、同参数命名/形状，且来自同一个 base 或处于可对齐的权重盆地**；把两个独立随机初始化、tokenizer 不同的模型逐元素平均，通常没有意义。

设共同 base 为 $\theta_0$，任务 $i$ 的微调模型为 $\theta_i$，task vector 为 $\tau_i=\theta_i-\theta_0$。

- **Model Soup**：直接对多个 fine-tuned checkpoints 做均匀或 greedy 权重平均。适合同一任务、同一预训练模型、不同超参/seed 的解位于相近低损失区域；目标更像提升鲁棒性/泛化，而非组合差异很大的技能。
- **Task Arithmetic**：$\theta'=\theta_0+\sum_i\lambda_i\tau_i$，可加、缩放或取负任务方向。适合同源 base 的不同任务 adapter/checkpoint，但系数需要验证，任务向量冲突会相互破坏。
- **TIES-Merging**：先裁掉任务向量中小幅、冗余变化（Trim），为每个坐标选一致符号（Elect Sign），再只合并与该符号一致的更新（Merge），缓解冗余和符号冲突。
- **DARE**：随机丢弃大比例 delta 参数，并把保留项按 $1/(1-p)$ 缩放，再配合平均、TIES 等合并；利用微调 delta 的冗余降低多模型干扰。drop rate 过大或 delta 不冗余会损伤能力。

合并不是“免费多技能”的保证。必须检查 tokenizer/chat template、embedding/output head、RoPE 配置、归一化和许可证兼容；对每个源任务、任务组合、安全、灾难性退化和校准集做评测，并搜索 merge weights。若模型异源、差异过大或需要按请求保留独立行为，LoRA 路由、MoE/ensemble 或重新多任务训练可能更合适。

### 面试简答版

Model Soup 平均同任务、同 base 的邻近 checkpoint；Task Arithmetic 把微调差值 $\tau_i=\theta_i-\theta_0$ 加到共同 base；TIES 通过裁小更新、统一符号、只合并同向坐标减少冲突；DARE 随机稀疏并重缩放 delta 后再合并。它们都更适合同架构、同 tokenizer、同源 base 的模型，合并后必须逐任务和安全回归，异源权重不能随意平均。
