## 我的答案

Shared Expert 与 Routed Expert 的职责不同：

- **Shared Expert** 对所有 token 固定激活，承载语法、通用事实、基础变换等公共能力；
- **Routed Expert** 由 Router 按 token 选择，学习领域、语言、推理模式等差异化知识。

若所有专家都参与竞争，每个 routed expert 都可能重复学习大量公共模式，稀疏参数被冗余占用。把一部分专家隔离为 shared experts 后，公共知识有稳定通道，routed experts 更有机会形成非重叠专门化。这也是 DeepSeekMoE 所强调的“shared expert isolation”。

一个简化输出可写为：

$$y_t=\sum_{i=1}^{K_s}E_i^{shared}(h_t)
+\sum_{j\in TopK(h_t)}g_{t,j}E_j^{routed}(h_t)$$

注意计算预算必须把 shared experts 算进去。比如“Top-2 routed”并不代表只执行两个 FFN；如果还有一个 shared expert，实际专家计算包含 shared + 两个 routed。不同实现还可能对多个 shared 输出缩放或合并，不能只凭名称推断。

### 收益与代价

收益是共享能力更稳定、Router 不必在所有 token 上重复发现公共路径，并可能缓解 routed experts 的知识冗余与训练抖动。代价是 shared expert 始终计算，可能成为固定 FLOPs 和单点热点；给 shared 的容量太大，会挤压 routed 专门化，太小又承接不了公共知识。

验证这一设计不能只看负载均匀。我会做消融：相同总参数和激活 FLOPs 下比较纯 routed 与 shared+routed，观察主任务质量、专家间表示/路由重叠、不同领域 token 分布以及 shared expert 的利用率。专家可解释标签应来自实验，不应仅凭若干 token 示例给它命名为“数学专家”。

### 面试简答版

Shared expert 对所有 token 常驻激活，吸收公共知识；routed experts 只处理 Router 选中的 token，负责差异化专门化。这样可减少每个 routed expert 重复学习通用模式，并给模型一条稳定公共路径。但 shared expert 也计入激活 FLOPs，可能成为固定热点；是否真正减少冗余，要在相同参数和计算预算下用消融、路由重叠及下游质量验证。
