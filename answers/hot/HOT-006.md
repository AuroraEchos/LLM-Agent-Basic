## 我的答案

Expert Parallelism（EP）把不同专家放到不同 GPU/rank 上，而共享 Attention 等部分可配合 Data、Tensor、Pipeline Parallel。因为 Router 是按 token 动态选专家，一个 rank 上的 token 很可能命中远端专家，因此典型 MoE 层有两次 All-to-All：

$$\text{本地 token}\rightarrow\text{按目标专家打包}\rightarrow
\text{All-to-All dispatch}\rightarrow\text{专家计算}\rightarrow
\text{All-to-All combine}\rightarrow\text{恢复原顺序}$$

通信不只是发一个专家编号，而是要传隐藏向量及必要元数据。粗略看，单向 payload 与 $T\times K\times d\times$ 元素字节数成正比，其中 $T$ 是 routing group token 数、$K$ 是每 token 专家数、$d$ 是隐藏维度；实际还受 padding、分片和量化影响。

### 为什么 All-to-All 容易成为瓶颈

- collective 通常受最慢 rank 限制，路由不均会造成热设备计算和收发双重过载；
- 跨节点带宽远低于节点内 NVLink，且小消息更受启动延迟影响；
- 细粒度专家拿到的 token 少，GEMM 时间短，通信难以被计算掩盖；
- 为提高每专家 batch 而积累 token，虽改善吞吐，却会增加在线排队和首 token 延迟；
- EP 与 TP/DP/PP 的通信若竞争同一链路，局部优化可能使全局更慢。

### 优化思路

1. 先做稳定负载均衡，按层观测每 rank 字节数和 P50/P99，而不只看平均专家 token 数；
2. 优先节点内放置通信密集的 EP group，使用分层 All-to-All，减少跨节点流量；
3. 将 dispatch/combine 与其他计算分块重叠，并使用连续布局、融合 permute/unpermute 和 grouped GEMM；
4. 调整 batch、capacity、Top-K 和专家粒度，在延迟、利用率与质量间取舍；
5. 对热点专家做拓扑感知放置或复制，但要处理副本权重同步和路由一致性；
6. 必要时降低通信精度，但必须验证数值稳定和模型质量。

最终应以端到端 tokens/s、TTFT/TPOT、网络利用率和尾延迟判断，而不是仅凭专家 FLOPs 宣称加速。

### 面试简答版

Expert Parallelism 把专家分散到不同 GPU。Router 选完专家后，先通过 All-to-All 把隐藏向量发到专家所在 rank，计算后再 All-to-All 发回并恢复 token 顺序。瓶颈来自通信量约随 $T K d$ 增长、跨节点带宽、负载最慢 rank 和小专家低算术强度。优化要联合做负载均衡、拓扑感知分组、通信计算重叠、融合重排/grouped GEMM及合理 batch，而不能只看稀疏 FLOPs。
