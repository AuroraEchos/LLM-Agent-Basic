## 我的答案

DeepSeek-V3 不是靠一个单点技巧，而是模型架构、数值格式和分布式系统协同设计。技术报告给出的规模是 671B 总参数、每 token 激活 37B，预训练 14.8T tokens；理解它时应分别看四个核心组件。

### 1. DeepSeekMoE

细粒度 routed experts 加 shared experts，让总容量可以扩大而每 token 只走少量专家；再用 expert-wise routing bias 做主要的 auxiliary-loss-free 均衡。收益是较大的模型容量与较低激活计算，风险是 All-to-All、负载长尾和小专家 kernel 效率。

### 2. MLA

对 K/V 做低秩联合压缩，生成时缓存压缩 latent 和解耦 RoPE key，显著降低长上下文 KV Cache，改善并发与 decode 内存压力。它没有消除 Attention 计算，而且需要专门训练和 kernel 支持。

### 3. FP8 mixed-precision training

把大量矩阵乘、存储和部分通信降到 FP8，以提高吞吐并减少显存/带宽；同时使用细粒度量化尺度、更高精度累加及对敏感算子的高精度保留来控制误差。FP8 不是“全模型所有数都 8 bit”，其稳定性依赖 scaling、accumulation、异常值和硬件实现。

### 4. Multi-Token Prediction（MTP）

训练时让每个位置预测多个未来 token，使监督信号更密，并促使表示提前规划后续内容。报告的消融表明它有助于性能，也提出可把 MTP 模块用于 speculative decoding；但训练收益和线上一定加速是两件事，后者还取决于 draft 接受率、验证成本和服务实现。

这些组件相互约束：MoE 节省的算力可能转化成通信瓶颈；MLA 降 KV 后瓶颈可能转到专家权重或网络；FP8 加速矩阵乘后更需要通信重叠；MTP 增加训练模块但可增强训练信号。报告中的训练成本也只代表其特定 H800 集群、软件栈和正式训练范围，不能直接外推为任何团队都能复现的预算。

### 面试简答版

DeepSeek-V3 的主线是系统协同：DeepSeekMoE 用 671B 总容量、37B token 激活控制计算；MLA 压缩 KV Cache；FP8 混合精度配合细粒度 scaling 和高精度累加提升训练效率；MTP 用多未来 token 目标加密训练信号，并具备 speculative decoding 潜力。四者分别优化容量、推理内存、训练吞吐和学习信号，但 MoE 通信、FP8 数值稳定及 MTP 接受率仍需端到端验证。
