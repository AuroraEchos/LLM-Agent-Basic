## 我的答案

三者主要区别在 KV Cache 如何表示和共享。设有 $n_h$ 个 query heads、每头维度 $d_h$：

- **MHA**：每个 query head 都有自己的 K、V，单层每 token 缓存量粗略为 $2n_hd_h$ 个元素，表达自由度高但长上下文缓存昂贵。
- **GQA**：$n_h$ 个 query heads 只配 $n_{kv}<n_h$ 组 K/V，缓存约为 $2n_{kv}d_h$；实现简单、kernel 成熟，但多个 query heads 共享 K/V，压缩程度与质量之间要取舍。
- **MLA**：把 K/V 联合压缩成低维 latent：$c_t^{KV}=W^{DKV}h_t$，需要时再通过上投影参与各头注意力；为兼容位置编码，还单独缓存携带 RoPE 的 key 分量。粗略缓存为 $d_c+d_h^R$ 个元素，具体维度依架构而定。

DeepSeek-V2/V3 的 MLA 在生成时只需缓存压缩 latent $c_t^{KV}$ 和 decoupled RoPE key，而不是所有 head 的完整 K/V。相关线性投影还可通过代数吸收进 query/output 投影，避免推理时简单地“每步完整还原所有 K/V”；但实际 kernel 路径取决于实现。

### 如何比较

GQA 是显式按头共享：结构直观，容易适配现有 Attention kernel，也常便于从 MHA 转换。MLA 是学习得到的跨头低秩表示，理论上能在较小缓存下重建更丰富的 head-specific 内容，但训练结构、RoPE 解耦和部署 kernel 更复杂，不是给已有 GQA 模型替换一个算子就能获得。

KV Cache 也不是唯一成本。prefill 仍有 Attention 计算，decode 可能受内存带宽、量化、分页管理和并发调度影响。应在同一模型质量、上下文、batch、精度和硬件上比较每 token cache 字节、最大并发、TTFT、TPOT，而不是只比某个理论压缩比。

### 面试简答版

MHA 为每个头缓存独立 K/V，缓存约随 $2n_hd_h$ 增长；GQA 让多个 query heads 共享较少的 KV heads，约为 $2n_{kv}d_h$；MLA 则把 K/V 联合压到低维 latent，并额外缓存解耦的 RoPE key 分量，约为 $d_c+d_h^R$。GQA 简单、kernel 生态成熟；MLA 压缩更灵活但架构和实现更复杂。最终要在等质量下比较真实 cache 字节、并发和延迟。
