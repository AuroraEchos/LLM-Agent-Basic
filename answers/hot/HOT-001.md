## 我的答案

MoE（Mixture of Experts）通常把 Transformer 中的 FFN 换成多个专家 FFN，并让 Router 对每个 token 动态选择少数专家。设 token 隐状态为 $h_t$，有 $N$ 个专家：

$$z_t=W_rh_t,\qquad p_{t,i}=\operatorname{softmax}(z_t)_i$$

Router 从 $p_t$ 中选出 Top-K 集合 $S_t$，再计算：

$$y_t=\sum_{i\in S_t}g_{t,i}E_i(h_t)$$

其中 $g_{t,i}$ 是门控权重。有的实现直接使用原概率，有的会在入选专家之间重新归一化，所以面试时不应把这一细节说成所有 MoE 都相同。

### 一次路由的完整过程

1. **打分**：Router 通常是一个很小的线性层，为每个 token 产生 $N$ 个专家分数；训练时还可能加入噪声或偏置。
2. **选路**：取 Top-1 或 Top-K。Top-1 通信和计算更省，Top-2/Top-K 有更强的组合能力和容错，但一个 token 会产生更多专家计算与通信。
3. **Dispatch**：按“专家编号”重排 token；若专家分布在不同设备上，还要进行 All-to-All，把隐藏向量和必要元数据发送到专家所在设备。
4. **专家计算**：每个专家只处理分给自己的 token，通常可合并成 grouped GEMM 或稀疏矩阵计算。
5. **Combine**：把专家输出发回原设备、恢复 token 顺序，并按门控权重加权求和。

Top-K 是离散选择，未入选专家不会从该 token 的主任务损失获得梯度；入选路径上的门控权重仍可微，Router 还可通过负载均衡损失、z-loss 或负载反馈偏置学习。路由的真正难点不只是“选最大值”，而是同时满足语义专门化、设备负载、容量与通信效率。

例如 8 个专家、Top-2 时，一个 token 只经过 2 个专家，而不是 8 个；但总参数仍包含 8 个专家，且路由不均可能令某个专家过载。因此线上还要观测每层每专家 token 数、路由概率、溢出/丢弃率、跨节点流量和尾延迟。

### 面试简答版

MoE Router 先用 $W_rh_t$ 为一个 token 对所有专家打分并 softmax，再选择 Top-K，token 被 dispatch 到这些专家，专家输出按门控权重合并。稀疏性来自“总专家很多、每个 token 只激活少数专家”。Top-K 本身是离散的，训练依靠入选路径的门控梯度及均衡约束；工程难点则是负载不均、容量溢出和跨设备 All-to-All，而不只是 Top-K 算法。
