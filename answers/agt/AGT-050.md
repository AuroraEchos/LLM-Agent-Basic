> **问题：** 如何在固定基础模型或替换基础模型的条件下，独立评估 Agent Harness 的规划、恢复、工具使用和上下文管理能力？
>
> **分类：** Agent 与工具调用

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

要独立评价 Harness，必须控制基础模型、环境、工具和预算，并把任务成功分解到规划、工具、恢复和上下文四类能力。最佳方法是“固定模型的 Harness 消融 + 固定 Harness 的跨模型矩阵”。

### 一、固定模型比较 Harness

冻结 model revision、sampling、tool backends/simulator、任务集和预算，比较：裸模型/简单 tool loop、旧 Harness、新 Harness。逐项消融 planner、memory、result normalization、retry、context compression 和 verifier，得到组件边际贡献。

任务多次运行并用 paired bootstrap/置信区间，防随机采样误判。相同总 token/tool calls，或报告质量—成本 Pareto。

### 二、能力专项评测

- 规划：必要步骤/依赖覆盖、可执行率、动态 replanning、无效步骤；
- 工具：选择混淆、参数语义、结果利用、权限与幂等；
- 恢复：注入 timeout、429、部分结果、Worker crash、状态改变，测恢复成功、重复副作用与额外成本；
- 上下文：长历史、冲突、位置置换、过期记忆、压缩恢复，测 constraint retention、evidence use 和 state synchronization；
- 停止：Done 验收、过早/过晚、循环和预算耗尽。

### 三、Oracle 与 Counterfactual

提供 gold plan、gold tool result、gold context 或 verifier，逐层替换定位上限和故障。Harness 若在 gold observation 下仍失败，是 context/decision；模型若给出合法 action 却被 Harness 丢弃，是适配/策略问题。

### 四、替换基础模型

构造 `models × harnesses × task slices` 矩阵。好的 Harness 应在多个能力档模型上稳定改善，并对弱模型提供约束、对强模型不过度限制。模型专属模板可作为适配层，但业务策略保持相同；分别报告绝对效果和 Harness uplift：

\[
Uplift(H,M)=Score(H,M)-Score(Baseline,M)
\]

### 五、指标与审计

最终环境 task success 为主，辅以成本/p95、工具正确、恢复、危险动作、人工接管和 trace-completeness。评测集覆盖正常、故障与攻击，不用开发中反复调过的 test。上线用 shadow/canary 验证 simulator 结论。

### 面试简答版

固定模型时冻结 revision、sampling、工具环境、任务和总预算，对比简单 tool loop、旧/新 Harness，并消融 planner、memory、result normalization、recovery、compression 和 verifier；专项测计划依赖、工具选择/参数、故障注入恢复、长上下文约束保留和停止。用 gold plan/result/context 的 oracle 替换定位责任。换模型时做 models×harnesses 矩阵，报告同一模型上的 Harness uplift，而非只比绝对分。最终以环境任务成功、成本、p95、重复副作用和安全为准，并用线上 shadow 验证。
