> **问题：** MCP 的 Tools、Resources 和 Prompts 有什么区别？
>
> **分类：** Agent 与工具调用
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

三者都是 MCP Server primitives，但交互意图和控制主体不同。官方概括是：**Prompts 偏用户控制，Resources 偏应用控制，Tools 偏模型控制**，具体 UI 可由实现决定，见[MCP Server primitives](https://modelcontextprotocol.io/specification/2025-06-18/server/index)。

### 一、Tools：执行能力

Tool 是可调用函数，含 name、description、`inputSchema`，可选输出 schema/annotations。用于查询 API、计算、写文件、发起业务动作等：

```text
tools/list → tools/call(name, arguments) → result
```

调用可能有副作用，因此 Host 必须校验、授权、限时并在必要时确认。Model-controlled 只表示模型可建议自动调用，不表示绕过用户控制。

### 二、Resources：可寻址上下文

Resource 是由 URI 唯一标识的数据，如文件、数据库 schema、Git 历史或应用对象：

```text
resources/list / templates/list
→ resources/read(uri)
```

它通常是读取式上下文，可带 MIME type、annotations，并可支持模板、订阅或列表变化通知。Host 决定何时展示、选择或加入模型上下文。Resource URI 仍需校验和权限检查。

### 三、Prompts：可复用交互模板

Prompt 是 Server 暴露的参数化消息模板或工作流入口，Client 可 list/get，用户常通过菜单或 slash command 主动选择。例如“评审代码”“生成周报”。它可返回多角色消息并嵌入 resource，但内容仍是模板，不是高于 Host system policy 的指令。

### 四、对比

| 原语 | 核心含义 | 典型控制 | 示例 |
|---|---|---|---|
| Tool | 做事/动态查询 | 模型提议，Host 执行 | 创建 issue、查询订单 |
| Resource | 读取可寻址数据 | 应用选择 | 文件、schema、文档 |
| Prompt | 启动模板化交互 | 用户选择 | `/review-code` |

有时同一后端可设计为不同原语：固定配置文件适合 Resource；带复杂查询参数的动态检索适合 Tool；引导用户完成配置审查的模板适合 Prompt。选择应按语义，不是按实现方便。

### 五、安全边界

三者都来自 Server，均可能含恶意或错误内容。Host 要显示来源、最小化共享数据、对 Tool 副作用确认、对 Resource 做 ACL，对 Prompt 防止覆盖系统策略。工具结果也可包含 resource link/embedded resource，但仍保留其数据身份。

### 面试简答版

Tools 是带 schema 的可执行函数，模型可建议调用，用于查询或产生副作用；Resources 是 URI 标识、由应用选择读取的上下文数据，例如文件和数据库 schema；Prompts 是用户通常显式选择的参数化消息模板或工作流入口。它们分别可概括为 model-controlled、application-controlled、user-controlled，但 Host 始终保留权限和 UI 控制。Tool 需执行审批，Resource 需 URI/ACL 校验，Prompt 不能覆盖 Host 的系统安全策略。
