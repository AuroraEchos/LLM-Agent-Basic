> **问题：** 如何从 Agent Trace 构造 SFT、偏好学习或强化学习数据，成功轨迹和失败轨迹分别有什么价值？
>
> **分类：** Agent 与工具调用
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

Agent Trace 可以转化为训练数据，但不能把线上轨迹原样当真值。先做脱敏、环境重放、结果验证、归因和去重，再针对 SFT、偏好或 RL 构造不同监督单位。

### 一、数据清洗与验真

绑定模型/Harness/工具/环境版本，移除 secret/PII 和无授权内容；用最终环境 predicate、测试、引用或人工审计判断成功。识别工具 bug、用户取消、环境不可达等非策略原因，避免惩罚模型。对近重复任务与模型自生成内容做去重，防数据回流放大偏差。

### 二、SFT 数据

从高质量成功轨迹抽取 state → next action/structured decision：

\[
(context_t, validated\ action_t)
\]

保留必要 observation、工具参数和停止决定，删除冗长自言自语与偶然绕路。也可让专家修复失败轨迹，得到“在错误状态下如何恢复”的 gold action。SFT 教默认行为，但模仿成功轨迹不代表学会探索。

### 三、偏好数据

在同一 state 比较 chosen/rejected action、plan 或 final answer。Chosen 可来自更高任务成功、更少危险调用、更低成本且满足约束的轨迹；需控制难度和资源，不能只因答案更长就选。失败轨迹与其专家修复、同题成功分支构成 hard preference pair。

### 四、强化学习数据/环境

Trace 用于构建可重放 environment、初始 states、tool simulators 和 reward signals：任务终态、步骤成本、安全约束、工具合法性。Online RL 仍应让当前策略探索；固定 trace 更适合 offline RL/行为克隆/奖励模型。Reward 不能只复制线上点击或 judge 分数，需防 hacking。

### 五、成功与失败的价值

- 成功：正确分解、工具选择、参数、恢复和停止，是正向策略样本；
- 失败：提供 hard negatives、错误分类、临界状态、恢复机会和评测案例；
- 近成功：最适合做局部 credit assignment；
- 安全拒绝：是正确负向行为，不能标成普通失败；
- 环境/工具故障：用于鲁棒性训练，但应与模型错误分开。

### 六、防止选择偏差

只训练成功轨迹会偏向容易任务；只收线上失败又忽略正常分布。按任务类型、难度、用户群、工具和结果分层采样，保留冻结测试集。评估离线 loss 之外的任务成功、成本和安全泛化。

### 面试简答版

先对 Trace 脱敏、去重并用真实环境 predicate 验证，区分模型、Harness、工具和外部故障。SFT 从成功或专家修复轨迹抽取“状态→合法下一动作/停止”；偏好学习在同一状态比较成功、安全、低成本的 action 与失败分支；RL 则用 Trace 构建初始状态、可重放环境和终态/成本/安全 reward，但当前策略仍需在线探索。成功轨迹教正确路径，失败和近成功轨迹提供 hard negatives、恢复和 credit assignment；安全拒绝不能误标失败，工具故障也不能归罪模型。
