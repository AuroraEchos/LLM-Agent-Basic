> **问题：** Agent 的最终效果为什么不仅取决于模型能力，Harness 会通过哪些机制放大或限制模型能力？
>
> **分类：** Agent 与工具调用

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

Agent 效果近似是模型能力与 Harness 可用信息、动作空间、反馈质量和控制策略的组合，而不是模型 benchmark 分数的直接映射：

\[
P(success)=f(Model,Context,Tools,Feedback,Control,Environment)
\]

强模型放在脏 observation、模糊工具和无停止条件的 Harness 中仍会失败；合适 Harness 则能把中等模型的能力转化为稳定任务成功。

### 一、上下文选择

Harness 决定 system policy、用户目标、历史、记忆、检索证据和工具 schema 的内容与顺序。相关信息缺失会让模型猜，噪声/超长会稀释约束，过期记忆会系统性误导。压缩若丢实体、否定或未完成任务也会限制模型。

### 二、动作空间与工具可供性

工具名称、description、schema 和候选数量决定模型能否把意图落成合法动作。Calculator、verifier、sandbox 和 API 可补足模型参数记忆与计算弱点；反之，万能 shell、重叠工具或错误权限会放大误调用和攻击面。

### 三、反馈与环境可观测性

结构化、及时、可验证的 Tool Result 使模型纠错；截断、模糊错误和伪成功会让后续推理建立在假状态上。Harness 还可用测试、引用、规则 verifier 和 read-after-write 将“看起来完成”转成真实反馈。

### 四、搜索与控制

计划、ReAct、重规划、并行、反思或 best-of-N 能增加搜索和修错机会，但也增加 token、错误传播和循环。预算、progress 检测、checkpoint 与任务验收决定计算是否有效。对简单任务，过度 Agentic 反而降低可靠性。

### 五、安全和权限

最小工具权限、参数校验、HITL、sandbox、幂等和网络/文件边界限制模型能力的危险部分，同时保留安全的只读探索。安全 Harness 的目标不是让模型“更听话”，而是即使决策错误也限制影响。

### 六、如何证明

做二维实验：固定 Harness 换模型，固定模型换 Harness；再消融 retrieval、tool descriptions、result normalization、planner、memory 和 verifier。用任务成功、成本、p95、危险调用、恢复率衡量，而非只看最终文本 judge。

### 面试简答版

模型提供潜在推理能力，Harness 决定这些能力能否转化为任务成功：它选择上下文和记忆，定义可用工具与参数空间，把工具结果结构化为可纠错反馈，选择规划/搜索/重试策略，并通过 verifier、预算、停止和权限控制约束错误。好的 Harness 能用工具与环境真值补足模型，坏 Harness 会用噪声、过期状态和模糊错误限制强模型。评测应固定 Harness 比模型、固定模型比 Harness，并逐项消融，而不能把所有提升都归因于模型。
