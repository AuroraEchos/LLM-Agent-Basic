## 我的答案

三类工具的共同原则是：**默认拒绝、最小权限、短生命周期、资源配额、完整审计，且不可信内容不能自行扩大工具权限**。但 Browser 重点防网络与页面注入，代码执行重点防任意计算逃逸，文件系统重点防路径和数据边界突破。

### 一、Browser Sandbox

- 使用隔离浏览器 profile/container，任务结束清除 cookie、storage、下载和 service worker；
- 网络 egress allowlist/denylist，阻止 localhost、内网、云 metadata、file URI 和非预期协议，防 SSRF；
- DNS 解析后和重定向后都校验目标 IP，限制重定向次数、下载大小与 MIME；
- 每站点/任务独立凭据，敏感站点需要用户交互和 step-up auth；
- 页面、DOM、下载和 tooltips 都是潜在 Prompt Injection，只按数据处理；
- 禁止任意自动上传本地文件、读取剪贴板、摄像头或跨域 secret；
- 对点击、表单提交、购买/发布做动作预览与确认。

### 二、代码执行 Sandbox

代码运行在一次性 VM/microVM/container 中，非 root、只读基础镜像、最小 syscall/capabilities，无宿主 socket/device。设置 CPU、内存、磁盘、进程数、文件句柄、输出大小和 wall-clock；默认断网，依赖从代理/镜像 allowlist 获取并锁版本。

工作目录仅挂载任务文件，secret 用短期代理能力而非环境变量；阻止 fork bomb、挖矿、逃逸、侧信道和访问其他租户。执行结束销毁环境，结果做 malware/secret 扫描。容器不是绝对安全边界，高风险多租户场景优先更强隔离。

### 三、文件系统 Sandbox

- 只暴露明确 workspace root，路径 canonicalize 后检查仍位于 root；
- 防 `..`、绝对路径、symlink/hardlink、mount 和 TOCTOU 绕过；
- 读写/创建/删除权限分开，敏感目录与 `.env/*.key` 永不暴露；
- 写入先临时文件再原子 rename，限制单文件/总容量；
- 删除优先回收站/版本控制，高影响批量操作确认；
- 记录 before/after hash 和 diff，防 Agent 修改自身安全规则、CI 或权限文件。

### 四、组合风险

工具组合会扩大攻击链：网页注入诱导读取私钥，再用 Browser 外传；代码生成 symlink 绕过文件边界。因此 policy 应基于整个数据流做 taint/egress 控制，而非每个工具各自“看起来安全”。OWASP 也强调最小权限、sandbox、网络限制和高风险审批，见[AI Agent Security](https://cheatsheetseries.owasp.org/cheatsheets/AI_Agent_Security_Cheat_Sheet.html)。

### 五、验证

用 SSRF/DNS rebinding、恶意重定向、fork bomb、容器逃逸探测、路径穿越、symlink race、隐藏网页指令和数据外传做持续红队。任何 sandbox 失败时 fail closed，并有 kill switch、隔离和取证日志。

### 面试简答版

Browser 应隔离 profile，限制域名/IP/重定向和下载，阻断 localhost、内网和 metadata，页面内容视为不可信，提交/购买需确认。代码在一次性非 root VM/container 中运行，只读镜像、默认断网，限制 syscall、CPU、内存、磁盘、进程和时间，不挂宿主 socket 或秘密。文件系统只暴露 workspace，canonicalize 路径并防 `..`、symlink 和 TOCTOU，读写删分权，写入原子化、删除可恢复。还要防网页→文件→网络的组合外传，全程审计与红队。
