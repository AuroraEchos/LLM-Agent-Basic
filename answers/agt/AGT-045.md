> **问题：** Agent 上下文缓存应如何设计命中键、版本绑定、失效条件和隐私隔离？

## 我的答案

Agent 上下文缓存既可能缓存静态 Prompt 前缀，也可能缓存检索、工具视图、摘要或最终答案。每层依赖不同；安全原则是**缓存键必须覆盖影响语义和权限的全部版本，命中后仍验证新鲜度，撤权/删除主动失效**。

### 一、命中键

静态前缀缓存可包含：

\[
K=H(modelRev,systemPromptRev,toolSetHash,toolSchemaRev,policyRev)
\]

动态上下文再加入 tenant、principal/permission fingerprint、goal/query、task state version、memory snapshot、index generation、evidence IDs/versions、locale 和输出 schema。采样参数若影响最终答案也需入键。

### 二、提高前缀命中

把稳定的 system instructions 和确定顺序 tool definitions 放前面，动态用户/任务内容放后面；工具列表确定性排序，避免无意义时间戳或随机 ID 破坏前缀。但不能为缓存而把已撤权工具继续暴露。

### 三、版本与失效

- Prompt、模型、tool schema、policy 或 compaction 算法变化：切 namespace；
- 文档/记忆/任务状态更新：按依赖图精确失效或变版本；
- ACL 撤销、删除、安全隔离：强制即时失效，不能等 TTL；
- 普通知识新鲜度：TTL/stale-while-revalidate 只用于允许陈旧的低风险内容；
- negative/无结果缓存短 TTL。

### 四、隐私隔离

缓存至少按 tenant 隔离；含私人数据时按 user 或 permission fingerprint。共享语义缓存只用于真正公共、稳定内容。值加密、最小化，日志不打印 key 原文/Prompt。命中时重新执行 ACL 与 evidence ACTIVE 检查，防权限在写入后变化。

### 五、任务状态与副作用

不能缓存“工具写操作成功”替代真实回执；相似 query 也不能复用会产生副作用的 Action。恢复任务时按 operation ID reconcile 外部系统。摘要缓存要绑定所覆盖 event range/hash，避免从旧 state 复用。

### 六、监控

报告各层 hit、token/延迟节省、false hit、stale serve、ACL rejection、失效传播和跨租户安全测试。缓存收益必须以正确性不回退为前提。

### 面试简答版

静态上下文缓存键至少包含模型、system Prompt、工具集合/schema 和策略版本；动态缓存再加 tenant、permission fingerprint、任务 state、记忆、索引 generation、证据版本和输出配置。稳定前缀放前、工具确定性排序可提高命中。Prompt/模型升级切 namespace，文档/记忆更新按 lineage 失效，撤权、删除和安全隔离必须即时清除，不能等 TTL。私人内容按用户/权限隔离，命中后重验 ACL 和证据 ACTIVE；副作用成功不能靠语义缓存推断。
