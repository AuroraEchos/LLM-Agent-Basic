> **问题：** 如何设计一个能够中断、恢复和持久化长任务的 Agent Runtime？

## 我的答案

可恢复长任务的核心是把 Agent 从“一次进程内循环”变成**持久化状态机 + durable event/work queue + 幂等活动**。模型上下文可重建，真实状态不能只存在内存里。

### 一、持久状态模型

持久化 run/task/node 状态、计划 DAG、输入输出 artifact 引用、事件日志、预算、模型/工具/策略版本、审批和外部 operation ID。状态转换例如：

```text
CREATED → RUNNING ↔ WAITING_TOOL/WAITING_HUMAN
        ↔ PAUSED → SUCCEEDED/FAILED/CANCELLED
```

每次 transition 使用事务/乐观锁并追加事件，snapshot 用于快速恢复，event log 用于审计和重放。

### 二、Checkpoint 边界

在模型决策后、工具调用前后、状态 patch、分支汇合和等待审批时 checkpoint。采用 write-ahead intent：先记录准备执行的 action 与幂等键，再调用外部工具，回执后提交完成状态。

若进程在外部动作后、保存回执前崩溃，恢复时通过 idempotency key/operation ID 查询状态，而不是重做。

### 三、中断与恢复

暂停时停止调度新节点，向在途操作发送取消；无法取消的操作标明并等待/核对。恢复获取 run lease，检查 schema/graph/model/tool 版本兼容，重建上下文并只调度 READY 节点。多个 Worker 用 lease/fencing token 防同一任务并发执行。

人为审批用持久 `WAITING_HUMAN`，approval token 绑定参数和版本；进程重启不丢失，也不能自动批准。

### 四、Artifacts 与上下文

大文件、工具结果和 Prompt payload 存对象存储，以 URI+hash 引用；数据库存元数据。恢复时从任务状态、经过验证的 observations 和摘要重建上下文，不要求复现私有 CoT。临时凭据不进 checkpoint，恢复时重新获取最小权限 token。

### 五、版本迁移与取消

在途 run 固定 workflow version 完成，或通过显式 migration 转换 state；不能悄悄套新图。取消进入 CANCELLING，执行补偿/资源清理后才 CANCELLED。长期任务设 TTL、心跳、dead-letter、孤儿扫描和人工修复工具。

### 六、验证

故障注入在每个 checkpoint 前后 kill Worker，模拟消息重复/乱序、工具超时、审批跨重启和版本升级；验证最终状态、无重复副作用和预算不重置。监控恢复时间、stuck runs、lease 抢占、重复执行和 checkpoint 成本。

### 面试简答版

长任务 runtime 用持久状态机、事件日志/队列和幂等 activity。保存计划 DAG、节点状态、预算、版本、artifact URI、审批与外部 operation ID；在工具调用前写 intent 和幂等键，调用后记录回执。崩溃若发生在两者之间，恢复时查询外部状态而非盲重做。暂停停止新调度并处理在途调用；恢复通过 lease/fencing 防双执行，从 checkpoint 重建上下文，重新获取短期凭据。图版本显式迁移，取消要补偿清理，并用逐点故障注入证明无重复副作用。
