## 我的答案

记忆系统应是有治理的数据生命周期，不是“把每轮对话做 embedding”。完整流程是候选提取 → 写入门控 → 检索 → 冲突/更新 → 合并 → 遗忘，并始终保留 provenance。

### 一、写入

仅写入未来有复用价值的信息。门控条件包括：用户明确陈述或可信工具验证、稳定性足够、有保存同意、不违反敏感数据策略、不是一次性任务状态。

```text
memory_id, owner, type, canonical_value
source_event, valid_from/to, confidence
sensitivity, ACL, created_at, expires_at
```

模型推断标为 inferred，不能升级为 asserted。密码、密钥、支付数据等默认不写。

### 二、检索

先做 owner/tenant/ACL/type/time 的硬过滤，再综合语义、关键词、显著性、新鲜度和置信度：

\[
score=w_r relevance+w_s salience+w_f freshness+w_c confidence
\]

限制 top-k 和 token，返回来源与时间。检索到的记忆是数据，若与当前用户陈述冲突，应询问或采用最新明确值。

### 三、更新与冲突

对有唯一当前值的事实使用版本化 upsert，而不是原地抹掉历史：旧记录设 `valid_to`，新记录关联 supersedes。对事件型记忆追加新事件。更新用乐观锁避免并发丢失；权限撤销需立即影响读取和缓存。

### 四、合并

相同来源事件的重复记录可按 canonical key 去重；近似事实先做实体解析、单位归一化和时间对齐，再决定合并。摘要记忆保留所覆盖原始 IDs，且摘要不能比证据更确定。矛盾记录不能为节省空间而平均掉。

### 五、遗忘

- TTL/时间衰减：短期和低价值信息自动过期；
- 容量/效用：长期未检索、低显著性记录降级或归档；
- 任务结束：清理临时状态与 artifacts；
- 用户删除/法规要求：级联删除向量、摘要、缓存和备份流程中的派生物；
- 错误/投毒：隔离并追踪所有派生记忆。

遗忘不是只从向量库删除一条；需要 lineage 和可验证 tombstone。

### 六、评测

测 write precision/recall、retrieval hit、过期/冲突使用率、错误记忆导致任务失败、跨用户泄漏、删除 SLA 和 memory token 成本。用“用户改变偏好”“来源撤回”“间接注入要求永久记住”等场景红队。

### 面试简答版

记忆写入要经过复用价值、来源可信、隐私同意和敏感性门控，并保存 owner、type、source、有效期、置信度和 ACL。检索先硬过滤身份与时间，再按相关性、显著性、新鲜度排序。事实变化用版本化 supersede，事件追加；合并前做实体、单位和时间对齐，矛盾不强行平均。短期状态按任务/TTL清理，长期低价值衰减；用户删除或投毒要沿 lineage 清理向量、摘要和缓存。核心指标是写入准确率、过期/冲突误用和跨用户泄漏。
