> **问题：** Leader-Worker、Peer-to-Peer 和层级式多 Agent 架构有何优缺点？
>
> **分类：** Agent 与工具调用
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

三种架构的差别是控制与通信拓扑。多 Agent 的价值来自可分解任务、专业能力和并行，而不是简单复制更多相同模型。

### 一、Leader-Worker

Leader 分解任务、分配 Worker、汇总和验收；Worker 专注执行子任务。

优点：控制面清晰，权限、预算、进度和最终输出易统一；子任务可并行，Worker 可使用不同工具/模型。缺点：Leader 是瓶颈和单点错误，错误分解会系统性污染所有 Worker，汇总时可能丢细节。

适合研究报告、代码修改、多个独立数据源等可分解且需要统一交付的任务。

### 二、Peer-to-Peer

Agents 直接交换消息、协商任务或共享 blackboard，无固定中心。

优点：弹性、局部协作、避免单一 Leader；适合角色对等、环境分布式的任务。缺点：通信趋近 \(O(n^2)\)，容易重复劳动、循环、责任不清、共识困难，权限和终止控制复杂。

生产中通常仍需一个外部 orchestrator 执行预算、路由和停止，即使语义上 Agents 对等。

### 三、层级式

顶层 Coordinator 分目标，中层 Manager 管领域，底层 Worker 执行。它把 leader-worker 递归化，适合组织规模大、任务树深的场景。

优点：控制范围可扩展、按领域封装、局部失败隔离；缺点：层层摘要造成信息损失，决策/通信延迟高，错误沿层级传播，调试困难。小任务采用层级式通常是过度设计。

### 四、比较

| 维度 | Leader-Worker | Peer-to-Peer | 层级式 |
|---|---|---|---|
| 控制 | 中心化 | 分布式 | 多级中心化 |
| 通信 | 星型 | 网状/共享板 | 树型 |
| 可审计 | 高 | 较低 | 中等但链路长 |
| 单点瓶颈 | Leader | 较少 | 各级 Manager |
| 适用规模 | 小中型可分解任务 | 对等协商 | 大型多领域任务 |

### 五、共同工程要求

使用结构化 task/artifact/message，而非自由聊天；每个 Agent 有最小工具权限，声明 owner、依赖、成功条件和预算。共享状态需版本/锁，消息去重并防 Prompt Injection。最终事实以工具和证据验证，不按角色地位自动相信 Leader。

### 面试简答版

Leader-Worker 由中心拆解、分配和验收，简单可控但 Leader 是瓶颈和共同错误源；Peer-to-Peer 让对等 Agent 协商，弹性强但通信、循环、共识和责任边界复杂；层级式用多级 Manager 扩展大任务，领域隔离好，却增加摘要损失和延迟。可分解的小中型任务通常先选 Leader-Worker，真正对等分布式场景才用 P2P，大规模多领域任务才值得层级化。无论哪种，都应由确定性系统限制权限、预算、共享状态和停止。
