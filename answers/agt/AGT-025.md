> **问题：** 什么时候多 Agent 优于单 Agent，如何证明收益覆盖了额外成本？
>
> **分类：** Agent 与工具调用
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

多 Agent 只有在**任务可分解、并行或专业化带来的质量/延迟收益，大于协调、重复、冲突和额外模型调用成本**时才优于单 Agent。默认基线应是一个强模型配好工具与工作流，而不是先堆角色。

### 一、可能有优势的场景

- 子任务相互独立，可并行缩短 wall-clock；
- 需要不同权限、工具、语言或领域模型，角色真正异构；
- 生成—审查职责分离，且 verifier 能发现不同错误；
- 搜索空间有多个有价值分支，需要并行探索；
- 上下文过大，可按数据域隔离处理后汇总；
- 任务天然分布在多个环境/组织边界。

### 二、通常没有优势的场景

简单串行任务、共享同一上下文与工具、错误高度相关、最终强依赖单个 Leader，或通信成本超过执行本身。多个相同模型“扮演专家”可能只是昂贵 self-consistency。

### 三、公平实验

至少比较：单 Agent、单 Agent + 更多推理/重试、best-of-N/self-consistency、多 Agent。固定模型或报告模型差异，并在以下口径之一严格配平：总 input/output tokens、模型调用费用、工具调用、wall-clock/并发资源。

\[
Utility=Quality-\lambda C_{money}-\mu T_{latency}-\nu Risk
\]

报告任务成功、正确性、覆盖、p95、成本、步骤数、冲突/重复率、安全违规和人工接管；多 seed 与置信区间。若多 Agent 多用了三倍 token，只比准确率不公平。

### 四、消融证明收益来源

- 去掉并行，看收益是延迟还是推理；
- 将专业 Worker 换成同一通用 Agent，验证专业化；
- 去掉 debate/arbiter，验证冲突机制；
- 给单 Agent 相同工具与总预算；
- 测子任务依赖变化、Worker 失败和同源错误；
- 记录通信 token 与 Leader 汇总损失。

### 五、上线门槛

多 Agent 必须在关键切片无质量回退，单位成功成本/延迟满足 SLO，且权限和审计没有扩大不可接受的攻击面。根据任务复杂度动态路由：简单任务单 Agent，达到分解/风险阈值才启用团队。

### 面试简答版

多 Agent 适合可并行的独立子任务、真正异构的领域/工具/权限、生成与独立验证、或需要探索多个分支的任务；简单串行任务和同模型复制通常只增加通信与相关错误。证明收益要与单 Agent、单 Agent 加同等推理预算、best-of-N 公平比较，固定总 token/费用/工具或明确报告资源，评估成功率、p95、单位成功成本、重复冲突和安全风险。再通过移除并行、专业角色和仲裁做消融。生产中应动态路由，只有效用超过协调成本才启用多 Agent。
