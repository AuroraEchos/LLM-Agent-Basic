> **问题：** 如何压缩或总结长轨迹，同时避免丢失约束、未完成事项、关键实体和可恢复状态？

## 我的答案

长轨迹压缩应从事件生成**结构化状态快照**，而不是让模型自由写一段摘要。可恢复信息与叙事解释分层：原始 events/artifacts 保留，摘要只是可重新生成的模型上下文视图。

### 一、不可丢的 State Schema

```yaml
goal: 原始目标与验收标准
constraints: 禁止项、范围、格式、预算
entities: ID、版本、单位和指代解析
plan: 每步状态、依赖、owner
verified_facts: value + source + observed_at
side_effects: operation_id + idempotency_key + receipt
open_items: 未完成、阻塞、待确认
attempts: 已试方法、失败分类、不可重复原因
artifacts: URI + hash + version
```

### 二、压缩过程

先解析 action/observation events，确定性提取 ID、状态和回执；再由模型总结原因与语义；最后 validator 对照原轨迹检查覆盖和矛盾。删除重复日志与已失效候选，但保留失败教训和未完成项。

### 三、分层摘要

近期步骤保留细节，较旧步骤滚动成阶段摘要；任务级 state始终单独存在。Hierarchical summaries 每层链接所覆盖 event range/hash，必要时按需展开。摘要更新采用 patch，不让整段重写意外删除旧约束。

### 四、防丢验证

定义 retention tests：原目标/禁止项、open item、关键实体、最新工具状态、审批和外部副作用能否从压缩状态回答；从 checkpoint 恢复后是否选择同一合法 next action。可对摘要反向生成 state 与原结构比对。

数字、路径、代码、错误码和工具 payload 不靠自然语言转述，存 typed fields/artifact。冲突事实保持多版本和状态，不在摘要中“调和”。

### 五、触发与边界

按 token 阈值、阶段完成或 checkpoint 触发，不每轮全量总结。压缩失败/验证不通过就回退较长上下文或请求人工，不能继续在损坏 state 上运行。原始数据按隐私 TTL 保存，不能为了可恢复而无限保留敏感历史。

### 面试简答版

不要把长轨迹只总结成一段话，而要从事件构建结构化快照：目标/验收、约束、实体 ID、计划状态、带来源事实、外部副作用回执、未完成项、失败尝试和 artifact。确定性提取字段，模型只做语义摘要，再由 validator 对原轨迹做覆盖检查。近期保细节、旧步骤做层级摘要，所有摘要链接原 event range；数字、路径、代码和 operation ID 保存在 typed fields。用 checkpoint 恢复和 next-action 一致性测试证明没有丢状态。
