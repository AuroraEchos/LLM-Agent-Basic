> **问题：** MCP 的 Host、Client、Server 分别是什么，它提供哪些核心能力？
>
> **分类：** Agent、工具与上下文工程
>
> **来源：** [CORE_INTERVIEW_QUESTIONS.md](../../CORE_INTERVIEW_QUESTIONS.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

MCP（Model Context Protocol）是 LLM 应用与外部上下文/能力之间的标准协议。它采用 Host—Client—Server 架构，基于 JSON-RPC 和有状态会话进行初始化、协议版本与 capability negotiation。当前定义应以[MCP 官方规范](https://modelcontextprotocol.io/specification/2025-06-18/architecture)为准。

### 一、Host

Host 是用户直接使用的 LLM 应用，例如 IDE、桌面助手或 Agent runtime。它负责：

- 创建和管理多个 MCP Client；
- 选择模型、组装上下文和运行 Agent 循环；
- 用户同意、权限策略、安全边界和 UI；
- 决定哪些 server、resource、prompt、tool 可暴露；
- 隔离不同 server，避免它们无意共享完整会话或凭据。

Host 是最终控制者，不应把授权责任推给模型或第三方 server。

### 二、Client

Client 是 Host 内与某个 MCP Server 建立一对一会话的协议组件。它负责初始化、版本/能力协商、JSON-RPC 请求响应、通知、取消、进度和连接生命周期，并将 server 能力转换成 Host 可用对象。

一个 Host 可运行多个 client 实例；“Client”不是最终用户，也通常不是独立聊天界面。

### 三、Server

Server 是通过 MCP 暴露能力的本地进程或远程服务，例如文件系统、Git、数据库或 SaaS 连接器。它可提供 Tools、Resources、Prompts，并声明相应 capabilities。Server 验证输入、访问自己的后端并返回结构化结果，但 Host 仍需独立做信任、权限和用户确认。

### 四、核心能力

- 基础协议：JSON-RPC request/response/notification 与错误；
- Lifecycle：初始化、protocol version 和 capabilities 协商；
- Server primitives：Tools、Resources、Prompts；
- Utilities：日志、进度、取消、补全等；
- Client capabilities：规范版本可包含 roots、sampling、elicitation 等能力，需协商后使用。

不要假设所有 server 或 protocol revision 支持相同特性；连接时协商而非硬编码。

### 五、安全边界

MCP 标准化通信，不自动使 server 安全。Host 应校验 server 来源、限制本地进程/网络/文件权限，按用户身份授权，显示高风险调用，隔离凭据并审计。Server 返回的描述、Prompt、resource 和 tool output 都可能是不可信内容。

### 面试简答版

MCP 中 Host 是承载模型与用户体验的应用，管理安全、上下文和多个连接；每个 Client 是 Host 内连接一个 Server 的协议会话，负责 JSON-RPC、初始化、版本和 capability negotiation；Server 则暴露文件、数据库或业务系统的 Tools、Resources、Prompts。MCP还提供生命周期、通知、取消、进度和日志等协议能力。它解决互操作，不替代认证授权：Host 仍要决定暴露什么、保护凭据、确认危险动作，并把 server 内容视作不可信输入。
