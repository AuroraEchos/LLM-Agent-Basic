> **问题：** LangChain、LangGraph、AutoGen、CrewAI、Dify 和 Coze 的定位有何不同？

> **分类：** Agent 与工具调用

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

这些产品跨越“代码库、Agent runtime、多 Agent 框架、低代码应用平台”不同层级，不能只按功能勾选比较。功能会随版本变化，选型应以目标版本官方文档和 PoC 为准。

### 一、定位

- **LangChain**：偏代码优先的模型、工具、retriever、middleware 与预构建 Agent 抽象，适合快速组合丰富集成；当前 Agent runtime 构建在 LangGraph 之上。[官方 Agents 文档](https://docs.langchain.com/oss/python/langchain/agents)
- **LangGraph**：较低层的状态图编排/runtime，强调持久状态、durable execution、streaming、human-in-the-loop，适合需要精确控制和恢复的长流程，可独立使用。[官方概览](https://docs.langchain.com/oss/python/langgraph/overview)
- **AutoGen**：面向消息驱动的单/多 Agent 应用；AgentChat 提供高层 team patterns，Core 更偏 event-driven、可扩展/分布式 runtime，适合多 Agent 协作研究与定制。[官方文档](https://microsoft.github.io/autogen/stable/index.html)
- **CrewAI**：围绕角色化 Agents、Tasks、Crews 与 Processes 提供高层团队抽象，同时用 Flows 做结构化、事件驱动的控制，适合快速表达“研究员—分析师—写作者”等团队。[官方概览](https://docs.crewai.com/core-concepts/Agents)
- **Dify**：开源低代码 AI 应用平台，集可视化 Workflow/Chatflow、模型管理、RAG、Agent、插件、API 与运营能力于一体，适合产品/运营和开发共同交付应用。[官方介绍](https://docs.dify.ai/versions/3-7-x/zh/user-guide/introduction)
- **Coze**：更偏托管式可视化 Bot/Agent 应用搭建和发布生态，通常强调插件、知识、工作流和渠道集成；适合快速业务原型和平台内分发，但要重点评估目标区域/版本的可用能力、数据治理与平台锁定。

### 二、选择维度

| 需求 | 倾向 |
|---|---|
| Python 代码快速集成模型、工具与 RAG | LangChain |
| 可恢复、强状态、复杂分支的自定义 runtime | LangGraph |
| 消息驱动/多 Agent team 与分布式研究 | AutoGen |
| 角色团队与任务编排的高层表达 | CrewAI |
| 自托管低代码、知识库、工作流和应用运营 | Dify |
| 托管低代码、快速 Bot 发布与渠道生态 | Coze |

### 三、不能忽略的工程问题

比较目标版本的 checkpoint/恢复、并发、HITL、tool/MCP、观测与 eval、部署/扩缩、RBAC/secret、数据驻留、插件供应链、迁移导出和许可。低代码缩短 PoC，不自动保证测试、事务、幂等和安全；代码框架更灵活，也意味着团队承担更多平台工程。

做同一真实用例 PoC，固定模型和工具，测成功率、p95、token/调用成本、恢复、调试时间和锁定风险。框架不能补救糟糕的工具边界或缺少业务状态机。

### 面试简答版

LangChain 是模型、工具、RAG 和高层 Agent 的代码集成层；LangGraph 是强调持久状态、恢复和 HITL 的低层图编排 runtime；AutoGen 偏消息驱动和多 Agent team/runtime；CrewAI 用角色、任务、Crew 加 Flow 快速表达团队协作；Dify 是含可视化工作流、RAG、插件、API 和运营的开源低代码平台；Coze 更偏托管可视化 Bot/Agent 与渠道发布。选型要按目标版本，用同一用例比较质量、恢复、观测、安全、部署和锁定，而不是按功能表或热度决定。
