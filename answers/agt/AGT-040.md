> **问题：** Context Engineering 与 Prompt Engineering 有什么区别，前者通常覆盖哪些系统组件？
>
> **分类：** Agent、工具与上下文工程
>
> **来源：** [CORE_INTERVIEW_QUESTIONS.md](../../CORE_INTERVIEW_QUESTIONS.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

Prompt Engineering 主要优化某次模型调用中的指令与示例；Context Engineering 关注整个系统在每一步**选择、组织、更新和压缩哪些信息与能力**。前者是后者的一部分，后者跨模型调用、检索、记忆、工具和 runtime。

### 一、Prompt Engineering

典型工作包括 system/user 指令、角色、任务分解提示、few-shot、输出 schema、rubric 和措辞/顺序。目标是在给定上下文和模型下提高输出质量。

它解决不了源文档未召回、工具结果错误、历史状态过期、权限越界或上下文超过预算等系统问题。

### 二、Context Engineering

可将一次调用上下文表示为：

\[
C_t=Policy+Goal+State_t+Memory_t+Evidence_t+Tools_t+Feedback_t
\]

Context Engineering 决定每一项从哪里来、是否可信、如何排序、何时失效以及占多少 token，并根据任务状态动态改变。

### 三、覆盖组件

- Instruction/policy 分层与版本；
- 对话历史选择、摘要、滑动窗口和 compaction；
- RAG 的 query、chunk、rerank、parent expansion 和引用；
- working/long-term memory 的写入、召回、冲突与遗忘；
- 工具发现、description/schema、候选过滤和 result normalization；
- 当前计划、任务状态、预算、失败账本与 HITL 决定；
- 多 Agent handoff/shared artifacts；
- token allocation、顺序、去重、Lost in the Middle 和缓存；
- provenance、ACL、secret/PII 和 Prompt Injection 边界。

### 四、优化目标

不是最大化上下文长度，而是最大化单位 token 的有效信息并维持状态真值：

\[
\max_{C:tokens(C)\le B} ExpectedUtility(C)
\]

要联合看任务成功、faithfulness、tool selection、p95 和成本。加入更多历史可能提高 recall，却降低 precision 和延迟。

### 五、工程方法

建立 context manifest，记录每段来源、版本、权限、token、选择原因和位置；可从 trace 重现某步 Prompt。按组件做消融和位置置换，使用 query 类型动态预算。确定性状态与权限由结构化字段/代码管理，不依赖自然语言 Prompt 重复提醒。

### 面试简答版

Prompt Engineering 优化一次调用的指令、few-shot、rubric 和输出格式；Context Engineering 则管理整个 Agent 生命周期中模型看到的 policy、目标、任务状态、历史、记忆、RAG 证据、工具 schema、tool results 和反馈，包括检索、排序、压缩、版本、ACL 与 token 预算。目标不是塞满窗口，而是在预算内提供最相关、最新、可信、可执行的信息。Prompt 是其中一层，源数据、状态机、权限和工具结果错误必须靠系统组件解决。
