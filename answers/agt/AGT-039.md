## 我的答案

工具原始返回不应直接拼进 Prompt。它可能过大、脏、含 secret/PII、字段不稳定、错误与成功混杂，甚至带间接 Prompt Injection。需要经过可信 adapter 的确定性处理管线。

### 一、处理链路

```text
Raw bytes + transport metadata
→ 大小/MIME/编码限制
→ parser + schema/version validation
→ semantic/business validation
→ sanitize/redact + injection marking
→ canonical structure + error classification
→ relevance selection/dedup/compression
→ artifact store + model-facing observation
```

### 二、裁剪而不丢真值

先按任务选字段、分页和 top-k，去模板/重复；大表返回 schema、相关行和统计，不截断半个 JSON。原始完整结果以受控 URI+hash 保存，Observation 标 `truncated`、总数和继续分页方式。摘要保留数字、单位、否定、实体和异常，不编造缺失值。

### 三、结构化与校验

解析为稳定 domain schema，验证必填、类型、enum、时间、总计、资源 owner 与 freshness。HTML/日志/CSV 使用专用 parser，不让模型自己猜格式。Schema valid 后仍需业务检查，例如 HTTP 200 内可能是错误对象。

### 四、去噪与安全

去 stack trace、重复日志、无关 debug 和广告；secret/PII 按任务与权限遮蔽。外部文本、代码注释和网页指令标为 untrusted data，消毒危险 HTML/URL，但保留审计原文。过滤器不是绝对防注入，工具权限仍需最小化。

### 五、错误分类

```text
VALIDATION / AUTHENTICATION / PERMISSION
NOT_FOUND / CONFLICT / RATE_LIMIT
TIMEOUT / TRANSIENT_UPSTREAM / PERMANENT_UPSTREAM
PARTIAL_RESULT / UNKNOWN_OUTCOME / INTERNAL
```

每类包含 `retryable、retry_after、safe_to_replay、user_action、details_ref`。超时写操作标 UNKNOWN_OUTCOME，不归类为普通 retryable failure。

### 六、写入上下文

模型只收到最小结构化 observation：结果、来源、时间、warnings、错误与可选 next actions。优先把关键事实放在明确字段而非叙述文本；控制 token budget。记录 adapter/version、raw hash、裁剪和校验决定，便于 trace 定位。

### 面试简答版

工具原始返回先做大小、MIME、编码和 parser 限制，再按版本 schema 与业务规则验证；随后去 secret/PII、重复和无关日志，把外部指令标成不可信数据，转换成稳定 domain structure。按任务裁字段/分页，大结果保存为 URI+hash，Observation 明示 truncated、总数和来源，不能截断半个 JSON。错误细分为参数、权限、冲突、限流、瞬时、永久、部分结果和未知副作用，并标 retryable/safe_to_replay。模型上下文只放最小必要的已验证视图。
