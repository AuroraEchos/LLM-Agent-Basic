> **问题：** LLM Agent 的模型、规划、工具、记忆和执行环境分别承担什么职责？
>

## 我的答案

LLM Agent 不是“一个会调用工具的模型”，而是一个闭环系统：模型根据目标与当前状态作决策，规划模块组织步骤，工具连接外部能力，记忆保存可复用状态，执行环境真正完成动作并返回可验证观察。

\[
s_t=(goal,history,memory,observations,budget),\qquad
a_t=\pi_{LLM}(s_t),\qquad s_{t+1}=Env(s_t,a_t)
\]

### 一、模型：理解、推理与决策

模型负责理解用户意图、从可用工具中选择动作、生成参数、解释 observation，并决定继续、重规划还是回答。它是概率决策器，不是真正的权限主体，也不应直接持有密钥或修改外部状态。

模型能力影响指令遵循、长上下文、结构化输出和错误恢复；但输出始终需要 schema、权限和业务规则校验。

### 二、规划：把目标变成可执行步骤

规划模块负责：任务分解、依赖排序、并行机会、资源预算、完成条件和失败分支。计划可由模型动态生成，也可由工作流/状态机固定。

简单可逆动作直接执行；多步骤、有依赖、高成本或不可逆任务先规划。计划不是承诺，environment observation 改变前提时需重规划。

### 三、工具：连接知识、计算与动作

工具把模型无法可靠完成的能力暴露为受控接口，例如搜索、数据库、计算器、代码 sandbox、邮件或业务 API。每个工具应有：明确名称与描述、JSON schema、权限范围、超时、幂等语义、错误类型和可审计结果。

工具结果是数据，不自动是真理或高优先级指令；网页、邮件等不可信内容可能含 Prompt Injection。

### 四、记忆：保存跨步骤或跨会话信息

- Working memory：本次任务的计划、变量、观察和未完成项；
- Episodic memory：过去任务及结果，用于相似案例；
- Semantic memory：稳定事实、用户偏好和知识；
- Procedural memory：工具用法、工作流和策略。

记忆必须有来源、时间、置信度、租户/用户 ACL、TTL 和删除机制。模型生成的总结不是原始事实，写入长期记忆前需验证；否则错误和注入会持久化。

### 五、执行环境：可靠且安全地落地动作

执行环境负责认证授权、参数校验、调用工具、隔离代码、管理超时/重试、状态持久化、并发、幂等、审批和审计。它维护真实的 state machine，是系统安全边界。

典型循环：

```text
目标 → 构造状态 → 模型给出结构化决策
→ policy/schema/权限检查 → 执行动作
→ 规范化 observation → 更新状态与记忆
→ 完成、继续、重规划或请求用户确认
```

### 六、模块边界

模型说“已发送”不能证明发送成功，只有工具回执能改变任务状态；记忆说用户有权限不能替代实时授权；计划说下一步删除数据不能绕过审批。生产 Agent 的可靠性主要来自这些确定性边界，而不是让 Prompt 更强硬。

监控要覆盖任务成功率、步骤/工具调用数、计划修改率、无效调用、超时、重复副作用、人工接管率、token/延迟/成本和安全违规。

### 面试简答版

模型负责理解目标、推理并选择下一动作；规划把目标分成有依赖、预算和停止条件的步骤；工具提供搜索、计算、数据库和业务动作等外部能力；记忆保存本任务状态以及经验证的跨会话经验；执行环境负责真正的授权、schema 校验、调用、超时重试、幂等、sandbox、审批和审计。模型只是概率控制器，不能充当权限和事实来源；只有受控工具回执才能证明外部状态改变。
