## 我的答案

记忆系统要分别评估**写入是否值得、检索是否找对、使用是否改善任务、数据是否新鲜、隐私是否守界**。只测向量 Recall@K 会忽略错误写入和跨用户泄漏。

### 一、评测集

构造带时间线的会话：用户声明/修改偏好，事实过期，多个相似用户，任务中临时信息，以及“不应记住”的秘密或一次性内容。标注每个 turn 应写、应更新/遗忘、查询时应召回哪些记忆及正确答案。

### 二、写入质量

- Write Precision：写入中真正值得长期保存的比例；
- Write Recall：应保存信息中被保存的比例；
- 类型、owner、来源、有效期和敏感等级准确率；
- inferred 被误标为 user-asserted 的比例。

写入 precision 通常比盲目高 recall 更重要，因为错误长期记忆会反复污染未来任务。

### 三、召回与使用

用 Recall@K、MRR/nDCG、context precision、重复率评估检索；再比较有/无记忆时的任务成功率、个性化正确率、澄清轮数和 token。命中但模型没有使用是 utilization failure，召回错误且模型采信是更严重的 harmful recall。

### 四、时效性

测 stale retrieval rate、冲突记录使用率、更新/撤销传播延迟、TTL 命中、权威源变化后的收敛时间。构造 T0 旧值、T1 更新、T2 查询，确保 T2 不返回旧 current value；历史查询仍能按时间找到旧值。

### 五、隐私与安全

- cross-user/cross-tenant retrieval rate 必须为零；
- 未获同意的敏感写入、secret/PII retention；
- 删除请求完成时间与派生物残留；
- 通过 membership inference、提示注入、伪造“记住它”和 ACL 变更测试；
- 日志、embedding、备份与缓存是否同样遵守权限。

采用 canary memory 测泄漏，但不使用真实秘密。

### 六、上线监控

按语言、用户群、记忆类型和年龄切片，记录 memory hit、来源、年龄、是否被答案引用、用户纠正/删除和失败原因。线上 A/B 必须同时看质量与隐私，任何跨用户泄漏都是安全事件，不能用平均收益抵消。

### 面试简答版

我会用带时间线和多用户隔离的评测集，先测应不应该写的 Write Precision/Recall、类型与来源，再测 Recall@K、MRR、context precision 和有无记忆的任务成功率。时效性看 stale retrieval、冲突误用、更新/撤销传播延迟；隐私看跨用户/租户泄漏、敏感数据未授权写入、删除后向量/摘要/缓存残留。还要区分“召回了但没用”和“错误召回且被采信”。平均个性化收益绝不能抵消一次权限泄漏。
