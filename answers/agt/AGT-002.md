> **问题：** ReAct 如何交替进行推理与行动，它与 CoT、Act-Only 有何差异？
>
> **分类：** Agent 与工具调用

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

ReAct 将语言推理与环境行动交替进行：模型先根据目标和已有 observation 判断下一步，再发出 action；环境执行后返回 observation，模型据此修正后续决策。其原始思路见 [ReAct 论文](https://arxiv.org/abs/2210.03629)。

```text
Thought/Decision: 需要查订单状态
Action: get_order({"id":"A123"})
Observation: {"status":"shipped", "eta":"2026-08-22"}
Thought/Decision: 已获得充分证据
Final: 订单已发货，预计……
```

### 一、ReAct 的闭环

在第 \(t\) 步：

\[
(r_t,a_t)\sim\pi(\cdot|q,a_{<t},o_{<t}),
\qquad o_t=Tool(a_t)
\]

推理用于维护目标、解释观察和选择动作；行动让模型获取参数中没有的实时事实或影响环境。新 observation 可以推翻先前假设，因此它适合信息不完备、工具反馈决定下一步的任务。

工程上不必展示或保存模型的自由文本隐式思维；可以让模型输出简短 `decision/rationale/action` 结构，并保存可审计的动作与证据。

### 二、与 CoT 的差别

CoT 主要在模型内部生成一条连续推理链：

```text
Question → reasoning tokens → answer
```

它适合已有信息足够的数学、逻辑和解释任务，但不能自行验证实时事实。错误前提可能在整条链中持续放大。ReAct 则能通过工具观察校正推理，但增加工具延迟、失败面和安全风险。

### 三、与 Act-Only 的差别

Act-Only 直接从 observation 选择动作，不显式维护任务分解或理由，适合动作空间小、反馈密集、策略明确的环境。复杂多步任务中，它容易重复调用、忘记依赖或无法解释为何停止。

ReAct 的推理状态有助于跟踪子目标和异常恢复，但也可能产生冗长循环或虚构 observation，所以环境必须把真实工具结果与模型文本分开。

### 四、适用与边界

适合网页/知识检索、交互式诊断、工具选择和反馈驱动任务。不适合直接承担高风险不可逆动作；此时需确定性工作流与审批。主要失败包括：

- Thought 合理但工具参数错误；
- 把工具报错当成功，或虚构未返回的字段；
- 在相同 query/action 上循环；
- 不可信 observation 注入新指令；
- 找到部分证据便过早停止。

应设置最大步数、token/费用预算、重复动作检测、schema/ACL、工具超时、证据充分性检查和高风险审批。

### 面试简答版

ReAct 按“推理/决策 → Action → Environment Observation → 更新决策”循环，让推理指导工具使用，工具反馈又能纠正推理。CoT 只在已有上下文内推理，成本较低但无法获取实时证据；Act-Only 直接选动作，适合简单反馈环境，却缺少显式任务跟踪。ReAct 适合信息不完备、多步且下一步依赖工具结果的任务，但必须防循环、虚构观察和间接注入，并设置 schema、权限、预算、停止条件及不可逆动作审批。
