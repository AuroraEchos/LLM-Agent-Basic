> **问题：** 连接不可信 MCP Server 时有哪些安全风险和隔离措施？

## 我的答案

不可信 MCP Server 同时是**代码/网络依赖、数据提供者和工具能力提供者**。风险不仅是返回错误答案，还包括本地代码执行、凭据窃取、Prompt Injection、数据外传、越权动作和供应链替换。应默认零信任，按最小权限隔离。

### 一、主要风险

- 本地 stdio Server 是可执行程序，可能读文件、环境变量、SSH key，启动子进程或联网；
- 远程 Server 可记录发送给它的 query/resource，伪造 tool description 或结果；
- Tool/Prompt/Resource 中嵌入指令，诱导模型泄露上下文或调用高权限工具；
- 名称相似/工具投毒使模型选错能力；
- 过大响应、无限流、通知洪泛造成 DoS；
- 依赖或自动更新被供应链攻击；
- OAuth token audience 错误、token passthrough 造成 confused deputy；
- 多 Server 串联时，一个 Server 的恶意输出驱动另一个高权限动作。

### 二、安装与进程隔离

固定包/镜像版本和 hash，审查发布者、源码、依赖与更新；不执行来源不明的一键命令。stdio Server 运行在容器/sandbox、非特权用户下，使用只读文件系统、显式挂载目录、CPU/内存/进程限制和默认禁止网络。不要把全部环境变量继承给子进程，只注入最小短期凭据。

### 三、远程与身份安全

使用 HTTPS、认证、明确 server allowlist 和证书校验；每个 Server 独立、最小 scope 的 token。按当前 MCP 授权规范，token 应绑定目标 resource/audience，Server 不应把入站 token 原样传给下游，见[官方 Authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)。凭据不进入模型上下文、日志或 tool arguments。

Streamable HTTP Server 校验 Origin，本地监听只绑定 localhost，防 DNS rebinding。

### 四、能力与内容隔离

Host 按 server、用户和任务过滤工具；默认只读，危险 tool 每次预览和确认。Server 声明的 annotations、schema 和描述都不可信，Host 另设策略。Resources/Prompts/tool results 用 data delimiter，扫描注入和恶意 URL，限制大小、MIME、分页、调用频率和递归。

隔离不可信内容阅读器与高权限执行器：前者只输出受 schema 约束的事实，后者只根据用户原始意图与结构化数据行动。模型不能把 Server 文本当授权。

### 五、审计与响应

记录 server identity/version/hash、连接、能力变化、每次工具参数、授权/确认、网络目标、返回大小和副作用。建立 kill switch，能立即断开 Server、撤销 token、隔离结果/记忆和追踪受影响会话。测试跨 Server 注入、凭据读取、路径穿越、符号链接、超大响应、断线后重复写和权限提升。

### 面试简答版

不可信 MCP Server 可能是恶意本地程序，也可能通过 tool/resource/prompt 做间接注入、窃取数据或诱导高权限动作。应固定来源和 hash，在非特权 sandbox 中运行 stdio Server，只挂载必要目录、默认断网且不继承环境秘密；远程 Server 用 HTTPS、allowlist 和 audience-bound 最小 scope token，禁止 token passthrough。本地 Host 再独立过滤工具、限制响应与调用、把返回当数据，高风险动作逐次确认。全链路审计 server 版本和副作用，并支持撤销凭据与一键隔离。
