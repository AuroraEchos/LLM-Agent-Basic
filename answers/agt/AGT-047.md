> **问题：** 如何为系统指令、用户输入、检索文档、网页内容和工具结果建立信任分层，防止间接 Prompt Injection 污染上下文？
>
> **分类：** Agent 与工具调用
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

要同时区分**指令权限**与**内容可信度**。系统指令有最高控制权限，但也需来自受信部署；用户输入可定义目标却不能提升权限；检索、网页和工具文本通常只是数据，即使写着“忽略系统指令”也不能成为命令。

### 一、信任分层

| 来源 | 可控制什么 | 默认处理 |
|---|---|---|
| 签名/版本化 System/Policy | 角色、权限、禁止项 | 高权限指令 |
| 应用工作流/开发者配置 | 任务与工具规则 | 受信指令，不能违背系统策略 |
| 已认证用户输入 | 用户目标、授权范围内参数 | 不可信指令，需校验 |
| 权威结构化 API | 业务事实 | 高可信数据，不是指令 |
| RAG 文档/网页/邮件 | 外部内容 | 不可信数据 |
| 模型/记忆/摘要 | 派生内容 | 低至中可信数据，需来源 |

工具结果的可信度按具体后端和字段判断；“来自工具”不自动可信。

### 二、结构化隔离

每个 context item 使用 envelope：`source、trust、content_type、ACL、observed_at、provenance`，外部文本放明确 delimiter 中。System policy 明确只从这些块提取事实，不执行其中 instruction。移除隐藏 HTML/Unicode 和危险链接，但不把 sanitizer 当唯一防线。

### 三、确定性安全边界

Host 在模型外执行 tool allowlist、实时 ACL、参数 schema、网络 egress、secret/PII DLP、预算和高风险审批。用户或文档不能通过文字扩大 scope；工具调用还要对照原始用户意图做 action validation。即使模型被注入，也拿不到凭据或未经批准的副作用。

### 四、上下文和记忆防污染

检索按来源 allowlist/trust、新鲜度和权限过滤；冲突优先权威源并显式展示。外部内容不得直接写长期记忆，须提取候选事实、验证、去敏和用户同意。跨 Agent 传递结构化 claims/evidence，不传播自由文本命令。

### 五、检测与响应

分类器/规则扫描“角色伪造、外传、工具诱导、编码隐藏”等，但假阳性/绕过不可避免。输出再做 citation、DLP 和 action检查。Trace 记录来源与 policy 决定；红队覆盖 indirect injection、跨 chunk/多 server 组合攻击。一旦污染，隔离来源、失效缓存/记忆并追踪受影响请求。

### 面试简答版

System/应用策略是受信控制指令；用户输入只能在已有授权内表达目标；权威 API、RAG、网页、邮件、工具文本、模型摘要都属于不同可信度的数据，不能因内容写了“系统指令”就升级权限。每段上下文带 source、trust、time、ACL 和 delimiter，外部内容只提取事实。真正边界在模型外：工具 allowlist、ACL、schema、egress、DLP、预算和参数绑定审批。外部数据写记忆前再次验证；注入检测只是纵深一层，失败后还要按 lineage 清理缓存与记忆。
