> **问题：** 什么是 Agent Harness，它与基础模型、Agent Framework 和 Agent Runtime 的边界分别是什么？
>
> **分类：** Agent、工具与上下文工程
>
> **来源：** [CORE_INTERVIEW_QUESTIONS.md](../../CORE_INTERVIEW_QUESTIONS.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

Agent Harness 是围绕基础模型搭建的**任务控制与能力使用层**：它把用户目标、工具、环境状态、上下文、记忆和安全策略组织成可执行闭环，并决定模型在每一步能看到什么、能做什么以及何时停止。

### 一、与基础模型的边界

基础模型提供条件生成能力：

\[
p_\theta(output\mid context)
\]

它理解文本、生成决策/代码/参数，但不天然拥有真实工具、持久状态、权限、可靠时钟或副作用证明。Harness 负责构造 context、解析结构化输出、验证决策并把真实 observation 返回模型。换模型不应改变业务状态机和权限语义。

### 二、与 Agent Framework 的边界

Framework 是可复用开发库/抽象，如 tool adapter、graph API、memory interface、callbacks。Harness 是某个产品/任务中的具体行为策略和装配：system policy、工具集合、上下文选择、循环、错误恢复、审批与评测。

可以用框架构建 Harness，也可直接代码实现；同一框架能承载不同 Harness。同样，一个 Harness 的接口也可迁移到不同框架。

### 三、与 Agent Runtime 的边界

Runtime 提供执行基础设施：队列、并发、持久化 checkpoint、定时器、worker、重试、隔离、流式事件、部署和观测。Harness 定义“任务该怎样做”，Runtime 保证“长时间可靠地跑起来”。

```text
基础模型：提出下一决策
Harness：组织上下文、策略、工具和反馈循环
Framework：提供构建这些逻辑的代码抽象
Runtime：调度、持久化、恢复、隔离和扩缩容
```

实际产品会有重叠，但责任要明确。例如重试策略由 Harness 决定哪些错误可重试，Runtime 负责可靠执行次数和 deadline。

### 四、Harness 的典型组件

- Instruction/policy 与任务解析；
- Context builder、history compression 和 RAG；
- Tool registry、routing、schema adaptation 与 result normalization；
- Plan/act/observe/reflect/stop 控制循环；
- working/long-term memory 策略；
- budget、循环检测、HITL 与安全 policy；
- output validation、citation/verifier、trace/eval hooks。

### 五、设计原则

Action/Observation 协议与模型供应商解耦；确定性业务规则不写进易漂移 Prompt；每个副作用由 Runtime/工具回执证明；Harness、模型、工具、Prompt 和策略都版本化。评测模型升级和 Harness 改动要分别做消融。

### 面试简答版

基础模型只是根据 context 生成推理或结构化决策；Agent Harness 是模型周围的任务控制层，负责上下文、工具、计划—行动—观察循环、记忆、验证、预算、审批和停止。Agent Framework 提供构建这些逻辑的通用代码抽象，Agent Runtime 则提供队列、并发、checkpoint、恢复、sandbox、部署和观测。可以用不同框架实现同一 Harness，也可替换模型而保留业务与安全状态机。最终效果必须分别归因于模型、Harness 和 Runtime。
