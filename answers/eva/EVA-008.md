> **问题：** 离线评测提升为什么可能无法转化为线上业务提升？
>
> **分类：** 评估、幻觉与安全
>
> **来源：** [CORE_INTERVIEW_QUESTIONS.md](../../CORE_INTERVIEW_QUESTIONS.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

离线指标提升只有在**任务分布、交互方式、系统约束和用户价值函数**与线上一致时才可能转化。离线常评“一次生成的答案”，线上用户体验却由检索、工具、延迟、失败恢复、成本和行为反馈共同决定。

### 一、分布偏移

Benchmark 语言规范、问题完整，线上有错字、歧义、长尾、恶意输入和动态知识；离线样本的用户/国家/设备比例也不同。总体提升可能来自低价值头部，关键人群反而回退。

### 二、代理指标错位

ROUGE/Judge 偏好流畅或较长回答，业务可能关注一次解决、转人工、转化、正确拒答或时间。模型把回答写长能提高 Judge，却增加用户阅读和成本。需要因果链：

\[
offline\ metric\rightarrow behavior\ change\rightarrow business\ outcome
\]

### 三、系统交互差异

线上 Prompt、RAG 索引、工具权限、缓存、限流和 UI 可能与离线不一致；更强模型也可能产生不同 tool call，触发真实 API 错误。离线没有网络超时、并发、状态变化和副作用。

### 四、延迟与成本

质量提高但 TTFT/p95、token、工具次数增加，会导致用户流失、超时或容量下降。线上降级/重试可能改变输出分布；只看成功请求形成 survivorship bias。

### 五、反馈与实验偏差

离线 Judge 与真实用户偏好不同；线上点击受位置、UI 和 novelty 影响。用户会改变提问方式，长期还可能产生学习、信任或滥用效应。短期 A/B 未必反映长期质量。

### 六、桥接方法

用真实脱敏日志建立离线集，按线上流量/价值加权；端到端 replay 包含检索和工具 simulator；报告质量—延迟—成本与关键切片。上线前 shadow，之后小流量 canary/A-B，设正确性、安全、p95 和成本 guardrails，并检查 offline-online metric correlation。

失败 trace 回流时保持新的冻结 holdout，避免又把线上指标过拟合成离线分数。

### 面试简答版

离线提升可能不转化，因为 benchmark 与线上长尾分布不同，Judge/ROUGE 等代理指标与一次解决、转人工或转化错位，线上还有 RAG、工具、权限、缓存、超时和副作用；更高质量若带来更长 p95 和成本也可能降低业务。应从真实日志构建端到端回放，按用户价值与切片报告质量—延迟—成本，先 shadow/canary，再随机 A/B，用安全、正确、p95 和成本作 guardrail，并验证离线指标与业务结果的相关/因果链。
