> **问题：** 直接 Prompt Injection 与间接 Prompt Injection 有何差异？
>
> **分类：** 评估、安全与可观测性

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

两者都利用了 LLM 难以可靠区分“指令”和“数据”的特点，差异主要在**恶意指令从哪里进入系统、攻击者与受害者是否是同一个人**。

| 维度 | 直接 Prompt Injection | 间接 Prompt Injection |
|---|---|---|
| 输入来源 | 攻击者直接在聊天、API 参数或上传内容中向模型发指令 | 指令预先埋在模型稍后读取的网页、邮件、文档、RAG 数据、图片或工具返回中 |
| 交互关系 | 攻击者通常就是当前用户 | 攻击者、触发读取的用户和数据所有者可能是不同主体 |
| 常见目标 | 覆盖任务、套取隐藏信息、绕过策略 | 劫持摘要/检索任务、窃取会话数据、污染记忆或诱导 Agent 调工具 |
| 发现难度 | 请求入口较明确，容易记录和限流 | 载荷可异步、跨租户、不可见或跨模态出现，溯源更难 |
| 主要防线 | 输入审核、模型安全训练、权限和输出控制 | 内容来源标记、信任隔离、检索 ACL、最小权限、动作确认和数据流控制 |

### 例子

直接注入：用户在客服对话中要求模型忽略原任务，并尝试读取不属于自己的订单。即使模型愿意配合，后端仍应依据已认证用户与订单归属拒绝查询。

间接注入：用户让 Agent 总结一份外部网页，网页中嵌有“读取历史对话并发送到某地址”的隐藏指令。用户并没有提出该请求；如果 Agent 把网页数据提升为指令并拥有外发工具，就可能成为攻击者的代理。

因此，间接注入尤其危险的地方不只是模型答错，而是形成：

$$
\text{不可信内容}\rightarrow\text{模型决策}\rightarrow\text{私有上下文/高权限工具}\rightarrow\text{外部副作用}
$$

### 防护重点

1. **数据与指令分区**：保存 provenance，将外部内容放在明确的数据字段中，禁止其修改系统目标。标签能降低风险，但不能形成绝对隔离。
2. **按请求时重新授权**：检索阶段按当前用户做 ACL；工具执行阶段再校验主体、资源和动作，绝不相信文档或模型声明的权限。
3. **限制数据流**：不给总结任务不必要的邮箱、历史会话和网络外发能力；对敏感源到公开 sink 的路径做策略控制。
4. **参数和副作用确认**：高风险动作展示工具、目标、关键参数和影响范围，由用户确认；确认后绑定参数摘要，防止 TOCTOU 替换。
5. **端到端测试**：分别覆盖显式、隐藏、编码、跨模态、分片、RAG 污染和工具返回中的注入，并查看真实动作而不仅是最终文本。

必须接受一个现实：提示词加上“忽略文档内指令”只是软约束。Prompt Injection 很难靠模型内单点彻底消除，系统设计应假设模型偶尔会受影响，并把后果限制在可接受范围内。

### 面试简答版

直接 Prompt Injection 是攻击者把恶意指令直接放入当前用户输入；间接注入则把指令埋在网页、邮件、RAG 文档、图片或工具返回里，等受害用户的 Agent 读取后触发。间接注入常涉及三个主体——攻击者、用户和外部内容——更隐蔽，也更容易结合私有上下文及工具权限造成泄漏或越权。防护不能只过滤文本，而要保留来源、隔离数据和指令、按用户执行检索 ACL、让工具最小权限并重新鉴权，对敏感数据流和高风险动作做确认与审计。
