## 我的答案

这几个概念不在同一层级：**越狱和 Prompt Injection 更接近攻击方式或漏洞利用，数据泄漏和有害输出是可能造成的结果，偏见则是系统性的质量与公平性问题。**

| 概念 | 核心含义 | 例子 |
|---|---|---|
| 越狱（jailbreak） | 攻击者通过输入绕过模型或应用的安全策略，使其完成本应拒绝的任务 | 通过角色设定、渐进诱导等方式获得禁止内容 |
| Prompt Injection | 不可信输入被模型当成指令，非预期地改变任务、数据流或工具行为 | 网页中的隐藏指令让总结 Agent 改为读取并外发私有信息 |
| 数据泄漏 | 未授权披露秘密、个人信息、跨租户数据、凭据或商业机密 | 回答中返回其他用户订单、工具令牌或内部文档 |
| 有害输出 | 输出本身造成安全、健康、违法、仇恨等危害 | 无攻击情况下也可能生成危险建议；也可能由越狱触发 |
| 偏见（bias） | 对群体存在系统性刻板印象、性能差异或不公平待遇 | 只改变姓名所暗示的群体，候选人评分却系统性变化 |

### 越狱与 Prompt Injection 的边界

两者高度相关，但关注点不同：

- 越狱强调**绕过安全意图**，目标通常是让模型输出被禁止的内容。
- Prompt Injection 强调**不可信内容改变指令流**，既可直接来自用户，也可间接来自网页、邮件、文件、图像或 RAG 文档。它未必以生成有害内容为目标，也可能操纵总结、泄露数据或触发未授权工具。
- 按 OWASP 2025 的表述，jailbreaking 可视为 Prompt Injection 的一种安全绕过形式；但工程评测中仍应拆开，因为纯聊天模型越狱与具备工具权限的间接注入，风险和防护完全不同。

同样，数据泄漏只是结果，不代表根因一定是注入：权限配置错误、跨租户缓存、日志暴露、训练数据记忆或错误的检索 ACL 都可能导致泄漏。有害输出也可能来自普通误答。偏见则需要观察跨样本、跨群体的稳定差异，不能仅凭单个冒犯性回答下结论。

### 评测方法也应分开

- **越狱**：按政策类别计算攻击成功率（ASR）、严重度加权 ASR、跨多次采样的稳定成功率，同时测良性请求的误拒率。
- **Prompt Injection**：分别测试直接、间接、跨模态和工具链场景；判断任务是否被劫持、秘密是否被读取、未授权动作是否真正执行。
- **数据泄漏**：使用无真实敏感性的 canary、跨租户隔离测试、DLP 规则和访问审计，目标通常是零严重泄漏。
- **有害输出**：按危害分类和严重等级统计 precision/recall、发生率与人工复核结果，区分“请求有害”与“响应实际提供了有害帮助”。
- **偏见**：使用群体切片、反事实成对样本、公平性与性能差距；还要控制职业、资历等混杂变量。

防护也要对应层级：模型安全训练和输入/输出分类器主要降低越狱与有害内容；数据—指令隔离、最小权限、参数校验和高风险动作审批主要限制注入影响；ACL、脱敏、租户隔离和密钥管理防泄漏；代表性数据、切片评测和产品流程审查治理偏见。仅靠一条更强的 system prompt 无法覆盖这些风险。

### 面试简答版

越狱是绕过安全策略，Prompt Injection 是不可信输入非预期地改变模型指令流；越狱可看作注入的一种安全绕过形式，但注入还可能劫持 RAG 或工具，而不只是生成违规内容。数据泄漏和有害输出是可能产生的安全结果，偏见则是跨群体的系统性差异。评测时我会分别看越狱 ASR、注入后的任务劫持或工具执行、canary 泄漏率、有害内容严重度以及群体/反事实差距；防护则组合安全训练、信任边界、最小权限、输出校验、租户隔离和人工审批。
