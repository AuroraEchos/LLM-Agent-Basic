## 我的答案

LLM 系统回归需要把 Prompt、模型、采样、检索和工具视为一个版本化依赖图。每个变更既做组件测试，也做固定快照上的端到端任务测试；不能只比较最终文本是否完全相同。

### 一、实验 Manifest

保存 model/tokenizer revision、system/few-shot/template hash、temperature/top-p/max tokens/seed、embedding/reranker/index generation、chunk/query config、tool schema/adapter/backend/simulator 版本、policy 与 runtime。缺一项就难以复现回归。

### 二、分层测试

- Prompt：必需约束、角色优先级、结构化输出、注入和边界示例；
- 模型：能力/安全/语言/长文本与输出 schema，固定 Prompt 做多 seed；
- Sampling：分布、重复、长度、pass@k 和成本，不能只测 temperature=0；
- Retriever：固定 corpus/query 的 Recall@K、rank、filter/ACL、引用与 index freshness；
- Tool：contract/schema、选择、参数、错误分类、超时/幂等、malformed response；
- E2E：环境最终状态、任务成功、p95、成本与安全。

### 三、Golden 与容差

确定性 JSON、工具调用和状态用 exact/schema/assertion；开放文本用 claim/rubric/semantic + 人工抽样。定义允许的等价集合和数值容差，避免脆弱 snapshot；但 ID、金额、权限、否定和引用不能被语义相似度掩盖。

### 四、变更隔离

一次只改一项做 paired comparison；必须组合升级时跑 factorial/ablation。使用录制的 tool/retrieval fixtures 隔离模型，再用真实 staging 验证集成。新 query embedding 与旧 index 不兼容时建新 generation，不能混用。

### 五、门禁与上线

CI 跑快速单元/contract/canary，夜间跑多 seed 大集与 adversarial；关键切片 no-regression，整体提升要有置信区间。版本通过 shadow/canary，支持回滚整个 manifest，而非只回滚模型。

### 六、维护

失败加入 development regression set，同时保留冻结 test；监控测试陈旧、污染和 flaky rate。报告 diff 到 stage：Prompt selection、retrieval rank、tool action、observation 或 final generation，才能快速定位。

### 面试简答版

先用 manifest 锁定 Prompt/template、模型、采样、embedding/index、reranker、工具 schema/backend、policy 和 runtime。Prompt 做约束/注入测试，模型和采样做多 seed 能力与分布，检索测固定语料 Recall/ACL，工具做 contract、错误、超时与幂等，最后以环境 task success 做 E2E。结构化结果 exact/schema，开放文本用 claim/rubric 和容差。变更做 paired/消融，CI→夜间大集→shadow/canary，并能按完整 manifest 回滚；失败进入开发回归集但不污染冻结测试。
