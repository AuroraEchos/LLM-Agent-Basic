## 我的答案

大模型应用需要能回答四个问题：**发生了什么、为什么发生、影响了谁、能否安全复现**。但“把所有 Prompt 和输出永久存下来”会把可观测系统本身变成高价值数据泄漏源，因此应采用结构化事件、默认最小化和分级取证。

### 应记录的内容

**请求与链路元数据**：`trace_id`、时间、服务/环境、匿名或伪名化主体、租户、会话 ID、入口、模型与 Prompt 模板版本、发布实验组。跨服务使用 trace/span 关联，而不是依赖原文搜索。

**模型调用**：模型版本、推理参数、输入/输出 token、截断与重试、缓存命中、首 token/总延迟、状态码、成本。必要时记录输入输出的脱敏摘要、内容哈希或受控引用，不默认保存完整思维过程。

**RAG 与记忆**：规范化查询的安全摘要、检索器/索引和 embedding 版本、命中文档 ID、版本、分数、ACL 决策、引用映射；记忆的读写、来源和过期策略。这样才能定位是检索错还是生成错。

**Agent 与工具**：计划状态、工具名/版本、参数的脱敏结构或摘要、调用者身份、授权决策及理由码、审批、幂等键、结果状态和副作用。密钥、Cookie、Authorization Header 和工具原始秘密绝不进入普通日志。

**质量与安全**：Schema/事实/引用检查结果、分类器及策略版本、置信分、拒答/降级/转人工理由、用户反馈和最终业务结果。高风险事件保留可审计的策略证据。

### 如何兼顾隐私

1. **目的限定与数据最小化**：每个字段都要有调试、计费、安全或合规目的；不需要原文就记 ID、枚举、计数、哈希或统计量。
2. **采集前脱敏**：在日志边界识别 PII、凭据和业务秘密，采用删除、掩码、tokenization 或带密钥的伪名化。普通哈希无法保护低熵邮箱和手机号，容易被字典反推。
3. **分级存储**：指标日志、脱敏 trace 与临时受限原文分开。原文只在用户同意、抽样调试或安全事件需要时短期保存，采用加密、细粒度 RBAC、审批和不可篡改访问审计。
4. **保留与删除**：按字段风险设置 TTL，支持用户/租户删除和法律保留；备份、分析仓库和标注导出也必须纳入生命周期。
5. **限制二次用途**：生产日志不自动进入训练集。训练、评测或人工标注需单独的合法依据、去标识流程、访问审批和数据血缘。
6. **防止日志注入**：用户文本作为数据字段结构化编码，控制长度与换行，不允许伪造日志级别或执行查询；日志查看器也要做 HTML 转义。

### 可观测架构与验证

在线指标保留聚合计数和分位数；分布式 trace 默认只含脱敏元数据；极少量受控样本进入隔离取证库。通过 `trace_id` 和权限化的原始对象引用关联，而不是到处复制内容。监控日志覆盖率、脱敏召回/误报、访问异常、TTL 执行和敏感字段 canary；定期演练“定位一次越权工具调用”和“删除某用户所有可删数据”。

可观测性还要避免高基数失控：不要把完整 Prompt、用户 ID 或文档正文作为 metrics label。它既导致成本与性能问题，也可能把隐私数据复制进多个监控后端。

### 面试简答版

我会记录贯穿请求、模型、RAG、Agent 和工具的结构化 trace：版本、延迟、token/成本、检索文档与 ACL、工具参数摘要、授权和审批、验证结果及业务结果。隐私上遵循目的限定和最小化，采集前脱敏，秘密与 Authorization Header 禁止入日志；聚合指标、脱敏 trace 和短期原文取证库分级存储，分别设置 RBAC、审计和 TTL。生产日志不能默认进入训练集，并要支持删除、数据血缘和日志注入防护。目标是无需广泛保存原文，也能重建关键决策链。
