> **问题：** Prefix Cache、Prompt Cache 和 KV Cache 是什么关系？

## 我的答案

三者不是三个完全独立的底层对象。KV Cache 是模型执行层保存的每层 K/V 张量；Prefix Cache 是把某段公共前缀对应的 KV Cache 持久化并在请求之间复用；Prompt Cache 是更宽泛、各产品定义不统一的叫法，可能指 Prefix/KV 缓存，也可能指应用层的完整响应缓存。

### KV Cache：单次自回归状态

在 Prefill 后，标准 Transformer 为每层保存 prompt 的 K/V。Decode 每生成一个 token 就追加一份 K/V，以避免重算历史前缀。它通常属于某个请求或会话，生命周期到请求结束、会话过期或显存回收为止。

KV Cache 的 key 隐含包含：模型权重、精确 token 序列、position IDs、Attention 配置等。它缓存的是模型中间状态，不是可读文本，也不是最终回答。

### Prefix Cache：跨请求复用公共 KV blocks

很多请求可能共享：

```text
相同 system prompt
+ 相同 few-shot 示例
+ 相同长文档前缀
```

第一次请求完成这段 Prefill 后，将其 KV blocks 放入全局或租户级缓存；后续请求若 token 前缀完全相同，可直接引用这些 blocks，只 Prefill 未命中的 suffix。

若请求 token 长度为 $S$，命中前缀长 $P$，理论上从头 Prefill 的工作缩为处理 $S-P$ 个新 token，并读取缓存的前缀 KV。Attention 仍需让 suffix query 读取 prefix KV，因此不是零成本。

实现常用 radix tree/trie 或按固定 block 的内容哈希：

```text
token block hash + parent hash + model/cache namespace → KV block
```

Block 粒度意味着最后一个未满或不匹配 block 可能需要重算。使用引用计数与 copy-on-write，可以让多个请求共享只读前缀，分叉后各自追加。

### Prompt Cache：先问清定义

“Prompt Cache”可能表示：

1. 将 prompt 的 KV 状态缓存，即 Prefix Cache；
2. 缓存 tokenization/模板渲染结果，只省 CPU 预处理；
3. 按完整 prompt 缓存最终生成回答，类似 response cache；
4. 供应商提供的输入前缀缓存能力，对命中 token 采用不同计费/延迟。

第 3 种只有在允许返回完全相同答案时才适用，会跳过整个模型执行；Prefix Cache 仍会正常生成新的 continuation，采样结果可以不同。因此面试中应先给术语下定义。

### Cache Key 必须包含什么

不能只对原始字符串做哈希。安全 key 至少考虑：

- token IDs 与 tokenizer/template 版本；
- model checkpoint、LoRA/adapter、量化版本；
- position/RoPE、Attention mask、模态特征；
- 影响 hidden state 的模型配置；
- 租户、权限和数据可见范围；
- 必要时的随机/运行配置——采样参数不影响 prompt KV，但影响完整 response cache。

Temperature/top-p 不影响同一前缀的 KV，通常不必放入 Prefix Cache key；它们必须进入最终响应缓存 key。工具权限或检索文档若已改变实际 prompt token，token key自然不同，但访问控制仍需单独隔离。

### 失效与安全

Prefix Cache 是显存/主存容量与命中率的权衡。常用 LRU/LFU、TTL、block-aware eviction；回收共享 block 时要处理引用计数，不能释放仍被活跃请求引用的页。

跨用户共享公共系统前缀可提高命中，但缓存命中侧信道、错误租户隔离或调试接口可能泄露信息。私有文档前缀应按租户/权限 namespace 隔离、加密或禁止共享，日志不得输出 KV 原始内容或可逆 token。

### 面试简答版

KV Cache 是一次自回归请求中按层保存的历史 K/V；Prefix Cache 是把公共前缀的 KV blocks 跨请求复用，后续只 Prefill 未命中的 suffix；Prompt Cache 是歧义术语，可能指前缀 KV、tokenization 或完整响应缓存。Prefix 命中要求模型、Tokenizer、模板、position 和 token IDs 精确一致，通常用 radix tree/块哈希、引用计数和 copy-on-write 管理。响应缓存还必须把采样参数放进 key。跨用户复用要按租户和权限隔离，不能只凭字符串哈希共享私有前缀。
