## 我的答案

PagedAttention 借鉴操作系统虚拟内存：把每个请求逻辑上连续增长的 KV Cache 切成固定 token 数的逻辑块，再映射到显存中任意空闲的物理块。请求不需要提前申请“最大可能输出长度”的连续大区域，因此显著减少预留浪费和外部碎片，并支持按 token 增长动态分配。

这一思想由 [vLLM/PagedAttention 论文](https://arxiv.org/abs/2309.06180)系统化用于 LLM 服务。注意 PagedAttention 既包含 cache 内存布局/管理，也需要 Attention kernel 按 block table 间接读取不连续 K/V；它不是把操作系统页表原样交给 GPU。

### 连续分配的问题

请求输入、输出长度事先未知。若每个请求按最大长度 $S_{max}$ 预留：

$$
M_{reserved}=S_{max}\cdot m_{token}
$$

实际只生成 $S$ 时浪费 $(S_{max}-S)m_{token}$。若只按当前长度不断扩大的连续数组，则扩容需要找到更大的连续显存、搬移旧 K/V，多个不定长请求还会造成外部碎片。

静态 batch 中短请求结束后，其预留空间也可能直到整个 batch 结束才回收，进一步压低并发。

### 分页映射

设每个 block 容纳 $T_b$ 个 token。请求的逻辑 KV 序列：

```text
logical blocks: 0 → 1 → 2 → 3
physical blocks: 7 → 2 → 19 → 5
```

每个 sequence 维护 block table：

$$
\text{logical block id}\rightarrow\text{physical block id}
$$

Decode 新 token 到来时：

1. 当前物理 block 未满则写入下一个 slot；
2. 已满则从全局 free list 申请任意空闲 block；
3. 更新该 sequence 的 block table；
4. PagedAttention kernel 根据 table gather 各块 K/V 完成 Attention。

请求结束即可把其独占 blocks 归还池中，无需等待同批其他请求。

### 碎片为什么变小

固定块消除了“必须连续”的外部碎片。单请求只可能在最后一个 block 有内部碎片，最坏浪费小于 $T_b$ 个 token：

$$
0\le W_i<T_b\cdot m_{token}
$$

块越小，内部碎片越少但 block table、调度和不连续访问开销越高；块越大，元数据少、kernel 更规整，但短请求浪费更多。Block size 是容量与访存效率的折中。

### Prefix Sharing 与 Copy-on-Write

Beam search、parallel sampling 或多个请求共享同一 prompt 时，可让逻辑 block table 指向相同的只读 prefix blocks，并维护引用计数。分支首次修改共享的最后一块时执行 copy-on-write：复制该块，再独立追加。

这避免为每个 beam 复制整个 prompt KV，但只有精确相同的前缀才能共享；请求权限、模型/adapter、位置配置也必须一致。

### 它带来的系统收益

- 按需分配，减少过度 reservation；
- 快速回收已完成请求的 blocks，支持 continuous batching；
- 更高 KV token capacity 和并发；
- prefix caching、beam sharing 与 preemption 更容易实现；
- 无需因 cache 扩展搬移整个连续数组。

### 代价与边界

- Attention kernel 要做地址间接寻址，block table 访问和非连续 gather 增加复杂度；
- block 太碎可能降低访存合并和 cache locality；
- page table、引用计数、free list 和调度本身占内存/CPU；
- 抢占时 swap/recompute KV 仍有成本，分页不会凭空增加物理容量；
- 多 GPU 下 block 的所有权、迁移和 TP/PD 传输需要协调；
- cache 量化时 scale 与 blocks 的布局也要一起管理。

PagedAttention 主要解决 KV 内存利用率和灵活分配，不直接减少模型 FLOPs；实际吞吐提升来自“能装更多活跃序列并持续批处理”，不是 Attention 数学复杂度改变。

### 面试简答版

PagedAttention 把每个请求的逻辑 KV 序列切成固定 token block，用 block table 映射到任意物理显存块。请求增长时按需从 free list 取块，结束后立即归还，因此不必按最大输出预留连续空间，消除了外部碎片，内部浪费最多是最后一个未满块。共享前缀/beam 可引用同一物理块并用 copy-on-write 分叉。代价是页表元数据、间接寻址和专用 kernel；它不降低 Attention FLOPs，而是提高 KV 容量利用率与 continuous batching 并发。
