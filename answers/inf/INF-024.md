> **问题：** Medusa、EAGLE 等多 token 推测方法与双模型投机解码有什么区别？

## 我的答案

传统双模型投机解码用一个独立小语言模型逐 token 起草；Medusa 和 EAGLE 则把 draft 能力附着在 target 模型的 hidden states/轻量模块上，避免维护完整第二模型。它们都仍需要 target 验证，区别主要在“候选从哪里来、是否自回归、候选是链还是树、需要怎样训练”。

### 双模型 Speculative Decoding

```text
small draft LM q 自回归生成一条长度 γ 的链
→ large target LM p 并行验证
→ exact acceptance + residual sampling
```

优点是可直接组合已有 target 与 draft，不修改 target 架构；理论修正可严格保持 target sampling 分布。缺点是两份权重/KV、两个服务版本和 draft 的串行 $\gamma$ 步。Draft 必须足够快且与 target 接近。

### Medusa：多个未来 token heads

[Medusa](https://arxiv.org/abs/2401.10774)在 target 最后一层 hidden state 上增加多个轻量 decoding heads：head 1 预测下一个 token，head 2/3/... 预测更远的 future tokens。一次 target step 可并行给出多个位置的候选，而不是再跑一个完整小 Transformer。

因为各 future head 从当前状态并行预测，后面的预测未完整条件于前面实际采到的 token，单链准确率会下降。Medusa 从各 head 的 top candidates 组合出候选 tree，再用 tree attention 把多个分支打包，让 target 一次验证多条路径的共享前缀。

优点：额外参数和显存较小，无独立 draft 服务；缺点：要为特定 target 训练 heads，tree 构建/Attention/KV 管理复杂，候选分支太多会指数膨胀。Medusa-1 可冻结 backbone 只训 heads；联合微调可提高 draft 质量但有改变 target 能力的风险。

Medusa 的 exact/lossless acceptance 配置可保持原目标行为；其 typical acceptance 等宽松策略会提高接受率但属于近似质量—速度折中，不能一概称为严格同分布。

### EAGLE：在 feature 层自回归起草

[EAGLE](https://arxiv.org/abs/2401.15077)认为 target 的高层 feature 比离散 token 更容易预测，于是训练轻量 draft module 自回归外推 target 的倒数第二层特征，再经 target LM Head 得到候选 token。

单纯预测下一 feature 存在不确定性：同一当前 feature 之后可能采到不同 token，而 token 会影响下一状态。EAGLE 将“向前错一位的已采样 token信息”与 feature 一起作为条件，降低 feature prediction uncertainty。

它比 Medusa 的独立 future heads 更具自回归依赖，候选通常也可扩展成 tree并由 target tree verification；轻量 feature predictor 比完整 draft LM 小，同时复用 target 的 embedding/LM head/feature空间。代价是需要访问 target 中间特征、为每个模型训练适配模块，并对推理引擎做更深集成。

### 核心对比

| 维度 | 双模型 | Medusa | EAGLE |
|---|---|---|---|
| Draft 来源 | 独立小 LM | target hidden 上多个 future heads | 轻量模块自回归预测高层 feature |
| 候选依赖 | 完整 draft 自回归 | future heads 近似并行，树组合 | feature-level 自回归 + token 条件 |
| 额外权重 | 一整套小模型 | 多个小 heads | 轻量 feature predictor |
| 训练要求 | 可直接用现成 draft，蒸馏更佳 | 为 target 训练 heads | 为 target 训练 feature module |
| 系统复杂度 | 双模型/KV/调度 | tree attention/多 heads | 中间 feature + tree verification |
| 严格分布 | exact residual 可保证 | 取决于 acceptance 方案 | exact target verification 可保证 |

### Tree Verification 为什么有用

多个候选序列共享前缀。把所有 tree nodes 放进一个 packed 序列，并用 tree causal mask 让节点只看到祖先，target 可在一次 forward 中验证多条分支；而不是每条分支单独跑 target。接受后只保留被选路径的 KV，其他节点释放。

Tree 宽度、深度和每个 head top-k 共同决定 verification token 数。过宽会让 target 计算、显存和调度成本超过接受收益，因此需按最近命中率剪枝。

### 选择边界

- 已有同词表高质量小模型、希望少改 target：双模型；
- 不想部署第二模型、可训练少量 heads：Medusa；
- 愿意深度集成 target feature、追求更高 draft 准确率：EAGLE 类；
- 模型频繁更新：附加 heads/module 也要重新训练和版本绑定；
- 高并发服务：额外候选 tokens 可能挤占 continuous batch，需端到端压测。

### 面试简答版

双模型投机用独立小 LM 自回归起草一条链，target 并行验证，部署两套权重/KV但无需改 target。Medusa 在 target hidden 上加多个 future-token heads，一次并行提出多位置候选并组成树，用 tree attention 验证，额外参数小但后续 heads 未完整条件于前 token。EAGLE 则用轻量模块在倒数第二层 feature 空间自回归预测，并加入前移 token 消除 feature uncertainty，通常 draft 更准但集成更深。三者都要 target 验证；只有采用 exact acceptance/residual 时才严格保持 target 分布，宽松 typical acceptance 是近似方案。
