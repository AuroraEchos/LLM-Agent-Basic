> **问题：** Repetition Penalty、Frequency Penalty 和 Presence Penalty 如何影响生成？

## 我的答案

三者都根据历史生成 token 修改下一步 logits，但惩罚函数不同：Repetition Penalty 通常对“出现过的 token”做乘除缩放；Presence Penalty 只关心是否出现过；Frequency Penalty 随出现次数线性增加。

设 token $i$ 在统计窗口内出现次数为 $c_i$。

### Repetition Penalty

一种广泛使用的 sign-aware 定义，惩罚系数 $r>1$：

$$
z_i'=\begin{cases}
z_i/r,&c_i>0,\ z_i>0\\
z_i\cdot r,&c_i>0,\ z_i<0\\
z_i,&c_i=0
\end{cases}
$$

正 logit 被缩小，负 logit 变得更负，从而降低已出现 token 的概率。之所以不能对所有 logits 直接除 $r$，是因为负数除以 $r$ 会更接近 0，反而提高概率。

有的实现允许 $r<1$ 鼓励重复，有的公式、统计 prompt 范围或 token 处理方式不同。“repetition penalty=1”通常表示关闭，但 API 需要核对。

### Presence Penalty

$$
z_i'=z_i-\alpha_p\mathbf1[c_i>0]
$$

只要出现过就减固定值，不论一次还是十次。正 $\alpha_p$ 鼓励引入尚未出现的 token/主题，适合提高词汇与内容覆盖；负值会鼓励沿用已出现 token。

### Frequency Penalty

$$
z_i'=z_i-\alpha_f c_i
$$

重复次数越多，惩罚越大，更针对“哈哈哈哈”、句子循环和高频口头禅。正值抑制重复，负值鼓励重复。

Presence 与 Frequency 可叠加：

$$
z_i'=z_i-\alpha_p\mathbf1[c_i>0]-\alpha_fc_i
$$

前者是第一次重复就收固定税，后者是每重复一次继续加税。

### Token 级惩罚的副作用

模型词表是子词而不是词。惩罚一个已出现 token 可能影响：

- 中文常用字和英文空格前缀，导致句子不自然；
- 人名、代码变量、JSON key 必须重复却被压低；
- 固定短语由不同 tokenization 组合，仍可能绕过；
- 同一单词大小写/空格形式是不同 token，惩罚不一致；
- EOS 若被错误惩罚，模型不愿结束。

所以惩罚过大会引发同义词乱换、事实实体漂移、语法破碎或无法闭合结构。代码、SQL、数学和工具调用通常需要精确复用标识符，应少用或关闭，改用 grammar/schema。

### 统计窗口与 Prompt

可统计：仅已生成内容、prompt+生成内容、最近 $W$ tokens 或整个上下文。统计 prompt 能避免模型复述用户，但也可能阻止正确引用问题中的实体。长输出用有限窗口可让早期 token 恢复，但无法阻止跨窗口长周期循环。

应排除或单独处理 BOS/PAD、必要分隔符、JSON 标点、代码缩进等 token。对话轮次中是否跨轮累计也要明确。

### 与其他方法的关系

- `no_repeat_ngram` 是硬约束：一旦形成已见 n-gram 就把候选设为 $-\infty$，比软惩罚激进；
- top-p/temperature 在惩罚后对新分布采样，惩罚会改变候选集合；
- 训练数据、prompt 与停止规则错误造成的循环，不能只靠解码参数根治；
- 检测到完整片段循环时，可做序列级检测/停止或回退，而非只罚单 token。

### 调参和评估

从无惩罚开始，逐步小幅增加，分任务统计 distinct-n、重复 n-gram 率、实体一致性、事实/执行正确率和格式合法率。不要只看“重复少了”：如果输出用大量不准确同义词避开重复，质量实际上下降。

### 面试简答版

Presence Penalty 是已出现 token 一次性减 $\alpha_p$，鼓励引入新内容；Frequency Penalty 按出现次数减 $\alpha_fc_i$，重复越多罚越重；常见 Repetition Penalty 对出现过的正 logit 除以 $r$、负 logit 乘 $r$，用 sign-aware 缩放降低其概率。它们都在 token 级工作，可能误伤必须重复的人名、代码变量和 JSON key；还要明确是否统计 prompt、窗口多长和是否排除特殊 token。结构化/代码任务优先用 grammar，重复惩罚应小幅调并同时评估实体与执行正确性。
