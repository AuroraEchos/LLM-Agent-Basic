## 我的答案

这些指标分别描述“多久看到第一个 token”“之后流得是否顺”“一共多久完成”和“系统单位时间处理多少工作”。首先必须统一计时边界：从客户端发请求、网关入队还是 GPU scheduler 接收开始；token 是服务端生成还是客户端收到。否则同名指标不可比较。

设请求到达时间为 $t_0$，客户端或服务端观察到第 $i$ 个输出 token 的时间为 $t_i$，输出 token 数为 $N$。

### TTFT：Time To First Token

$$
\operatorname{TTFT}=t_1-t_0
$$

通常包含：排队、请求解析/tokenization、prefix cache lookup、Prefill、首 token logits/sampling，以及定义为客户端口径时的网络传输。近似分解：

$$
TTFT=T_{queue}+T_{preprocess}+T_{prefill}+T_{first\ sample}+T_{network}
$$

TTFT 对 prompt 长度、Prefill batch/chunk、排队和 prefix cache 命中很敏感。只测 GPU Prefill kernel 不能代表用户 TTFT。

### ITL：Inter-Token Latency

对第 $i$ 个 token：

$$
\operatorname{ITL}_i=t_i-t_{i-1},\qquad i\ge2
$$

它是一组分布而非单个数。流式体验尤其受 P95/P99 ITL 和最大停顿影响；均值很好但偶尔 2 秒 stall，用户仍会觉得卡顿。Chunked prefill、GC、网络 flush 和调度抢占都会制造尾部尖峰。

### TPOT：Time Per Output Token

常见定义之一是首 token 之后的平均 token 间隔：

$$
\operatorname{TPOT}
=\frac{t_N-t_1}{N-1},\qquad N>1
$$

即平均 ITL。也有系统把“总 decode 时间/输出 token 数”或“端到端时间/输出 token 数”称为 TPOT。后两种会把首 token/Prefill 混进去，语义不同。因此报告时必须给公式，并单独处理 $N=1$ 请求。

TPOT 常被换算为单请求生成速率 $1/TPOT$，但这不是服务全局 output tokens/s：多个请求可并行 Decode。

### 端到端延迟 E2E

$$
\operatorname{E2E}=t_N-t_0
$$

若使用上述服务端定义：

$$
E2E=TTFT+\sum_{i=2}^{N}ITL_i
\approx TTFT+(N-1)TPOT
$$

还应区分正常 EOS、达到 max tokens、超时和客户端取消；截短请求的低 E2E 不代表服务质量高。

### 吞吐量

吞吐可有多个口径：

- requests/s：单位时间完成的请求；
- input tokens/s：Prefill token 吞吐；
- output tokens/s：已确认生成 token 吞吐；
- total tokens/s：输入+输出，但两类计算成本不同，求和可能掩盖负载变化；
- goodput：在 TTFT/TPOT/E2E SLO 内完成的有效请求或 token/s。

$$
\operatorname{goodput}
=\frac{\#\{\text{满足全部 SLO 的请求}\}}{\text{时间}}
$$

离线最大 tokens/s 往往通过大 batch 获得，却可能让在线 TTFT/TPOT 超标。因此容量规划应画 throughput–latency 曲线，并报告达到目标 SLO 时的最大 goodput。

### 统计方法

- 按 prompt/output 长度、模型、租户和 cache hit 分桶；
- 同时报 median、P90/P95/P99，不只平均；
- 使用足够长的稳态窗口，区分 warmup 与过载；
- 使用真实到达过程，而非只在 closed-loop 中等待上个请求完成；
- 客户端和服务端同时打点，拆出网络/网关；
- token streaming 需明确 buffering 与 flush 粒度。

### 面试简答版

TTFT 是请求到首 token 的时间，包含排队和 Prefill；ITL 是相邻输出 token 的间隔，是需要看 P99 的分布；TPOT 常定义为 $(t_N-t_1)/(N-1)$，即首 token后的平均 ITL，但不同系统口径不一必须写公式；端到端延迟是 $t_N-t_0=TTFT+\sum ITL$。吞吐要区分 requests/s、input/output tokens/s，线上更应看满足 TTFT/TPOT SLO 的 goodput。所有指标都要说明客户端/服务端计时边界并按长度和 cache 命中分桶。
