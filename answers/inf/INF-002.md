> **问题：** KV Cache 为什么能够降低自回归解码的重复计算？

> **分类：** 推理与部署

## 我的答案

KV Cache 利用了 causal self-attention 的一个性质：生成新 token 时，历史 token 在每一层计算出的 Key 和 Value 不会因未来 token 到来而改变，因此可以保存并复用；新一步只计算新 token 的 Q/K/V，而不必重新对整个前缀做 forward。

### 单层过程

历史长度为 $t$ 时，缓存：

$$
K_{1:t},V_{1:t}
$$

新 token $x_{t+1}$ 到来，在某层只计算：

$$
q_{t+1}=h_{t+1}W_Q,quad
k_{t+1}=h_{t+1}W_K,quad
v_{t+1}=h_{t+1}W_V
$$

把新 K/V 追加：

$$
K_{1:t+1}=[K_{1:t};k_{t+1}],\qquad
V_{1:t+1}=[V_{1:t};v_{t+1}]
$$

新 query 的 Attention 为：

$$
o_{t+1}=\operatorname{softmax}
\left(\frac{q_{t+1}K_{1:t+1}^{\top}}{\sqrt{d_h}}
\right)V_{1:t+1}
$$

只需要新位置的输出，因为历史位置的 logits 不会再用于生成下一 token。

### 节省了哪些重复计算

若不用 cache，为生成第 $t+1$ token，必须把长度 $t+1$ 的整个序列重新送进所有层，重复历史 token 的 QKV 投影、Attention、FFN 和 Norm。生成多个 token 时，同一前缀会被一遍遍重算。

使用 cache 后：

- 每层历史 K/V 投影只算一次；
- 历史 token 的 FFN、Norm 和层间 hidden states 不再重算；
- 每个 decode step 只做一个新 token 的 dense model 计算；
- 仍需让新 query 与所有保留的历史 K/V 做 Attention。

因此对单个 decode step，历史部分的计算从“重新处理 $t$ 个 token”降为“读取 $t$ 个 KV 并做一次新 query Attention”。它没有把长上下文 Attention 变成 $O(1)$：单步仍是 $O(t)$，生成 $T$ 个 token 的 Attention 总量包含 $O(ST+T^2)$。

### 代价：用显存和带宽换 FLOPs

每一层、每个历史 token 都保存 K 和 V，cache 容量随 batch 和上下文线性增长。Decode 每步还要从 HBM 读取历史 cache，因此长上下文常从计算瓶颈转为 KV 容量/带宽瓶颈。GQA/MQA、KV 量化、分页管理和滑动窗口就是在优化这一代价。

### 为什么通常不缓存 Q

历史 query 只用于产生历史位置的输出，未来 token 不会再查询“历史 Q”；未来计算需要的是新 Q 与历史 K/V，所以缓存 K/V 足够。某些特定架构可能缓存其他 latent，但标准 Attention 不需要 Q cache。

### 何时缓存失效

Cache 与以下内容绑定：

- 精确 token 前缀及顺序；
- 模型权重、adapter 和量化版本；
- position IDs/RoPE 配置；
- Attention mask、模态输入和部分运行配置。

修改前缀中任意 token 后，其后所有层的 hidden/K/V 都可能变化，只能复用最长完全相同前缀。多轮聊天若模板增加在尾部，可复用旧前缀；若重写 system prompt 或截断中间历史，则要失效/重算。跨用户 prefix cache 还要防止权限与隐私泄漏。

### 训练时为什么不依赖它

Teacher forcing 训练能并行计算整段所有位置，并需要所有 token 的梯度；KV Cache 会破坏这种并行并占用额外长期状态。它主要服务于无梯度的自回归推理。流式训练/超长序列的特殊算法可能保存状态，但不等同于常规推理 cache。

### 面试简答版

Causal Attention 中历史 token 的 K/V 在未来 token 到来后不会改变，所以 Prefill 后按层缓存它们。Decode 新一步只计算新 token 的 Q/K/V，把新 K/V 追加，并用新 Q 读取历史 K/V；这样避免反复计算整个前缀的投影、FFN 和 hidden states。代价是 cache 显存随层数、batch、长度线性增长，且单步仍要读取全部历史 KV，Attention 仍为 $O(S)$。Q 不必缓存，因为未来只会使用新 query。任何前缀、模型、位置或 mask 变化都可能使相应 cache 失效。
