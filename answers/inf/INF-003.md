## 我的答案

标准 MHA/GQA/MQA 的 KV Cache 主体公式是：

$$
M_{KV}=2\cdot B\cdot S\cdot L\cdot n_{kv}\cdot d_h\cdot b
$$

其中：

- 2：Key 和 Value 两份；
- $B$：并发序列数，包括 beam 展开后的有效 batch；
- $S$：每条序列已缓存 token 数，等于 prompt 加已生成 token；
- $L$：Transformer 层数；
- $n_{kv}$：每层 KV head 数；
- $d_h$：每个 head 的维度；
- $b$：每元素字节数，如 FP32=4、FP16/BF16=2、INT8/FP8约=1、INT4 主体约=0.5。

结果单位是 bytes。若各请求长度不同，更准确写为：

$$
M_{KV}=2L n_{kv}d_hb\sum_{i=1}^{B}S_i
$$

Paged KV 管理可接近按真实 token 分配；静态连续 buffer 常按 $B\cdot S_{max}$ 预留，内部碎片更大。

### 例子

一个 32 层 GQA 模型，$n_{kv}=8$、$d_h=128$，单请求长度 4096，BF16：

$$
M=2\times1\times4096\times32\times8\times128\times2
=536{,}870{,}912\text{ bytes}
=512\text{ MiB}
$$

每增加一个 token 的 cache 为：

$$
2\times32\times8\times128\times2
=131{,}072\text{ bytes}=128\text{ KiB}
$$

若 16 个请求都达到 4096 token，仅 cache 主体就是 8 GiB。若使用 beam width 4 且不能共享 prefix blocks，逻辑 batch 还会再扩大 4 倍。

### Tensor Parallel 下每卡大小

如果 KV heads 沿 TP 维均匀分片，理想每卡约为：

$$
M_{KV,rank}\approx M_{KV}/N_{TP}
$$

但当 $n_{kv}<N_{TP}$ 时，某些系统会复制 KV heads 而不是继续切 head，不能再按 TP 度等比例下降。Context/sequence parallel、PD 分离和 cache transfer 也会改变每设备驻留方式。应查看推理引擎的实际 layout。

### 量化 Cache 的附加开销

INT8/INT4 不只是把 $b$ 改小。还需保存 scale，非对称量化还可能有 zero point：

$$
M_{total}=M_{quantized\ values}+M_{scale}+M_{zero\ point}+M_{metadata}
$$

scale 粒度越细（per-token/per-head/per-channel/group），精度通常越好，元数据比例越高。INT4 还可能因打包对齐不能达到精确 4 倍压缩。

### 系统层额外内存

- 分页 block 未填满造成的内部碎片；
- page table、block ID、sequence metadata；
- prefix cache 引用计数和 copy-on-write；
- CUDA graph 预留、临时 Attention workspace；
- beam search parent mapping；
- allocator reserved memory 和安全余量。

容量规划应使用：

$$
M_{available\ for\ KV}
=M_{GPU}-M_{weights}-M_{runtime}-M_{workspace}-M_{margin}
$$

再除以每 token cache bytes 得到理论 token capacity，并通过实际请求长度分布和碎片率压测。

### MLA 等架构的例外

MLA 缓存的是低维 latent 和可能单独的 positional/RoPE 分量，不应强行用 $n_{kv}d_h$ 公式；应按它实际持久化的每 token 向量维度 $d_{cache}$ 计算：

$$
M\approx BSLd_{cache}b
$$

是否有两份、scale 和额外分量由具体结构决定。

### 面试简答版

标准 Attention 的 KV Cache 是 $2BSLn_{kv}d_hb$ bytes，2 代表 K/V；变长批次应把 $BS$ 换成 $\sum_iS_i$。例如 32 层、8 个 KV 头、head dim 128、4096 token 的单请求 BF16 cache 是 512 MiB，每新 token 128 KiB。还要考虑 beam、TP 是否真分片 KV、分页碎片、元数据和量化 scale；INT4 不一定精确省 4 倍。最终用显存减权重/runtime/workspace 后的余额除以每 token bytes，并按真实长度分布压测。
