> **问题：** Temperature 如何改变概率分布，设为 0 在工程实现中通常表示什么？
>
> **分类：** 推理、解码与 KV Cache

## 我的答案

Temperature $T$ 在 softmax 前缩放 logits：

$$
p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)},\qquad T>0
$$

它不改变正温度下 logits 的排序，但改变概率差距。两个 token 的概率比为：

$$
\frac{p_i(T)}{p_j(T)}
=\exp\left(\frac{z_i-z_j}{T}\right)
$$

因此 $T<1$ 放大 logit 差，分布更尖锐；$T>1$ 缩小差距，分布更平坦。

### 极限与直觉

- $T\to0^+$：概率集中到最大 logit；若多个 token 并列最大，极限质量在它们之间分配，具体实现可能按 tie-break 选一个；
- $T=1$：原始模型 softmax；
- $T\to\infty$：所有未 mask、有限 logit 的 token 趋近均匀；
- $T<0$ 通常无有效生成语义，会反转偏好，API 应拒绝。

例如 logits `[2, 1, 0]`：低温时第一个 token 概率显著上升，高温时三个概率接近。Temperature 不会把原本 top-2 的 token变成 top-1；它改变的是采样概率，不是排序。

### `temperature=0` 不是直接除以 0

公式只对 $T>0$ 定义。工程 API 中 `temperature=0` 通常是一个 sentinel，表示关闭随机采样并走 greedy argmax：

```python
if temperature == 0:
    next_token = argmax(processed_logits)
else:
    probs = softmax(processed_logits / temperature)
    next_token = multinomial(probs)
```

具体接口也可能要求同时设置 `do_sample=false`，或者不允许 0。不能把所有框架的 `0` 语义视为标准；应查接口并记录实际 decoding configuration。

### “0 温度”也未必逐位确定

Greedy 只移除 multinomial 随机性，仍可能因以下原因产生差异：

- GPU reduction/低精度导致非常接近的 logits 排序变化；
- 不同模型、量化、kernel 或并行拓扑；
- prompt 模板、Tokenizer 或 system 内容变化；
- 并列 argmax 的 tie-breaking；
- 服务端仍启用了其他随机/动态处理或模型本身含未关闭 dropout。

所以“temperature=0 保证任何环境完全一致”是错误表述。

### 与 Top-K/Top-P 的组合

典型流程先应用 hard constraints、bad words、重复惩罚等 logits processors，再做 temperature scaling 与 top-k/top-p 过滤，最后归一化采样。不同库的确切顺序可能不同，而 top-p 的候选集合依赖缩放后的概率，因此温度与 top-p 不是独立旋钮。

低温 + 很小 top-p 可能几乎退化成 greedy；高温会把尾部抬高，再由 top-p 截断出更大候选集。参数应联合评测，而不是分别解释后简单叠加。

### 对质量的影响

低温通常更稳定、一致，但可能重复、模式化并放大模型最偏好的错误；高温增加新颖性和多样性，也增加事实错误、格式破坏和低概率 token 风险。任务建议：

- JSON、工具调用、抽取：0/低温 + grammar/schema；
- 普通问答：较低到中等温度并做事实验证；
- 创作/头脑风暴：较高温度配 top-p；
- self-consistency：用非零温度产生真正不同推理，再投票/验证。

不存在跨模型通用的最佳数值，因为 logit 校准和词表不同。应在目标任务上测准确率、格式合法率、多样性、重复率和成本。

### 面试简答版

Temperature 用 $z_i/T$ 做 softmax；$T<1$ 放大 logit 差让分布更尖，$T>1$ 让分布更平，正温度不改变 token 排序。数学上 $T=0$ 未定义，工程接口通常把它当作 greedy argmax 的特殊开关，而不是真的除以 0；有些框架还需 `do_sample=false`。Greedy 也不保证跨硬件逐位一致。Temperature 会影响 top-p 的候选集合，应联合调参：结构化输出用 0/低温配 grammar，开放创作可提高温度并用 top-p 控制尾部。
