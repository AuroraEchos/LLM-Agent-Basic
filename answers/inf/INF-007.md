## 我的答案

KV Cache 只能复用**token 级最长公共前缀**。多轮对话看起来只是“追加一轮”，但 chat template、空白、工具 schema 或历史裁剪只要改变了前面的任何 token，变化位置之后的 cache 就无效。

### 理想的追加式复用

第 $r$ 轮已完成的规范序列为：

```text
P_old = system + user1 + assistant1 + ... + assistant_r + end_marker
```

新一轮构造：

```text
P_new = P_old + user_(r+1) + assistant_start
```

若 `P_old` 的 token IDs、position IDs 和模型状态完全不变，可保留旧 cache，只 Prefill 新追加部分，然后继续 Decode。这是会话 KV 复用最可靠的情况。

### 必须以重新序列化后的 token 为准

不能假设“消息对象没变，所以前缀相同”。每轮都用同一个版本化模板把完整消息历史重新渲染和 tokenize，再与 cache 元数据中的 token IDs 比较：

$$
P=\operatorname{LCP}(ids_{cached},ids_{new})
$$

只复用前 $P$ 个 token 对应的完整 cache blocks；从第一个不匹配 token 开始重算。若引擎按 16-token block 缓存，实际安全复用长度通常向下对齐到完整 block，除非支持部分 block 校验。

### 常见失效来源

- chat template 升级，角色标记、换行或 BOS/EOS 改变；
- system prompt、few-shot、工具定义或工具顺序变化；
- Tokenizer/normalization/added tokens 版本变化；
- 历史摘要替换原对话，或从中间删除消息；
- context window 超限后采用 left truncation；
- 图片、音频 embedding 或检索文档内容变化；
- 模型权重、LoRA、adapter、量化或 RoPE 配置变化；
- position IDs、sliding-window 状态或 attention mask 不同。

采样 temperature/top-p 不改变已经给定前缀的 K/V，可以继续复用；但若前一轮 assistant 输出因采样不同而改变，它已经成为下一轮前缀的一部分，token 自然不同。

### 模板变更如何上线

给 template 和 tokenizer 分配不可变版本，并把版本放入 cache namespace。部署新模板时：

1. 新请求写入新 namespace；
2. 旧会话可固定旧模板继续，或完整重算迁移到新模板；
3. 不要把旧 KV 与新模板 suffix 直接拼接；
4. 等旧会话/TTL 结束后回收旧 namespace。

这比试图判断一次文本模板修改是否“语义等价”安全，因为 KV 只关心精确数值前缀。

### 历史裁剪和摘要

若删除最早消息，剩余 token 虽文本相同，其绝对位置和因果历史都变了，标准全局 Attention 下不能把旧 cache 简单左移后复用。应对新的“system + summary + retained turns”重新 Prefill。

若架构原生支持滑动窗口，窗口外 token 按定义不可见，仍需依照引擎对 position/RoPE 和 layer cache 的规则处理；“已被窗口淘汰”不自动意味着任意重编号等价。

可在上下文接近上限时提前异步生成摘要并建立新 cache，减少用户下一轮的阻塞，但新旧 cache 必须是两条明确分支。

### Prefix Tree 与分支会话

编辑上一条消息、重新生成回答或对话分叉时，用 radix tree 保存公共 block：分叉点之前共享只读 blocks，之后 copy-on-write。需要保存：

- token block hash/内容校验；
- parent chain 和有效 token 长度；
- model/template/adapter namespace；
- position range、引用计数和最后访问时间。

哈希命中后最好仍校验 token 内容或使用足够强的内容寻址，不能让碰撞复用错误 KV。

### 一致性与隐私测试

在关闭采样或固定随机种子时，比较“全量重新 Prefill”与“复用 LCP cache”的首 token logits/输出，应在数值容差内一致。测试模板空格、工具增删、历史编辑、截断、adapter 切换和跨租户访问。Cache miss 只应损失性能，绝不能改变语义正确性或返回其他用户状态。

### 面试简答版

多轮 KV 复用的判据是重新套用版本化 chat template 并 tokenize 后的最长公共 token 前缀，而不是消息对象看起来相同。旧历史纯追加时只 Prefill suffix；从首个不匹配 token起必须重算。模板、system、工具 schema、Tokenizer、adapter、position 或历史裁剪变化都会失效；left truncation 后不能简单左移旧 cache。模板升级用独立 cache namespace，分支对话用 radix tree 和 copy-on-write 共享分叉前 blocks，并用全量重算对照测试 logits。跨租户缓存必须权限隔离。
