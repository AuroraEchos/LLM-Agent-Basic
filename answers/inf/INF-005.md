> **问题：** KV Cache 量化、滑动窗口和 Token Eviction 各有什么质量与效率代价？

## 我的答案

三种方法从不同维度减少 KV 成本：量化降低每个缓存元素的位宽；滑动窗口只保留最近固定长度；Token Eviction 根据策略选择性丢弃历史 token。前者近似保留全部位置但引入数值误差，后两者直接减少可访问历史，质量风险通常更结构化且不可逆。

### KV Cache 量化

把 FP16/BF16 的 K/V 转为 INT8、FP8、INT4 等：

$$
q=\operatorname{clip}\left(\operatorname{round}(x/s)+zight),qquad
\hat x=s(q-z)
$$

理论主体显存从 2 bytes/element 降至 1 或 0.5 bytes，同时减少 Decode 读取带宽、提高并发。代价包括：

- 反量化和 scale 读取的额外 kernel/FLOPs；
- 量化误差改变 $qK^T$ 和 $\operatorname{softmax}(\cdot)V$；
- per-tensor scale 便宜但受 outlier 支配，per-head/channel/token 更准但元数据和计算更多；
- K 的误差会改变注意力分布，V 的误差直接污染聚合内容，两者最佳位宽/粒度未必相同；
- cache 越长、检索越精细，微小误差越可能影响关键 token 排名。

还要区分量化“已缓存旧块”和最新 token 的 residual cache：可让最近一小段保留高精度，旧块再量化，降低实时量化开销和近邻质量损失。

### 滑动窗口

每个 token 只关注最近 $W$ 个位置：

$$
\mathcal A_t=\{\max(0,t-W+1),\ldots,t\}
$$

Cache 从随总长度 $S$ 增长变为每层最多 $O(W)$，单步 Attention 读取也有上界。若模型训练时就是 sliding-window/local attention，这属于架构定义，质量已在训练中适应；部分层还可使用全局 Attention 传播远程信息。

若对一个训练为全局 Attention 的模型在部署时突然截成窗口，超出窗口的 system 指令、早期实体、文档证据会彻底不可见，属于 train–serve mismatch。窗口滚动还要正确维护绝对 position/RoPE，不能简单把保留 token 的位置全部重编号。

### Token Eviction

Eviction 不一定只保留最近 token，而是从历史中挑选预算 $K$：

- recency：最近 token；
- attention score/heavy hitters：历史上累计受关注的 token；
- attention sink + recent：保留开头少量 sink 和最近窗口；
- 分层/池化：对旧 token 下采样或摘要；
- 任务感知：保留 system、检索证据、工具结果或特殊 token。

它可在同样容量下比纯窗口保留更多远程关键信息，但风险是选择依据来自过去 attention，未必预测未来需要。一个早期数字过去从未被关注，最终问题才需要它；一旦 K/V 被丢弃，之后无法凭 cache 恢复。

Eviction 还可能在各层选择不同 token，带来稀疏索引、非连续内存和 kernel 效率问题。若为了规则内存而频繁搬移 cache，节省的带宽可能被 gather/scatter 抵消。

### 三者比较

| 方法 | 容量变化 | 主要质量风险 | 系统特点 |
|---|---|---|---|
| KV 量化 | 每元素变小，位置全保留 | 数值误差 | 需 scale/反量化和专用 kernel |
| 滑动窗口 | 只保留最近 $W$ | 固定丢失远程上下文 | 规则、容量和单步成本可预测 |
| Token Eviction | 选择性保留 $K$ | 错删未来关键 token | 策略灵活，但索引和 kernel 更复杂 |

三者可以组合，例如旧 KV INT4 + 最近窗口 BF16 + 少量全局 sink，但组合误差必须端到端评估。

### 如何评估

- 显存/每 token bytes、最大并发、TPOT 和总吞吐；
- 长上下文 retrieval/needle、早期 system 指令保持；
- 多轮实体一致性、代码/数学精确复制、长文档 QA；
- 不同长度、层、head 和量化位宽的质量曲线；
- eviction 命中率：最终被引用的证据是否仍在 cache；
- P99 延迟和分页/碎片，而不只平均 kernel 时间。

如果原始文本仍可访问，错删后理论上可重新 Prefill 恢复 cache，但这会产生大的 TTFT/计算开销；实时系统不能把它当作免费回退。

### 面试简答版

KV 量化把 BF16/FP16 cache 降到 INT8/INT4，保留所有位置并省容量/带宽，但加入 scale、反量化和 Attention 数值误差；滑动窗口把 cache 和单步 Attention 限制为最近 $W$，成本最可预测，但全局模型部署时硬截会丢远程指令和证据；Token Eviction 按 recency、heavy-hitter、sink 或任务规则保留预算，可能比窗口更聪明，却可能错删未来才需要的 token，且稀疏索引影响 kernel。应联合比较并发、TPOT 与长上下文检索/复制质量，不能只看显存压缩倍数。
