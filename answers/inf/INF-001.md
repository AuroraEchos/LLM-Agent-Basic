> **问题：** Prefill 与 Decode 两个阶段的计算特征和性能瓶颈有什么不同？
>
> **分类：** 推理与部署
>
> **来源：** [CORE_INTERVIEW_QUESTIONS.md](../../CORE_INTERVIEW_QUESTIONS.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

自回归推理分为：Prefill 一次处理完整输入 prompt，产生首个输出 logits 并建立每层 KV Cache；Decode 之后每一步只输入最新 token，读取已有 KV Cache 并追加一个 K/V，直到停止。两阶段运行的是同一模型，但矩阵形状和主要瓶颈差异很大。

### Prefill：多 token 并行，通常更偏计算密集

设 prompt 长度为 $S$。每层可以同时对 $S$ 个 token 做 Q/K/V、FFN 和 LM Head 计算，大矩阵乘法形如：

$$
[BS,H]\times[H,H]
$$

权重从 HBM 读取一次后可被许多 token 复用，算术强度高，Tensor Core 更容易跑满，因此中短上下文 Prefill 常是 compute-bound。

标准 Attention 还要计算 $S\times S$ 的 causal 注意力，FLOPs 随 $O(S^2H)$ 增长；长上下文时 Attention 计算、临时激活和 HBM I/O 会成为显著瓶颈。FlashAttention 通过分块避免物化完整 $S^2$ 矩阵，但不能消除必要的注意力计算量。

Prefill 的用户指标主要是 TTFT（Time To First Token）。长 prompt、排队、tokenization、prefix cache 是否命中和 chunked prefill 调度都会影响它。

### Decode：单 token 串行，通常更偏带宽和延迟

有 KV Cache 时，每个请求每步只有一个 query token。线性层形状近似：

$$
[B,1,H]\times[H,H]
$$

单请求或小 batch 下，每一步都要读取大量模型权重，却只做少量 token 计算，权重复用低，算术强度小，常是 memory-bandwidth-bound。每层还要读取随上下文增长的 K/V Cache；长 context 下 KV 带宽和容量也会主导。

Decode 存在严格自回归依赖：第 $t+1$ token 必须等第 $t$ token 采样完成，不能像 Prefill 一样沿时间维并行。Continuous batching 可把多个请求同一步合并，提高权重重用和吞吐，但 batch 太大又会增加排队与 TPOT。

Decode 的关键指标是 TPOT/ITL（每输出 token 时间/相邻 token 延迟）和 output tokens/s，而不是 TTFT。

### 复杂度与 Roofline 直觉

| 阶段 | token 维度 | 权重复用 | Attention | 常见瓶颈 |
|---|---|---|---|---|
| Prefill | 一次 $S$ 个 | 高 | $O(S^2)$ | GEMM 算力；超长时 Attention/显存 I/O |
| Decode | 每步 1 个 | 低，小 batch 尤甚 | 新 query 读 $S$ 个 KV，单步 $O(S)$ | 权重/KV HBM 带宽、kernel/通信延迟 |

这不是绝对分类：超长 prefill 可能 memory-bound，足够大的 decode batch 也能提高算术强度并逐渐 compute-bound。模型大小、量化、GQA/MQA、并行拓扑和硬件都会移动边界。

### 服务系统中的相互干扰

大 Prefill 请求占用 GPU 很久，会阻塞等待 decode 的请求，造成 TPOT 尖峰；一味优先 decode 又会让新请求 TTFT 饥饿。常见方法包括 chunked prefill、iteration-level scheduling、prefill/decode 分离部署和分别设置 token budget。

优化方向也不同：

- Prefill：FlashAttention、大 GEMM、prefix cache、prompt 分块和 context parallel；
- Decode：权重/KV 量化、GQA/MQA、PagedAttention、continuous batching、投机解码；
- 两者都需优化 TP/PP 通信、调度和 kernel fusion。

### 面试简答版

Prefill 一次并行处理全部 prompt，建立 KV Cache；矩阵大、权重可跨 token 复用，通常算术强度高、偏 compute-bound，但长上下文 Attention 是 $O(S^2)$。Decode 每步只处理一个新 token并读取全部模型权重和历史 KV，时间维又必须串行，小 batch 下通常受 HBM 带宽和 kernel/通信延迟限制，单步 Attention 随上下文是 $O(S)$。Prefill 主要决定 TTFT，Decode 主要决定 TPOT；continuous batching、chunked prefill 和 PD 分离是在两类延迟与吞吐之间调度。
