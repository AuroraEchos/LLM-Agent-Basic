## 我的答案

服务吞吐由三类资源共同约束：Prefill/Decode 计算与带宽、每个活跃请求持有的 KV Cache，以及调度器能否把不同长度请求高效组成 batch。请求长度不是只影响一次计算，它还决定请求占用 KV 容量和 batch slot 的持续时间，因此长尾分布比平均长度更重要。

### 输入长度的影响

Prompt 长度为 $S_{in}$：

- Prefill dense projection/FFN 近似随 $O(S_{in})$ 增长；
- 全局 Attention FLOPs 随 $O(S_{in}^2)$ 增长；
- 建立的 KV Cache 随 $O(S_{in})$ 增长；
- 长 Prefill 若不分块，会阻塞 active decodes，拉高 TPOT。

所以少量 100K prompt 可支配总计算并造成队头阻塞。Prefix cache 命中能省共享前缀的 Prefill，但仍占用/引用相应 KV blocks，并不消除后续 Attention 读取。

### 输出长度的影响

输出为 $S_{out}$：

- 需要 $S_{out}$ 次串行 Decode；
- 每一步 context 逐渐变长，KV 读取量上升；
- 请求在整个生成期间占用 cache；
- 长输出让 batch slot 和显存迟迟不能释放。

因此同样总 token 数，“短 prompt + 很长输出”与“长 prompt + 短输出”的瓶颈不同：前者是持续 Decode/驻留，后者是突发 Prefill/TTFT。

### KV 容量形成 admission 上限

标准 cache 每 token bytes：

$$
m_{tok}=2Ln_{kv}d_hb
$$

活跃请求 $i$ 已缓存长度为 $S_i$ 时：

$$
M_{KV}=m_{tok}\sum_iS_i+M_{metadata/fragmentation}
$$

可用于 KV 的显存为总显存减模型权重、runtime/workspace 和余量。调度器必须为已运行请求的未来增长保留安全空间，否则中途 OOM。PagedAttention 减少预留与外部碎片，但物理 token capacity 仍有限。

超出容量时只能排队、拒绝、抢占并 swap/recompute，或降低每请求上限；频繁抢占会浪费已做的 Prefill。

### 并发数的三阶段

1. **低并发**：GPU 尤其 Decode 利用率低；增加请求可复用权重，global tokens/s 上升；
2. **有效 batching 区**：吞吐接近平台峰值，TTFT/TPOT仍满足 SLO；
3. **饱和/过载**：KV、计算或带宽达到上限，队列增长，延迟快速恶化，吞吐不再明显增加。

Little's Law 在稳态下给出：

$$
N_{in\ system}=\lambda W
$$

到达率 $\lambda$ 或平均驻留时间 $W$ 增大，系统中的并发请求增加，继而推高 KV 占用。长输出增大 $W$，即使 requests/s 不变也会造成更大并发。

### 长度方差与调度

- 静态 batching 被最长序列拖住，短请求 slot 闲置；
- continuous batching 可及时替换完成请求；
- chunked prefill 控制超长输入的单轮占用；
- length-aware batching 能减少 padding，但按估计输出长度分组可能不准；
- shortest-job-first 降低平均延迟，却可能饿死长请求；
- FCFS 公平但容易 head-of-line blocking；
- aging/deadline/租户配额用于平衡。

输出长度事先未知，可由请求 max_tokens、历史统计或小模型预测做 admission，但必须保守并允许动态调整。

### 提高吞吐的手段与代价

- GQA/MQA/MLA、KV 量化：增加 token capacity/降低带宽，需质量与 kernel验证；
- PagedAttention：降低碎片，不改变每 token 数学存储；
- continuous batching：提高 slot 利用率，过大 batch 会恶化 TPOT；
- prefix cache：降低重复 Prefill，受命中率和隐私边界限制；
- speculative decoding：减少 target 串行 steps，增加候选计算/显存；
- PD disaggregation：隔离两阶段干扰，增加 KV 传输和路由；
- admission control：保护 SLO，但会拒绝/排队更多请求。

### 容量评测

必须使用联合的 input/output 长度分布和真实到达率做 open-loop 压测，逐步提高 QPS，记录：goodput、TTFT/TPOT P99、KV block 使用率、preemption、队列长度和 OOM margin。用平均 1K/200 token 的固定请求无法预测 heavy-tail 生产负载。

### 面试简答版

长输入提高 Prefill 的线性 dense 计算和二次 Attention，并立即占 KV；长输出需要更多串行 Decode，且请求长期持有不断增长的 KV。总 cache 是 $m_{tok}\sum_iS_i$，显存容量给活跃并发设硬上限；并发从低到高会先提升 batching 和吞吐，饱和后队列与 P99 急升。Little's Law $N=\lambda W$ 说明长输出增大驻留时间就会提高系统并发。应使用 continuous batching、chunked prefill、分页 KV 和 admission control，并用真实长度长尾做 open-loop goodput 压测。
