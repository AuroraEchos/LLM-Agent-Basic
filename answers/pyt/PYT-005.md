## 我的答案

装饰器本质上是一个可调用对象变换：

```python
@decorator(config)
def target(...):
    ...

# 等价于
target = decorator(config)(target)
```

它接收函数（也可以接收类），返回原函数或一个新可调用对象。带参数装饰器多一层闭包，用于保存配置。多个装饰器按靠近函数的先应用，即 `@A @B def f` 等价于 `f = A(B(f))`。

### 1. 同时支持同步与异步的计时装饰器

不能用普通 `def wrapper` 调用异步函数后立刻计时，因为这只得到 coroutine 对象，真正执行尚未发生。应在装饰阶段检查，并分别生成包装器：

```python
import functools
import inspect
import time
from collections.abc import Callable
from typing import Any, ParamSpec, TypeVar, cast

P = ParamSpec("P")
R = TypeVar("R")

def timed(func: Callable[P, R]) -> Callable[P, R]:
    if inspect.iscoroutinefunction(func):
        @functools.wraps(func)
        async def async_wrapper(*args: P.args, **kwargs: P.kwargs):
            start = time.perf_counter()
            try:
                return await func(*args, **kwargs)  # type: ignore[misc]
            finally:
                record_latency(func.__qualname__, time.perf_counter() - start)
        return cast(Callable[P, R], async_wrapper)

    @functools.wraps(func)
    def sync_wrapper(*args: P.args, **kwargs: P.kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            record_latency(func.__qualname__, time.perf_counter() - start)
    return sync_wrapper
```

这里用 `time.perf_counter()` 测经过时间，并在 `finally` 中保证成功、失败、取消都记录。`functools.wraps` 保留 `__name__`、`__doc__`、`__wrapped__` 等元数据，便于调试、依赖注入和框架反射。示例中的 `record_latency` 应避免抛异常覆盖业务异常，也不要记录敏感参数。

### 2. 重试装饰器的关键语义

重试不是简单循环 N 次，至少要明确：

- 只重试白名单中的**瞬时异常**，参数错误、权限错误和业务拒绝通常立即失败；
- 最大尝试次数、总 deadline，以及指数退避加 jitter，例如
  $d_k=\min(d_{max},d_0 2^k)\cdot U(0.5,1.5)$；
- 同步版本用 `time.sleep`，异步版本必须 `await asyncio.sleep`，不能阻塞事件循环；
- `CancelledError`、`KeyboardInterrupt`、`SystemExit` 等取消或进程控制信号不应被宽泛捕获后重试；
- 有副作用的写操作只有具备幂等键、去重或事务保证时才能安全自动重试；
- 最后一次失败应保留原异常 traceback，必要时用领域异常 `raise ... from exc` 增加上下文。

类型上可以通过 overload 分别描述同步 `Callable[P, R]` 和异步 `Callable[P, Awaitable[R]]`，避免 `Any` 抹掉调用签名。若装饰器既负责重试、日志、指标、熔断又负责权限，组合顺序会改变语义，最好保持每个装饰器职责单一。例如计时在重试外层测总耗时，在内层则测每次 attempt。

### 3. 常见陷阱

- 在异步 wrapper 中忘记 `await`，返回嵌套 coroutine。
- 用 `except Exception` 无差别重试所有错误，形成重试风暴。
- 装饰实例方法时误处理 `self`，或装饰器对象没有实现 descriptor 行为。
- 装饰后丢失签名，导致 FastAPI、CLI、测试 mock 或文档生成失效。
- 日志输出完整 prompt、token、密码等敏感参数。

### 面试简答版

装饰器是“接收可调用对象并返回可调用对象”的变换，`@d` 等价于 `f = d(f)`。要同时支持同步和异步函数，应使用 `inspect.iscoroutinefunction` 在装饰时分流：同步 wrapper 直接调用，异步 wrapper 必须 `await`；两者都用 `functools.wraps` 保留元数据，并以 `finally` 记录计时。重试还要限制瞬时异常、总 deadline 和次数，使用指数退避加 jitter；异步等待用 `asyncio.sleep`，取消不重试，有副作用操作只有幂等时才能自动重试。
