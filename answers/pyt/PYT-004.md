## 我的答案

三者的核心区别是：容器通常**持有全部元素**，迭代器保存“下一个元素在哪里”的遍历状态，生成器则是用可暂停函数方便地实现迭代器。

### 1. Iterable、Iterator 与 Generator

- **可迭代对象（iterable）**实现 `__iter__()`，能产生迭代器；列表、字典、文件等都可迭代。它通常可以重复遍历，但不是协议保证。
- **迭代器（iterator）**实现 `__iter__()` 和 `__next__()`；`__iter__()` 返回自身，`__next__()` 返回下一个值，结束时抛 `StopIteration`。它有状态，通常只能向前消费一次。
- **生成器（generator）**是包含 `yield` 的生成器函数调用后得到的对象；它自动实现迭代器协议，并在每次 `yield` 时保存栈帧和局部状态。

```python
def read_batches(rows, batch_size):
    batch = []
    for row in rows:
        batch.append(row)
        if len(batch) == batch_size:
            yield batch
            batch = []
    if batch:
        yield batch
```

调用 `read_batches(...)` 时函数体不会立即完整执行；每次 `next()` 执行到下一个 `yield`，耗尽后抛 `StopIteration`。

### 2. 为什么能降低内存

假设输入有 $N$ 个对象，每个平均占 $s$ 字节。先构建列表的结果内存约为 $O(Ns)$；惰性流水线只保存当前元素和各阶段状态，理想情况下是 $O(s)$，分批时约为 $O(Bs)$，其中 $B$ 是 batch size。

```python
# 会一次构造全部中间结果
eager = [embed(clean(x)) for x in documents]

# 每次只产生一个，消费者可以边读边写
lazy = (embed(clean(x)) for x in documents)
for vector in lazy:
    vector_store.add(vector)
```

收益尤其适合大文件、数据库 cursor、日志流、ETL 和模型输入批处理。它也能缩短首个结果延迟，并让消费者提前停止。

### 3. 生成器并非免费

1. **只能消费一次**：要重跑应保存可迭代源或生成器工厂，而不是复用已耗尽的生成器。
2. **惰性错误**：异常发生在迭代时而非创建时；资源生命周期和日志位置要设计清楚。
3. **仍可能积压**：`list(generator)`、无界 `tee`、下游缓存或把所有批次留在列表中，会重新变成高内存。
4. **不自动加速**：逐元素 Python 调用可能比向量化慢；GPU/数据库通常需要合适 batch，过小会降低吞吐。
5. **资源释放**：生成器中打开文件时，未耗尽就停止可能延迟清理。优先由外层 `with` 管资源，或在 `try/finally` 中清理并在需要时调用 `close()`。

生成器还支持 `send()`、`throw()`、`close()` 和 `yield from`，但复杂的双向控制流常不如显式状态机或 `asyncio` 易读。异步数据源要使用异步迭代协议：`__aiter__`、`__anext__` 和 `async for`；它解决等待时让出事件循环，不等于普通生成器。

### 面试简答版

容器通常一次持有全部元素；迭代器保存遍历状态，通过 `__next__` 惰性地产生元素；生成器是用 `yield` 自动实现的单次迭代器，会在暂停处保留执行状态。对 N 个元素，列表结果通常占 $O(N)$，流式生成器理想情况下只占 $O(1)$，分批则是 $O(B)$。但生成器不自动提高速度，可能有单次消费、惰性异常、资源未及时关闭和 batch 太小等问题，工程中仍需结合有界缓冲与背压。
