## 我的答案

先区分语言规范与实现：**引用计数是 CPython 的主要内存管理机制，不是 Python 语言对所有实现的保证**。CPython 还用循环垃圾回收器补充引用计数。

### 1. 引用计数

对象大致维护被强引用的数量。名称绑定、放进容器、作为对象属性等会增加引用，删除绑定或容器元素会减少引用；计数降为 0 时，CPython 通常立即终结并回收对象。

```python
a = []
b = a       # 同一对象多一个强引用
del a
del b       # 若无其他强引用，CPython 通常可立即回收
```

`sys.getrefcount(obj)` 本身传参会临时增加引用，只适合辅助理解，不能当稳定业务指标。弱引用 `weakref` 不增加强引用计数，适合不应延长对象寿命的缓存、观察者和反向索引，但不是所有类型都支持弱引用。

### 2. 循环引用与垃圾回收

两个不可达对象可能仍互相引用，使各自引用计数都不为 0：

```python
a, b = [], []
a.append(b)
b.append(a)
del a, b
```

CPython 的循环 GC 会追踪可能参与环的容器对象，按代检查不可达对象图并回收环。新对象通常更频繁检查，存活较久的对象进入更老的代，这是基于“多数对象朝生夕灭”的经验优化。具体代数、阈值和策略会随 CPython 小版本变化；例如 3.14 系列内就调整过中间代与阈值行为，面试中应讲机制而不是死背某个阈值。

`del x` 只删除一个名称/引用，不保证对象立刻释放；`gc.collect()` 也只处理符合条件的不可达对象，不是通用“清空内存”按钮。资源释放更不能依赖 GC，应使用 `with` 或显式 `close()`。

### 3. 为什么长期 Agent 服务仍会“泄漏”

内存持续增长不一定都是 GC 无法处理的循环，常见原因包括：

1. **仍然可达的无界状态**：conversation、prompt、trace、LRU/cache、全局字典、去重集合、指标 label 不设上限；GC 正确地不会回收它们。
2. **后台任务和闭包**：未完成 task、callback、异常 traceback、队列元素持有整个请求上下文；断连后未取消的流式生成仍继续占资源。
3. **对象环与终结/扩展边界**：Python 环多数能收集，但 C 扩展或错误的资源封装可能不可收集或延迟释放。
4. **原生内存**：PyTorch/CUDA、NumPy、tokenizer、HTTP 库、驱动在 Python heap 外分配，`tracemalloc` 不一定能看到。
5. **allocator 与碎片**：对象已释放给 Python allocator，却未立即归还操作系统，所以 RSS 不下降；这与对象仍可达不同。
6. **模型框架缓存**：GPU caching allocator 保留已释放块以便复用；应同时看 allocated、reserved 和系统显存，而不是只看一个数字。
7. **worker 生命周期**：反复加载模型、热更新、fork 前后状态、线程局部变量或连接池没有正确关闭。

### 4. 定位方法

先做稳定可复现的负载和请求结束后的静置/必要 GC，对比对象数、Python heap、native RSS、GPU allocated/reserved，定位是哪一层增长。Python 对象可用 `tracemalloc` snapshot diff、`gc.get_stats()`、`gc.get_objects()`，并通过 `gc.get_referrers()` 辅助找持有链；后者只适合调试，结果本身也会改变引用。原生内存再用系统 profiler、框架 memory snapshot 等工具。

修复优先处理所有权和上限：有界 cache/queue、TTL、断连取消、移除 callback、关闭资源、避免异常/traceback 长期保留，并加 soak test 与按请求/租户的内存基线。定期 `gc.collect()` 或重启 worker 可以止血，但不是根因修复。

### 面试简答版

CPython 主要靠引用计数，对象强引用降到 0 时通常立即回收；互相引用的不可达对象计数不为 0，所以再用分代循环 GC 找不可达对象图。长期 Agent 服务仍会涨内存，最常见的是无界会话/cache/queue、未取消 task 与 traceback 仍保持可达，也可能是 C/CUDA 原生内存、allocator 碎片或框架缓存。排查应分开观察 Python heap、RSS 和 GPU allocated/reserved，用 snapshot diff 找增长类型和持有链，再通过有界容量、TTL、取消传播及明确资源生命周期修复，而不是只靠 `gc.collect()`。
