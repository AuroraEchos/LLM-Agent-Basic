## 我的答案

LEGB 描述 Python 解析一个**名称**时的查找顺序：

1. **L — Local**：当前函数的局部作用域；
2. **E — Enclosing**：外层嵌套函数的作用域，由内向外；
3. **G — Global**：当前模块的全局作用域；
4. **B — Built-in**：`builtins` 中的名称，如 `len`。

找不到名称会抛 `NameError`。类体作用域和推导式等细节比四字口诀更复杂，但普通嵌套函数题可先用 LEGB 分析。

### 1. 查找与赋值不是一回事

函数体内只要对名称有普通赋值，编译器通常就把它判定为该函数的局部变量；因此赋值前读取会得到 `UnboundLocalError`，不会退回全局变量：

```python
count = 10

def bad():
    print(count)  # count 已被判定为局部变量，但此时尚未绑定
    count += 1
```

- `global x` 表示该函数的赋值作用于模块级 `x`。
- `nonlocal x` 表示赋值作用于最近的、已经存在的外层函数绑定；它不能创建模块级名称。
- 修改对象不等于重绑定名称。`items.append(x)` 通常不需要 `nonlocal`，而 `items = items + [x]` 会重绑定，需要声明。

### 2. 闭包是什么

内层函数引用外层函数的自由变量，并且在外层调用结束后仍保留这些绑定，就形成闭包。闭包捕获的是**变量的 cell/绑定**，不是在函数定义瞬间自动复制一份值。

```python
def make_counter(start=0):
    count = start

    def next_value():
        nonlocal count
        count += 1
        return count

    return next_value

c1 = make_counter()
c2 = make_counter(10)
assert (c1(), c1(), c2()) == (1, 2, 11)
```

每次调用 `make_counter` 都创建独立的闭包状态。闭包适合函数工厂、配置绑定、回调和轻量状态封装；状态复杂、需要并发保护或可序列化时，显式类往往更清楚。

### 3. 晚绑定陷阱

循环中创建的闭包在真正调用时查找同一个变量，所以常全部得到最终值：

```python
funcs = [lambda: i for i in range(3)]
assert [f() for f in funcs] == [2, 2, 2]

# 默认参数在定义函数时求值，可用于冻结当前值
fixed = [lambda i=i: i for i in range(3)]
assert [f() for f in fixed] == [0, 1, 2]
```

异步创建任务时也常踩这个坑：循环变量、请求上下文或工具参数被迟到的协程共同读取。更稳妥的是显式参数传递或使用函数工厂，而不是依赖隐式捕获。

### 4. 工程边界

- 避免用 `global` 保存请求状态，否则测试隔离、多 worker 和并发访问都困难。
- `nonlocal` 解决的是名称绑定，不提供线程安全或协程安全；共享闭包状态仍可能需要锁或单 owner。
- 不要遮蔽 `list`、`id`、`input` 等内置名称，以免后续调用出现难懂错误。
- 调试可查看函数的 `__code__.co_freevars` 和 `__closure__`，但业务代码不应依赖这些内部细节修改状态。

### 面试简答版

名称读取通常按 Local、Enclosing、Global、Built-in 查找；函数内有赋值时，该名称会被判为局部变量，赋值前读取可能抛 `UnboundLocalError`。闭包是内层函数保留并引用外层自由变量的机制，捕获的是绑定而非定义时的值，所以循环创建闭包会有晚绑定问题，可用默认参数或函数工厂冻结值。`nonlocal` 用于重绑定最近的外层函数变量，`global` 用于模块变量；它们都不提供并发安全。
