## 我的答案

Python 变量保存的不是“值本身”，而是**对象的引用（更准确地说是名称与对象的绑定）**。对象有身份 `id`、类型和值；可变性描述的是：对象创建后，能否在保持身份不变的情况下修改内部状态。

### 1. 可变与不可变对象

- 常见不可变对象：`int`、`float`、`bool`、`str`、`bytes`、`tuple`、`frozenset`。所谓“修改”通常会创建新对象并重新绑定名称。
- 常见可变对象：`list`、`dict`、`set`、大多数自定义类实例。原地操作可以保持 `id` 不变而改变内容。
- `tuple` 不可变只表示它保存的引用序列不能变；如果其中引用了列表，列表自身仍然可以改变。

```python
a = [1, 2]
b = a
a.append(3)
assert b == [1, 2, 3]       # a、b 指向同一个可变对象

x = "ab"
y = x
x += "c"
assert y == "ab"            # x 被重新绑定到了新字符串

t = ([1], 2)
t[0].append(3)               # 合法，改变的是 tuple 内的 list
```

可哈希性与不可变性高度相关但不是完全同义。字典键要求对象的哈希值在其生命周期内稳定，因此列表不可哈希；只包含可哈希元素的元组才可哈希。自定义可变对象也能人为实现 `__hash__`，但若参与哈希的字段会变，就可能破坏集合和字典的不变量。

### 2. 函数参数实际如何传递

Python 使用 **call by sharing / object sharing（共享对象传递）**：调用时，把实参所指对象绑定给函数的形参。形参是局部名称，不是调用方变量的别名。

```python
def mutate(items):
    items.append("x")        # 修改共享对象，调用方可见

def rebind(items):
    items = ["new"]          # 只重新绑定局部名称，调用方不可见

data = []
mutate(data)
assert data == ["x"]
rebind(data)
assert data == ["x"]
```

因此“不可变参数不能修改、可变参数按引用传递”只是表象。两者的传参机制完全相同，差别在于对象是否支持原地修改。`+=` 也要看类型：列表通常执行原地更新，元组和字符串则生成新对象。

### 3. 工程中的典型陷阱

1. **可变默认参数**只在函数定义时创建一次，会在多次调用间共享：

   ```python
   def collect(x, result=None):
       if result is None:
           result = []
       result.append(x)
       return result
   ```

2. 返回或缓存内部可变对象会暴露状态，可按语义返回副本、不可变视图，或明确约定所有权。
3. 多个请求共享同一个列表/字典时，别名会造成跨请求污染和并发竞态；不能因为有 GIL 就认为复合状态更新具有业务原子性。
4. API 设计应明确函数是纯函数、原地修改，还是返回新对象。例如用 `*_inplace` 命名或在类型/文档中说明。

### 面试简答版

Python 名称绑定到对象；可变对象能在 `id` 不变时修改内部状态，不可变对象的所谓修改会创建新对象并重新绑定。函数调用采用共享对象传递：实参对象绑定给局部形参，所以修改共享的列表、字典会被调用方看到，给形参重新赋值则不会。工程上要警惕可变默认参数、嵌套别名、共享状态和不稳定哈希，并明确对象所有权与函数是否原地修改。
