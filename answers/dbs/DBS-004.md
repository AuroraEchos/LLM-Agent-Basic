## 我的答案

- **脏读（Dirty Read）**：读到另一事务尚未提交的数据；对方回滚后，所读值从未真正存在。
- **不可重复读（Non-repeatable Read）**：同一事务两次读取同一行，期间另一事务提交了更新/删除，结果不同。
- **幻读（Phantom Read）**：同一事务重复执行一个谓词查询，期间另一事务提交插入/删除，符合条件的行集合改变。

SQL 标准给出的最低保证通常概括为：

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---|---:|---:|---:|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 防止 | 可能 | 可能 |
| Repeatable Read | 防止 | 防止 | 标准允许可能 |
| Serializable | 防止 | 防止 | 防止 |

实现可以比标准最低要求更强。例如 PostgreSQL 的 Read Uncommitted 实际按 Read Committed 工作，Repeatable Read 基于 snapshot isolation 并避免普通幻读，但仍可能有 serialization anomaly/write skew；Serializable 检测危险依赖并可能中止事务。MySQL/InnoDB 的快照、当前读与 gap/next-key lock 又有不同表现。因此面试应先答标准，再说明必须查具体引擎、版本、语句类型。

一个经典 write skew：两名值班医生分别看到“还有另一人在岗”，并发各自下线；每个事务读取的行可重复，最终却无人值班。它不属于简单三异常，Repeatable Read/快照隔离未必阻止，需要 Serializable、显式锁或将不变量编码成可冲突的约束/行。

隔离越强不等于零代价：可能更多等待、死锁或 serialization failure，应用必须对**整个事务**有限重试，并保证事务外副作用不会重复。普通读一致性与 `SELECT ... FOR UPDATE` 锁定读取也不同。选择原则是先列业务不变量和并发交错，再选能阻止它的约束/原子 SQL/锁/隔离，而不是全库盲目升最高级别。

### 面试简答版

脏读是读到未提交值，不可重复读是同一行两次读因并发提交而变化，幻读是同一条件返回的行集合变化。标准上 Read Uncommitted 三者都可能，Read Committed 禁脏读，Repeatable Read 再禁不可重复读但标准仍允许幻读，Serializable 等价某个串行顺序。具体引擎可能更强或采用不同锁/MVCC；还要防 lost update、write skew 等不在三口诀里的异常，并准备重试 serialization failure。
