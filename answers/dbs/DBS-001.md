## 我的答案

先区分**约束**和**访问结构**：主键/唯一约束表达数据不变量，数据库通常用唯一索引实现；普通/联合索引主要改善访问路径。具体物理组织随 PostgreSQL、InnoDB 等引擎不同。

- **主键（Primary Key）**：一行的规范身份，一张表只能声明一个主键，但它可包含多列；列必须非 NULL 且组合唯一。外键通常引用主键或其他候选唯一键。代理 ID 适合稳定引用，业务自然键仍应另加唯一约束防重复。
- **唯一索引/唯一约束**：保证索引键不存在不允许的重复，可有多个。NULL 是否互相视为重复、是否支持条件/表达式唯一等依数据库而异，不能只凭 `UNIQUE` 猜业务语义。
- **普通索引**：不保证唯一，只为过滤、连接、排序、聚合等提供候选访问路径。
- **联合索引**：一个索引键由多列按顺序组成，如 `(tenant_id, status, created_at)`；既可普通也可唯一。列顺序决定可支持的查询前缀、排序与范围扫描。

```sql
CREATE TABLE tool_call (
  id          bigint PRIMARY KEY,
  tenant_id   bigint NOT NULL,
  request_id  text NOT NULL,
  status      text NOT NULL,
  created_at  timestamp NOT NULL,
  UNIQUE (tenant_id, request_id)
);
CREATE INDEX idx_tool_call_queue
  ON tool_call (tenant_id, status, created_at);
```

这里主键提供内部身份，联合唯一约束实现每租户幂等 request，普通联合索引支持按租户/状态取最早任务。只给 `request_id` 单列 unique 可能错误地跨租户冲突。

索引不是越多越好：每次 INSERT/UPDATE/DELETE 要维护索引，会增加 WAL、随机 I/O、锁/页竞争、存储和 vacuum 成本；低选择性单列索引也可能不被优化器采用。建索引应从真实 query pattern、选择性、排序/分页、写入比和执行计划出发，并用约束而不是应用“先查再插”保证并发唯一性。

### 面试简答版

主键是一行的非空唯一身份，一表一个但可多列；唯一约束/索引保证候选键唯一，一表可多个，NULL 语义看数据库；普通索引只优化访问不保证唯一；联合索引按有序列组合建立，可同时是唯一索引，列顺序影响可用查询。Agent 表常用代理主键、`(tenant_id, request_id)` 唯一约束做幂等，再按 `(tenant_id, status, created_at)` 建队列索引。索引会增加写放大和存储，应以执行计划和真实查询验证。
