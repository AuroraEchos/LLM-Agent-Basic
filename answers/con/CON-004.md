## 我的答案

它们构成一条执行链：`async def` 定义异步函数；调用它得到尚未执行完的 Coroutine 对象；Task 将 Coroutine 包装并安排并发运行；Event Loop 驱动 ready Task，在 Coroutine 执行 `await` 等待未完成对象时切换到其他 Task。

### 各自含义

**Coroutine** 是可暂停/恢复的计算及其 frame。调用异步函数只创建 coroutine；如果既不 `await` 也不包装成 Task，它不会正常执行，并可能出现 “coroutine was never awaited”。Coroutine 通常只能被 await 一次。

**`await`** 等待 awaitable（Coroutine、Task、Future 等）。若对象未完成，当前 Task 保存状态并把控制权还给 event loop，完成后从该行继续。`await` 不会开启新线程，也不保证并发：

```python
a = await fetch_a()
b = await fetch_b()  # 默认串行，b 在 a 完成后才开始
```

**Task** 是 Coroutine 的调度和生命周期容器，保存结果、异常、取消和 context。`asyncio.create_task(coro)` 让它有机会与当前 Task 并发运行；应保存引用并最终 await。相关子任务优先使用 `TaskGroup`，退出时统一等待，失败时按结构化并发规则处理兄弟任务。

**Event Loop** 维护 ready queue、timer、I/O selector、Future 和 Task。它反复执行可运行 Task，Task 等 I/O 时再处理其他工作。一个线程通常运行一个 loop；loop 上的长 CPU/阻塞函数会使所有 Task 停顿。

### 执行例子

```python
async def main():
    async with asyncio.TaskGroup() as tg:
        t1 = tg.create_task(fetch("a"))
        t2 = tg.create_task(fetch("b"))
    return t1.result(), t2.result()

asyncio.run(main())
```

`asyncio.run` 创建并运行 event loop；TaskGroup 将两个 Coroutine 包装为 Task。每个 `fetch` 等 socket 时 `await`，loop 驱动另一个；退出 block 时两者均有明确终态。

### Future 的位置

Future 代表未来可用的一次性结果，通常由低层 I/O、executor 或库创建。Task 是 Future 的高层实现之一，负责驱动 Coroutine 并把返回/异常放入自身；业务代码通常创建 Task，少直接创建 Future。

### 常见误区

- 连续两个 `await` 默认串行，需要 TaskGroup/gather 才并发，但并发量仍需 Semaphore/连接池限制。
- `create_task` 后丢引用会导致异常无人处理、生命周期不清；不要无管理 fire-and-forget。
- Task cancellation 是协作式，在下一取消点生效；代码应在 `finally` 清理并通常重新传播取消。
- TaskGroup 与 `gather` 的异常/取消语义不同，不能只为语法短而互换。
- Event loop 并发不等于 CPU parallelism，CPU 任务需线程/进程/外部 worker。

### 面试简答版

`async def` 定义异步函数，调用后得到 Coroutine；`await` 等待 awaitable，未完成时暂停当前 Task并把控制权还给 Event Loop；Task 是 Coroutine 的调度和生命周期容器，`create_task` 后才可与当前流程并发；Event Loop 负责 I/O ready、timer 和 runnable Task。连续两个 `await` 默认串行，并发应使用 TaskGroup 等结构化方式，同时限制并发。它们都不自动创建线程或提供 CPU 多核并行，阻塞 event loop 仍会卡住全部协程。
