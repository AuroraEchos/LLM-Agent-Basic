## 我的答案

三者都是并发执行单元，但调度者、内存隔离和切换成本不同：进程/线程通常由操作系统抢占调度，协程由语言运行时在 `await/yield` 处协作切换。

| 维度 | 进程 | 线程 | 协程 |
|---|---|---|---|
| 调度 | OS，抢占式 | OS，抢占式 | 用户态 event loop，协作式 |
| 地址空间 | 原则上独立 | 同进程共享 heap/代码 | 通常同一线程/进程共享对象 |
| 私有状态 | 独立虚拟内存、资源表 | 独立 stack/register/thread-local | 独立 coroutine frame、局部变量/上下文 |
| 通信 | pipe/queue/socket/shared memory | 共享内存+锁/queue | 共享内存+async primitive/queue |
| 创建/切换 | 最重 | 中等 | 最轻，可大量并发 |
| CPU 并行 | 可以 | 取决于 runtime/GIL/native 代码 | 单 event loop 本身不提供多核并行 |

### 进程

每个进程有独立虚拟地址空间，默认不能直接访问另一个进程的 Python 对象。隔离降低数据竞争和故障扩散，能利用多个 CPU core；代价是启动、内存和 IPC/序列化较高，大模型权重若每进程复制会非常昂贵。

适合纯 Python CPU 密集、故障隔离和独立 worker。共享内存可降低复制，但会重新引入同步、生命周期与一致性问题。

### 线程

同一进程内线程共享 heap、文件描述符和连接池，每线程有自己的调用栈和寄存器。OS 可在任意指令附近抢占，所以共享可变状态需要 Lock、Condition、Queue、atomic 或不可变设计。

线程适合阻塞 I/O 库、共享大只读数据、native 扩展释放 GIL 的计算。缺点是 race/deadlock 难复现，一个线程的进程级崩溃会影响全部线程；共享内存快也不代表没有锁竞争和 cache coherence 成本。

### 协程

调用 `async def` 产生 coroutine；event loop 在其等待 I/O/定时器时切换到其他 Task。切换在用户态且 frame 轻量，适合上万网络连接、模型流式输出和工具并发。

协作式意味着一个协程若执行长 CPU 循环或阻塞 socket/sleep，整个 loop 的其他任务都无法运行。单线程协程在没有 `await` 的片段中不会被另一协程插入，但跨 `await` 的 read-modify-write 仍可能竞态，需要 `asyncio.Lock/Queue` 或单 owner 状态机。

### Agent Runtime 的组合

API 和模型/工具网络请求用 asyncio；不支持异步的短阻塞 SDK 放有界线程池；纯 Python解析/OCR 重计算放进程池/独立 worker；模型推理由 GPU server 承担。各层通过有界队列、deadline、取消和背压连接，而不是为每个请求开进程。

### 面试简答版

进程由 OS 调度、地址空间独立，IPC 和启动较重，但能多核并行且隔离强；线程也由 OS 抢占调度，共享进程内存，适合阻塞 I/O或释放 GIL 的 native 计算，但要处理锁、竞态和死锁；协程由 event loop 在 `await` 处协作切换，最轻、适合海量 I/O 并发，却不能让单 loop 的 CPU 代码并行，任何阻塞都会卡住全部任务。Agent 常用 asyncio 编排网络，线程池包阻塞 SDK，进程/独立 worker 承担 CPU 密集任务。
