## 我的答案

没有现成标准答案，不代表无法评测；应先构造**问题—证据真值**，再由证据得到参考答案。对 RAG 而言，标出“哪些来源足以回答、哪些看似相关但不能回答”通常比写唯一标准措辞更重要。

### 一、评测集来源

1. 从真实搜索日志、客服工单和用户追问分层抽样，脱敏后由专家补证据；
2. 从权威文档反向生成问题，再由另一位标注员验证问题自然、答案确实可由该段推出；
3. 邀请领域专家写高价值、多跳、时间敏感和边界问题；
4. 收集线上失败案例，但保留长期冻结 holdout，避免只针对已知错误过拟合；
5. 加入语料中无答案的问题，用于评估拒答与越界生成。

每条记录 question、必要/可选 evidence IDs、可接受 claim、时间/地域/版本、答案状态和难度。开放问题可以标注 rubric 与必要事实集合，而非强制一个字符串答案。

### 二、正例与负样本

正例应分级：直接完整证据、部分证据、背景相关。负样本需要覆盖真实检索边界：

- 随机负样本：容易，适合基础训练但区分力弱；
- BM25 hard negative：关键词相同但答案不符；
- dense hard negative：主题相近、实体或条件错误；
- 同实体不同时间/版本/地域；
- 数字相近、否定相反、关系方向颠倒；
- 包含部分多跳事实但缺关键一跳；
- 重复、低权威和越权文档。

不能把未标注文档直接当负例，因为它可能也是正确证据。应 pool 多个 retriever 的 top results，由人工判定，或采用 positive-unlabeled 思路降低 false negative。

### 三、合成数据的使用

可让 LLM 基于给定文档生成问题、答案和 hard negative，再进行规则检查与人工抽样。生成时要求引用原句和证据位置；过滤泄漏文档措辞、无意义问句与依赖外部常识的答案。合成集适合扩大覆盖，最终权重与结论仍应以真实 query 为主。

### 四、质量控制

双人独立标注并仲裁，报告一致率；用明确指南区分“主题相关”和“足以回答”。按 query 类型、来源、语言、答案长度和难度切分，避免相邻 chunk 或同一文档模板跨 train/test。版本化语料快照，否则 gold evidence 被文档更新后会失效。

评测时分别测 evidence Recall@K、hard-negative 排序、无答案拒答、最终 claim correctness 和 citation。再定期人工复核高分错误与低分正确样本，校准 LLM judge。

### 面试简答版

没有标准答案时，我会先建立问题—证据真值：从真实日志、专家问题和权威文档反向生成问题，标必要证据、可接受 claim、版本条件和无答案状态。负样本不能只随机采，要加入关键词相同、语义相近但实体/时间/否定错误、只含部分多跳事实等 hard negatives；未标注文档不能直接视为负例，要做候选池人工判定。LLM 可辅助合成，但需引用原文、规则过滤和人工抽检。最终分层评估召回、排序、拒答、答案 claim 和引用，并冻结语料与测试版本。
