> **问题：** Bi-Encoder 检索与 Cross-Encoder Reranking 的差别是什么？

## 我的答案

Bi-Encoder 用两个可独立计算的向量做相似度，适合从海量语料快速召回；Cross-Encoder 把 query 与 document 一起编码并做深度 token 交互，相关性更准但无法预先缓存文档分数，适合对少量候选重排。

### 一、Bi-Encoder

\[
e_q=f_q(q),\qquad e_d=f_d(d),\qquad s(q,d)=e_q^Te_d
\]

文档向量可离线预计算并建立 ANN 索引，在线只编码一次 query，因此能搜索百万/亿级数据。双塔可以共享参数，也可用不同 query/document encoder 或 prefix。

局限是 query 与文档在压成单向量之前没有直接 token 交互，数字、否定和细粒度条件可能被压缩；一个长 chunk 的多个主题也会竞争有限维度。

### 二、Cross-Encoder

\[
s(q,d)=g([CLS]\ q\ [SEP]\ d)
\]

模型通过 self-attention 联合查看两段文本，可学习 query 中每个条件与文档 token 的精确匹配，通常排序更好。代价是每个候选都要单独前向，复杂度约随候选数 \(K\) 增长；文档表示不能跨 query 复用，所以无法直接全库扫描。

### 三、典型两阶段架构

```text
BM25 / Bi-Encoder ANN：全库召回 top 100～1000
→ 去重、ACL/filter
→ Cross-Encoder：重排 top 20～200
→ 选 top-k 给 LLM
```

第一阶段优化 recall，第二阶段优化 precision/nDCG。候选集没包含正确证据时，reranker 无法凭空找回；所以要分别评估 retrieval Recall@K 和 rerank 后 nDCG/Hit@k。

### 四、训练差别

Bi-Encoder 常用对比损失和大量 in-batch/hard negatives，必须避免 false negatives；Cross-Encoder 常用 pointwise 分类、pairwise 排序或 listwise loss，并能作为教师蒸馏给 Bi-Encoder。训练/评测负样本应来自实际第一阶段候选，否则 reranker 只会区分过于容易的随机负例。

### 五、工程取舍

| 维度 | Bi-Encoder | Cross-Encoder |
|---|---|---|
| 文档表示 | 可预计算、建 ANN | 与 query 联合计算，不能缓存通用分数 |
| 规模 | 百万/亿级召回 | 数十/数百候选精排 |
| token 交互 | 压缩后点积 | 完整 cross-attention |
| 延迟/成本 | 低 | 随候选数与长度增加 |
| 精细条件排序 | 较弱 | 通常更强 |

部署要联合调 retrieval depth、rerank depth、最大文档长度和 batch；可对候选批处理、蒸馏或使用轻量 reranker。不要因 Cross-Encoder 更准就对全库运行，也不能只调小候选数追求低延迟而牺牲 recall。

### 面试简答版

Bi-Encoder 分别把 query 和文档编码成向量，文档可离线缓存并用 ANN 全库召回，速度快、规模大，但单向量压缩使细粒度 token 交互有限。Cross-Encoder 把 query-document 拼接后联合编码，能精确判断否定、数字和条件，排序更准，却要对每个候选重新前向，成本随候选数增长。因此常用 Bi-Encoder/BM25 先召回 top-K，再用 Cross-Encoder 重排较小集合；前者看 Recall@K，后者看 nDCG/最终 Hit@k，并联合调候选深度、长度、batch 与延迟。
