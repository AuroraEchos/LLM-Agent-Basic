## 我的答案

RAGAS 可以快速提供一组检索与生成指标，但它不是“跑一个总分就完成评测”。可靠方案是：**自建代表性、可版本化的评测集，优先用确定性指标和人工真值，再用 RAGAS/LLM judge 扩充语义判断，并对 judge 本身做校准**。

### 一、评测样本结构

每条至少包含：

```json
{
  "question": "...",
  "reference_answer": "...",
  "reference_evidence_ids": ["doc:v3:p12"],
  "retrieved_contexts": ["..."],
  "response": "...",
  "metadata": {"type": "multi_hop", "language": "zh"}
}
```

gold evidence 比只有 reference answer 更重要，因为它能区分“没召回”与“召回了但模型没用”。加入 unanswerable、冲突文档、旧版本、权限边界和 adversarial query。

### 二、构造自建评测集

1. 从真实线上 query 分层抽样，去除隐私并保留长尾；
2. 由领域专家标 reference answer、必要 evidence、可接受变体和无答案条件；
3. 按事实型、多跳、比较、聚合、表格、模糊问法与语言划分；
4. train/dev/test 隔离，测试集不能用于反复调 chunk/K/Prompt；
5. 保存语料快照、索引版本和标注指南，双人标注分歧并仲裁；
6. 合成问题只用于补覆盖，必须抽检真实性，不能替代真实分布。

### 三、分层指标

- 检索：Hit/Recall@K、MRR、NDCG、完整多跳 evidence recall；
- 上下文：precision、冗余率、冲突率、token 利用率；
- 生成：factual correctness、answer relevance/completeness、faithfulness；
- 引用：citation validity、correctness、completeness；
- 系统：p95/p99、成本、超时、拒答和 ACL 泄漏率。

RAGAS 官方提供 Context Precision、Faithfulness 等指标；当前接口和指标集合应以[官方文档](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)为准，并锁定库版本与 evaluator 配置。

### 四、正确使用 LLM-as-a-Judge

Faithfulness 常把回答拆成 claim，再判断能否从 context 推出；context relevance/precision 则判断片段是否支持问题。使用时必须固定 evaluator model/version、temperature、rubric、语言和重试策略，并缓存原始 judgment 与理由。

在人工标注子集上测 judge 的准确率、precision/recall、分组偏差和重复运行一致性。用另一个 prompt 或模型做抽查，并加入“答案流畅但证据不支持”“证据正确但回答简短”等 hard cases。LLM 分数不是客观真值，也不应与被评模型共享同一盲点却无人复核。

### 五、实验与上线门槛

每个改动与固定 baseline 做 paired evaluation，报告均值、bootstrap 置信区间和分类切片；同时固定模型、语料快照和预算，一次只改 chunker、retriever、reranker 或 Prompt 中的一项。不要把多个版本变化归因给一个组件。

上线前定义质量门槛，例如：关键领域无回退、faithfulness 与 citation precision 达标、ACL 泄漏为零、p95/成本不超预算。上线后 shadow/A-B，并把失败 trace 回灌为新评测样本，但保持一个长期冻结的 holdout 防止测试集过拟合。

### 六、失败定位

```text
gold evidence 未进 Top-K → 解析/chunk/query/retriever
进 Top-K 但未进最终 context → fusion/reranker/budget
已在 context 但答案遗漏 → prompt/model/context position
答案声称 context 外事实 → faithfulness/拒答约束
引用存在但不支持 claim → citation alignment
```

### 面试简答版

我会自建带 question、reference answer、gold evidence、语料版本和类型标签的评测集，覆盖真实长尾、无答案、冲突、权限和多跳问题。检索层测 Recall/MRR/NDCG，上下文测 precision/冗余，生成测 correctness、faithfulness、完整性和引用，系统层测 p95、成本与泄漏。RAGAS 可快速提供 Context Precision、Faithfulness 等 LLM 指标，但要锁定版本、judge、Prompt 和温度，并在人工标注子集上校准 judge。每个改动做配对实验、置信区间与切片，保留冻结 holdout，不能用单一总分替代故障分层。
