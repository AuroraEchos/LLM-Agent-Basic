## 我的答案

RAG（Retrieval-Augmented Generation）可以拆成两条链路：**离线把异构知识变成可检索、可追踪的索引；在线把用户问题变成检索请求，找出证据并约束模型回答**。高质量系统还需要贯穿两条链路的权限、版本、观测与评测。

### 一、离线索引链路

```text
数据源接入
→ 解析与结构恢复
→ 清洗、规范化、去重
→ 切块与上下文增强
→ 元数据/权限绑定
→ 稀疏与稠密表示
→ 写入索引
→ 质量检查、版本发布
```

#### 1. 数据接入与变更捕获

从网页、PDF、数据库、Wiki、对象存储或业务 API 抽取原文。为每份文档分配稳定 `document_id`，记录 source URI、抓取时间、内容 hash、版本、语言、所属租户和 ACL。增量索引要识别新增、修改、删除；删除文档时也必须清理旧 chunk，避免“幽灵知识”。

#### 2. 解析与结构恢复

将文件还原为标题、段落、列表、表格、图片说明、页码和章节层级。扫描件需要 OCR；PDF 还要处理多栏排版、页眉页脚与阅读顺序。解析失败若不显式标记，后面再强的 embedding 也无法恢复已丢失的信息。

#### 3. 清洗与规范化

去除导航、广告、重复页眉页脚和模板噪声，统一 Unicode、空白、编码和必要的格式；保留对语义有用的标题、表头、代码缩进、单位与出处。做 exact/near-duplicate 去重，但不能把不同版本或权限的相似文档误合并。

#### 4. Chunking 与上下文增强

按 token、段落、标题、表格或语义边界切块，可配置 overlap。每个 chunk 应携带章节路径，必要时附加文档摘要、父标题或表头，使其离开原文后仍可理解。通常同时保留 parent-child 关系，检索小块、展示较大的父块。

#### 5. 表示与索引

- 稠密索引：用固定版本 embedding model 生成向量，适合语义近义匹配；
- 稀疏索引：BM25/倒排索引，适合专有名词、编号、错误码和精确关键词；
- 结构化索引：文档、实体、时间、权限等 metadata filter；
- 特殊模态：表格、图片、代码可使用专门表示或保存可引用原始对象。

向量必须记录 embedding model、维度和归一化方式。换模型后新旧向量通常不可直接比较，应建新索引并灰度切换。

#### 6. 发布前检查

检查解析覆盖率、空块率、长度分布、重复率、语言分布、权限继承、embedding 异常和一组 golden query 的 recall。索引应以版本/alias 原子发布，避免查询读到半新半旧数据。

### 二、在线查询链路

```text
请求鉴权与理解
→ 查询改写/分解
→ 候选召回
→ 融合与过滤
→ 重排
→ 上下文组装
→ 受证据约束生成
→ 引用、校验与反馈
```

#### 1. 请求理解

识别意图、实体、时间范围、语言、租户和用户 ACL；解析多轮对话中的指代，但不要把无关历史全拼入查询。对于复杂问题可生成多个 query、HyDE 文本或子问题。

#### 2. 候选召回

并行使用 dense retrieval、BM25、metadata filter、知识图谱或 SQL。召回阶段目标是高 recall，候选数通常大于最终给模型的数量。权限过滤必须在返回内容前强制执行，不能只靠 prompt 要求模型保密。

#### 3. 融合与重排

用 RRF 或校准分数融合多路候选，去重后用 cross-encoder、reranker 或 LLM 按“query—chunk 是否直接相关”重排。必要时对时间新鲜度、来源权威性和文档版本加约束。

#### 4. 上下文组装

在 token budget 内选择互补证据，恢复父标题/相邻块，避免重复 chunk 占满窗口；按来源分组并为每段分配稳定 citation ID。防止检索文本中的 prompt injection 被当成系统指令。

#### 5. 生成与校验

Prompt 明确要求基于证据回答、证据不足时说不知道，并输出可回溯引用。生成后可做 citation entailment、数字一致性、结构化输出校验和敏感信息检查。高风险任务应返回原文证据供用户确认。

### 三、关键评测与可观测性

不能只看最终回答。要分层定位：

| 层次 | 常用指标 |
|---|---|
| 解析/索引 | 解析成功率、空块率、索引新鲜度、ACL 正确率 |
| 召回 | Recall@k、Hit Rate、MRR、候选覆盖率 |
| 重排 | nDCG@k、Top-k precision、正例排名变化 |
| 上下文 | 证据覆盖、重复率、token 利用率、lost-in-the-middle |
| 生成 | 正确性、faithfulness、citation precision/recall、拒答质量 |
| 系统 | p50/p95 延迟、QPS、embedding/rerank/LLM 成本、缓存命中率 |

线上 trace 应能从答案回溯到 query rewrite、候选列表、分数、过滤原因、最终 chunk、Prompt 和索引版本，否则无法判断错误发生在哪一层。

### 面试简答版

RAG 离线链路是数据接入和增量变更、文档解析、清洗去重、按结构或语义切块、绑定来源与 ACL、生成稀疏/稠密表示、写入版本化索引并做质量验收。在线链路先鉴权和理解/改写查询，再用 BM25、向量和元数据多路召回，融合去重、重排，在 token budget 内恢复必要上下文，最后要求模型基于证据生成、引用和校验。工程上必须逐层监控解析率、Recall@k、nDCG、faithfulness、引用准确率、延迟和成本，并能从答案 trace 回具体索引版本与证据。
