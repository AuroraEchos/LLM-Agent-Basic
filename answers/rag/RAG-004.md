## 我的答案

四种 Chunking 的区别在于**边界由什么决定**：Fixed 只看长度，Recursive 按分隔符逐级拆，Semantic 按语义变化切，Structure-Aware 服从原文结构。选择时要同时考虑文档结构是否可靠、查询粒度、解析成本和召回/生成目标。

### 一、Fixed-Size Chunking

按固定 token/字符窗口切分，例如每 512 tokens 一块、重叠 64 tokens。

**优点**：实现简单、吞吐高、块长均匀，方便估算 embedding 和上下文成本；适合结构很弱的纯文本、日志或快速基线。

**缺点**：可能在句子、定义和表格中间切断；标题与正文分离；同一主题被机械拆开。字符数也不等于模型 token 数，多语言下差异明显，所以最好按目标 tokenizer 计数。

### 二、Recursive Chunking

先按较大的自然分隔符切，如 `章节 → 段落 → 句子 → token`；块超过上限才继续向下递归，过小则合并相邻单元。

**优点**：成本接近 Fixed，却更能保留段落/句子完整性，是通用文本的强基线；长度仍较可控。

**缺点**：依赖分隔符质量，网页转文本或 OCR 断行错误时效果差；只知道语法边界，不知道相邻段落是否语义突变。对代码、表格等特殊结构仍需定制 separator。

### 三、Semantic Chunking

先对句子或小段落编码，计算相邻单元的语义距离；当距离超过阈值或检测到主题变化时切分。例如：

\[
d_i=1-\cos(e_i,e_{i+1}),\qquad
d_i>\tau\Rightarrow\text{boundary}
\]

实际可用滑动窗口表示、聚类或变点检测，避免单句 embedding 太噪。

**优点**：在没有显式标题的长叙述、访谈和会议记录中，更可能保持一个主题完整。

**缺点**：离线计算更贵，阈值随领域和 embedding 模型变化；块长不均匀，可能产生超大或很小的块；“语义相似”并不保证问答证据应该放在一起。它也不能替代可靠的版面/表格结构。

### 四、Structure-Aware Chunking

利用 Markdown/HTML 标题树、PDF layout、代码 AST、表格行列、邮件线程或法律条款等结构切块。块会携带结构路径：

```text
《员工手册》 > 第三章 假期 > 3.2 病假 > 第 4 段
```

**优点**：边界符合作者组织方式，可保留标题、表头、函数/类、条款和父子关系；引用与解释性最好。

**缺点**：依赖高质量 parser，每种文档要定制；结构节点可能远超模型窗口，也可能只有一句，需要进一步递归拆分/合并。原文结构不一定恰好等于用户问题粒度。

### 五、如何选择

| 场景 | 首选 | 原因 |
|---|---|---|
| 快速 PoC、纯文本、日志 | Fixed/Recursive | 简单、稳定、成本低 |
| 普通文章、Markdown | Recursive + 标题元数据 | 保留段落且长度可控 |
| 无标题访谈、会议转写 | Semantic | 主题切换比格式边界更可靠 |
| API 文档、法律合同、代码 | Structure-Aware | 函数、条款和章节不可随意切断 |
| 表格 | 表级/行组结构切块 | 必须重复表头与单位 |
| 多模态 PDF | Layout/Structure-Aware | 文本、图、表和页码关系重要 |

生产中最常见的是混合方案：先按结构找到原子单元，再 recursive packing 到目标 token 范围；若结构缺失，才用 semantic boundary；最后给过短块合并、过长块递归拆分。

### 六、Parent-Child 与 Small-to-Big

检索所需粒度和生成所需上下文经常不同。可以为小段落建 embedding 以提高定位精度，命中后返回其父章节或邻接窗口：

```text
检索：小 child chunk
重排：child 与 query
生成：去重后的 parent/section context
```

这能兼顾细粒度召回和上下文完整，但父块仍要受 token budget 限制，不能命中一个小点就把整份文档塞给模型。

### 七、不要凭经验拍参数

用真实 query—evidence 标注集比较不同方案的 Recall@k、nDCG、答案 faithfulness、引用粒度、平均上下文 token 和延迟。还应按文档类型切片，因为一种 chunker 很少对代码、表格和叙述文本都最优。

### 面试简答版

Fixed 按固定 token 切，便宜稳定但容易截断语义；Recursive 按章节、段落、句子逐级拆，是普通文本的通用强基线；Semantic 根据相邻表示的主题变化切，适合缺少可靠格式的访谈或长叙述，但成本高、阈值敏感且块长不均；Structure-Aware 按标题树、表格、代码 AST 或法律条款切，最能保留作者结构，但依赖解析器。生产中通常先结构化，再递归装箱，必要时语义切分，并用 child 检索、parent 回填兼顾精确召回与完整上下文。
