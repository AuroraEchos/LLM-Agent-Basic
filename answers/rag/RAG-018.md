## 我的答案

可验证引用要求建立一条不可伪造的链：**答案中的具体 claim → 引用 ID → 实际送入模型的证据片段 → 原文版本与位置**。不能让模型自由编 URL、页码或来源名。

### 一、上下文准备

服务端为每个检索片段分配短而稳定的 ID：

```text
[S1]
source_id: policy-2026-v3
title: 费用政策 > 退款
location: page 12 / chars 840-1020
content: ...
```

映射表保存在结构化状态中，模型只允许输出 `[S1]`，最终由服务端渲染为真实链接、页码和高亮范围。这样可阻止模型引用未检索来源，也便于文档更新后识别版本。

### 二、生成格式

Prompt 要求：

- 每个外部可验证事实、数字、日期和关键结论紧跟引用；
- 一个引用只支持它实际蕴含的 claim；
- 无证据时说“不足以判断”，不得借参数记忆补事实；
- 多来源冲突时分别引用并说明口径；
- 输出结构化 `claims: [{text, citation_ids}]`，再渲染自然语言，可靠性通常高于事后从整段答案猜引用。

### 三、引用一致性检测

先把答案拆成原子 claim \(c_i\)，对其引用证据集合 \(E_i\) 判断蕴含：

\[
\operatorname{support}(c_i,E_i)\in
\{entailed, contradicted, insufficient\}
\]

检测可分层：

1. **格式/存在性**：ID 是否来自允许集合，链接和页码能否解析；
2. **定位一致性**：引用文本是否仍与索引 hash/版本匹配；
3. **词法与字段规则**：数字、单位、日期、实体、否定极性是否一致；
4. **语义蕴含**：NLI/LLM judge 判断证据是否足以支持 claim，而非仅主题相关；
5. **人工审计**：高风险、冲突或低置信样本回看原页。

LLM judge 自身会错，需用人工标注集校准阈值、测 precision/recall，并尽量让 judge 与生成模型、训练 reward 隔离。

### 四、核心指标

- Citation correctness/precision：给出的引用中真正支持 claim 的比例；
- Citation completeness/recall：需要证据的 claim 中有充分引用的比例；
- Citation validity：引用 ID 与原文位置真实有效的比例；
- Faithfulness：答案 claim 能否从检索上下文推出；
- Source quality：即使引用一致，来源本身是否权威、新鲜且适用。

“引用真实存在”不等于“支持这句话”；“支持这句话”也不等于来源事实正确，这三层要分开。

### 五、工程边界

合并或摘要 chunk 后仍要保留字符/单元格级 provenance；表格引用应带表名、行键、列名和单位；PDF 最好保存页码与 bounding box。访问链接时再次执行 ACL，不能因答案中出现 citation URL 绕过权限。文档删除或更新后，历史回答应显示其引用版本已过期，而非悄悄指向新文本。

### 面试简答版

我会给每个实际检索片段分配服务端 citation ID，保存 source、版本、页码/字符范围和 hash，只让模型输出 ID，再由服务端渲染链接，禁止模型自由编来源。答案先结构化为原子 claim 与 citation_ids。校验分四层：ID 是否存在、原文版本是否匹配、数字/日期/否定等字段是否一致、NLI 或独立 LLM 是否判断证据蕴含 claim；高风险低置信样本人工复核。分别报告 citation validity、precision、completeness 和 faithfulness，并区分“引用存在”“引用支持结论”“来源本身可信”。
