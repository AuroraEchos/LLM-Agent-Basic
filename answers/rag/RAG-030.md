## 我的答案

企业级 RAG 监控要能回答四个问题：**答得对吗、哪里慢、钱花在哪、有没有越权或被攻击**。只监控 LLM 请求成功率无法发现“系统稳定地返回错误答案”。应把每次请求的 trace 贯穿 ingestion、retrieval、rerank、context、generation 和 citation。

### 一、质量指标

- 数据层：解析成功率、空块/乱码/重复率、文档覆盖、新鲜度和索引延迟；
- 召回层：离线 golden Recall@K/Hit@K、零结果率、过滤后不足 K、各路贡献与 score 分布；
- 重排/上下文：NDCG、gold rank 变化、context precision、重复 token、unique source、冲突率和截断率；
- 生成：正确性、answer completeness/relevance、faithfulness、拒答和 unsupported claim；
- 引用：validity、precision、completeness、链接可访问率；
- 用户信号：纠正/升级人工、重复提问、满意度，但点击和点赞不能替代真值。

线上无 gold 时用小比例抽样人工审计、独立 LLM judge 和 canary questions；judge 必须在人工集上校准并监控漂移。

### 二、延迟与可靠性

按 stage 记录 p50/p95/p99：认证、query rewrite、embedding、BM25/dense、rerank、上下文构造、LLM TTFT/生成和校验。另看端到端 timeout、错误率、QPS、并发、限流、索引可用性、缓存命中、降级/重试和队列积压。

平均值会掩盖尾延迟；按租户、query 类型、候选数、文档长度和模型切片。重试可能让成功率好看却翻倍成本，必须单独记录。

### 三、成本与容量

- ingestion/OCR/embedding/图抽取与全量重索引成本；
- 每请求检索、rerank、input/output tokens、工具和 guardrail 成本；
- 向量/倒排/原文存储、备份与网络流量；
- `cost per answered query`、`cost per correct answer`、每租户预算；
- rollout/query fan-out、缓存节省和闲置 GPU/副本利用率。

设置预算告警和 per-tenant quota，优化时同时看 quality–latency–cost Pareto，不能以降低 token 为由牺牲证据完整性。

### 四、安全与合规

- 跨租户/越权检索必须为零，ACL propagation 和删除 SLA；
- prompt injection/poisoning 检测率、来源信任分布、异常文档命中激增；
- PII/secret 输出、DLP 拦截、系统 Prompt 泄漏和恶意 URL；
- 未授权工具调用、审批绕过、网络 egress 和 sandbox 违规；
- cache leakage、citation 篡改、审计日志完整性；
- 密钥轮换、依赖漏洞、数据驻留与留存策略。

安全告警需能关联到文档和所有受影响请求，并有 quarantine、cache invalidation 与 kill switch。

### 五、SLO、告警和发布

为关键用户旅程定义 SLO，而非单指标：例如授权正确、索引新鲜、p95、faithfulness/人工正确率与可用性。告警结合错误预算和持续窗口，避免瞬时噪声。

每次更换 parser、chunker、embedding、索引、reranker、Prompt 或 LLM，都记录版本并运行离线回归、shadow/canary 和安全红队。Dashboard 可分 executive 端到端 SLO 与工程 stage metrics；单次请求可下钻完整 trace，但对日志脱敏和限权。

### 面试简答版

企业 RAG 要分层监控：数据解析与索引新鲜度；Recall@K、零结果和 rerank NDCG；上下文 precision、重复与冲突；答案 correctness、faithfulness、拒答和引用；各阶段 p95/p99、TTFT、QPS、超时；每请求 token、重排、存储和每个正确答案成本；以及跨租户、ACL/删除传播、注入投毒、PII、缓存和工具安全。每条请求绑定数据、索引、模型和 Prompt 版本并可下钻 trace。所有组件变更先离线回归，再 shadow/canary 与红队，并为高价值路径定义质量、延迟和安全 SLO。
