## 我的答案

这些指标覆盖 RAG 的不同层：Recall@K 看“有没有找回来”，MRR 看“第一个正确结果有多靠前”，NDCG 看“整份分级排序有多好”，Context Precision 看“交给模型的上下文有多纯”，Faithfulness 看“答案有没有超出证据”。不能用其中一个替代端到端质量。

### 一、Recall@K

对 query 的相关文档集合 \(Rel\) 与 top-K 结果 \(Ret_K\)：

\[
Recall@K=\frac{|Rel\cap Ret_K|}{|Rel|}
\]

若每题只有一个 gold evidence，常退化为 Hit@K（命中为 1）。它衡量召回覆盖，适合第一阶段 retriever；不关心正确证据排第 1 还是第 K，也不惩罚大量无关候选。

多跳问题应评估“所有必要证据是否都命中”，仅命中一跳不能算完整成功。

### 二、MRR

设第 \(i\) 个 query 的首个相关结果排名为 \(rank_i\)：

\[
MRR=\frac1Q\sum_{i=1}^{Q}\frac1{rank_i}
\]

没有相关结果贡献 0。它强烈奖励第一个正确结果靠前，适合导航、单答案或用户通常只看首个命中的场景；但忽略第二个及之后的所有相关证据，不适合评价多证据完整性。

### 三、NDCG@K

NDCG 支持 graded relevance。设第 \(i\) 名相关等级为 \(rel_i\)：

\[
DCG@K=\sum_{i=1}^{K}\frac{2^{rel_i}-1}{\log_2(i+1)},
\qquad NDCG@K=\frac{DCG@K}{IDCG@K}
\]

IDCG 是理想排序的 DCG。它同时考虑相关程度和位置，适合 reranker、多答案和“直接证据 > 背景证据 > 无关”的标注。若只有二元单正例，优势比 MRR 小。

### 四、Context Precision

它衡量最终 retrieved context 中相关内容的比例或相关 chunk 是否排在前面。最简单的集合版本为：

\[
ContextPrecision=\frac{\# relevant\ retrieved\ chunks}{\# retrieved\ chunks}
\]

不同框架可能使用 rank-aware 定义或 LLM judge 判相关，因此报告时必须写清具体实现。高值说明上下文噪声少，但如果只返回一个相关块却漏掉其余必要证据，precision 高而 recall 低。

### 五、Faithfulness

先把答案拆为可验证 claim，计算能被检索上下文支持的比例：

\[
Faithfulness=\frac{\# supported\ answer\ claims}{\# answer\ claims}
\]

它评价生成是否 grounded，不等于答案正确性：若上下文本身错误，忠实复述仍可 faithfulness 高；模型只回答一个安全但不完整的事实也可能高。因此要搭配 factual correctness、answer completeness 和 source quality。

### 六、怎样组合使用

```text
Retriever：Recall@K / Hit@K
Ranker：MRR、NDCG@K
Context builder：Context Precision + evidence completeness
Generator：Faithfulness + correctness + citation metrics
System：latency、cost、refusal/no-answer quality
```

所有指标要按 query 类型、语言、文档版本和难度切片，并给置信区间。标注单位也要明确是 document、chunk 还是原子 evidence；重叠 chunk 不能被当作多个独立正例。

### 面试简答版

Recall@K 看所有相关证据有多少进入 top-K，适合召回层但不关心顺序；MRR 用首个相关结果排名倒数，强调第一个正确结果；NDCG 用位置折损和分级相关度评价整份排序，适合 reranker；Context Precision 看最终上下文中相关证据的纯度或排序质量；Faithfulness 看答案中的 claim 是否可由上下文推出。Faithfulness 高不保证来源正确，Precision 高也可能漏证据，所以要把 recall、ranking、context、grounding 与最终 correctness 分层联合评估。
