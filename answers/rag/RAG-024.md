## 我的答案

Graph RAG 将文档中的实体和关系显式连接，既可沿局部关系检索多跳证据，也可对图社区预生成摘要回答“整个语料有哪些主题”这类全局问题。这里以 Microsoft 的 [From Local to Global](https://arxiv.org/abs/2404.16130) 方法为代表，但广义 Graph RAG 还有许多不同实现。

### 一、离线建图

```text
文档解析与 text units
→ LLM/IE 抽取实体、类型、关系、claims
→ 实体消歧与合并
→ 节点/边绑定原文 provenance
→ 图清洗、加权、社区检测
→ 分层社区报告 + 向量索引
```

实体节点可为人、组织、地点、概念；边含关系类型、方向、描述、时间、置信度和证据片段。实体消歧是核心难点：同名不能误合并，别名不能漏合并。所有事实必须回链 text unit，LLM 抽取结果不能自动当真值。

### 二、社区与摘要

对实体关系图运行 Leiden 等社区检测，得到相互关联较密的群组，并可形成从细到粗的层级。每个社区收集其实体、关系和原始证据，由 LLM 生成 community report，包括主题、关键实体、关系和 supporting evidence。

社区摘要是有损派生数据：要保存生成模型、Prompt、图版本和来源，图更新后只刷新受影响社区；还要检查摘要是否遗漏少数但重要事实或放大抽取错误。

### 三、查询模式

#### Local Search

适合“某实体与谁相关、发生了什么”。先用 query 匹配实体/节点，扩展一到多跳邻域，再结合关系、claims、社区信息和原始 text units 组装上下文。限制路径长度、关系类型、时间与预算，避免高度节点导致邻域爆炸。

#### Global Search

适合“语料的主要主题、跨文档趋势是什么”。从选定社区层级的 reports 出发，采用 map-reduce：各批报告生成带重要度的中间要点，再聚合高价值要点生成答案。官方说明可见 [GraphRAG Global Search](https://microsoft.github.io/graphrag/query/global_search/)。

### 四、多跳问题

将 query 链接到起点实体，按允许关系做 beam/path search：

\[
score(path)=\sum_e relevance(e)-\lambda\,length(path)
+\gamma\,sourceQuality(path)
\]

对候选路径补回每条边的原始文本，rerank 后让模型在显式路径上推理。必须防止仅因图中存在 A–B、B–C 就声称 A–C 关系成立；关系方向、时间和限定条件必须保留。

### 五、边界

图构建和社区摘要的 LLM 成本高，增量更新、实体消歧与时态事实复杂；抽取错误会跨社区和路径传播。结构清晰、跨文档关系/全局主题丰富的语料更受益；简单 FAQ 或精确段落查找往往普通 hybrid RAG 更便宜。应与向量基线在固定成本下比较 local/global query 的正确率、引用、构建时间和新鲜度。

### 面试简答版

Graph RAG 先从 text units 抽取带 provenance 的实体、关系和 claims，做实体消歧并构图；再运行社区检测形成层级，对每个社区预生成可追溯摘要。实体问题用 local search：链接起点实体、扩展受限邻域并补回原文；全语料主题问题用 global search：对社区报告 map-reduce。多跳时检索显式关系路径，再验证每条边的方向、时间和证据。它擅长跨文档关系与全局总结，但建图、摘要、更新昂贵，抽取错误会传播，因此不能替代原文引用和普通向量基线。
