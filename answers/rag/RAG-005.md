## 我的答案

Chunk Size 与 Overlap 决定了检索系统的基本“分辨率”。**小块更容易精确命中但上下文不足；大块信息完整但语义被稀释、成本更高；Overlap 能缓解边界截断，却会制造重复、索引膨胀和分数相关性。** 最优值取决于问题所需证据跨度，而不是一个通用常数。

### 一、Chunk Size 的影响

#### 小 Chunk

优点：

- embedding 表示的主题更单一，细粒度问题更容易匹配；
- 相同生成预算可容纳更多来源，重排也更精确；
- 引用能定位到具体句段，减少无关内容。

问题：

- 定义与解释、条件与结论、表头与数据可能被分开；
- 块脱离标题和上文后产生代词、缩写和主体歧义；
- chunk 数量、索引条目和 ANN 候选去重成本增加；
- 回答多跳问题需要命中多个相邻块，单块 Recall 高不代表证据集合完整。

#### 大 Chunk

优点：保留完整段落、步骤、表格或章节关系，一次命中就可能提供足够生成上下文；chunk 数量更少。

问题：

- 一个向量要压缩多个主题，局部相关信号被平均，精确召回下降；
- 无关 token 占用 context window，增加 prefill 延迟与 LLM 成本；
- top-k 相同的情况下覆盖的独立来源变少；
- 长上下文中模型可能忽略中部证据，引用粒度也更粗。

因此 size 不是越小 recall 越高：如果正确答案需要跨两段，小块且只取很小 top-k 反而会漏掉完整证据。

### 二、Overlap 的影响

设原文长度为 \(N\)，chunk size 为 \(S\)，相邻重叠为 \(O<S\)，步长为 \(S-O\)，块数近似：

\[
n\approx 1+\left\lceil\frac{N-S}{S-O}\right\rceil
\]

索引文本膨胀倍数近似为：

\[
\frac{S}{S-O}=\frac{1}{1-O/S}
\]

例如 512-token 块重叠 128，理论膨胀约 \(512/384=1.33\) 倍；重叠 256 则约 2 倍。

适度 overlap 能让跨边界的句子、定义和条件至少在某个块中保持完整，提高 boundary recall。但过大 overlap 会：

- 重复计算 embedding、占用存储并增加增量更新成本；
- top-k 被几乎相同的相邻块占满，降低文档/观点多样性；
- 重复内容挤占 LLM 上下文，增加延迟和费用；
- 使离线评测虚高：多个命中可能其实是同一证据副本。

所以在线组装前要按文档位置合并邻块、去重或做 MMR，多样性指标应按 source/evidence cluster 计算。

### 三、对召回与生成的联合影响

可以把总成功率粗略理解为：

\[
P(\text{correct})\approx
P(\text{evidence retrieved})
\times P(\text{answer correct}\mid\text{context})
\]

小块可能提高第一项中的定位精度，却降低第二项的上下文完整性；大块相反。Overlap 主要减少边界导致的第一项损失，但过度重复又会破坏重排和上下文利用。

只优化 embedding Recall@k 可能选出非常小且高度重叠的块，却让最终回答更差。必须端到端联合看 evidence recall、answer accuracy/faithfulness 和 token 成本。

### 四、实用调参方法

1. 先根据自然证据单元定范围：FAQ 可较小，法律条款/技术步骤较大，表格按结构处理；
2. 用 tokenizer 而非字符计数，并为标题、metadata 和生成 Prompt 预留预算；
3. 建立真实 query—evidence 集，网格测试 size 与 overlap，而非只看几个 demo；
4. 固定总 retrieval/context token budget 比较，避免“大块 top-10”天然使用更多计算；
5. 同时测 Recall@k、MRR/nDCG、完整证据召回、重复率、最终正确性、引用准确率、p95 延迟和单请求成本；
6. 按短事实、多跳、表格、代码、长文档分别切片；
7. 命中小块后动态扩展相邻或 parent context，比把所有索引块永久做大更灵活。

### 五、常见起点而非标准答案

普通知识文档可以从数百 token、约 10%～20% overlap 做 baseline，再通过评测调整。若结构边界清晰，应优先在段落/章节处切，overlap 可以更小；若 OCR 文本边界混乱，可适度增加 overlap，但首先应修解析。代码和表格不应机械套这一经验值。

还可根据查询动态选择粒度：精确 ID/术语查询召回小块，解释性问题回填父章节，多跳问题检索多个互补块。

### 面试简答版

小 chunk 主题单一、定位和引用精确，但容易丢掉标题、条件和跨段关系，索引条目也更多；大 chunk 上下文完整，却会稀释局部语义、占用生成窗口并增加 prefill 成本。Overlap 能覆盖切分边界，但其索引膨胀近似为 \(S/(S-O)\)，过大会让相似块占满 top-k 和上下文。调参要按真实证据跨度，固定总检索/上下文 token 预算，同时评估完整证据 Recall、nDCG、最终正确性、重复率、延迟和成本。常用做法是小块检索、去重后按 parent 或邻接块动态扩展。
