## 我的答案

RRF（Reciprocal Rank Fusion）是一种只依赖**名次**、不依赖原始分数尺度的多路排序融合方法。它特别适合把 cosine、BM25、不同 query rewrite 的结果合并，因为这些分数无法直接比较。

### 一、公式

对多个排序器 \(R_1,\ldots,R_m\)，文档 \(d\) 的 RRF 分数为：

\[
\operatorname{RRF}(d)=
\sum_{j=1}^{m}\frac{w_j}{K+\operatorname{rank}_j(d)}
\]

- \(\operatorname{rank}_j(d)\) 通常从 1 开始；
- 若 \(d\) 不在第 \(j\) 路截断列表中，该路贡献 0；
- \(K\) 是 rank constant，用来控制头部名次差异的强弱；
- \(w_j\) 是可选的路权重，原始无权版本可令全部为 1。

原始方法见 [Cormack、Clarke 与 Büttcher 的 RRF 论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)。

例如 \(K=60\) 时，某 chunk 在 dense 排第 1、BM25 排第 4：

\[
s=\frac1{61}+\frac1{64}
\]

另一 chunk 只在 dense 排第 1，则只有 \(1/61\)。因此多个列表都靠前的候选会得到共识加成，但只被某一路强烈命中的稀有实体也仍能进入结果。

### 二、为什么 RRF 稳健

BM25 分数可能从 0 到几十，cosine 常在一个较窄区间；直接相加会让数值尺度更大的一路支配。RRF 抛弃分数绝对值，只利用顺序，因此：

- 不要求跨 retriever 做 score calibration；
- 对单路异常大分数不敏感；
- 可融合 dense、sparse、多语言、多 query rewrite 和不同索引；
- 实现简单，适合作为无训练数据时的 baseline。

代价是丢失了分数间距信息：第 1 与第 2 的巨大置信差在 RRF 看来只是一名之差；质量很差的一路也可能持续注入噪声。

### 三、参数 \(K\) 的作用

较小 \(K\) 时，头部名次差异更显著：

\[
\frac1{K+1}-\frac1{K+10}
\]

会更大，融合更信任各路 top rank；较大 \(K\) 会压平同一路内部的名次差异，更强调“被多少路共同召回”。经典实现常从 60 开始，但它不是普适最优值。

调参应联合考虑每路 retrieval depth：如果每路只取 top-10，却设很大的 \(K\)，1～10 名贡献非常接近；若取 top-1000，尾部大量弱候选可能累积噪声。候选深度、\(K\)、最终 top-n 和 reranker 容量要一起搜索。

### 四、权重如何选择

若两路整体同等可靠，先用 \(w_j=1\)。有标注集后可按 query 类型调权：

- exact ID query 增大 BM25 权重；
- 释义/跨语言 query 增大 dense 权重；
- 某个 query rewrite 质量不稳定则减权；
- 不同路返回重复度很高时，增加它的权重未必有收益。

权重需通过 validation set 的 Recall/nDCG 和端到端答案效果选择，不能用同一个 test set 反复调参。若数据充足，也可使用 learning-to-rank 或校准后的 score fusion，但复杂度和漂移风险更高。

### 五、工程细节与陷阱

1. 先统一 canonical chunk/document ID，同一结果跨路出现时必须合并；
2. 明确 rank 从 0 还是 1 开始，线上线下保持一致；
3. ACL、租户和时间过滤尽量在各路召回时执行，不能融合后泄漏；
4. 若融合 chunk，避免同一文档的重叠块占满 top-k，可做 source cap 或 MMR；
5. 记录每个最终结果的逐路 rank 与贡献，便于解释和调试；
6. RRF 只做候选融合，通常之后仍需 cross-encoder/LLM rerank 判断真正相关性；
7. 新增一路会改变总分分布，若下游用绝对阈值需重新校准。

### 面试简答版

RRF 用 \(\sum_j w_j/(K+rank_j(d))\) 融合多路结果，不比较 BM25、cosine 等不可比的原始分数。候选在多路都靠前会累积更高分，只在一路命中也能保留。\(K\) 小时更强调每路头部名次，\(K\) 大时排名更平、共识更重要；60 只是常用起点，要与各路 top-k 和 reranker 容量联合验证。默认先等权，有业务标注后再按 exact/semantic query 调权，并做好 ID 去重、ACL、一致的 rank 起点和逐路贡献日志。
