> **问题：** 如何区分检索失败、重排失败、上下文构造失败和生成失败？

## 我的答案

区分四类失败的关键是保存端到端 trace，并用 gold evidence 在每个漏斗节点做“oracle 检查”。同一个错误答案不能仅凭肉眼归因于“模型幻觉”。

### 一、逐层判定

| 层 | 判定问题 | 失败证据 |
|---|---|---|
| 检索 | gold evidence 是否进入初始候选 Top-K？ | 没进入，或被错误 filter/ACL 排除 |
| 重排 | 已进入候选的 gold 是否进入 rerank 后 Top-N/最终候选？ | 分数过低，被噪声挤出 |
| 上下文构造 | gold 是否完整、无截断且真正进入最终 Prompt？ | 去重/扩展/预算/顺序导致丢失或缺关键条件 |
| 生成 | Prompt 中已有充分证据，答案是否正确使用？ | 忽略、曲解、混合冲突或无依据补充 |

### 二、Oracle 实验

1. **Oracle retrieval**：直接把 gold chunks 交给现有重排/生成；若恢复，召回是主因。
2. **Oracle rerank**：把 gold 强制放在上下文首部；若恢复，说明 rank/cutoff 有问题。
3. **Oracle context**：人工构造最小充分、无冲突证据；若仍失败，生成/Prompt/模型能力有问题。
4. **Oracle answer from evidence**：让规则或专家抽取答案，区分知识链路与任务本身不可判定。

一次只替换一层，并保持其他层、模型和 Prompt 不变，才能建立因果归因。

### 三、必须记录的 Trace

```text
原 query / 改写 / filters / ACL
各 retriever 候选、分数、rank、索引版本
融合与 rerank 前后列表、删除原因
parent 扩展、去重、截断和最终 token 位置
完整 Prompt、模型版本、生成参数
答案 claim、citation 和校验结果
```

还要区分源文档/解析错误：如果 gold 在原文件中，却在索引 chunk 中已经错乱，它属于 ingestion failure，不能算向量检索器的问题。

### 四、自动化故障标签

有 evidence 标注时可以生成漏斗指标：`gold_in_retrieval`、`gold_after_rerank`、`gold_in_prompt`、`answer_supported`。无 gold 时可先用独立 judge 找出支持答案的候选，再人工复核；不确定就标 unknown，不能强行归类。

多跳问题要检查每一跳，因为“召回了一半”与完全漏召回不同。生成失败还可细分为 evidence ignored、contradiction mishandled、unsupported claim、format failure 和 refusal error。

### 面试简答版

我会保留每层候选和最终 Prompt，用 gold evidence 做漏斗诊断：没进初始 Top-K 是检索失败；进了候选却被 reranker 排除是重排失败；重排后存在但在去重、parent 扩展、token 截断或排序中没完整进入 Prompt，是上下文构造失败；最小充分证据已在 Prompt 中却仍答错，才是生成失败。再用 oracle retrieval、oracle rerank 和人工最小上下文逐层替换验证因果。解析错误应单列 ingestion failure，多跳问题逐跳检查。
