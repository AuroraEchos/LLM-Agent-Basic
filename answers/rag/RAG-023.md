## 我的答案

Agentic RAG 把一次固定检索改为带状态的决策过程：模型可判断是否需要外部知识、选择检索器、阅读结果、改写或分解问题并循环，直到证据充分或预算耗尽。关键是让停止由**证据充分性与预算**共同控制，而不是让模型凭感觉无限搜索。

### 一、是否检索

可用规则 + 分类器/LLM router：

- 需要最新、私有、可引用事实或用户明确要求来源 → 必须检索；
- 数学计算、数据库状态、执行动作 → 调对应工具，而非文档 RAG；
- 闲聊、改写用户提供文本、无需外部事实 → 可不检索；
- 不确定时优先低成本检索，但高风险领域不能依赖参数记忆。

Router 应用标注集评估 false negative；“不检索却自信回答”通常比一次多余检索更危险。

### 二、选择检索器

| 查询特征 | 路由 |
|---|---|
| 错误码、SKU、引号、专名 | BM25/精确索引 |
| 同义改写、概念解释 | Dense |
| 混合自然语言与 ID | Hybrid + rerank |
| 关系路径、多跳实体 | Knowledge Graph/Graph retrieval |
| 数值聚合、过滤、实时状态 | SQL/API |
| 全语料主题与趋势 | Community summaries/Graph global search |

复杂问题先 decomposition；子问题可并行，但后续依赖前一步实体时应串行。每次 action 保存 query、结果、引用、覆盖的子目标和未解决项。

### 三、证据充分性与继续条件

把当前状态表示为：

\[
S_t=(Q_{remaining},E_t,C_t,B_t)
\]

分别是未解决子问题、已收集证据、冲突和剩余预算。继续检索当：必要 claim 无支持、来源冲突未解释、检索置信低或还存在未完成子问题。可用 coverage rubric、citation entailment、结果分数与来源多样性共同判断，不应只看向量最高分。

### 四、停止条件

- 所有必要 claim 有足够、适用且可引用的证据；
- 新一轮没有新增独立证据，边际收益低；
- 达到最大轮数、tool calls、token、时间或费用；
- 连续 query 语义重复或结果集合高度重合；
- 权威来源明确无答案，或用户权限不足。

预算耗尽但证据不足时必须带不确定性回答或拒答，不能把“停止搜索”误当成“已经知道”。

### 五、工程防护与评测

检索内容是不可信数据，不能执行其中指令；工具 schema、域名、SQL 与 ACL 由服务端限制。循环需要去重和幂等，缓存相同 query，并记录完整 trajectory。

评测除最终正确率，还看 retrieval decision precision/recall、router accuracy、平均轮数、成功所需 tool calls、证据覆盖、停止过早/过晚率和成本。与固定单轮 RAG 在相同预算下比较，证明 agent loop 的收益来自更好证据而非只用了更多计算。

### 面试简答版

Agentic RAG 先由 router 判断任务是否需要最新/私有事实、引用、计算或工具，再按查询类型选择 BM25、Dense、Hybrid、KG、SQL/API；复杂问题分解为子问题并维护已收集证据、冲突和未完成项。只要必要 claim 没有支持、冲突未解或检索置信低就继续；证据充分、新一轮无新增，或达到轮数/token/延迟预算就停止。预算耗尽不等于知道答案，应明确证据不足。还要限制循环、ACL 和工具权限，并在相同预算下评估路由、停止、证据覆盖与成本。
