## 我的答案

三者都在解决朴素“先切块、每块独立编码、原块直接给 LLM”造成的**检索粒度与上下文完整性冲突**，但作用位置不同：Parent-Child/Small-to-Big 在检索后扩大返回上下文；Late Chunking 在生成 chunk embedding 时引入全文上下文。

### 一、Parent-Child Chunk

离线同时保存两种粒度：

```text
Parent：完整章节或较大段落，适合生成
  ├─ Child 1：小片段，建立向量索引
  ├─ Child 2：小片段，建立向量索引
  └─ Child 3：小片段，建立向量索引
```

查询时对 child 做精确匹配，命中后通过 `parent_id` 取回较大的 parent。它解决“小块容易搜到但脱离上下文，大块上下文全却难以精确匹配”的矛盾。

实现要点：

- child 与 parent 使用稳定 ID、版本和相同 ACL；
- 多个 child 命中同一 parent 时合并分数与去重，避免重复塞入；
- parent 不能无限大，需按 token budget 截取命中位置附近内容；
- parent 更新时要原子替换所有 child，不能残留旧引用。

### 二、Small-to-Big Retrieval

Small-to-Big 是更广义的查询时上下文扩展策略：先用小单元检索和重排，再根据需要扩展到相邻句、窗口、父章节、整张表或完整函数。Parent-Child 是它的一种层级实现。

例如命中条款 3.2 的一句话后，可以取：

\[
C_{final}=C_{hit}\cup C_{prev}\cup C_{next}\cup C_{header}
\]

扩展范围可根据 query 类型、reranker 分数和剩余 token budget 动态决定。它不仅能取固定 parent，还能：

- 合并连续命中的相邻 child；
- 为表格补完整表头和相关行；
- 为代码补函数签名、类定义或被引用符号；
- 为多跳问题保留多个来源，而不是一个巨大父块。

风险是“一个小命中扩展整章”引入大量噪声。应先去重、合并区间，再进行 context-level rerank，并监控扩展前后 evidence precision 和 token 增量。

### 三、Late Chunking

普通方法先切文本，再让 embedding model 分别编码：

\[
e_i=\operatorname{Pool}(E(c_i))
\]

因此 `他于 2020 年接任 CEO` 这类 chunk 单独看时可能不知道“他”是谁。Late Chunking 则先让长上下文 embedding model 对较长文档一次性产生上下文化 token hidden states，再按预先确定的 chunk token span 池化：

\[
(h_1,\ldots,h_n)=E(x_{1:n}),\qquad
e_{a:b}=\operatorname{Pool}(h_a,\ldots,h_b)
\]

切分发生在 Transformer 编码之后、pooling 之前，所以该 chunk 中每个 token 表示已经通过 self-attention 看过周围文档上下文。原始方法见 [Late Chunking 论文](https://arxiv.org/abs/2409.04701)。

它仍然产出小 chunk 向量，却减少指代、省略和局部片段“离开全文就无法理解”的问题；不需要把大 parent 全部返回给生成模型。

### 四、Late Chunking 的限制

- 文档必须放得进 embedding model 的有效上下文，超长文档仍需分段；
- 编码整篇长文的 attention、显存与延迟更高，局部修改也可能要求重算较大范围；
- 要准确把字符级 chunk 边界映射到 token span，并正确处理特殊 token 和 padding；
- embedding model 必须真的能利用长上下文，标称窗口大不等于远距离信息质量稳定；
- 它改善表示，不会自动恢复给生成模型的缺失原文，回答阶段仍可能需要 parent/neighbor expansion；
- 全文上下文也可能把多个主题混入局部表示，必须在领域数据上评估。

### 五、如何选择与组合

| 方法 | 介入阶段 | 直接解决的问题 | 主要代价 |
|---|---|---|---|
| Parent-Child | 检索后 | 小块命中后缺大段语境 | parent 占用生成 token、去重复杂 |
| Small-to-Big | 检索后动态扩展 | 固定 parent 粒度不灵活 | 扩展策略与二次重排复杂 |
| Late Chunking | embedding 阶段 | 小块向量本身缺全文语境 | 长文编码成本、上下文长度限制 |

它们可以组合：Late Chunking 生成更有上下文的 child embedding，先精确检索 child，再按 Small-to-Big 只补充生成所需的 parent/邻块。评测需分别看 child Recall@k、扩展后证据完整率、上下文 precision、最终 faithfulness、索引时间和在线 token 成本。

### 面试简答版

Parent-Child 为小块建索引，命中后按 parent ID 返回大章节，兼顾精确召回和生成上下文；Small-to-Big 是更通用的动态扩展，可按查询与预算补邻块、标题、表头或父节点，Parent-Child 是其特例。Late Chunking 则先用长上下文 embedding model 编码整段文档，再对每个 chunk 对应的 contextualized token states 池化，使小块向量包含全文指代和背景。前两者解决返回上下文不足，后者解决 chunk 表示本身失去语境；生产中可组合，但要控制长文编码和扩展 token 成本。
