> **问题：** `P0` 缓存穿透、击穿和雪崩分别是什么，常见治理方式有哪些？

> **分类：** 缓存、消息队列与分布式基础

> **来源：** [ENGINEERING_FOUNDATIONS_PATCH.md](../../ENGINEERING_FOUNDATIONS_PATCH.md)

## 我的答案

- **缓存穿透**：持续查询本来就不存在/无权限的数据，cache 总 miss，请求每次打到 DB。可能是错误参数、攻击或没有缓存空结果。
- **缓存击穿（hot-key breakdown）**：一个极热 key 过期/被淘汰瞬间，大量并发同时回源，压垮下游。
- **缓存雪崩**：大量 key 同时失效，或整个 cache 集群故障，回源流量在同一时段暴增；范围比单 hot key 更广。

### 治理方法

穿透：入口校验与鉴权、请求限流；缓存“不存在”短 TTL 的 negative result（注意创建后主动失效）；已知合法 key 集可用 Bloom filter 在 cache 前拦截确定不存在者，但 Bloom 有假阳性、删除/重建和租户权限边界，不能替代数据库校验。

击穿：singleflight/request coalescing 让一个请求加载、其他等待；分布式互斥后要 double-check cache；逻辑过期让后台刷新、前台短期返回 stale；热 key 预热/延长 TTL、多级缓存。锁等待必须有 timeout，loader 失败要释放且允许降级，不能让所有请求无界排队。

雪崩：TTL 加随机 jitter，分批预热/刷新，避免同批部署写入同一过期时间；cache 集群高可用与容量/淘汰监控；回源侧限流、bulkhead、熔断、降级/陈旧数据和有界队列。cache 恢复时也要限制重填速度，避免二次冲击。

这些问题本质是流量放大，应监控 hit ratio 但不能只看平均：按 key/tenant 看 miss QPS、backend amplification、loader concurrency、eviction、expired、cache latency 和 DB saturation。若 cache 数据涉及权限，negative/stale 缓存也必须按 tenant/user/版本分区，不能为了可用性泄露旧授权结果。

### 面试简答版

穿透是查不存在数据导致每次回源，用参数校验、限流、短期空值缓存或 Bloom filter；击穿是单个热 key 失效时并发回源，用 singleflight/互斥双检、逻辑过期、后台刷新和预热；雪崩是大批 key 同时过期或 cache 故障，用 TTL jitter、分批刷新、高可用、回源限流熔断和 stale 降级。核心是限制 miss 流量放大，并按 key 监控而非只看整体命中率。
