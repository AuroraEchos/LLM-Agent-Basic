## 我的答案

语音系统要同时保留“说了什么”的语义和“怎么说”的声学信息，并以因果方式处理不断到来的波形。常见路线是级联 `ASR→LLM→TTS`，或将连续/离散音频表示直接接入统一模型；前者可控、易调试，后者能保留语气与低延迟交互，但训练和安全更难。

### 音频表示

1. **连续声学特征**：波形分帧做 STFT，再映射为 log-Mel spectrogram，经 CNN/Conformer/Transformer encoder 产生低帧率 embedding。适合 ASR、说话人和情感理解；时间分辨率高导致序列长，需下采样。
2. **自监督语音表示**：从波形学习上下文特征，兼具音素和部分声学信息，可通过 projector 接 LLM。
3. **离散 codec token**：神经 codec encoder + residual vector quantization 将音频变为多 codebook token，decoder 重建波形。低层 token保留音色/音质，高层更偏语义/韵律；适合统一自回归理解与生成，但 token rate 和多 codebook 使序列很长，量化误差决定音质上限。
4. **文本 token**：先 ASR 得到文字，成本最低、复用 LLM 最容易，却丢音色、语速、重音、环境声和部分情绪。

实际可做双通路：文本/语义 token供推理，压缩声学 token供说话风格与 TTS，避免 LLM 对每个高频声学 token 做全局 attention。

### 流式输入

音频以 10–40ms 帧进入 ring buffer，经 VAD、降噪/回声消除和特征提取，按 chunk 送入 causal/chunked encoder。encoder 缓存左上下文 KV/卷积状态，只允许有限右看窗口；右看越大准确率越好但算法延迟越高。

流式 ASR 输出 partial hypothesis，并标注 stable prefix 与可能修订后缀。LLM 只在语义边界或足够稳定的前缀上启动，避免每次 ASR 改字都重算。Endpointing 结合 VAD 静音、语义完成和最大等待；太激进会截断，太保守使对话停顿。

### 低延迟输出与双工

LLM 流式生成语义/文本 token，TTS 按短语或增量声学 token 合成，音频 decoder 分 chunk 播放并做 overlap/cross-fade。延迟可拆为：

$$
T_{first\ audio}=T_{capture}+T_{endpoint/commit}+T_{encoder}+T_{LLM\ first}+T_{TTS\ first}
$$

只优化 LLM TTFT 可能毫无意义，endpointing 常是最大部分。真正实时交互还要支持 barge-in：用户一开口立即停止尚未播放/生成的音频，取消 LLM/TTS，回声消除避免把系统自己的声音识别成用户，并保存“实际播放到哪里”而非完整生成文本作为对话历史。

网络层使用有序带时间戳的音频 frame、jitter buffer、背压与丢包策略；慢客户端不能无限积压。断线重连携带 session/sequence，但敏感音频不长期缓存。

### 安全、隐私与评估

音频可能包含旁人、声纹、背景地址、隐藏超声/语音指令；需同意、最小化、VAD 分段、访问控制和短保留。声音克隆要验证授权并加水印/滥用检测，高风险工具不能因语音说“我是管理员”就授权。

指标包括 ASR WER/CER、实体/数字准确、语音活动/端点错误、首字/首音频延迟、实时因子 RTF、打断停止延迟、TTS MOS/可懂度/说话人相似、安全和不同口音/噪声切片。用真实网络抖动、重叠说话、回声和长停顿端到端压测。

### 面试简答版

音频可表示为 log-Mel/encoder 连续特征、自监督 embedding、神经 codec 离散 token 或 ASR 文本；前两者适合理解，codec 同时保留语义和声学、可生成，但 token 率高。流式系统用 VAD+chunked causal encoder，缓存左上下文、限制右看，ASR 只提交 stable prefix；LLM 增量生成后由流式 TTS 分块播放。首音频延迟要拆成采集、端点、encoder、LLM 首 token 和 TTS。双工还需回声消除、barge-in 端到端取消，并评测 WER、端点、首音频、RTF、打断延迟、音质和口音公平性。
