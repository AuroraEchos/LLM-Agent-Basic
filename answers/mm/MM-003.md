> **问题：** ViT 如何把图像转换成 token，Patch Size 会带来什么影响？

> **分类：** 多模态大模型

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

ViT 将二维图像切成固定大小 patch，把每个 patch 线性投影成一个 token，再像 NLP Transformer 一样处理 token 序列。

设图像 $x\in\mathbb R^{H\times W\times C}$，patch 边长为 $P$，且 $H,W$ 可被 $P$ 整除，则 token 数为：

$$
N=\frac{H}{P}\cdot\frac{W}{P}=\frac{HW}{P^2}
$$

每个 patch 展平为 $x_p^i\in\mathbb R^{P^2C}$，再做共享线性投影：

$$
z_0=[x_{cls};x_p^1E;x_p^2E;\ldots;x_p^NE]+E_{pos}
$$

其中 $E\in\mathbb R^{P^2C\times D}$，$E_{pos}$ 提供二维位置展开后的位置信息；分类模型常加 `[CLS]`，VLM 通常保留 patch tokens。工程实现中 patchify+linear 等价于 kernel/stride 都为 $P$ 的卷积。

### Patch Size 的影响

**更小的 $P$**：

- token 更多，空间分辨率更高，更有利于小物体、OCR、细粒度定位和密集预测；
- self-attention 复杂度约为 $O(N^2D)$，而 $N\propto1/P^2$，所以 patch 边长减半，token 约变 4 倍，attention pair 约变 16 倍；
- activation、视觉 projector 输出、LLM prefill 和 KV/上下文成本也增加。

**更大的 $P$**：吞吐和显存更好，但一个 token 混合更大区域，细节和边界在 patch embedding 阶段不可逆丢失。即使后面 Transformer 很强，也无法恢复未被采样保留的小字。

例如 $224\times224$ 图像：$P=16$ 时有 $14^2=196$ 个 patch；$P=14$ 时有 $16^2=256$ 个；若分辨率增到 $448$ 而 $P=14$，则为 $32^2=1024$ 个 token。高分辨率输入会快速放大成本。

### 分辨率和位置问题

预训练分辨率与推理分辨率不同，绝对位置 embedding 通常需插值；插值只是形状兼容，不保证对极端长宽比和小字泛化。直接拉伸会改变几何，中心裁剪可能丢内容；文档/图表常使用保持长宽比的 padding、tiling、动态分辨率或多尺度方案，并保存 tile 坐标。

可以用 patch merge、pooling、token pruning、Perceiver/Q-Former resampling 减少进入 LLM 的视觉 token，但要验证是否丢掉问题相关细节。动态 token 数提升效率，却给 batching、位置编码和 serving 带来复杂性。

### 如何选 Patch Size

它是数据与预算相关的超参：分类/自然图像可偏大，OCR、医学影像、遥感和文档问答通常需要更细 patch 或高分辨率 tile。应联合比较目标任务质量、最小目标尺寸、视觉 token 数、encoder latency、LLM TTFT/显存，而非只比较 ImageNet accuracy。

### 面试简答版

ViT 把 $H\times W$ 图像切成 $P\times P$ patch，展平后线性投影为 $D$ 维 token，加位置编码送入 Transformer，token 数是 $N=HW/P^2$。patch 越小，细粒度和 OCR 能力通常越好，但边长减半会让 token 约 4 倍、全注意力 pair 约 16 倍，并增加 VLM 的 prefill 与上下文成本；patch 越大更快但早期丢失小目标和边界。实际还要处理长宽比、位置插值、tiling 和 token 压缩，并按目标任务质量—延迟—显存共同选择。
