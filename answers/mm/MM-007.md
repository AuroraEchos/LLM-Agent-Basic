> **问题：** AnyRes、Image Tiling 和 Naive Dynamic Resolution 分别解决什么问题？

## 我的答案

三者都在解决“现实图片分辨率和长宽比不固定，而 vision encoder 往往按固定尺寸训练”的问题，但抽象层次不同。**Image Tiling 是通用手段，AnyRes 是候选网格式 tiling 策略，Naive Dynamic Resolution 则让原生尺寸直接对应可变 patch/token 序列。**具体实现随模型会有差异，面试时应先说明所指论文或模型版本。

### Image Tiling

把大图按固定窗口或网格切成多张 encoder 能处理的 tile，常加一张全局 thumbnail。它解决固定 vision tower 无法直接处理超大图的问题，工程上容易复用预训练模型。

优点是局部像素密度高、无需改 encoder；缺点是 tile 数随图像增长，边界可能切开文字/物体/跨页表格，重叠产生重复，且模型需理解 tile 在原图中的位置。需要保存 `(row,col,bbox)`、separator 和全局缩略图，并限制最大 tile。

### AnyRes

AnyRes 类方法通常根据原图长宽比和大小，从预定义的分辨率/网格候选中选择一个较合适的画布；图像保持比例 resize/pad 后切为固定大小 patch/tile，再把局部特征和全局视图按空间顺序送入 LLM。

它相比固定单图输入保留更多细节，也相比无上限切图能用有限候选控制 token。问题是网格选择是离散的，padding/切边可能浪费像素，tile 展平后二维结构容易弱化；高宽极端图仍可能需要很多 token。AnyRes 解决的是“利用固定 encoder 支持多种高分辨率与长宽比”，不是原生无限分辨率。

### Naive Dynamic Resolution

这类方案不先把每张图强制变成少数固定网格，而是保持长宽比，将尺寸调整为 patch/merge 单元的整数倍，直接产生与像素数对应的可变数量视觉 token。通常通过 `min_pixels/max_pixels` 或 token budget 控制范围，并使用能表达二维位置的编码。

优点是少做扭曲和无效 padding，分辨率—token 成本连续可调，也方便将多张不同大小图片 pack；缺点是序列长度差异大，训练 batching、位置编码、显存准入和 serving 调度更复杂。没有严格预算时，超长图仍会造成 token 爆炸。

### 对比

| 方案 | 输入处理 | 主要优势 | 主要代价 |
|---|---|---|---|
| 固定 Tiling | 固定窗口切块 | 易实现、兼容任何固定 encoder | 边界/重复、tile 数和位置关系 |
| AnyRes | 从有限候选网格中选择并切 tile | 兼顾长宽比、细节与可控成本 | 离散网格、padding、二维结构重建 |
| Naive Dynamic Resolution | 原生比例产生可变 patch/token | 少扭曲，像素/token 预算连续 | 长度不齐、位置和 serving 更复杂 |

实际系统可混合：原生动态低/中分辨率作为全局视图，对文档小字或用户选区再 tile 放大。选型应在相同最大视觉 token 下比较 OCR、定位、计数、长宽比鲁棒性、TTFT 和显存，不能拿 token 预算不同的结果直接比。

### 面试简答版

Image Tiling 是把高分辨率图切成固定 encoder 能吃的块，通用但有边界、重复和位置重建问题。AnyRes 通常从有限候选网格中按长宽比选一个，resize/pad 后切 tile，并结合全局图，在复用固定 vision tower 的同时控制 token。Naive Dynamic Resolution 则保持长宽比，让实际像素直接变成可变数量 patch token，用 min/max pixel 或 token budget 限制，更少扭曲和 padding，但 batching、位置编码和显存调度更难。比较时必须固定视觉 token 预算，并看 OCR/定位与延迟的 Pareto。
