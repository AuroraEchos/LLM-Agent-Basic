> **问题：** 多图、视频和长文档输入如何组织位置与时间信息？

## 我的答案

这三类输入都需要同时表示**元素内部位置**和**元素之间的顺序/时间/层级**。只把所有 patch token 首尾拼接，会让模型难以区分“第几张图、哪一帧、哪一页”，也容易在上下文变长时丢失绑定关系。

### 多图输入

每张图独立编码，加入稳定的 image index、边界 token 和可选全局描述：

```text
<image_1> [global][2D patch tokens] </image_1>
<image_2> [global][2D patch tokens] </image_2>
问题：比较 image_1 与 image_2 ...
```

视觉 token 内部保留二维 `(x,y)` 或 tile `(row,col,local_x,local_y)` 位置；跨图位置重置或加入 image embedding，不能只依赖一维序列偏移。训练问题要明确引用图片编号，并包含交换图片顺序的反事实样本，防止模型默认“第一张是之前、第二张是之后”。

### 视频输入

视频多一维时间。每个 token 可表示为 `(t,x,y)`，使用可学习 3D position、分解的 spatial+temporal embedding、3D/M-RoPE 或时间 token；关键是让模型知道真实 timestamp，而不只是帧序号，因为采样间隔可能不均匀。

长视频不能逐帧全分辨率编码，通常分层处理：镜头检测/均匀+事件采样→帧/短 clip 编码→空间 token pooling→时间聚合→关键片段高分辨率复查。字幕/ASR 带开始结束时间，与帧时间轴对齐；音画延迟和剪辑跳转要在数据中标注。

任务不同采样不同：动作顺序需要密集相邻帧，长视频摘要需要跨段覆盖，OCR 画面可选稳定关键帧。过稀采样会把“未采到”误当“不存在”，因此回答应能表达证据缺失。

### 长文档

文档位置是层级而非只有页码：`document→section→page→block→line/cell/figure`。每个元素保存 page、bounding box、reading order、标题祖先和原文偏移；表格还需 row/column，跨页表保留表头和续表关系。

输入可按页/章节分组，使用 `<page_i>`、section embedding 与二维 layout position；但百页 PDF 不能把所有视觉 token直接送入 LLM。应先基于 OCR/布局/文本和视觉索引检索相关页或元素，再把命中区域、相邻结构和全局目录放入上下文。跨页问题由层级 retriever 汇总证据。

### 位置编码与上下文工程边界

- 一维绝对位置简单，但混合图像和文本后距离迅速增大，且不能天然表达二维/三维邻接。
- 分解位置编码更高效，但需验证不同分辨率、帧率和页数外推；位置插值不保证泛化。
- 拼接顺序必须与坐标/时间一致，padding 和 packing 要用 attention mask 隔开不同图片/视频，避免跨样本 attention。
- token 压缩要保留索引到原图/帧/页的映射，否则无法提供可验证引用。

评测包括图片顺序交换、多图指代、视频前后/持续时间/事件定位、文档跨页/表格引用，以及在不同帧率、页数和 token 预算下的稳定性。最终答案引用应落到 image id+bbox、timestamp range 或 page+bbox。

### 面试简答版

多图要同时编码每图 ID、边界和图内二维位置；视频在 `(x,y)` 上再加真实时间 $t$，使用空间/时间分解位置或 3D RoPE，并把字幕按 timestamp 对齐；长文档则使用页码、bounding box、reading order 和 section/page/block 层级。多图可直接分组，长视频和长文档必须先分层采样/检索，再对关键片段高分辨率编码。无论如何都要保留压缩 token 到原图、时间段或页坐标的映射，并用顺序交换、事件定位和跨页题评测，而不是只看普通 VQA。
