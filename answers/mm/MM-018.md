## 我的答案

视频比图片多时间维，原始帧高度冗余但关键事件可能很短。系统必须共同解决：采到正确时刻、保留动作顺序、将 $T\times$ 空间 patch 的巨大序列压到模型预算内。

### 帧与片段采样

- **均匀采样**覆盖全局，适合场景摘要，但可能漏掉短事件；
- **随机/分段采样**用于训练增强，每个时间段取一帧或短 clip；
- **密集短 clip**保留局部运动，适合动作、手势和因果顺序；
- **镜头/事件/运动自适应**在切镜、音频峰值、字幕实体或帧差处加密；
- **查询相关采样**先低成本索引全视频，再围绕检索到的时间段高分辨率重看。

所有帧保存真实 timestamp 和采样间隔。变帧率视频只用 frame index 会误判持续时间；没采到某事件时模型应表达证据不足，而不是断言不存在。

### 时序建模

1. 3D CNN/tubelet 同时在空间和时间卷积，局部运动归纳偏置强；
2. 每帧 2D encoder 后用 temporal Transformer/RNN 聚合，易复用图像模型；
3. joint space-time attention 交互最充分，但成本最高；
4. factorized/divided attention 先帧内空间、再同位置/聚合 token 跨时间，将全局 $(TN)^2$ 交互分解；
5. 视频 LLM 将帧/clip token 加 timestamp/3D position 后送 LLM，通过 instruction tuning 学时序问答。

位置需要同时表达 `(t,x,y)`。动作顺序、速度和持续时间评测要求模型使用 temporal position，不能只靠帧内容共现。

### token 爆炸

若每帧 $H\times W$、patch 为 $P$，$T$ 帧视觉 token：

$$
N_v=T\frac{HW}{P^2}
$$

例如每帧 576 token、64 帧就是 36,864 token，直接进 LLM会占满上下文和 prefill/KV。常用压缩：

- patch merge/pooling、Q-Former/resampler，把每帧压到固定 token；
- tubelet 在相邻帧合并时空块，减少时间 token；
- 只保留每帧 CLS/少量 region token，但细粒度定位会下降；
- 相邻帧差异/冗余感知 token pruning，保留变化区域；
- 镜头→片段→全视频分层摘要与 memory；
- 稀疏/局部/分解 attention，或先检索时间段再精看。

压缩后的 token 必须保留到原 timestamp/frame/bbox 的映射，才能定位和引用。摘要不能成为唯一真值，后续精确问题应回查原片段。

### 长视频系统

离线预处理生成镜头、关键帧、ASR/字幕、OCR、对象/动作与多尺度 embedding 索引。查询时做文本—视频混合检索，选 top temporal windows，补前后邻居和字幕，再用多模态模型推理；跨全片问题先分段回答后用证据 reducer 汇总。

在线流式视频使用滑动窗口和持久事件 memory，旧帧压缩为结构化事件；对乱序、丢帧和延迟设置 watermark。隐私上处理人脸、声音、地理和旁观者数据，工具动作不以视频中的文字指令为授权。

### 评估

分别测动作/对象、前后顺序、持续时间、事件定位 IoU、长视频检索、跨段推理、OCR/字幕和幻觉。用帧率变化、删除关键帧、顺序打乱、重复帧和相同场景不同动作做反事实；同时报告帧数/token、P95、显存和每分钟视频成本。

### 面试简答版

视频先按任务选择均匀、分段、密集 clip、镜头/事件或查询相关采样，并保存真实 timestamp。时序可用 3D/tubelet、每帧 encoder+temporal Transformer，或 divided space-time attention；位置编码同时表示 $(t,x,y)$。token 数是 $T\cdot HW/P^2$，长视频必须用空间 pooling、tubelet、resampler、冗余剪枝和镜头—片段—全片分层索引，查询时检索关键时间窗再高分辨率重看。压缩 token 保留到原帧/时间映射，并用顺序打乱、关键帧删除和事件定位评测真实时序能力。
