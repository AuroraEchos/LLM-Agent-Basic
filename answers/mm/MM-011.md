> **问题：** 图文对齐数据中的噪声、错配和重复应如何清洗？

## 我的答案

图文数据清洗不能只设一个 CLIP 相似度阈值。需要分别治理**文件质量、文本质量、图文一致性、精确/近似重复、合规与数据泄漏**，并保留每个决策的来源和 reason code，才能做消融、追责和删除。

### 1. 先做来源与合规治理

源注册时记录 URL/数据 owner、采集时间、许可证/同意、用途、地域、删除渠道和数据分类。图片可能包含人脸、证件、地址或版权水印，caption 也可能含 PII、秘密和有害内容；检测后按策略删除、脱敏、隔离或限制用途。无法确认使用权的数据不应靠“模型训练合理使用”假设直接放行。

原始文件按内容哈希存入不可变 landing zone，清洗产物保存 parent id、代码/模型/阈值版本。先校验 MIME magic bytes、解码、尺寸、长宽比、损坏、纯色/占位图、极端压缩和恶意文件。

### 2. 单模态质量

**图像侧**：过滤过小、严重模糊、截图边框/水印占比过高、重复拼图、NSFW/违法内容；但 OCR、低光和艺术图任务不能沿用自然图阈值。检测多图拼接、文字密度、人脸/敏感区域并打标签，未必全部删除。

**文本侧**：语言识别、Unicode/HTML/模板清理，检查乱码、关键词堆砌、导航文本、过短/过长、机器翻译和生成模板。caption 应描述可见内容；纯文件名、“image”或 SEO 列表信息量低。保留原文和规范化文本两份，避免清洗改变事实。

### 3. 图文错配与噪声

组合多个信号：CLIP/跨模态 embedding 相似度、image-text matching 模型、caption 中实体/属性与检测/OCR 的一致性、网页 DOM 距离和来源信誉。高置信一致直接保留，明显错配删除，中间区域人工抽检或降低权重。

CLIP 分数不是语义真值：短而通用的“一个人”可能高分却信息少；正确的罕见文字/医学描述可能低分；相似度模型还继承偏见。因此阈值按语言、来源和领域校准，并查看 precision/recall，而非全局一刀切。

需要区分：

- **错配**：文字描述了另一张图；
- **部分对齐**：caption 只覆盖图中一个主体，仍可用于全局对比但不适合密集 grounding；
- **矛盾**：颜色、数量、否定或身份与图像冲突；
- **弱关联**：网页主题相关却不是图片描述。

为不同训练目标打用途标签，比把所有非完美样本都删掉更合理。

### 4. 多层去重

- 文件 byte hash 和解码后像素 hash 做完全重复；
- 图像用 pHash/dHash 或局部特征找 resize、裁剪、加水印和轻微编辑的近重复；
- caption 用规范化 hash、n-gram MinHash/LSH 找模板与近重复；
- 图像 embedding + 文本 embedding 联合聚类识别“同图不同 caption”“同 caption 不同图”和成套模板；
- pair-level canonical key 防重复图文对。

保留哪一份依据分辨率、许可、来源、caption 质量和元数据完整性。不要粗暴只留一张图的一个 caption：多条互补且正确的描述可作为多正例；但训练对比损失时，同图/同语义样本若被放进同 batch 当负例，需要多正例 loss 或分组采样。

训练、验证、测试必须按近重复 cluster、网页/视频/文档源 group 切分，防同图裁剪版泄漏到评测。还要与公开 benchmark 做图像及文本近重复污染检测。

### 5. 质量控制与版本化

每个数据版本报告源/语言/主题/人群、分辨率、相似度、过滤、去重簇、PII/安全命中和抽检结果。对阈值上下样本分层盲审，测分类器在小语种和群体上的误删；用训练消融验证高分数据是否真正提升下游，而非只提升 CLIP 相似度。

### 面试简答版

我会分五层清洗图文对：先审来源许可和 PII/安全，再做图片解码、模糊/尺寸及文本语言/模板质量；随后组合 CLIP 相似度、匹配模型、OCR/实体一致和 DOM 来源判断错配，并按语言/领域校准阈值。去重同时做文件/像素 hash、图像 pHash/embedding、文本 MinHash 和 pair cluster；同图的互补 caption 可保留为多正例。训练/评测按近重复 cluster 和来源切分，避免裁剪或水印变体泄漏。所有过滤保留 lineage、reason code、版本和分层人工抽检。
