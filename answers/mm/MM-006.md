## 我的答案

分辨率决定输入中可被视觉编码器保留的最小细节，动态切图决定如何把任意长宽比映射到固定输入的 vision tower，视觉 token 数则决定这些信息进入 LLM 后的显存与延迟。三者是一个**精度—信息—计算预算**联合问题。

### 分辨率与视觉 token

若 ViT patch size 为 $P$，输入尺寸为 $H\times W$，不考虑特殊 token：

$$
N_v=\left\lceil\frac{H}{P}\right\rceil
\left\lceil\frac{W}{P}\right\rceil
$$

分辨率提高通常改善小字、细小目标、图表和密集场景；但也可能加入背景噪声，并且模型若没有在相应分辨率/位置编码上训练，收益会饱和。把长图强行缩成正方形会扭曲内容，中心裁剪又可能直接丢失边缘信息。

视觉编码器 full attention 约为 $O(N_v^2d_v)$；若把所有视觉 token 拼进 LLM，LLM prefill 也会随总序列长度增长，self-attention 近似：

$$
O\bigl((N_{text}+N_v)^2d_{llm}\bigr)
$$

实际实现有 FlashAttention、局部 attention 和 connector 压缩，复杂度常数不同，但 token 越多会明确增加 TTFT、activation、上下文占用；在 decoder-only 拼接中，视觉前缀还会形成每层 KV Cache，占用后续生成显存。

### 动态切图

对于固定输入尺寸 $S\times S$ 的 vision tower，可将高分辨率图像按网格切成 $K$ 个 tile，每个 tile 产生约 $(S/P)^2$ token，并常附一张全局缩略图：

$$
N_{total}\approx (K+1)\left(\frac{S}{P}\right)^2
$$

局部 tile 保留细节，全局图保留整体关系；但 tile 边界会切断对象/表格，重叠又会重复 token。同一物体可能在多个 tile 出现，导致计数和位置混乱，因此需要 tile 行列/原图坐标、separator 和全局—局部映射。

动态策略可根据长宽比、像素数和任务选择网格或原生可变 token，并设置 `min_pixels/max_pixels`、最大 tile 和总视觉 token 预算。不能让用户上传一张超长图片就占满上下文或触发 OOM。

### 效果与成本的典型取舍

- 自然图像整体分类/描述，较低分辨率和少量 token 通常够用；文档 OCR、遥感、医学、小物体更依赖高分辨率。
- connector pooling、Q-Former、patch merge/token pruning 可降 token，但可能首先丢掉小字、边缘或问题尚未指出的细节。
- 多图/视频时总预算更紧：应在图数、每图分辨率、帧数和 token/帧间分配，而非每张图都使用最高分辨率。
- 高分辨率会降低 batch size、加剧长度不齐的 padding/调度问题；可按 token bucket 分桶和 continuous batching。

### 工程落地

先按图像类型和问题意图估算所需细节，使用渐进式方案：全局低分辨率先编码，若 OCR/细粒度问题或低置信，再选择相关区域高分辨率重编码。每个请求有像素、tile、视觉 token、TTFT 和费用上限；记录实际缩放、裁剪、坐标和模型版本供引用与复现。

评测必须画 resolution/tile/token 数与 OCR、定位、计数、通用 VQA、幻觉、P95、显存和吞吐的 Pareto 曲线，并包含长宽比、超长图和小目标切片。只看平均 benchmark 容易把成本和最坏输入隐藏掉。

### 面试简答版

ViT 的视觉 token 约为 $HW/P^2$，分辨率越高越能保留小字和小目标，但视觉 encoder 与 LLM prefill 成本、KV/上下文和 TTFT 都增加。固定分辨率 vision tower 常把图切成 $K$ 个 tile 加全局缩略图，token 约为 $(K+1)(S/P)^2$；局部细节更好，但有边界切断、重复计数和位置映射问题。生产中要设置像素/tile/token 上限，按自然图、文档或细粒度任务动态分配，并用全局低清→相关区域高清的渐进编码控制成本，最终以质量—延迟—显存 Pareto 选型。
