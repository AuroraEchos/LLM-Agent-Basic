> **问题：** Linear Projector、MLP Projector、Q-Former 和 Cross-Attention Connector 有何不同？
>
> **分类：** 多模态大模型
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

四者都解决视觉特征与 LLM 表示/接口不匹配，但在**是否压缩 token、是否非线性、是否由 query/文本选择信息、对 LLM 的侵入程度**上不同。

| Connector | 机制 | token 数 | 优点 | 局限 |
|---|---|---:|---|---|
| Linear Projector | 每个视觉 token 做 $h=zW+b$ | 通常不变 | 参数少、训练稳、架构最简单 | 表达能力有限，不主动筛选/汇聚信息 |
| MLP Projector | Linear–激活–Linear，逐 token 非线性映射 | 通常不变 | 比线性层更能适配分布，仍易训练/部署 | 视觉 token 多时上下文成本不降，跨 token 聚合依赖 encoder/LLM |
| Q-Former | 固定数量 learnable queries cross-attend 视觉特征，再经 Transformer 交互 | 固定/压缩 | 将可变视觉序列压为少量 query token，可在冻结两端时学习桥接 | 固定 query 可能丢细节，预训练目标和实现更复杂 |
| Cross-Attention Connector | 文本/latent query 在一个或多个层 cross-attend 视觉 memory | 可不占文本序列或先压缩 | 能按当前文本动态取视觉信息，跨模态交互更深 | 修改 LLM、KV/serving复杂，训练成本高 |

### 具体理解

线性和 MLP projector 通常作用于每个 patch：

$$
H_v=\phi(Z_vW_1+b_1)W_2+b_2
$$

然后直接与文本 embedding 拼接。它们不改变 $N_v$，因此保留较多空间细节，也让 LLM self-attention 承担视觉 token 间和图文间融合。若 encoder 输出 1024 token，LLM 就要处理近似这 1024 个额外 token。

Q-Former 使用 $M$ 个可学习 query，$M\ll N_v$：

$$
Q'=\operatorname{CrossAttn}(Q,Z_v,Z_v)
$$

多个层中 query 可自注意并读取冻结的视觉特征，输出固定 $M$ 个 token。它类似“可学习的信息瓶颈”，便于适配不同分辨率和冻结 LLM，但压缩过强会伤害 OCR、计数、密集目标。

Cross-attention connector 可以是独立 resampler，也可在 LLM 若干层插入 gated cross-attention。后者让每层文本 hidden state 按问题动态读取图像，而不是把所有图像 token 当普通前缀；代价是无法直接使用未修改的 LLM serving kernel，模型转换、缓存和量化更复杂。

### 如何选择

- 追求简单、复用现有 LLM、视觉 token 可控：先用 MLP baseline；线性层适合快速验证。
- vision tower 和 LLM 都冻结、图像 token 很多或需固定输入预算：Q-Former/Resampler 更合适。
- 需要强文本条件的细粒度交互、多图/视频，且能承担架构改造：考虑多层 cross-attention。
- 文档 OCR 或小物体不能只看平均 benchmark；对 connector 的压缩率做细粒度/位置消融。

连接器能力更强不必然更好：数据量小会过拟合，LLM 解冻可能掩盖 connector 问题。应在相同 encoder、LLM、视觉 token 预算和训练数据下比较质量、TTFT、显存和吞吐。

### 面试简答版

Linear 和 MLP 都把每个视觉 token 映射到 LLM 维度，通常不压缩 token；Linear 最轻，MLP 多了非线性、适配能力更强。Q-Former 用固定数量可学习 query cross-attend 大量视觉特征，相当于可训练信息瓶颈，适合冻结两端和控制上下文，但可能丢小字/密集细节。Cross-Attention Connector 让文本状态在一层或多层动态读取视觉 memory，交互最深但需要改 LLM，训练和 serving 更复杂。选择要在相同 token 预算下联合比较细粒度质量、延迟和显存。
