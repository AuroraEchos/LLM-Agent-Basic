## 我的答案

SwiGLU 用两条输入投影，一条经 SiLU 作 gate，与另一条逐元素相乘后再降回模型维度：

$$SwiGLU(x)=W_{down}\big(\operatorname{SiLU}(W_{gate}x)\odot W_{up}x\big)$$

```python
import torch.nn.functional as F
from torch import nn

class SwiGLUFFN(nn.Module):
    def __init__(self, d_model, d_ff, bias=False):
        super().__init__()
        self.gate_proj = nn.Linear(d_model, d_ff, bias=bias)
        self.up_proj = nn.Linear(d_model, d_ff, bias=bias)
        self.down_proj = nn.Linear(d_ff, d_model, bias=bias)

    def forward(self, x):
        return self.down_proj(F.silu(self.gate_proj(x)) * self.up_proj(x))

def swiglu_param_count(d_model, d_ff, bias=False):
    weights = 3 * d_model * d_ff
    biases = (2 * d_ff + d_model) if bias else 0
    return weights + biases
```

无 bias 时参数量是：两个 $D\rightarrow F$ 投影加一个 $F\rightarrow D$ 投影，共 $3DF$。普通两层 FFN（如 GeLU）是 $2DF_{dense}$。若要大致保持参数和计算相同，应取：

$$F_{swiglu}\approx\frac{2}{3}F_{dense}$$

例如传统 `d_ff=4D`，SwiGLU 可取约 $8D/3$，再向硬件友好的 128/256 倍数取整。不能在比较时两者都使用 `4D` 然后声称 SwiGLU 没有额外成本。

工程上常把 gate/up 合成一次 `Linear(D,2F)` 再 chunk，以减少 kernel launch；量化时 gate 激活分布和逐元素乘会影响 scale，需单独校准。MoE 中每个 expert 往往就是这样一个 SwiGLU FFN。

### 面试简答版

SwiGLU 计算 `down(silu(gate(x)) * up(x))`，有 gate、up、down 三个矩阵，无 bias 参数量为 `3*d_model*d_ff`。为和参数量 `2*d_model*dense_ff` 的普通 FFN公平比较，SwiGLU hidden 通常取原来的约 `2/3` 并做硬件对齐。实现可把 gate/up 融合成一次投影后 chunk。
