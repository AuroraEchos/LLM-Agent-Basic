## 我的答案

MQA 是所有 query heads 共享一组 K/V；GQA 是若干 query heads 共享一组 K/V。设 `Hq` 个 query heads、`Hkv` 个 KV heads，则要求 `Hq % Hkv == 0`，每个 KV head 服务 `group = Hq/Hkv` 个相邻 query heads。

```python
import math
import torch
from torch import nn

class GroupedQueryAttention(nn.Module):
    def __init__(self, d_model, num_q_heads, num_kv_heads):
        super().__init__()
        if d_model % num_q_heads or num_q_heads % num_kv_heads:
            raise ValueError("invalid q/kv head configuration")
        self.hq, self.hkv = num_q_heads, num_kv_heads
        self.dh = d_model // num_q_heads
        self.q_proj = nn.Linear(d_model, self.hq * self.dh, bias=False)
        self.k_proj = nn.Linear(d_model, self.hkv * self.dh, bias=False)
        self.v_proj = nn.Linear(d_model, self.hkv * self.dh, bias=False)
        self.o_proj = nn.Linear(self.hq * self.dh, d_model, bias=False)

    @staticmethod
    def repeat_kv(x, repeats):
        # [B,Hkv,T,Dh] -> [B,Hkv,group,T,Dh] -> [B,Hq,T,Dh]
        B, H, T, D = x.shape
        return (x[:, :, None, :, :]
                .expand(B, H, repeats, T, D)
                .reshape(B, H * repeats, T, D))

    def forward(self, x, causal=True):
        B, T, _ = x.shape
        q = self.q_proj(x).view(B, T, self.hq, self.dh).transpose(1, 2)
        k = self.k_proj(x).view(B, T, self.hkv, self.dh).transpose(1, 2)
        v = self.v_proj(x).view(B, T, self.hkv, self.dh).transpose(1, 2)

        group = self.hq // self.hkv
        k = self.repeat_kv(k, group)
        v = self.repeat_kv(v, group)
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.dh)
        if causal:
            mask = torch.ones(T, T, dtype=torch.bool, device=x.device).tril()
            scores = scores.masked_fill(~mask, torch.finfo(scores.dtype).min)
        p = torch.softmax(scores.float(), dim=-1).to(x.dtype)
        y = (p @ v).transpose(1, 2).contiguous().view(B, T, -1)
        return self.o_proj(y)
```

`Hkv=1` 是 MQA，`1<Hkv<Hq` 是 GQA，`Hkv=Hq` 退化为 MHA。上面为易读性逻辑广播 K/V；高效 kernel 不会真的复制 KV Cache，而是根据 `kv_head = q_head // group` 读取共享块。

每层每 token 的 K/V 元素数从 MHA 的 $2H_qd_h$ 降为 $2H_{kv}d_h$，压缩比约为 $H_q/H_{kv}$。这降低 decode 的缓存和带宽，但更多 query heads 共享同一 K/V，可能损失质量；应配合训练/微调和真实 kernel 评测。

### 面试简答版

GQA 保留 `Hq` 个 Q heads，只投影 `Hkv` 个 K/V heads，每个 KV head 被 `Hq/Hkv` 个 Q heads 共享；`Hkv=1` 就是 MQA。手写时可 `expand+reshape` 到 Q 头数，高效 kernel 则按 `q_head//group` 索引而不复制 cache。它把 KV Cache 约缩小 `Hq/Hkv` 倍，代价是 K/V 共享可能影响质量。
