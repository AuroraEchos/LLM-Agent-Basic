## 我的答案

Speculative Decoding 用便宜 draft model 连续提议 $K$ 个 token，再让 target model 一次验证。为了保持与 target 分布一致，不能简单做“相同则接受，不同则取 target argmax”，而要用接受—拒绝修正。

下面是单样本教学实现，两个函数都接收 `[1,T]` 并返回下一 token logits `[1,V]`。为突出算法，它未做 target 的并行一次前向和 KV Cache 优化。

```python
import torch

def _sample(probs, generator=None):
    return torch.multinomial(probs, 1, generator=generator).item()

@torch.no_grad()
def speculative_step(prefix, draft_next, target_next, k=4, generator=None):
    """返回 prefix 后本轮新增 token；采样分布与 target 保持一致。"""
    device = prefix.device
    draft_tokens, q_dists = [], []
    running = prefix.clone()

    # 1) draft 自回归提议 K 个 token，并保存每步 q_i。
    for _ in range(k):
        q = torch.softmax(draft_next(running).float(), dim=-1)[0]
        y = _sample(q, generator)
        draft_tokens.append(y)
        q_dists.append(q)
        running = torch.cat([running, torch.tensor([[y]], device=device)])

    accepted = []
    running = prefix.clone()
    # 2) target 逐位置验证；生产中一次 forward 得到所有 p_i。
    for y, q in zip(draft_tokens, q_dists):
        p = torch.softmax(target_next(running).float(), dim=-1)[0]
        accept_prob = min(1.0, (p[y] / q[y]).item())
        if torch.rand((), generator=generator).item() <= accept_prob:
            accepted.append(y)
            running = torch.cat([running, torch.tensor([[y]], device=device)])
            continue

        # 拒绝时从修正分布 normalize(max(p-q, 0)) 采一个 token并结束本轮。
        residual = torch.clamp(p - q.to(p.device), min=0)
        if residual.sum() <= 0:  # 仅用于有限精度兜底
            residual = p
        replacement = _sample(residual / residual.sum(), generator)
        accepted.append(replacement)
        return torch.tensor(accepted, device=device)

    # 3) K 个全接受后，再从 target 的第 K+1 个分布采一个 bonus token。
    p_bonus = torch.softmax(target_next(running).float(), dim=-1)[0]
    accepted.append(_sample(p_bonus, generator))
    return torch.tensor(accepted, device=device)
```

接受率为 $\min(1,p_i(y_i)/q_i(y_i))$；拒绝后的 $(p_i-q_i)_+$ 修正确保最终边缘分布仍是 target。target 必须在“原前缀 + 前面 draft tokens”的正确位置给出各 $p_i$，并使用相同 tokenizer/vocab。

真实加速来自 target 一次并行验证 K 个位置，收益约受接受长度、K、draft 成本、target batch 和内存带宽共同决定。草稿太弱接受率低，太强又本身昂贵；拒绝后还要正确回滚/截断两边 KV Cache。

### 面试简答版

Draft 先采 K 个 token并保存每步分布 q，target 一次得到对应 p。每个 draft token 以 `min(1,p(y)/q(y))` 接受；首次拒绝就从归一化的 `(p-q)_+` 采 replacement；若全接受，再从 target 下一个分布采 bonus token。这个修正保证分布等价于 target。工程重点是一次并行验证、KV Cache 回滚和接受率—draft 成本权衡。
