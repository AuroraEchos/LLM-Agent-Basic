## 我的答案

三类 penalty 的语义不同。下面输入 `history=[B,T]`，只惩罚历史中出现过的 token：

```python
import torch

def apply_token_penalties(logits, history, repetition=1.0,
                          frequency=0.0, presence=0.0):
    """logits: [B,V]；返回新 tensor，不原地修改输入。"""
    if repetition <= 0:
        raise ValueError("repetition penalty must be positive")
    x = logits.clone()
    counts = torch.zeros_like(x, dtype=torch.float32)
    ones = torch.ones_like(history, dtype=torch.float32)
    counts.scatter_add_(1, history.long(), ones)

    # Repetition penalty：对出现过的 logit 做符号感知缩放。
    if repetition != 1.0:
        seen = counts > 0
        x = torch.where(
            seen & (x >= 0), x / repetition,
            torch.where(seen & (x < 0), x * repetition, x)
        )

    # Frequency 随出现次数线性增加；Presence 只看是否出现。
    x = x - frequency * counts.to(x.dtype)
    x = x - presence * (counts > 0).to(x.dtype)
    return x
```

- **Repetition penalty** 常见实现是乘法式且符号敏感。若负 logit 也直接除以大于 1 的系数，反而会让它变得不那么负、概率上升，所以负数要乘。
- **Frequency penalty**：$l_i'=l_i-\alpha_f c_i$，重复越多惩罚越重。
- **Presence penalty**：$l_i'=l_i-\alpha_p\mathbf1[c_i>0]$，出现一次和十次相同，主要鼓励新 token。

不同 API 的具体定义和系数范围并不统一，必须按产品契约实现。计数范围也可只含生成内容、或包含 prompt；对聊天模板、标点、换行和代码盲目惩罚会破坏格式。通常在 temperature、Top-K/P 之前处理 logits，并和禁词、min length 等 processor 固定顺序。

测试可构造正/负 logits 和重复计数 0/1/3，逐项核对；还要验证 input logits 未被意外原地修改。

### 面试简答版

Repetition penalty 对出现过的 token 做符号感知乘法：正 logit 除、负 logit 乘 penalty；Frequency penalty 按出现次数减分；Presence penalty 只要出现过就减一次。三者通常在采样过滤前应用，必须明确计数是否含 prompt、processor 顺序和 API 公式，否则很容易在负 logit 或代码/标点场景产生反效果。
