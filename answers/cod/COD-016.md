## 我的答案

RRF 不直接融合不同检索器的原始分数，而只使用名次：

$$RRF(d)=\sum_{j=1}^{M}\frac{w_j}{k_0+rank_j(d)}$$

```python
from collections import defaultdict

def reciprocal_rank_fusion(rankings, k0=60, weights=None, top_k=None):
    """
    rankings: 多个有序 doc_id 列表，rank 从 1 开始
    weights: 各检索路权重；默认全为 1
    返回 [(doc_id, rrf_score), ...]
    """
    if k0 < 0:
        raise ValueError("k0 must be non-negative")
    weights = [1.0] * len(rankings) if weights is None else weights
    if len(weights) != len(rankings):
        raise ValueError("weights/rankings length mismatch")

    scores = defaultdict(float)
    best_rank = {}
    for source_idx, (ranking, weight) in enumerate(zip(rankings, weights)):
        seen = set()
        for rank, doc_id in enumerate(ranking, start=1):
            if doc_id in seen:       # 同一路重复文档不能重复加分
                continue
            seen.add(doc_id)
            scores[doc_id] += weight / (k0 + rank)
            best_rank[doc_id] = min(best_rank.get(doc_id, rank), rank)

    result = sorted(scores.items(),
                    key=lambda x: (-x[1], best_rank[x[0]], str(x[0])))
    return result if top_k is None else result[:top_k]
```

例如 BM25 分数可能在几十，cosine 在 `[-1,1]`，直接相加需要校准；RRF 只看 rank，因此对分数尺度稳健，也能奖励“多路都排在前面”的文档。`k0` 越大，头部第 1 与第 10 名差距越平缓；它不是返回数量 K。

代价是丢掉了 score margin：第一名远胜第二名和略胜第二名在 RRF 中一样。若某一路质量差，它仍会贡献分数，因此可加权、截断每路深度，并在 held-out query 上调参。融合前还要统一 canonical doc id 和去重 chunk；同一文档拆成多个 chunk 占据多个名次会产生偏差。

### 面试简答版

RRF 给文档在每一路的第 r 名加 `w/(k0+r)`，再跨路求和排序。它不要求 BM25、向量或其他检索分数同尺度，且会奖励多路共同靠前的结果。实现重点是 rank 从 1 开始、同一路去重、统一文档 ID；缺点是忽略原分数差距，弱检索路也会投票，所以需要权重、深度截断和验证集评测。
