## 我的答案

RoPE 把相邻两维视为二维向量，按位置 $p$ 和频率 $\theta_i$ 旋转。点积因此自然包含相对位置差。下面假设 Q/K 最后两维是 `[T, head_dim]`，且 `head_dim` 为偶数。

```python
import torch

def precompute_rope(max_seq_len, head_dim, base=10_000.0,
                    device=None, dtype=torch.float32):
    if head_dim % 2:
        raise ValueError("RoPE head_dim must be even")
    # theta_i = base^(-2i/d)，i=0...d/2-1
    inv_freq = 1.0 / (base ** (
        torch.arange(0, head_dim, 2, device=device, dtype=torch.float32)
        / head_dim
    ))
    pos = torch.arange(max_seq_len, device=device, dtype=torch.float32)
    angles = torch.outer(pos, inv_freq)          # [T,d/2]
    cos = angles.cos().repeat_interleave(2, -1)  # [T,d]
    sin = angles.sin().repeat_interleave(2, -1)
    return cos.to(dtype), sin.to(dtype)

def rotate_half(x):
    # [x0,x1,x2,x3] -> [-x1,x0,-x3,x2]
    even, odd = x[..., 0::2], x[..., 1::2]
    return torch.stack((-odd, even), dim=-1).flatten(-2)

def apply_rope(q, k, cos, sin, positions=None):
    """q/k: [...,T,d]；positions: [T] 或可索引位置。"""
    T = q.size(-2)
    positions = (torch.arange(T, device=q.device)
                 if positions is None else positions.to(q.device))
    c = cos[positions].to(device=q.device, dtype=q.dtype)
    s = sin[positions].to(device=q.device, dtype=q.dtype)
    # 在 batch/head 前缀维自动广播
    return q * c + rotate_half(q) * s, k * c + rotate_half(k) * s
```

增量 decode 时 `positions` 必须从 cache 的 `past_len` 开始，而不能每次从 0；packed sequence 也要给各 token 正确的 position ids。部分模型只旋转 `rotary_dim < head_dim`，此时把前 `rotary_dim` 旋转后与剩余维拼接。

频率的计算最好保持 FP32，应用时再转到 Q/K dtype。长上下文的 RoPE scaling（interpolation、NTK、YaRN 等）会改变位置/频率映射，必须与 checkpoint 配置一致，不能只替换 `base` 后假设质量不变。

### 面试简答版

RoPE 先为每个位置和每对维度预计算 cos/sin，再把 `(x_even,x_odd)` 旋转成 `(x_even cos-x_odd sin, x_odd cos+x_even sin)`。代码最容易错的是维度配对、广播 shape，以及 decode 时忘记把 position 加上 `past_len`。频率用 FP32 计算，长上下文 scaling 必须和模型训练配置匹配。
