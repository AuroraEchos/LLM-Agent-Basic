## 我的答案

LRU（Least Recently Used）需要同时支持 O(1) 查找和 O(1) 更新最近使用顺序。Python 的 `OrderedDict` 本质上提供了哈希表 + 双向链表所需操作。

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        if capacity <= 0:
            raise ValueError("capacity must be positive")
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key, default=-1):
        if key not in self.data:
            return default
        self.data.move_to_end(key, last=True)  # 最右端=最近使用
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.data[key] = value
            self.data.move_to_end(key, last=True)
            return
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)       # 淘汰最左端 LRU

    def __len__(self):
        return len(self.data)
```

测试：

```python
c = LRUCache(2)
c.put(1, "a"); c.put(2, "b")
assert c.get(1) == "a"     # 顺序变成 2,1
c.put(3, "c")              # 淘汰 2
assert c.get(2) == -1 and c.get(3) == "c"
c.put(1, "new")            # 更新也应成为 MRU，不增加 size
assert len(c) == 2 and c.get(1) == "new"
```

`get/put` 平均时间 O(1)，空间 O(capacity)。若面试要求从零实现，就用 `dict[key] -> doubly-linked node`，链表头/尾哨兵让删除、插入、淘汰都是 O(1)；只有 dict 或只有链表都会有一项退化到 O(n)。

工程版还要决定线程安全、TTL、容量按条数还是字节、淘汰回调和缓存击穿保护。加一把锁可保护结构，但不能在锁内执行慢加载；应使用 per-key singleflight。LRU 也未必适合扫描型访问，因为一次大扫描会污染热点，可考虑 segmented LRU/LFU。

### 面试简答版

LRU 用哈希表做 O(1) 定位，用双向链表维护新旧顺序：get/更新都把节点移到 MRU 端，超容量从 LRU 端删除。Python 可用 OrderedDict 的 `move_to_end` 和 `popitem(last=False)`，时间均摊 O(1)、空间 O(capacity)。工程上再补锁、TTL、按字节容量和缓存击穿控制。
