## 我的答案

余弦相似度是点积除以两个向量范数。批量检索时先把 query 和文档各自 L2 normalize，之后一个矩阵乘即可得到所有相似度。

```python
import torch
import torch.nn.functional as F

def cosine_topk(queries, documents, k=5, doc_ids=None):
    """
    queries:   [B,D]
    documents: [N,D]
    返回 scores/indices: [B,K]
    """
    if queries.ndim != 2 or documents.ndim != 2:
        raise ValueError("expected 2-D tensors")
    if queries.size(1) != documents.size(1):
        raise ValueError("embedding dimensions differ")
    if documents.size(0) == 0:
        raise ValueError("empty document matrix")

    q = F.normalize(queries.float(), p=2, dim=-1, eps=1e-12)
    d = F.normalize(documents.float(), p=2, dim=-1, eps=1e-12)
    similarities = q @ d.T                         # [B,N]
    k = min(max(int(k), 1), documents.size(0))
    scores, indices = torch.topk(similarities, k, dim=-1,
                                 largest=True, sorted=True)
    if doc_ids is None:
        return scores, indices
    ids = torch.as_tensor(doc_ids, device=indices.device)
    return scores, ids[indices]
```

时间复杂度为 $O(BND)$，完整相似度矩阵内存为 $O(BN)$。文档不变时应离线归一化，查询时不必重复；规模很大时分块矩阵乘维护 running Top-K，或使用 ANN 索引。分块 Top-K 的关键是把当前块候选与历史 K 个候选合并后再次 Top-K，并保留全局 doc offset。

零向量经 `eps` 处理后仍是零，与所有文档得分为 0；业务上通常应在 embedding 入库时拒绝/标记，而不是把它当正常相关性。还要保证 query/document 使用同一 embedding 模型、归一化配置和版本。

### 面试简答版

把 `[B,D]` query 和 `[N,D]` documents 沿最后一维 L2 归一化，再做 `q @ d.T` 得到 `[B,N]` 余弦相似度，最后按文档维 Top-K。复杂度是 `O(BND)`、分数矩阵 `O(BN)`；大库用离线归一化、分块 running Top-K 或 ANN，并显式处理零向量与 embedding 版本一致性。
