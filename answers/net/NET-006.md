> **问题：** `P0` HTTP 中 GET、POST、PUT、PATCH 和 DELETE 的语义与幂等性有何区别？
>
> **分类：** 计算机网络、HTTP 与 RPC
>
> **来源：** [ENGINEERING_FOUNDATIONS_PATCH.md](../../ENGINEERING_FOUNDATIONS_PATCH.md)
<!-- AUTO-QUESTION:END -->

## 我的答案

HTTP 方法描述客户端希望对资源执行的语义。**幂等**指同一个意图重复执行一次或多次，对服务端预期状态的效果与执行一次相同；不代表响应完全相同、没有日志/计费，也不代表天然安全并发。

| 方法 | 典型语义 | 安全 | 规范语义下幂等 |
|---|---|---:|---:|
| GET | 获取资源当前表示，不应请求状态变更 | 是 | 是 |
| POST | 让目标资源按自身语义处理内容，常用于创建子资源、执行动作 | 否 | 否 |
| PUT | 用请求内容创建或完整替换客户端指定 URI 的资源 | 否 | 是 |
| PATCH | 对资源应用一组部分修改 | 否 | 不保证 |
| DELETE | 删除 URI 与当前资源的关联 | 否 | 是 |

安全方法表示客户端不要求状态改变，但服务端仍可记访问日志、计费统计等附带效果。幂等也只看**预期效果**：重复 DELETE 首次可能返回 204、之后 404，状态仍然是“不存在”；重复 PUT 同一表示最终状态相同。

PUT 与 POST 的关键区别不是“更新/创建”：PUT 的目标 URI 通常由客户端确定且语义是替换，因此可重放；POST 的处理结果由服务端决定，重试“创建订单”可能创建两份。PATCH 是否幂等由 patch 文档决定：`set status=done` 可设计为幂等，`increment counter by 1` 则不是。

网络超时时客户端常不知道服务端是否已提交。自动重试应同时满足方法/业务幂等、瞬时错误、次数与 deadline。POST/PATCH 可用 idempotency key + 服务端原子去重和结果缓存获得业务幂等；PUT/DELETE 也要用 `If-Match`/ETag、版本号或事务避免并发覆盖，不能只凭方法名保证正确性。

### 面试简答版

GET 用于读取，是安全且幂等；POST 是按资源语义处理，通常非幂等；PUT 对指定 URI 做完整创建/替换，幂等；PATCH 做部分变更，是否幂等取决于操作；DELETE 删除资源关联，规范语义幂等。幂等指重复请求的预期服务端效果相同，不要求状态码相同，也不解决并发冲突。生产重试还需要幂等键/条件请求、原子去重、有限次数和总 deadline。
