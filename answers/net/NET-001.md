## 我的答案

TCP/IP 常用四层模型描述“每一层只解决一类通信问题，并向上提供抽象”：

| 层 | 解决的问题 | 典型协议/标识 |
|---|---|---|
| 应用层 | 应用消息的语义、格式和交互 | HTTP、DNS、TLS（常放在应用与传输之间理解）、gRPC；URL、Header |
| 传输层 | 端到端进程通信、可靠性、流控/拥塞控制或数据报 | TCP、UDP、QUIC；端口 |
| 网际层 | 跨网络寻址与路由，尽力交付分组 | IPv4/IPv6、ICMP；IP 地址 |
| 链路层 | 同一链路/一跳内传输帧和访问介质 | Ethernet、Wi-Fi、ARP/ND；MAC 地址 |

发送时应用数据逐层封装成传输段/数据报、IP 包、链路帧；路由器主要根据 IP 头逐跳转发，每一跳的链路帧会变化，目的主机再反向解封装。分层是逻辑模型，真实系统会有 NAT、VPN、代理、负载均衡、硬件 offload 等跨层实现。

### 一次 HTTPS 请求的主要步骤

以首次访问 `https://api.example.com/v1/chat` 为例：

1. **解析 URL 与查缓存**：客户端得到 scheme、host、port、path，并检查 HTTP cache、已有连接和 HSTS/代理配置。
2. **DNS 解析**：在本机/系统/递归 DNS 缓存未命中时查询 A/AAAA 等记录，得到候选 IP；DNS 也可能返回服务选择相关记录。
3. **选路和邻居解析**：操作系统查询路由表，选择本地接口与下一跳；局域网内通过 ARP（IPv4）或 Neighbor Discovery（IPv6）获得下一跳链路地址。
4. **建立传输连接**：HTTP/1.1、HTTP/2 常在 TCP 上三次握手；HTTP/3 使用基于 UDP 的 QUIC。代理存在时，实际首先连接代理。
5. **TLS 握手**：校验证书链与主机名、协商密钥和 ALPN（如 `h2`），建立机密性和完整性保护。QUIC 集成 TLS 1.3，但仍有安全握手语义。
6. **发送 HTTP 请求**：方法、target、headers 和可选 body 被编码；TCP 把它视为有序字节流，HTTP/2/3 则再拆成 frame/stream。
7. **服务端链路处理**：数据可能经过 CDN/WAF、负载均衡、API Gateway、反向代理，再到应用；服务可能访问缓存、数据库、模型或其他服务。
8. **返回与消费响应**：先收到状态与响应头，再接收 body；流式模型响应会边生成边传输。TCP/QUIC 处理丢包、流控和拥塞控制。
9. **复用或关闭**：连接通常放回连接池供后续请求复用；若关闭，按传输协议终止连接并释放资源。

延迟不是简单“服务器耗时”，冷请求近似为：

$$T \approx T_{DNS}+T_{connect}+T_{TLS}+T_{request}+T_{server}+T_{first\ byte}+T_{body}$$

这些阶段可能重叠或被缓存/复用，排障时应分别观测 DNS、connect、TLS、TTFB、首 token 和总下载时间。

### 面试简答版

TCP/IP 四层中，应用层定义 HTTP/DNS 等消息语义，传输层用 TCP/UDP/QUIC 提供进程到进程通信，网际层用 IP 负责跨网寻址路由，链路层负责一跳帧传输。一次 HTTPS 请求通常经历 URL/缓存检查、DNS、路由与邻居解析、TCP 或 QUIC 建连、TLS、发送 HTTP、代理和服务端处理、接收响应，最后连接复用或关闭。工程排障要把 DNS、connect、TLS、TTFB、首 token 和 body 耗时分开，而不是只看总延迟。
