## 我的答案

选择依据不是语法偏好，而是要表达哪种关系：接口描述“需要具备什么能力”，抽象基类复用受控模板和不变量，组合表示“拥有/使用某能力”，继承表示真正稳定的“is-a”替换关系。工程中优先组合，因为它在运行时更容易替换、测试和组合行为，继承层次则容易把父类内部细节扩散给所有子类。

### 接口

接口只定义行为契约，不提供或仅提供极少实现。Python 中可用 `Protocol` 做结构化类型，Java/Go 有显式 interface。适合 Agent 中的 `ModelPort、Tool、StateStore、Retriever、EventSink`：

```python
class Retriever(Protocol):
    async def search(self, query: Query) -> list[Document]: ...
```

调用方依赖最小能力，不关心实现是向量库、BM25 还是混合检索。接口需要明确输入输出、错误、幂等、取消和超时语义，只有方法名不算完整契约。

### 抽象基类（ABC）

ABC 既能强制实现抽象方法，又可复用模板方法和共同不变量。例如所有 provider adapter 共用“限流→重试→指标→调用 `_send`”骨架，而 `_send` 由子类实现。

它适合真正稳定且所有子类都需要的生命周期；若子类不断覆盖父类方法、出现 `if isinstance` 或不需要大部分默认行为，说明继承抽象错了。ABC 还带运行时耦合，修改父类可能影响所有子类。

### 组合

组合通过持有协作者并委托：

```python
agent = Agent(
    planner=Planner(model),
    executor=ToolExecutor(policy, sandbox),
    memory=Memory(store, retriever),
)
```

重试、缓存、限流、观测可实现为 decorator/middleware 组合，而不是创建 `CachedRetryingObservedOpenAIClient` 多层子类。测试时替换单个组件，运行时也可按租户/任务注入不同 Strategy。

### 继承

继承适用于稳定的 is-a，且子类满足 Liskov Substitution Principle：任何接受父类的地方都能接受子类，不加强前置条件、不削弱后置保证、不改变关键语义。例如只读工具不能继承 `WritableTool` 后把 `write()` 改为抛异常，这违反可替换性。

继承的风险包括脆弱基类、菱形/初始化复杂、状态与生命周期隐式共享、为了复用少量代码而继承错误概念。更安全的做法是先提取 helper 或组合 collaborator；只有需要统一模板与不变量时用浅层继承。

### 选择顺序

1. 只需要调用契约、会有多实现或测试替身：接口/Protocol；
2. 需要切换算法：接口 + Strategy 组合；
3. 多实现共享稳定模板和不变量：浅层 ABC；
4. 是真正可替换的专门化且继承关系长期稳定：继承；
5. 只是想复用代码：优先提取函数/对象并组合。

### 面试简答版

接口表达“能做什么”，适合 Model、Retriever、Tool、Store 等 ports；抽象基类在接口上增加稳定模板方法和共同不变量；组合表示对象使用多个可替换协作者；继承只用于真正的 is-a 且必须满足 LSP。Agent 工程通常优先组合，因为模型、重试、缓存、权限和观测可以独立替换和测试，不会形成脆弱继承层次。我的选择顺序通常是 Protocol 定契约、composition root 注入 Strategy，需要共享稳定生命周期才用浅层 ABC，而不是为复用几行代码继承。
