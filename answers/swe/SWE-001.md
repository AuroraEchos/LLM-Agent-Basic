## 我的答案

这四个原则的共同目标是：让 Agent 的业务编排不被某个模型 SDK、向量库或工具实现绑死，并让每个模块只有清晰的变化原因。它们应体现在代码边界和依赖方向上，不等于把系统拆成大量微服务。

### 高内聚、低耦合

高内聚是把共同维护同一能力的数据和行为放在一起。例如 `ToolExecutor` 内聚工具参数校验、授权、超时和执行结果规范化；`ConversationState` 管理状态转换与版本，而不是散落在路由、Prompt 和数据库代码里。

低耦合是模块只通过小而稳定的契约交互：

```text
AgentOrchestrator
 ├─ ModelPort
 ├─ ToolPort / ToolRegistry
 ├─ StateRepository
 ├─ PolicyPort
 └─ EventSink
```

传递结构化 `ModelRequest/ToolCall/StepResult`，避免共享可变 dict、读取对方内部字段或让组件互相回调。非关键旁路如指标、审计可通过事件发布，核心授权和状态提交则使用显式同步接口，不能为了“解耦”变成无保证的异步事件。

### 单一职责（SRP）

SRP 指“只有一个主要变化原因”，不是“一个类只能有一个方法”。例如：

- Planner：根据目标产生计划；
- Orchestrator：驱动状态机和步骤依赖；
- ModelClient：协议、重试、流式响应适配；
- ToolRegistry：工具元数据和发现；
- PolicyEngine：授权与风险判断；
- StateRepository：持久化与并发控制；
- Evaluator/Observer：评价和观测，不改变业务状态。

如果 `AgentRunner` 同时拼 Prompt、调用供应商 SDK、写数据库、鉴权、发邮件和打指标，它会因任何需求变化而修改，测试也只能端到端，说明职责过多。

### 依赖倒置（DIP）

高层业务规则依赖抽象端口，具体供应商适配器依赖这些端口，而不是反过来：

```python
class ModelPort(Protocol):
    async def generate(self, request: ModelRequest) -> ModelResponse: ...

class AgentOrchestrator:
    def __init__(self, model: ModelPort, tools: ToolPort,
                 state: StateRepository): ...
```

`OpenAIAdapter`、`LocalModelAdapter` 实现 `ModelPort`；Postgres、内存 Fake 实现 `StateRepository`。依赖由 composition root/Factory 注入。高层不应知道 SDK 的异常类型和返回 JSON；adapter 将其映射为领域错误与统一流事件。

### 一个重构例子

坏设计中，Planner 直接 import 某模型 SDK，解析函数调用后执行 shell 并写 Redis。重构后：Planner 只返回计划 DTO；Orchestrator 校验状态；Model Adapter 负责 SDK；Tool Executor 经 Policy 校验后调用沙箱；Repository 以 CAS 持久化；Observer 消费事件。更换模型只改 adapter，换 Redis 只改 repository，安全策略可独立测试。

### 工程边界

- 抽象应围绕业务稳定点，不要为每个函数创建接口；只有一个实现且无隔离价值时可保持简单。
- “低耦合”不等于隐藏必要一致性。状态提交、幂等和授权应有明确事务边界。
- DTO 要小且版本化，不能退化为任意 `dict[str, Any]`；否则耦合只是被隐藏。
- 模块化单体通常是合理起点；按独立扩缩容、故障域和团队所有权需要再拆服务。

### 面试简答版

在 Agent Runtime 中，高内聚是把规划、工具执行、权限、状态持久化和观测分别聚合成清晰模块；低耦合是它们只通过小型 typed contract 和事件交互。SRP 要求每个模块只有一个主要变化原因，例如 Orchestrator 只驱动状态机，Model Adapter 只屏蔽供应商协议。DIP 则让高层 Orchestrator 依赖 `ModelPort、ToolPort、StateRepository`，具体 SDK/数据库实现这些端口并由 composition root 注入。这样换模型、工具或存储不改业务编排，同时可用 Fake 独立测试。
