## 我的答案

这些模式解决不同变化轴：Adapter 统一外部接口，Strategy 替换算法，Factory 隔离构造，Observer 分发旁路事件，State Pattern 让行为随显式状态改变。不要为“用了设计模式”而套模式；只有对应变化确实存在时才引入。

| 模式 | Agent 中适合的组件 | 解决的问题 |
|---|---|---|
| Adapter | 模型供应商、向量库、MCP/工具、对象存储 | 把不同 SDK/协议转换为内部统一 port |
| Strategy | 模型路由、检索、重试、规划、上下文裁剪 | 在相同契约下运行时切换算法 |
| Factory | 按配置创建 model/tool/agent、加载版本与依赖 | 集中复杂构造，调用方不依赖具体类 |
| Observer | metrics、trace、审计、UI stream、计费 | 一个领域事件通知多个松耦合旁路消费者 |
| State | Agent step、长任务、审批、工具调用生命周期 | 显式定义合法转移与每个状态允许的行为 |

### Adapter

内部定义 `ModelPort.generate()`，`OpenAIAdapter`、`LocalVLLMAdapter` 将供应商请求、流事件、usage 和异常映射为统一领域模型。Adapter 只做协议/语义翻译，不应偷偷决定模型路由或业务权限，否则职责混乱。要用 contract tests 验证各 adapter 的取消、超时、工具调用和错误语义一致。

### Strategy

例如 `RoutingStrategy` 可有成本优先、质量优先、deadline-aware；`RetrievalStrategy` 可有 BM25、vector、hybrid。Context 将任务和候选交给 Strategy，算法不改变调用契约。Strategy 应尽量无状态或显式配置，便于 A/B；需要远程模型/数据库时也要通过注入的 port。

### Factory

Factory 根据版本化配置组装 `Agent(planner, memory, tools, policy)`，校验兼容性并注入依赖。简单构造器不需要 Factory；当创建涉及 provider、凭据、缓存、middleware、生命周期时才值得。Factory 不应变成充满所有业务 `if/else` 的 Service Locator，返回对象的依赖仍应透明。

### Observer

Orchestrator 发布 `StepStarted/ToolCompleted/TaskFailed`，metrics、trace、审计和 UI 各自订阅。Observer 适合“不影响核心正确性”的通知；授权、扣款、状态提交等关键动作不能只依赖可能丢失的异步 observer。事件需要 schema/version、trace id、顺序/幂等语义，慢 observer 不应阻塞主流程。

### State Pattern

将 `PENDING、RUNNING、WAITING_APPROVAL、RETRYING、SUCCEEDED、FAILED、CANCELLED` 及合法转移显式化。不同状态对象实现 `handle(event)`，或用状态表驱动：

```text
RUNNING + approval_required → WAITING_APPROVAL
WAITING_APPROVAL + approved → READY
SUCCEEDED + retry → invalid
```

这比散落的 boolean `is_done/is_waiting/has_error` 更不易产生非法组合。状态转移应持久化并用 CAS 防并发重复执行。

### 模式协作示例

Factory 组装 Agent；Router 选择 Strategy；Model Adapter 调供应商；State 驱动工具步骤；状态变化通过 Observer 发送指标和 UI。每个模式只控制一个变化维度，因此可独立测试和替换。

### 面试简答版

Adapter 用于把不同模型 SDK、向量库和 MCP 工具映射成统一内部接口；Strategy 用于可替换的路由、检索、重试或规划算法；Factory 负责按版本配置组装复杂 Agent 和依赖；Observer 让 metrics、trace、审计、UI 订阅状态事件；State Pattern 则显式建模 `RUNNING/WAITING_APPROVAL/FAILED` 等合法转移。关键边界是 Observer 不承担授权和事务正确性，Adapter 不做业务决策，Factory 不变成 Service Locator，状态转移要持久化和并发安全。
