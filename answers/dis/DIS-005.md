> **问题：** ZeRO-1、ZeRO-2 和 ZeRO-3 分别切分哪些训练状态？

## 我的答案

普通 Data Parallel 在每个 rank 复制参数、梯度和优化器状态。ZeRO 在 DP group 内逐级分片这些冗余状态，设 DP size 为 $D$：

| 阶段 | 分片内容 | 每 rank 长期持有 |
|---|---|---|
| ZeRO-1 | Optimizer states | 完整参数、完整梯度、约 $1/D$ 优化器状态 |
| ZeRO-2 | + Gradients | 完整参数、约 $1/D$ 梯度、约 $1/D$ 优化器状态 |
| ZeRO-3 | + Parameters | 约 $1/D$ 参数、梯度和优化器状态 |

以 mixed-precision Adam 粗略看，参数本体可能 BF16 2B，gradient 2/4B，FP32 master weight 4B，Adam m/v 8B；因此 ZeRO-1 先切最重的 optimizer states 就能显著省显存。确切字节取决于实现的 dtype 和是否保留 master weights。

### 通信代价

- ZeRO-1：各 rank 可先同步梯度，负责某参数 shard 的 rank 更新 optimizer，再 All-Gather 更新后的参数。
- ZeRO-2：梯度用 Reduce-Scatter 直接落到 owner rank，更新后 All-Gather 参数，避免每卡保存完整 gradient。
- ZeRO-3：计算某层前需要 All-Gather 参数 shard，用后可 reshard；反向再 gather，并对梯度 Reduce-Scatter。长期显存最低，但通信更频繁、预取/重叠和 layer wrapping 更关键。

ZeRO stage 不是越高越快：模型能放下时 ZeRO-3 的细粒度参数通信可能降低吞吐。CPU/NVMe offload 是另一维，把状态移出 GPU，进一步省 HBM但受 PCIe/NVMe 带宽与延迟限制；不属于 ZeRO-1/2/3 的定义本身。

Checkpoint 也必须理解分片格式：保存 local shard 快但恢复/改 world size 需要分布式 checkpoint 重分片；聚合 full state dict 易兼容但会在 rank 0 形成内存与 I/O 峰值。

### 面试简答版

ZeRO-1 只分 optimizer states；ZeRO-2 再分 gradients；ZeRO-3 连 parameters 也分。DP size 为 D 时，被分状态长期显存约降到 1/D。代价是通信逐级增加：ZeRO-2 常用梯度 Reduce-Scatter，ZeRO-3 每层计算前还需 All-Gather 参数并在之后 reshard。stage 应按能否放下与通信拓扑选，offload 和 checkpoint 分片是另外的工程维度。
