## 我的答案

Kernel 优化先用 profiler/roofline 判断是 memory-bound、compute-bound 还是 launch-bound，再改数据布局和算法；四种技术通常组合使用。

### 1. Memory Coalescing

让同一 warp 的相邻 thread 访问相邻、对齐的 global memory 地址，使硬件用尽量少的 memory transactions 服务。常把最后一维映射给 `threadIdx.x`，使用连续布局/vectorized load；跨大 stride、随机 gather 会浪费 cache line。还要让读写双方布局都合理，transpose 可能需要 tiled shared memory。

### 2. Tiling

把大矩阵/序列分成适配 block 的 tile，协作加载到 shared memory/register，重复使用后再移动下一块，提高 arithmetic intensity。例如 GEMM tile 让 A/B 元素被多个 FMA 复用。tile 太小复用差，太大则 shared memory/register 占用高、active blocks 少；边界 tile 要 mask，shared layout 要防 bank conflict，可加 padding。

### 3. Parallel Reduction

每线程先局部累积，再在 warp 内用 shuffle 做树形归约，跨 warp 用 shared memory/第二级归约，减少全局 atomic 和同步。Softmax 通常先 reduce max，再 reduce exp sum；Attention 用 online rescaling合并 block。浮点加法不结合，归约顺序会改变舍入，必要时用更高精度累加并设数值容差。

### 4. Kernel Fusion

把 producer-consumer 算子如 bias+activation、residual+norm 融为一个 kernel，中间值留 register/shared，不往 HBM 落地，并减少 launch。收益大多来自少读写和少启动；但 fusion 过度会增加 registers、降低 occupancy、限制调度/复用并造成更多 shape 专用编译。

每次优化都要用 reference 做多 shape/dtype/边界正确性，再比较有效带宽、Tensor Core利用、occupancy、spill、launch数和端到端时间。单 kernel 变快不代表整步变快。

### 面试简答版

访存合并让 warp相邻线程读连续地址；tiling 把数据放 shared/register提高复用；归约用线程局部→warp shuffle→跨warp分层合并；fusion 消除中间 HBM读写和 launch。它们互相制约：tile/fusion过大可能吃满 register/shared memory、降低occupancy。先用 roofline判断瓶颈，再以正确性和端到端 profile验收。
