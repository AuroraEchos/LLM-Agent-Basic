> **问题：** Sequence Parallel、Context Parallel 和 Ring Attention 有何区别？

## 我的答案

三者都可能沿 token/sequence 维切分，但解决的内存区域不同，且 “Sequence Parallel” 在不同系统中存在命名差异。

### Megatron Sequence Parallel（SP）

TP 之后，一些操作如 LayerNorm、Dropout、residual 本来会在每个 TP rank 保存相同的整段序列激活。SP 把这些区域的激活沿序列切成 $1/P$，通过 Reduce-Scatter/All-Gather 与 TP 的 Column/Row Parallel 边界衔接。它主要消除 TP rank 间的激活冗余，并不单独把 full attention 的 QK 计算和 KV 全部跨卡分解。

### Context Parallel（CP）

CP 是面向长上下文的更完整分片：每个 rank 只持有一段序列的输入/激活/KV，并通过 ring、all-gather 或 all-to-all 完成跨段 attention。它要正确处理全局 position ids、RoPE、causal mask、反向和负载；目标是让可训练长度随 CP size 增加。

### Ring Attention

Ring Attention 是实现精确 CP Attention 的一种算法。每个 rank 保留自己的 Q block，K/V block 沿环轮转；每到一块就算局部 score，并用 online softmax 维护全局 max、归一化和加权 V。通信与 block attention 重叠，不物化全局 $L^2$ score，但全局计算量仍是精确 full attention 的二次量。

还有 Ulysses 一类方案通过 all-to-all 在 sequence 与 head 布局间转置，有些库也称其为 sequence parallel。因此面试时我会先定义：“我说的 SP 是 Megatron 的激活分片，CP 是长上下文分片，Ring 是 CP 的 attention kernel/通信方式”。

选型看序列长度、head 数可整除性、CP rank 数、链路和通信重叠。Ring 的轮数随 rank 增长，all-to-all 方案受 bisection bandwidth 影响；最终比较每卡峰值内存、tokens/s 和扩展效率。

### 面试简答版

Megatron SP 主要把 TP rank 间在 Norm/Dropout/residual 等处重复的序列激活切开；CP 则把长上下文的激活和 Attention 状态真正分到多卡；Ring Attention 是一种精确 CP 实现，让 K/V block 沿环移动并用 online softmax 合并。Ring 降每卡内存但不改变 full attention 总体二次 FLOPs。术语依框架而异，回答要先说明切分对象和 collective。
