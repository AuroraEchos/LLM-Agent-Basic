> **问题：** CUDA Kernel 优化中 Occupancy、Register、Shared Memory 和 Memory Coalescing 分别意味着什么？

## 我的答案

这四个概念共同决定一个 SM 能同时驻留多少工作、每次访存是否有效，以及能否隐藏延迟。

- **Occupancy**：每个 SM 实际 active warps 与硬件最大 active warps 的比值。更多 warps 可在某 warp 等内存时切换执行，但 occupancy 只是延迟隐藏手段，不是性能目标；计算密集且指令级并行高的 kernel 在中等 occupancy 也可能最快。
- **Registers**：每线程私有的最快存储，保存累加器、索引和临时值。每线程 register 太多会限制每 SM 可驻留的 blocks/warps；编译器不足时 spill 到所谓 local memory，而 local memory 实际在 device memory，代价很高。
- **Shared Memory**：每 block 共享的片上 scratchpad，用于 tile复用、线程协作和跨warp归约。每 block 用得太多同样减少 resident blocks；还要处理 bank conflict、同步和容量。它不是全局共享，也不会跨 block 保留。
- **Memory Coalescing**：一个 warp 的 global memory 访问能否合并成少量对齐 transaction。即使 occupancy 很高，若每线程跨大 stride导致大量 transaction，仍会严重 memory-bound。

资源约束可粗略理解为：每 SM active blocks 同时受 threads/block、registers/thread × threads/block、shared bytes/block 和架构 block上限的最小值约束。增大 tile 可能提高数据复用，却增加 registers/shared；减小 block 可能提升理论 occupancy，却减少并行/复用。

优化步骤是查看编译器 register/spill 报告与 profiler 的 achieved occupancy、memory transaction/effective bandwidth、stall reason和指令吞吐；针对多个 block size/tile 做 sweep。不要为达到 100% occupancy 强制限制 register，若导致 spill，常会更慢。

### 面试简答版

Occupancy 是 active warps占上限的比例，用于隐藏延迟但不是越高越好；register是每线程高速私有状态，太多会压低驻留、太少会spill到显存；shared memory是block内可编程缓存，利于tiling/归约但受容量和bank conflict限制；coalescing则决定warp访存能否合并。优化要在复用、寄存器/shared占用和有效带宽之间实测，而不是只追100% occupancy。
