> **问题：** All-Reduce、Reduce-Scatter、All-Gather 和 All-to-All 分别用于哪些并行方式？

## 我的答案

Collective 的区别可以从每个 rank 的输入和输出看：

| Collective | 操作后每个 rank 得到什么 | 常见场景 |
|---|---|---|
| All-Reduce | 所有 rank 输入做 sum/mean 后，每个 rank 都有完整结果 | DDP 梯度同步、Row Parallel partial output 求和 |
| Reduce-Scatter | 先 reduce，再把结果分片，每个 rank 只留一片 | ZeRO/FSDP 梯度分片、Sequence Parallel |
| All-Gather | 汇集所有 rank 的不同 shard，每个 rank 得到完整拼接结果 | FSDP 参数 materialize、TP/SP 恢复完整激活 |
| All-to-All | 每个 rank 分别给每个其他 rank 一段不同数据，并收到各方对应段 | MoE token dispatch/combine、某些 sequence/head transpose |

All-Reduce 在逻辑上可分解为 Reduce-Scatter + All-Gather，因此分片算法常把这两半拆开：梯度算完只需 owner shard，就停在 Reduce-Scatter；下一次计算需要完整参数时才 All-Gather，从而省长期内存并创造预取/重叠机会。

不同并行的典型映射：

- DP/DDP：梯度 All-Reduce；ZeRO-2/3、FSDP：梯度 Reduce-Scatter、参数 All-Gather；
- TP：Row Parallel 输出 All-Reduce，Column/Sequence 布局之间可能 All-Gather/Reduce-Scatter；
- EP：按 Router 目的专家做 All-to-All，专家算完再反向 All-to-All；
- PP：主要不是 collective，而是相邻 stage 的 point-to-point send/recv。

逻辑操作不等于固定算法：All-Reduce 可选 ring/tree，All-to-All 可做分层/分组；性能取决于消息大小、rank 数、拓扑、是否跨节点和最慢 rank。还必须保证 process group、tensor shape/dtype 和调用顺序一致，否则会 hang 而不是返回普通错误。

### 面试简答版

All-Reduce 是“归约后每卡完整”；Reduce-Scatter 是“归约后每卡一片”；All-Gather 是“把各片拼成每卡完整”；All-to-All 是“每卡向所有卡发送不同分片”。DDP 常用 All-Reduce，ZeRO/FSDP 用 Reduce-Scatter 梯度和 All-Gather 参数，TP组合这些操作，MoE EP 用两次 All-to-All，PP主要用相邻 stage 点对点通信。
