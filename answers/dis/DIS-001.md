## 我的答案

区分这些并行方式最清楚的方法是问：**同一时刻，每张卡持有什么参数、处理哪些 token、需要交换什么？**

| 并行方式 | 主要切分对象 | 各 rank 的典型状态 | 主要通信 |
|---|---|---|---|
| Data Parallel（DP） | batch/sample | 完整模型副本，不同数据 | 梯度 All-Reduce，或 Reduce-Scatter + All-Gather |
| Tensor Parallel（TP） | 一层内部矩阵/attention heads/FFN hidden | 同一层的参数和激活分片 | 层内频繁 All-Reduce/All-Gather/Reduce-Scatter |
| Pipeline Parallel（PP） | 连续层/模型深度 | 每 rank 只放若干层 | stage 间点对点传 activation/gradient |
| Sequence Parallel（SP） | 序列维上的部分激活 | 每 TP rank 只保留一段 token 的 Norm/Dropout 等激活 | 与 TP 配套的 All-Gather/Reduce-Scatter |
| Expert Parallel（EP） | MoE experts | 每 rank 只放部分专家 | token dispatch/combine 两次 All-to-All |

DP 最容易扩吞吐，但每卡完整参数/优化器可能放不下；ZeRO/FSDP 是把 DP 的状态进一步分片。TP 能让单层本身跨卡，但每层都通信，通常放在 NVLink/NVSwitch 等高速域内。PP 只在 stage 边界通信，适合跨节点扩模型深度，却有 pipeline bubble 和 stage 不均。SP 术语依框架而异：Megatron SP 主要去除 TP rank 间非 TP 区域的重复激活，不等于完整的长上下文 Context Parallel。EP 只在 MoE 中成立，其 All-to-All 对拓扑和负载均衡非常敏感。

这些维度通常组合成并行网格，而非五选一。例如 TP=8 放一个节点内，PP=4 跨四个节点，剩余副本做 DP；长序列再加 CP/SP，MoE 层加入 EP。要注意 EP 与 DP/TP 的 process group 可能重叠或嵌套，不能永远简单把所有数字相乘。

### 面试简答版

DP 切 batch、复制模型并同步梯度；TP 切一层内部矩阵，层内频繁 collective；PP 切连续层，只在 stage 间传激活/梯度；Megatron SP 切序列维上的重复激活，通常服务于 TP；EP 切 MoE 专家，靠 All-to-All 搬 token。实际会按拓扑组合：高频 TP/EP 通信尽量放节点内，PP 可跨节点，DP 用剩余设备扩吞吐。
