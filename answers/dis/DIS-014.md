> **问题：** Activation Recomputation、CPU Offload 和 NVMe Offload 的收益与瓶颈是什么？
>
> **分类：** 分布式训练与 AI Infra

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

三者都是“用别的资源换 HBM”，但交换资源不同。

### Activation Recomputation / Checkpointing

前向只保存选定边界输入，不保存内部激活；反向需要时重跑该段 forward。收益通常是显著降低随 batch/sequence 增长的 activation memory，代价是额外 GPU FLOPs和 kernel launch。分段越细，保存越少但重算/调度越多；实际常 selective checkpoint Attention/FFN 中昂贵保存项，并保留成本高或状态敏感算子。

必须保持重算一致：Dropout RNG state、autocast、参数版本和有副作用的层不能随意变化。重算增加计算，所以当训练本来 compute-bound 时吞吐下降明显；如果省出的内存允许更大 micro-batch、提升 GEMM，端到端反而可能更快。

### CPU Offload

把 optimizer state、参数或激活放主存，按需经 PCIe/NVLink-C2C 等搬回。容量远大于 HBM，但瓶颈是 host bandwidth/latency、pinned memory、NUMA 和 CPU optimizer 算力。要双缓冲、预取并与 GPU 计算重叠；若每层计算不足以掩盖传输，GPU 会等待。

### NVMe Offload

主存仍不够时再把状态分层到 NVMe，容量更大但比 DRAM 延迟高、随机小 I/O差。需要大块顺序 I/O、足够 queue depth、异步 prefetch、CPU staging/pinned buffer，并关注本地盘容量、共享带宽和故障。它适合让超大模型“能训练”，通常不是追求最高 tokens/s 的第一选择。

选型顺序通常先 fused/FlashAttention、合理 micro-batch和重计算，再状态分片；仍不足才 CPU/NVMe offload。用 roofline 思路比较每层可重叠计算时间与搬运字节/有效带宽，并报告 exposed I/O，而不是只说 offload 后显存下降。

### 面试简答版

Recomputation 用额外 GPU 计算换激活显存，需处理 RNG/副作用；CPU offload 用主存容量换 PCIe/NUMA 传输和 CPU optimizer开销；NVMe 再用更大容量换更高 I/O 延迟，需要大块异步预取。优先做高效算子、分片和选择性重算，仍放不下再逐级 offload；是否值得取决于传输能否被层计算覆盖，而不只是 HBM 数字。
