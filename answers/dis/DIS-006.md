## 我的答案

二者解决的是同一个核心问题：Data Parallel 各 rank 不必长期复制全部参数、梯度和优化器状态；计算时按需聚合，之后再分片。但 **ZeRO 是分片优化思想/阶段体系，FSDP 是 PyTorch 中围绕模块包装、参数生命周期和 state dict 构建的具体实现体系**，不能把名字当作完全同一套代码。

### 概念对应

- ZeRO-1：分 optimizer states；ZeRO-2：再分 gradients；ZeRO-3：再分 parameters。
- FSDP 的 full sharding 在语义上最接近 ZeRO-3：某个 FSDP unit 前向前 All-Gather 参数，用后可 reshard；反向再次准备参数，梯度 Reduce-Scatter 后各 rank 只留 shard。
- FSDP 也可选择只分梯度/优化器或 hybrid sharding；具体策略名和 API 应以使用的 PyTorch 版本为准。

### 工程差异重点

1. **分片粒度**：FSDP 以 wrapped module/unit 决定参数何时 gather/释放，auto-wrap policy 直接影响峰值显存、collective 数量和重叠；unit 太小消息碎，太大峰值高。DeepSpeed ZeRO 则通过其 parameter partition/bucket/prefetch runtime 管理。
2. **参数表示**：实现可能 flatten 参数，也可能保留原 parameter view；这会影响 optimizer 构建、共享权重、冻结参数和自定义访问。必须遵循“先 wrap 还是先建 optimizer”的框架约定。
3. **Offload/生态**：DeepSpeed 提供 ZeRO-Offload/Infinity 等 CPU/NVMe 路径和一体化 engine；FSDP 更贴近原生 PyTorch module、distributed checkpoint 与编译生态。功能覆盖会随版本变化，选型要实测。
4. **Checkpoint**：两边都有 sharded/full state 的概念，但 key、flatten、world-size reshard 和 optimizer state 转换接口不同，不能直接假设格式互通。

性能选择看模型是否能放下、网络、模块结构和团队栈。full shard 最省长期显存，却增加参数 gather；hybrid shard 可把高频 gather 限在节点内、节点间复制较少副本。迁移时先用小模型验证一 step 的 loss/梯度/optimizer state，再做故障恢复和改 world size 测试。

### 面试简答版

ZeRO 是按 optimizer、gradient、parameter 三阶段消除 DP 冗余的算法体系；PyTorch FSDP 是按 module unit 管理参数 All-Gather、reshard 和梯度 Reduce-Scatter 的原生实现，full shard 语义接近 ZeRO-3。两者目标相同，但 wrapping 粒度、参数表示、offload runtime、checkpoint 和 API 不同，不能认为 checkpoint/配置可直接互换；最终按显存、通信拓扑和生态实测选择。
