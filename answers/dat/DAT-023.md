## 我的答案

合成数据的价值是用程序、模型或环境生成真实数据中稀缺、昂贵或难标注的训练信号；主要风险是把教师模型的错误、偏见和有限分布递归放大。高质量方案应形成“**定目标—多样生成—可验证过滤—真实数据锚定—独立评估**”闭环，而不是把一个模型的大量自由采样直接回灌给自己。

### 常见生成方法

#### Self-Instruct / Evol-Instruct

从少量种子任务出发，让教师生成新指令、答案，再改写、增加约束或提高难度。适合扩充指令覆盖，但容易产生固定措辞和伪难题，需要任务去重与可解性检查。

#### 蒸馏与多教师生成

让更强模型为真实 prompt 生成回答、解释、工具轨迹或偏好对，再训练较小模型。多教师或多 checkpoint 能降低单一风格偏置；要保存教师版本、prompt、采样参数和生成 provenance。

#### Rejection Sampling / Best-of-N

同一问题采样 $K$ 个候选，通过 verifier、reward model、执行器或规则选择：

$$
y^*=\arg\max_{y_k} s(x,y_k)
$$

它能提高正确率，但若评分器有漏洞，生成器会偏向“骗过评分器”的模式；只保留最高分也会压缩回答多样性。

#### Self-Play 与环境交互

在游戏、代码沙箱、工具 API 或模拟用户中生成轨迹，利用环境返回作为标签。Agent 数据可通过生成任务—调用工具—观察结果—修正计划构建，比纯语言自评更可靠。

#### 程序化生成与扰动

用模板、语法、知识图谱、定理生成器、程序执行或已有样本变换产生数据。数学等式、SQL、结构化抽取、边界输入和对抗测试特别适合，因为答案可自动计算。模板必须足够多样，且 train/test 的生成种子和规则族要隔离。

#### 合成少数类与负例

针对拒答边界、工具参数错误、代码 bug、长尾语言和失败恢复生成 hard negatives。负例要注明“为何错”和正确修复，否则只告诉模型一个回答不好，学习信号有限。

### 过滤与验证体系

过滤应由确定性到主观性分层：

1. **格式与 schema**：JSON 是否可解析、字段和类型是否匹配、特殊 token 是否正确；
2. **执行验证**：代码编译/单测、SQL 在隔离数据库执行、工具调用在 mock 环境验证；
3. **符号验证**：数学答案代回、等式化简、单位/约束检查；
4. **检索与引用**：结论是否由给定证据支持，引用 span 是否存在；
5. **一致性**：多次采样、不同教师或正反向求解是否一致；
6. **模型评分**：正确性、相关性、完整性、安全性和风格分维度打分；
7. **去重与多样性**：n-gram/MinHash/embedding 聚类，限制模板簇占比；
8. **人工抽检**：按领域、难度、分数区间和失败类型分层抽样。

模型自评不应是唯一裁判，特别是生成器和裁判来自同一模型族时，二者会共享盲点。对可执行任务应优先使用外部可验证信号。

### 什么是模型坍缩

当后代模型越来越多地用前代模型输出训练，而缺少真实分布锚点时，低概率模式、长尾事实和表达多样性会逐代消失；错误模式则可能被当作真数据强化。表现包括：

- 输出措辞和推理路径高度同质化；
- 罕见类别、少数语言和边界情况召回下降；
- 事实错误或格式习惯跨代积累；
- 训练 Loss 看似下降，真实独立测试集却退化；
- 模型更擅长教师生成的题，而不是现实用户问题。

根因是合成分布 $q(x)$ 只近似真实分布 $p(x)$。若反复从 $q$ 采样并最大似然拟合，未被教师覆盖的质量会越来越少，筛选器还会进一步截断分布。

### 防止坍缩的方法

#### 保留真实数据锚点

每轮训练始终混入足够的、去重后的真实数据，并设置合成数据比例上限。对稀有语言和真实用户失败样本单独保留，不让总量巨大的合成数据淹没它们。

#### 扩大生成分布，而不只提高平均分

- 多教师、多 prompt、多温度和多解法采样；
- 按任务、语言、难度和风格设置配额；
- 聚类后每簇限量，保留一部分非最高分但正确的多样解；
- 生成器、验证器和最终模型尽量异构；
- 基于真实失败日志定向生成，不让教师凭空决定所有任务。

#### 用外部事实和环境闭环

把检索语料、编译器、单元测试、计算器、定理证明器、API schema 和模拟器作为 ground truth。模型负责提出候选，环境负责判定可验证部分，避免“一个模型说、另一个相似模型同意”形成自洽错误。

#### 严格追踪数据世代

每条数据记录真实/合成标记、教师、父样本、生成 prompt、验证器、得分和版本。训练集按世代和来源限额，避免合成数据在抓取网页或下一轮生成中被当成新真实数据再次回流。

#### 在独立真实集上早停

验证集不能由同一生成流程产生。持续比较真实用户集、私有盲测、长尾切片、表达多样性和校准度；一旦 synthetic-only 指标上升而真实指标下降，就应停止或调整混合。

### 数据选择的精度—覆盖权衡

过滤阈值太低会保留错误，太高则只剩容易、同质的答案。可把样本按“正确性硬门槛 + 多样性软目标”选择：先删除无法验证或明显错误项，再在任务/难度簇内分层采样，而不是全局取分数最高的前 $K$。

还应防止 benchmark contamination：生成器可能记得公开题，合成的“新题”只是改写。需对题干、答案和程序结构做精确、近似及语义去重，并让最终测试使用独立模板、时间和题源。

### 面试简答版

合成数据可通过 Self-Instruct、强模型蒸馏、Best-of-N、程序化生成和环境 self-play 产生。过滤时优先用 schema、编译/单测、数学求解器、工具环境和引用核验等外部可验证信号，再用多教师一致性、模型评分、去重和人工抽检补充。模型坍缩来自多代训练不断拟合模型自身的近似分布，导致长尾消失、错误累积和风格同质化。防范关键是持续混入真实数据锚点，限制合成比例和重复世代，使用多教师/多采样并按任务簇保留多样答案，记录完整生成血缘，最终只在独立真实盲测集上判断收益。
