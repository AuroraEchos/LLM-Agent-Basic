> **问题：** 继续预训练时应复用原词表还是扩展词表，分别有什么代价？
>
> **分类：** Tokenizer、数据与预训练

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

继续预训练（Continued Pretraining，CPT）时，选择取决于原 Tokenizer 对目标领域的覆盖是否已经可接受。**复用原词表兼容性最好；扩展词表可能提高新语言或专业领域的 token 效率，但会引入新参数、分布迁移和部署兼容成本。** 它不是“领域数据来了就一定扩词表”。

### 方案一：完全复用原词表

优点是：

- token-ID 映射和所有 Embedding 行保持不变，可直接加载原模型；
- 原有能力、聊天模板、量化权重和推理服务兼容性最好；
- 无新增随机参数，不需要专门教模型控制新 token；
- checkpoint、LoRA、蒸馏模型和多机并行配置更容易复用。

主要代价是目标领域可能被过度切碎。例如医学术语、化学式、低资源语言或代码 API 名被拆成大量 token，会造成：

- 同一 context window 能容纳的有效文本变少；
- 训练和推理要走更多 token step；
- 一个概念分散到多个短片段，学习和复制可能更难；
- 大量 byte fallback 使序列更长、语义共享更弱。

不过“一个术语不是单 token”不等于模型学不会。Transformer 可以组合多个子词；如果膨胀率不高，复用往往是更稳妥的选择。

### 方案二：在原词表末尾扩展 token

做法通常是从领域语料挖掘高频且能显著减少 token 数的片段，追加 $k$ 个 token，并将输入 Embedding 和 LM Head 从 $V$ 扩为 $V+k$。这样保留所有旧 ID，不破坏旧 token 的参数语义。

收益包括：

- 目标语言、术语、代码结构和公式的序列更短；
- 固定 context 可装入更多领域内容；
- 高频领域单元获得独立表示，复制和生成可能更稳定；
- 若节省的序列计算大于新增输出头成本，端到端吞吐可能提高。

但代价不能忽略。

#### 新参数没有预训练语义

新增行通常用随机值、原拆分 token 的均值或相近 token 初始化。它们必须在 CPT 中获得足够频次和上下文才能学好。若一个新 token 只出现几十次，独立占词表往往不划算。

#### 既有文本的切分分布会变化

新增普通 token 后，Tokenizer 可能把以前的多个旧 token 合并成新 token。模型原来在旧切分上学到的模式不再以相同形式出现，而新 Embedding 又未成熟，初期 Loss 可能升高。这种变化不仅影响领域文本，也可能误匹配通用文本。

可以控制 added token 的匹配范围、只选高收益片段，并在训练数据中混入通用回放数据来缓解遗忘，但不能完全假设扩容是无风险的。

#### 模型和系统变大

若输入输出权重绑定，新增参数约为：

$$
\Delta P=k\cdot d
$$

若不绑定且忽略 bias，则约为：

$$
\Delta P\approx2k\cdot d
$$

词表变大会增加 Embedding/LM Head 存储、输出投影和 softmax 计算，也可能影响张量并行整除、量化与推理引擎支持。对于大 $k$，这些成本可能抵消序列缩短收益。

#### 兼容性与版本管理

新 Tokenizer 不能随便配旧模型使用；模型扩容后的 checkpoint、LoRA adapter、服务端 tokenizer、chat template 和 stop ID 必须配套。回滚、混部、缓存键和 API 版本也要区分。已有 adapter 若依赖旧切分，通常需要重新验证甚至重训。

### 不建议：重训全新词表并直接套旧权重

如果全新词表重排了 token ID，即使词表大小不变，第 $i$ 行 Embedding 的含义也可能完全不同，旧模型不能直接解释。除非建立旧—新 token 的参数映射并进行充分再训练，否则这更接近 tokenizer transplantation，风险远高于“末尾追加”。

只有在目标语言与原模型差异极大、原词表效率极差，并且预算足以进行大量继续训练时，才可能考虑全面替换。此时还要接受通用能力和生态兼容性下降。

### 如何做决策

我会先在目标语料和通用回放语料上测：

1. bytes/token、token 膨胀率和长尾分位数；
2. `<unk>`、byte fallback 和过碎术语的占比；
3. 候选 token 的频次、节省 token 数及覆盖样本数；
4. 扩词表后 LM Head 的额外参数、FLOPs 和推理延迟；
5. 旧领域与新领域的 Loss、下游质量及灾难性遗忘。

候选 token 的粗略收益可按语料上的总节省量评估：

$$
G(t)=\sum_x \bigl[T_{\text{old}}(x)-T_{\text{with }t}(x)\bigr]
$$

但还要扣除歧义匹配、新参数训练和输出头成本。实践中可做三组小规模等算力实验：原词表、少量追加、较大追加，再比较质量—吞吐—兼容性的 Pareto 前沿。

### 折中策略

- 只增加少量高频、高收益且边界清晰的领域 token；
- 保留全部旧 ID，并将新 ID 追加在末尾；
- 用旧切分子词向量的均值初始化新 Embedding；
- CPT 中混合领域数据和通用数据，监控新旧基准；
- 对特殊控制 token 与普通领域 token 分开管理；
- 若只是几十个专用标签，可考虑用现有保留 token 或文本模板，而不是扩大词表。

### 面试简答版

原词表对目标领域切分尚可时，我优先复用：它保持 token ID、Embedding、checkpoint、LoRA 和推理服务完全兼容，也没有新参数冷启动；代价是专业术语或新语言可能过碎，浪费上下文和训练 token。只有当目标语料的 bytes/token、fallback 率和长尾膨胀明显恶化时，才考虑在词表末尾追加少量高收益 token，并同步扩展 Embedding 与 LM Head。扩词表会带来新行训练不足、旧文本切分变化、softmax 成本上升及部署版本不兼容，所以应通过等算力消融比较新旧领域质量和端到端吞吐，而不是只看 token 数。
