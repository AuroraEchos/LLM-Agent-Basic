> **问题：** 词表大小如何影响参数量、序列长度、训练效率和下游效果？
>

## 我的答案

词表大小 $V$ 存在一个核心权衡：**大词表能用更少 token 表示同样的文本，但会增加 Embedding/LM Head 参数、词表 Softmax 计算和低频 token 的学习难度；小词表的基础单位更易充分训练和组合，但序列更长，浪费上下文窗口并增加 Transformer 计算。**

### 对参数量的影响

设 hidden size 为 $d$，Embedding 矩阵为：

$$
E\in\mathbb{R}^{V\times d}
$$

其参数量为 $Vd$。LM Head 也通常是 $V\times d$：

- 如果 Embedding 与 LM Head 权重绑定，总参数中只计一份 $Vd$；
- 如果不绑定，两者合计约 $2Vd$；
- 还可能有 $V$ 维输出 bias，但相对 $Vd$ 很小。

词表每增加 $\Delta V$，绑定时至少增加 $\Delta Vd$ 参数，未绑定时约增加 $2\Delta Vd$。训练还要为这些参数保存梯度和优化器状态，checkpoint 和通信开销也会增加。

### 对序列长度的影响

词表更大时，更多高频词、子词、中文词组、代码片段可作为单个 token，同样的原始文本通常变成更少 token。设原始内容为 $C$ 个字符，平均每 token 承载 $r(V)$ 个字符，则：

$$
N(V)\approx\frac{C}{r(V)}
$$

更短的 $N$ 会：

- 让固定 context window 承载更多原始文本；
- 减少训练 token 数和自回归生成步数；
- 减少 Attention 的 $O(N^2d)$ 项和 KV Cache 的 $O(N)$ 项。

但 $V$ 增大后，序列长度的边际收益通常递减：最常见片段会先进入词表，后面增加的大量长尾 token 对全局平均长度改善很小。

### 对每 token 计算的影响

对 $B\times N$ 个 hidden state，训练时密集 LM Head 的矩阵乘约为：

$$
F_{lm}\approx2BNdV
$$

随后的 Softmax/交叉熵也要处理 $BNV$ 个 logit。因此大词表会增加：

- LM Head 矩阵乘；
- logits 激活显存，训练时可能很大；
- vocabulary parallel 的分片/通信复杂度；
- Decode 每步产生下一 token 分布的成本。

权重绑定只节省参数，不会消除 $hE^T$ 的输出计算。在推理时，大词表使“每步”更贵，但可能减少“总步数”；必须看端到端的每原始字符或每请求延迟，不能只看 tokens/s。

### 对整体训练效率的权衡

对固定原始内容，可用一个粗略成本函数理解：

$$
F(V)
\approx
\underbrace{aN(V)d^2}_{\text{Transformer 线性层}}
+
\underbrace{bN(V)^2d}_{\text{Attention}}
+
\underbrace{2N(V)dV}_{\text{LM Head}}
$$

$V$ 变大会降低 $N(V)$，但增大最后一项。所以存在与语料、模型宽度、序列长度和硬件相关的折中点，没有通用的“词表越大越好”。

### 对学习和下游效果的影响

#### 大词表的可能优势

- 常见词、专业术语和代码片段作为稳定单元，序列更短。
- 中文和小语种若获得足够词表配额，可减少 byte fragmentation 和计算不公平。
- 复制固定名称、API、URL 片段时需预测的步数更少。

#### 大词表的可能问题

- 长尾 token 出现次数少，Embedding 和输出分类向量学不充分。
- 把长串当作一个原子 token 可减少对子结构的组合学习，拼写变形或稍微改动后又会切成完全不同的序列。
- vocabulary competition 可使高资源语言占用过多 token，全局压缩率变好却损害特定语种。
- 输出候选类别更多，每个 token 获得的直接正样本更少，可能增加 softmax 分类难度。

#### 小词表的特点

字符/byte 级单位出现频繁、覆盖稳定，对新词、拼写和形态变化的组合能力强。但模型要用更多层和 token 步骤将底层符号组合成词义，对长文本、中文和自回归生成特别昂贵。

### 如何选择

1. 在代表性多语言/多领域 held-out 数据上，画出 vocabulary size 与 chars/token、bytes/token、fallback 率的曲线。
2. 计算不同 $V$ 下 Embedding/Head 参数占比、实际序列长度和理论 FLOPs。
3. 实测每原始 MB/字符的训练吞吐，以及生成同等文本的端到端延迟，不只比 tokens/s。
4. 检查 token 频次分布和 vocabulary utilization，如果大量 token 几乎从不出现，词表可能过大或语料分布失配。
5. 在同等训练预算下比较下游任务；不能直接比较不同 Tokenizer 的 token-level perplexity，可转换为每字节 NLL/bits-per-byte 等共同单位。

### 面试简答版

词表大小为 $V$、hidden size 为 $d$ 时，Embedding 和 LM Head 各需 $Vd$ 参数，权重绑定可只存一份，但输出矩阵乘 $O(NdV)$ 仍然存在。大词表可将常见片段合成单 token，减少序列长度、Attention 开销、KV Cache 和自回归步数，但会增加参数、logits 显存和每步 Softmax 成本，且长尾 token 可能学不充分。小词表的基础单位频次高、组合性强，但序列长且生成慢。因此应根据多语言压缩率、词表利用率、模型宽度和端到端吞吐联合选择，不是越大越好。
