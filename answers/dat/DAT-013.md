## 我的答案

预训练数据清洗的目标不是把文本变得“越干净越好”，而是在**合法、可追溯、低泄漏**的前提下，减少低价值和重复 token，同时保留语言、领域和格式的多样性。一个典型流水线可以概括为：

```text
采集与登记 → 解析/抽取 → 基础规范化 → 语言与类型识别
→ 规则过滤 → 质量/安全分类 → 去重与污染过滤
→ PII/版权策略处理 → 分域采样与混配 → 切分/打包 → 审计发布
```

实际系统可能合并步骤，但必须记录每一步的版本、输入输出和拒绝原因。

### 1. 数据源登记与合规过滤

在下载或解析前记录来源 URL/数据集、时间、许可协议、内容类型、采集方式和可撤回标识，并执行 robots、授权范围、地域和组织政策。对于明确禁止使用或来源不明的数据，应尽早排除，避免它进入后续缓存和派生数据。

这是数据血缘的起点。只保存最终文本而丢失来源，后续很难做版权删除、污染追踪或质量复盘。

### 2. 解析与正文抽取

针对 HTML、PDF、Office、代码仓库、论坛等格式提取正文及必要元数据，去除导航栏、Cookie 提示、广告、重复页眉页脚和抓取错误。此阶段要保留段落、标题、代码块、表格等结构，不能简单把所有标签删除后拼成一行。

解析质量通常比后续语言模型过滤更基础：乱码、错列 PDF 和模板噪声若没有先处理，会污染质量分数和去重特征。

### 3. 基础规范化

常见操作包括统一字符编码、修复可识别乱码、标准化换行和有限的 Unicode 规范化。原则是**最小且可解释**，并保留原文或可逆映射。

不能过早 lowercase、删除标点或折叠所有空白，因为代码缩进、数学公式、专有名词和语言识别会依赖这些信息。URL、邮箱等是否替换也应由明确策略决定。

### 4. 语言、领域与文档类型识别

为文档或段落打上语言、代码/自然语言、领域、来源和时间标签。混合语言页面最好段落级识别，而不是整页只给一个标签。这些标签将用于不同阈值、采样权重和评估切片。

短文本的语言识别置信度通常较差，不应直接用统一阈值删除；代码、公式和专有名词也容易被误判为未知语言。

### 5. 规则与启发式过滤

低成本规则先剔除明显坏样本，例如：

- 文本过短、字符重复、乱码或控制字符比例过高；
- 字母/数字/标点比例异常；
- 导航链接、SEO 关键词、广告模板占比高；
- 行重复、超长单词或异常高压缩率；
- 解析失败、内容为空或二进制伪装成文本。

规则应按语言和数据类型配置。英文标点比例阈值直接用于 LaTeX 或代码，会误删大量高价值数据。

### 6. 质量与安全分类

可用分类器或小模型判断可读性、连贯性、信息密度、广告/垃圾、成人内容、仇恨、恶意代码等，并按政策做删除、隔离、降权或保留标签。质量不应只由“像百科”定义，否则会系统性淘汰口语、方言、论坛经验和低资源语言。

对于模型打分，应校准不同语言/领域的通过率，并人工抽检阈值附近、最高分和最低分样本。

### 7. 去重与 Benchmark 污染过滤

先做规范化后的精确哈希，再做段落/模板去重和 MinHash、SimHash 等近似去重。随后用保留的评测集、题目变体、答案和元数据做 contamination 检测。去重通常要在全局或足够大的数据分区上进行，仅在每个 shard 内去重会漏掉跨分片副本。

去重后应保留 canonical 文档和重复簇映射，而不是只剩一个不可追溯结果。

### 8. PII、秘密信息与策略处理

检测电话号码、邮箱、身份证件、地址、API key、私钥和其他敏感信息。根据风险采用删除文档、字段脱敏、占位符替换或受控隔离，并保留审计计数。正则适合结构明确的秘密，实体模型适合上下文相关 PII，两者通常结合使用。

脱敏必须谨慎安排在去重前后：先脱敏可减少敏感信息传播，但大量统一占位符会制造假重复；先去重则原始敏感数据会进入更多中间产物。工程上常在受控原始区先做高风险扫描和隔离，再对可用文本去重，并限制中间数据访问。

### 9. 采样、混配与去污染后的切分

按语言、领域、时间、来源和质量分桶，设置采样权重。高资源网页若按自然频率训练会淹没代码、数学和低资源语言；但过度上采样小语料又会导致多轮重复和记忆。

完成全局去重与 benchmark 隔离后，再划分 train/validation/test。最好按文档、站点、作者、仓库或时间做 group split，不能把同一文章的段落随机分到训练和验证。

### 10. Tokenize、切块和打包

最后根据模型上下文长度切块、拼接和加入文档边界 token。要避免把样本答案与下一样本问题无意拼接成可利用结构，也要决定跨文档 Attention、position reset 和 Loss mask。此阶段统计 token 数、截断率、padding 浪费和各域占比。

### 为什么顺序重要

顺序决定后续步骤看见的信号，也决定成本和可追溯性：

1. **先抽取再判质量**：否则 HTML 导航和 PDF 乱码会让好文档被误判；
2. **规范化要先于哈希去重**：否则只差换行或 Unicode 形式的副本不会相等；
3. **但不能过度规范化**：否则不同代码、公式或身份字符串会发生假碰撞；
4. **便宜规则先于昂贵模型**：减少需要分类和 embedding 的数据量；
5. **全局去重先于数据切分**：避免同一内容同时进入 train 与 validation/test；
6. **污染过滤先于打包**：打包后文档边界模糊，更难定位和删除；
7. **采样在过滤后计算**：否则实际保留比例与目标混配比例不一致；
8. **Tokenizer 统计放在最终文本上**：早期统计无法反映清洗后的真实 token 预算。

### 质量控制与可回滚性

每一步都应输出漏斗统计：输入/输出文档与 token 数、按语言和来源的通过率、拒绝原因、重复簇大小、PII 命中率。为防止静默偏差，还需要：

- 固定 golden set 做回归测试；
- 对各阶段进行分层人工抽检；
- 保存原始对象 ID、内容哈希、处理版本和 lineage；
- 用数据卡记录许可、时间范围、分布、已知盲区；
- 支持按来源、哈希或删除请求追溯并重建训练集。

### 面试简答版

预训练清洗一般按“来源与许可登记、正文解析、最小规范化、语言/类型识别、低成本规则过滤、质量与安全分类、全局精确和近似去重、benchmark 污染与 PII 处理、分域采样、数据切分、tokenize/打包”执行。顺序很重要：解析和适度规范化影响质量判断与去重，便宜规则要先降低昂贵模型成本，全局去重和污染过滤必须在 train/val/test 切分与打包之前，否则会产生泄漏。整个过程还要保存血缘、拒绝原因和分域漏斗，避免清洗把低资源语言或代码公式系统性误删。
