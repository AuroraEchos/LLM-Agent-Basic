## 我的答案

它们会把训练数据管线从一次性的“抓取—训练”流程，变成可审计、可限制、可追溯删除并能重建的长期数据治理系统。核心工程要求是：**每个数据对象都知道从哪里来、基于什么规则使用、包含哪些风险、进入过哪些派生数据和模型版本。**

具体义务会因国家/地区、数据来源、合同和使用目的而不同，下面是工程设计原则，不替代针对项目法域的法律意见。

### 版权如何影响管线

“互联网上能访问”不等于“可以任意复制并用于训练”。数据接入层需要记录：

- 来源 URL、发布者、抓取时间和内容哈希；
- 许可证、服务条款、授权合同及允许的用途/地域/期限；
- 是否允许商业使用、再分发、衍生数据和模型训练；
- 署名、notice、退出或删除要求；
- 数据集是否混入第三方作品，提供者是否真有相应权利。

不同法域对训练复制、文本与数据挖掘、合理使用及权利保留的规则并不相同，且仍在发展。例如美国版权局已经专门发布生成式 AI 训练报告并讨论许可与潜在市场影响，这恰恰说明不能把某一种法律结论写死在通用 ETL 代码中，应由 policy engine 根据数据源和部署法域执行。[美国版权局 AI 研究与训练报告](https://www.copyright.gov/policy/artificial-intelligence/index.html)

工程上应使用 allowlist/denylist、license policy、域名与作品 ID 级退出列表，在下载、混配和发布三个关口重复校验。版权命中不能只在最终文本删除：原始快照、解析文本、去重 canonical、副本簇、tokenized shard 和备份都要有处理策略。

### 个人信息如何影响管线

个人信息治理通常要求明确处理目的和依据、数据最小化、保存期限、访问控制、安全保护以及数据主体权利处理。中国《个人信息保护法》第四十七条规定了若干应主动删除或个人可请求删除的情形，并要求建立权利请求受理机制；欧盟 GDPR 第 5 条包括目的限制、数据最小化和存储限制，第 17 条规定了附带条件和例外的删除权。[中国《个人信息保护法》](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2022/art_04a0f1fb5df244e39688fd5372623a8d.html)、[欧盟 GDPR 正文](https://eur-lex.europa.eu/eli/reg/2016/679/oj)

因此数据管线至少要：

1. 在原始受控区检测身份证件、联系方式、地址、账号、健康/生物识别等信息；
2. 区分公开可见、获得授权、敏感和未成年人数据，按政策删除、脱敏或隔离；
3. 对 API key、私钥、密码等秘密使用高召回规则并立即隔离；
4. 加密存储和传输，最小权限访问，记录谁在何时读取/导出；
5. 规定 raw、派生数据、日志和备份的保存期限；
6. 评估跨境传输、第三方处理者和供应商数据流；
7. 对检测器做多语言、误报/漏报和人工抽检，避免只靠英文正则。

哈希化或替换姓名并不必然使数据匿名：上下文、唯一标识和外部数据仍可能重新识别。工程上应区分可逆假名化与难以重新识别的匿名化，并由风险评估决定用途。

### 遗忘请求如何传播

收到删除/退出请求后，先完成身份和授权验证，明确目标范围，再把请求转成稳定的 deletion key，例如来源 URL、文档 ID、内容哈希、作品 ID 或主体关联 ID。随后沿数据血缘图传播：

```text
source object
├─ raw snapshot / cache / backup
├─ parsed document
├─ normalized paragraphs
├─ duplicate cluster / canonical document
├─ train/validation shards
├─ synthetic or distilled derivatives
└─ trained checkpoints / deployed endpoints
```

仅删除数据库一行不够：同一内容可能有镜像、段落副本、搜索索引、对象存储版本、训练 shard 和下游导出。去重系统应保存 duplicate cluster 映射，派生数据应记录 parent IDs，才能找到所有副本。

处理状态应是幂等、可审计的状态机，例如 `received → verified → scoped → quarantined → deleted/restricted → validated → closed`。每一步保存法律/政策依据、操作对象、执行时间和证明，但审计日志本身也不应复制被删除的敏感全文。

### 已经训练进模型怎么办

从未来训练集删除数据，并不等于现有 checkpoint 已遗忘。需要分层处理：

- **尚未训练**：更新 denylist，删除或隔离所有数据副本并重建受影响 shard；
- **训练中/待发布**：停止使用相关 checkpoint，回到污染前 checkpoint 或重建训练；
- **已经训练**：评估模型是否能复现目标信息以及风险，选择重训、从合规基座恢复、机器遗忘方法或输出缓解；
- **已部署**：同步更新模型、检索索引、缓存和日志策略，并做定向提取/成员推断与回归测试。

机器遗忘不是简单删掉 Embedding 中某一行：一条样本的影响分散在大量参数中。现有近似 unlearning 方法可能损害邻近知识，也难证明完全消除。因此架构上应尽量把频繁变化、需精确撤回的私有事实放在可删除的 RAG/数据库中，而不是依赖参数记忆；高风险语料则通过隔离训练 run 和细粒度 provenance 降低重训范围。

若技术上不能立即从某些备份或模型中精确删除，不能自行宣称请求已完成。应按适用规则和组织政策限制后续处理、阻止恢复回流、记录原因和补救计划，并由隐私/法务负责人判断是否满足义务。中国《个人信息保护法》第四十七条本身也区分了删除与在特定情况下停止除存储和必要安全保护外的处理，说明工程状态不能只有一个 `deleted=true`。

### 需要建立哪些系统能力

- 数据目录与 lineage：source → shard → run → checkpoint → deployment；
- Policy-as-code：按许可、法域、目的、期限和敏感级别准入；
- 可重建的不可变数据版本，以及独立的 tombstone/denylist；
- 内容哈希、近似匹配和镜像簇，用于找到变体；
- DSAR/版权请求工单、SLA、审批和证据链；
- 训练 manifest：每个 checkpoint 精确关联数据版本和代码版本；
- 发布门禁：未完成删除传播和验证的模型不可上线；
- 定期红队：测试 PII 提取、逐字复现、RAG 缓存和日志泄漏。

需要注意，删除权、版权退出、合同终止和安全事件的适用条件并不相同，数据表中应分别记录法律/合同依据，而不是都归成一个模糊的“用户要求删除”。

### 面试简答版

版权和个人信息要求训练管线具备来源许可、用途/法域、保存期限、敏感级别和完整血缘，不能把公开可访问等同于可训练。接入时做 license policy、PII/秘密扫描和最小权限隔离；每个 checkpoint 必须关联精确的数据 manifest。遗忘请求经身份与范围验证后，要沿 source、镜像/去重簇、解析文本、token shard、派生合成数据、备份、RAG 索引和模型部署传播。未训练数据可删除重建；已进参数则需评估重训、回滚或机器遗忘，且近似 unlearning 不能轻易承诺完全删除。具体义务依适用法域和合同确认，工程上应让请求幂等、可审计、可验证并防止删除数据从缓存或备份回流。
