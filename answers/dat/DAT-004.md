## 我的答案

Unigram Tokenizer 称为“自顶向下裁剪”，是因为它不像 BPE 那样从字符开始逐个合并，而是**先构造一个远大于目标词表的候选子词集，建立概率模型，再反复删除对语料似然不重要的 token。** Viterbi 算法则在给定词表和 token 概率时，用动态规划选出一条全局概率最大的分词路径。

### Unigram 概率模型

对一个文本片段 $x$，假设某种分割为：

$$
s=(t_1,t_2,\ldots,t_m)
$$

Unigram 做一个简化假设：分割中的 token 概率独立，因此：

$$
P(s)=\prod_{i=1}^{m}P(t_i)
$$

对数形式是：

$$
\log P(s)=\sum_{i=1}^{m}\log P(t_i)
$$

同一字符串往往有多种可能分割，如 `unigram`可能分成：

```text
unigram
uni + gram
un + i + gram
u + n + i + g + r + a + m
```

模型需在这些路径之间进行全局选择或求和，而不是只看当前位置的最长 token。

### 为什么先大后小

#### 1. 生成大型候选词表

先从语料中收集字符和大量频繁子串。候选数可远大于最终词表，以便同时保留多种粒度的可能分割。

基础字符、byte fallback token、特殊 token 等通常是必保留项，否则裁剪后可能出现某些文本完全无法分割的情况。

#### 2. 估计 token 概率

在当前词表下，使用 EM 式过程优化 token 概率：

- E 步骤根据当前概率，计算各 token 在所有合法分割中的期望使用次数；
- M 步骤使用期望计数重新估计 $P(t)$。

完整训练统计可使用 forward-backward 式动态规划对多条分割路径求和。这与只选一条最优路径的 Viterbi 不完全相同。

#### 3. 评估删除每个 token 的损失

对候选 token $t$，估计如果删除它，原来使用 $t$ 的文本改用其他分割后，语料负对数似然会增加多少。

- 删除后 loss 增加很大：该 token 很重要，应保留。
- 删除后 loss 几乎不变：该 token 可被其他分割良好替代，可优先裁剪。

#### 4. 分批裁剪并重新训练

每轮删除一小部分低价值 token，然后重新估计剩余 token 概率。不一次删到目标大小，是因为 token 的价值相互依赖：删除一个 token 后，其他 token 的期望计数和替代价值会变化。反复执行直到接近目标 vocabulary size。

因此它是“自顶向下”：从过完备的候选集出发做消融，而不是从最小单位不断生成新 merge。

### Viterbi 在编码中做什么

将字符串的每个位置看作图中的节点。若子串 $x_{j:i}$ 是词表 token，就有一条从位置 $j$ 到 $i$ 的边，边分数为 $\log P(x_{j:i})$。问题变成 DAG 上的最高分路径。

定义 $dp[i]$ 为前 $i$ 个字符的最优对数概率：

$$
dp[i]
=
\max_{j<i,\,x_{j:i}\in V}
\left(dp[j]+\log P(x_{j:i})\right)
$$

同时保存使得最大值成立的 `backpointer[i]`。到达字符串末尾后，沿 backpointer 回溯就得到全局最优 token 序列。

设文本长度为 $N$，词表最长 token 长度为 $M$，用 trie 查找可匹配子串时，编码复杂度可近似为 $O(NM)$，而不需枚举指数多条完整分割。

### Viterbi 与采样的区别

- 确定性编码使用 Viterbi，返回 $\arg\max_sP(s)$。
- Subword Regularization 可以从多个 segmentation 按概率采样，让模型训练时不过度依赖唯一分词。
- N-best Viterbi 可以返回多条高分路径，但与严格按后验分布采样仍是不同操作。

### 与 BPE 的本质差异

BPE 编码由学习到的 merge rank 决定，词表 token 本身通常没有用于分割的显式概率。Unigram 可能的分割共享同一个概率词表，使用 DP 进行全局最优化或采样。这使 Unigram 更自然地支持分词不确定性，代价是训练和编码实现比贪心/有序合并更复杂。

### 面试简答版

Unigram 先收集一个很大的候选子词集，假设一条 segmentation 的概率是各 token 概率之积，通过 EM 估计 token 概率。然后估算删除每个 token 会使语料 loss 增加多少，分批删除低影响 token 并重新估计，直到目标词表大小，所以是自顶向下裁剪。编码时将字符位置视为 DAG 节点，词表 token 是带 $\log P(t)$ 分数的边，Viterbi 用动态规划选出总对数概率最大的全局分割。训练的期望计数可用 forward-backward 对多路径求和，不应把整个 Unigram 训练简化为只跑 Viterbi。
