## 我的答案

先澄清一个容易混淆的层次：**BPE、WordPiece 和 Unigram 是构建/分割子词的算法思路；Byte-Level BPE 是 BPE 在字节基础符号上的变体；SentencePiece 是一套可直接在原始 Unicode 文本上训练/编码的工具与方案，它可在内部使用 BPE 或 Unigram，不是与它们完全同级的第四种分割目标。**

### BPE

BPE 从字符等小单位开始，反复合并当前语料中最高频的相邻 token pair，直到词表达到目标大小。

- **训练方向**：自底向上合并。
- **优化信号**：相邻 pair 的频次。
- **编码**：按有顺序的 merge rank 重放可用合并。
- **优点**：简单、确定、训练和编码高效；常见片段变短，罕见词可拆成子词。
- **限制**：高频 pair 不一定对应语义边界；若底层字符集不完整且没有 byte fallback，仍可能 OOV。

### Byte-Level BPE

Byte-Level BPE 先将文本编码为 UTF-8 字节，再在 256 种基础字节及它们的合并上运行 BPE。某些实现会先将字节可逆映射成便于存储和显示的 Unicode 符号。

- **基础单位**：Byte，而不是 Unicode code point。
- **优点**：任意文本、代码、emoji 或未见字符都能退化为字节序列，基本没有 `<unk>`。
- **限制**：一个非 ASCII 字符通常对应多个 UTF-8 byte，若语料中没学到好的合并，中文、小语种和罕见字符序列可能较长。单个 token 的可视字符边界也不一定直观。

### WordPiece

WordPiece 也是自底向上构造词表，但合并不只看 pair 的绝对频次，而更倾向选择能提高语料概率/关联强度的组合。常见教学式 score 为：

$$
\operatorname{score}(a,b)
\propto
\frac{\operatorname{count}(ab)}
{\operatorname{count}(a)\operatorname{count}(b)}
$$

它会降低由两个各自高频、但结合不突出的 token 形成的 pair 的优先级。精确训练目标与实现可有差异，应理解为“似然/关联改善”，而不是将上述比值当成所有 WordPiece trainer 的唯一规范。

编码时 WordPiece 常对每个预分词结果使用从左到右 longest-match-first，并用如 `##ing` 的标记区分词首和词中子词。若某个词无法完全由词表片段覆盖，某些实现会将整个词变成 `[UNK]`。

### Unigram Language Model

Unigram 与 BPE/WordPiece 的构建方向相反：它先生成一个较大的候选子词集，然后迭代估计每个 token 的概率并裁掉对语料似然最不重要的 token，直到目标词表大小。

对分割 $s=(t_1,\ldots,t_m)$：

$$
P(s)=\prod_{i=1}^{m}P(t_i)
$$

编码时可用 Viterbi 动态规划选择概率最大的全局分割，而不是局部贪心合并。因为同一文本有多条可能分割，训练时还可按概率采样多种 segmentation，实现 subword regularization。

### SentencePiece

SentencePiece 的关键特点是将输入视为原始 Unicode 字符串，不强制依赖语言特定的空格分词器。它通常将空格显式转换为如 `▁` 的元符号，使空白成为可学习且可逆的序列一部分。

SentencePiece 可选择：

- BPE model：训练有序 merge；
- Unigram model：训练概率词表并用 DP 分割。

它还可集成 Unicode normalization、字符覆盖率、byte fallback、special/control symbol 和 segmentation sampling。因此说“SentencePiece 比 BPE 的合并目标更好”是一个类别错误：SentencePiece 本身可以就在运行 BPE。

### 核心对比

| 方法 | 基础单位 | 词表构建 | 默认分割思路 | OOV 特点 |
|---|---|---|---|---|
| BPE | 字符/自定义 alphabet | 高频 pair 自底向上合并 | 按 merge rank | 取决于初始 alphabet/fallback |
| Byte BPE | 256 种字节 | 高频 byte/token pair 合并 | 按 merge rank | 基本无 OOV，罕见字符可能多 token |
| WordPiece | 字符/词内片段 | 按似然或关联改善合并 | 常用最长匹配 | 无完整覆盖时可产生 UNK |
| Unigram | 大型候选子串 | 概率建模后自顶向下裁剪 | Viterbi/采样全局分割 | 通过必保留字符/fallback 控制 |
| SentencePiece | Unicode 原始文本接口 | 可用 BPE 或 Unigram | 取决于内部 model | 支持字符覆盖和 byte fallback |

### 面试简答版

BPE 从字符出发反复合并最高频 pair，编码时按 merge rank 重放。Byte-Level BPE 只是将底层单位换成 256 种 UTF-8 字节，因此基本没有 OOV，但非 ASCII 罕见字符可能更长。WordPiece 合并时更关注语料似然或 pair 关联度，编码常用 longest-match-first。Unigram 从大候选词表出发，按删除 token 对似然的影响逐步裁剪，编码用 Viterbi 选全局最优分割。SentencePiece 是不依赖语言特定预分词的原始 Unicode 文本工具，可在内部使用 BPE 或 Unigram，因此不应把它当作与 BPE/Unigram 并列的单一分割算法。
