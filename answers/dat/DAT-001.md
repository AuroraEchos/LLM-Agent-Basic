## 我的答案

BPE（Byte Pair Encoding）是一种**自底向上的确定性子词构建方法**：训练时从字符或字节等基础符号出发，反复合并语料中最常见的相邻符号对；编码时按训练得到的合并优先级重放这些合并。

### 训练前处理

一条完整 Tokenizer 管线通常先做：

1. **Normalization**：根据需要做 Unicode 规范化、大小写处理或其他文本清洗。
2. **Pre-tokenization**：按空格、标点、正则或语言规则切成若干片段。某些实现不依赖空格分词，但仍会显式编码词边界或空白。
3. **统计片段频次**：相同片段可只存一份符号序列，同时保存它在语料中的频次，以减少重复计算。

BPE 算法本身与这些前处理可分离：两个都称为“BPE Tokenizer”的系统，如果 normalization 和 pre-tokenization 不同，最终词表和编码也会很不同。

### 训练过程

假设预切分后的语料片段及频次是：

```text
low     5
lower   2
lowest  2
```

若以字符为初始符号，可写成：

```text
l o w
l o w e r
l o w e s t
```

实际中常加词尾标记或在 token 上保留词首/空格信息，以区分词边界。

#### 1. 初始词表

初始 vocabulary 包含所有基础符号。字符级 BPE 以语料中的字符为基础；Byte-Level BPE 则以全部 256 种字节值等的可逆映射为基础。特殊 token 通常预先保留，不参与普通合并。

#### 2. 统计所有相邻符号对

对当前分割结果中的每个相邻 pair 计数，并乘以对应片段在语料中的频次。例如 `(l, o)` 出现在上述三种片段中，加权计数为 $5+2+2=9$。

#### 3. 选择最高频 pair 并合并

如果 `(l, o)` 是最高频 pair，则新建 token `lo`，记录合并规则：

```text
l o -> lo
```

并把语料中对应的相邻出现替换为 `lo`。下一轮可能再将 `(lo, w)` 合并为 `low`。

#### 4. 反复迭代

每轮都在更新后的序列上重新统计 pair，直到：

- vocabulary 达到目标大小；
- 达到指定 merge 次数；
- 最高 pair 频次低于阈值。

训练产物至少包括 token-to-id 词表和有顺序的 merge list/rank。同频 pair 必须有确定性 tie-break 规则，否则同一语料可能得到不同词表。

### 对新文本的编码过程

1. 使用与训练时**完全相同**的 normalization 和 pre-tokenization。
2. 将每个片段初始化为字符或字节符号序列。
3. 查找当前存在的可合并相邻 pair，优先应用训练中 rank 最高（最早学到）的 merge。
4. 合并后重新检查新产生的相邻 pair，直到没有规则可应用。
5. 将最终 token 查表转为 token ID，并根据模型模板加入 BOS、EOS 等特殊 token。

编码不能简化为“每次都选最长词表 token”。BPE 的分割由**有顺序的 merge rank**决定；WordPiece 才常使用从左到右的 longest-match-first。高效 BPE 实现会用优先队列和局部更新避免每轮扫描所有 merge，但语义应与 rank 重放一致。

### OOV 如何处理

- 字符级 BPE 若遇到初始 alphabet 中不存在的字符，仍可能输出 `<unk>`。
- Byte-Level BPE 或带 Byte Fallback 的 BPE 可将任意 Unicode 文本的底层 UTF-8 字节表示出来，基本避免真正 OOV。
- “无 OOV”不代表分词质量高：罕见字符若被拆成多个 byte token，会增加序列长度并损失直观语义单位。

### 边界和工程注意

- BPE 优化的是语料中相邻 pair 频次，不是直接优化下游任务效果或语言学边界。
- 高频词常会变成一个或少量 token，低频词会保留为可组合子词，在词级与字符级之间折中。
- 修改 normalization、pre-tokenizer、merge rank、词表 ID 或特殊 token 都会改变模型输入，不能在加载已训练模型时随意替换。
- 生产系统应做 `decode(encode(text))` 回转测试，但如果 normalization 本身有损，只能保证对规范化后文本可逆，不能恢复原始字节。

### 面试简答版

BPE 训练时先将语料表示成字符或字节序列，统计所有相邻 pair 的加权频次，每轮将最高频 pair 合并为新 token，记录合并顺序，直到词表达到目标大小。编码新文本时，先使用与训练相同的规范化和预分词，再从基础符号出发，按学到的 merge rank 反复合并当前相邻 pair，最后查词表得到 ID。Byte-Level BPE 以 256 种字节为底层覆盖，基本避免 OOV；字符级 BPE 若没有 byte fallback，遇到初始字符集之外的字符仍可能输出 `<unk>`。
