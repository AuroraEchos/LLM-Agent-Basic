## 我的答案

三者都在解决“真实文档长度不一致，而加速器喜欢规则密集张量”的矛盾：Padding 让张量等长但可能浪费计算；Packing 把多个短样本装进一个序列提高有效 token 比例；Sequence Length Warmup 让训练早期先处理短序列，降低初期计算和优化难度，再逐步达到目标长度。

### Padding：实现简单，但空位也可能消耗算力

一个 batch 有 $B$ 条样本，长度为 $l_i$，补到该 batch 最大长度 $L$。token 利用率为：

$$
U_{\text{pad}}=\frac{\sum_{i=1}^{B}l_i}{B\cdot L}
$$

例如长度为 100、200、900、1000 的 4 条样本都补到 1000，利用率只有 55%。若内核仍对 padding 位置执行投影和 Attention，大量 FLOPs 与显存带宽被浪费。

attention mask 只能保证 pad 不影响语义，不等于硬件自动跳过其计算。按相近长度 bucketing、动态 batch、varlen/FlashAttention 内核可减少浪费，但会增加数据调度复杂度。

### Packing：把空白位置变成有效 token

若目标长度为 1024，可以把多个短文档拼到同一 1024-token block，接近：

$$
U_{\text{pack}}=\frac{\text{有效非 padding token}}{B\cdot L}\approx1
$$

常见方法包括：

- **Greedy/First-Fit Packing**：按长度把样本装入固定容量 bin；
- **Concatenation + Chunking**：连续拼接 token 流，再切固定长度 block；
- **Variable-length packed sequence**：物理连续存储多条序列，用边界信息让 Attention 内核分别计算。

Packing 对大量短样本尤其有效，既提高每步有效 token 数，也减少 padding 的激活与通信浪费。

### Packing 的语义边界

把文档 A 和 B 拼在一起后，必须决定 B 能否看到 A。

#### 允许跨文档 Attention

只插入 `<eos>` 后使用普通 causal mask，B 可以看到 A。实现简单且训练密集，但会制造本来不存在的跨文档条件关系，甚至把前一文档答案泄给后一题。大规模预训练中偶尔的随机相邻影响可能有限，SFT、评测和隐私敏感数据则通常不可接受。

#### 使用 block-diagonal causal mask

每条样本只关注自身更早位置，逻辑上等价于独立序列。此时要同步处理：

- 每段 position IDs 是否从 0 重置；
- BOS/EOS 和文档分隔 token；
- 每段 loss mask，尤其 prompt 部分和 padding；
- Attention 内核是否真正支持 varlen/block-diagonal，而不只是构造一个巨大的稠密 mask。

如果仍对长度 $L$ 的完整稠密矩阵计算，Packing 虽减少 token padding，却不一定减少 Attention 的 $O(L^2)$ 计算。支持按各段长度计算的 varlen 内核，其注意力成本更接近：

$$
\sum_j O(l_j^2)
$$

而不是 $O((\sum_jl_j)^2)$。

### Packing 不一定让“每步样本数”固定

一个 packed sequence 中可能装 2 条，也可能装 20 条。训练指标和梯度归一化应按有效 loss token 计算，而不是简单按 packed block 数；分布式训练还要确保各 rank 的有效 token 数和计算量尽量均衡。

样本跨 block 截断时，要明确是允许长文档连续分块，还是丢弃尾部。若拼接后直接定长切块，边界附近的短尾可能与下一文档混合，因此需要记录 segment IDs。

### Sequence Length Warmup

设目标长度为 $L_{\max}$，训练进度为 $t$，可用分段或平滑 schedule：

$$
L(t)=\min\bigl(L_{\max},L_0+(L_{\max}-L_0)s(t)\bigr)
$$

其中 $s(t)$ 从 0 增长到 1。早期用 $L_0$：

- Attention 成本更低，可更快处理大量 token；
- 激活显存较小，可使用更大 batch；
- 先学习局部语言规律，优化通常更稳定。

但调长序列时必须明确保持什么不变：

- 若保持每步 sequence 数不变，tokens/step 和显存会大涨；
- 若保持 global tokens/step 不变，sequence 数会下降；
- 若保持训练 step 不变，总 token 预算会改变。

因此学习率、梯度累积、batch size 和日志都应以实际 non-pad loss token 为基准。长度切换最好平滑，并提前验证位置编码、RoPE 扩展和 checkpoint 重启。

### 长度 Warmup 的能力风险

短序列省下算力并不自动带来长上下文能力。模型必须在后期见到足够多、真正包含长距离依赖的长文档；把许多互不相关短文档 pack 到 32K，只是张量长，不代表学到了 32K 依赖。

评估应覆盖长文档 perplexity、needle/retrieval、跨段推理和位置鲁棒性，并按真实长度分桶，而不是只看训练总 Loss。

### 面试简答版

Padding 把 batch 补到同长，简单但利用率 $\sum l_i/(BL)$ 可能很低，而且 mask 掉语义不代表跳过计算。Packing 把多个短样本装入固定 block，可把有效 token 比例提高到接近 100%，但必须正确设置 EOS、segment、position ID、loss mask 和 block-diagonal causal attention，防止跨样本泄漏；最好配合真正的 varlen 内核。Sequence Length Warmup 早期用短序列降低 Attention 和激活成本，后期逐步升到目标长度，但要按有效 token 调整 batch/学习率，并给长文档和长距离依赖足够训练量，否则只是支持长位置，未必会使用长上下文。
