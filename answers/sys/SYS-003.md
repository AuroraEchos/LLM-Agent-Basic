## 我的答案

统一平台不意味着在线和离线共用一条队列。正确思路是**共享控制面、模型制品和执行协议，隔离数据面队列、SLO 和资源配额**：在线追求低尾延迟，离线追求吞吐、可恢复和低成本。

### 架构

```text
                    Unified Control Plane
 Model Registry / Runtime Spec / Policy / Quota / Scheduler / Observability
              │                                  │
      Online API & Stream                 Batch Job API
              │                                  │
      Bounded Priority Queue              Durable Job Queue
              │                                  │
      Reserved Online Pools  ←elastic→   Batch / Spot Pools
              └────────── Unified Worker Runtime ──────────┘
                   Object Store / Result Manifest
```

模型注册中心保存不可变 artifact digest、tokenizer、runtime、量化、并行、LoRA、Prompt/安全策略和兼容 Schema。在线请求与批任务都转换成统一 `InferenceRequest`，worker 使用相同预处理、推理、后处理和遥测代码，避免两套结果语义漂移。

### 在线路径

网关完成鉴权、配额、deadline 和请求大小校验，路由到模型专属的短有界队列；GPU 池常驻模型，使用 continuous batching 和流式返回。在线池预留最低容量，不能被离线任务占满。超载时尽早返回 429、降级或切备用池，不能进入数小时的持久队列。

### 离线路径

用户提交输入数据 URI、模型/配置版本、输出位置、优先级和预算。控制面生成 job 与分片 manifest，数据保留在对象存储，队列只传引用。worker 拉取分片、微批推理并写临时结果，成功后原子提交 manifest。

任务状态机可为 `PENDING→RUNNING→SUCCEEDED/FAILED/CANCELLED`。每个分片有 lease、heartbeat、attempt 和幂等输出键；worker 故障后 lease 过期可重试。语义通常选择 at-least-once 执行 + 幂等提交，而不是声称真正 exactly-once。支持 checkpoint、部分重跑、失败记录隔离和最终汇总。

### 资源调度和隔离

- 在线池保留容量；离线任务使用剩余、谷时或可抢占/Spot 资源。在线 SLO burn 或队列上升时，停止新离线分片并在安全点抢占。
- 按模型、GPU 类型、显存、上下文和数据驻留做 placement；批任务尽量按模型和 adapter 聚合，减少反复加载。
- 使用层级配额和加权公平调度，token/GPU-second 计费；离线任务设并发、最大重试和成本上限。
- 模型制品本地/节点缓存，校验 digest；缓存与数据严格按租户和权限隔离。

离线可以使用更大的静态/动态 batch 和吞吐优化，在线则使用小等待窗口的 continuous batch。两者不要强行使用相同 batch 参数，只共享可版本化的 runtime 能力。

### 一致性、版本与可观测性

job 提交时将模型、Prompt、tokenizer、检索快照和输出 Schema 固定到具体版本，确保运行数小时后仍可复现。模型升级不能让一个 job 的不同分片产生混合版本；需要升级时创建新 job 或显式迁移。

在线监控 TTFT、TPOT、P99 和流中断；离线监控排队时间、吞吐、完成 ETA、分片重试和失败样本；共同监控 GPU/KV、token、成本、版本和质量。数据采用加密、短期凭据、租户 ACL 和保留/删除策略，日志不复制完整输入输出。

### 面试简答版

统一推理平台应共享模型注册、版本、执行协议、worker runtime 和可观测性，但在线与离线使用隔离队列及 SLO。在线走常驻模型、短有界队列、continuous batching 和流式返回，并保留容量；离线走持久 job/分片队列、对象存储 manifest、大 batch 和谷时/Spot 资源。离线采用 lease、heartbeat、checkpoint、at-least-once 加幂等输出提交来容错。调度器允许离线填充闲置资源，但在线压力上升时在安全点抢占。提交时固定模型、Prompt 和数据快照版本，防止长任务混用版本。
