> **问题：** 在 GPU 数量固定的情况下，如何为业务制定模型质量、延迟、吞吐和成本的容量方案？

## 我的答案

固定 GPU 下不能同时无限提高质量、低延迟和吞吐。方法是先把质量和 SLO 定成硬约束，再用真实流量对候选模型/引擎压测，求一个在峰值和故障场景仍可行的路由与资源分配方案。

### 1. 描述业务负载

按任务、租户和优先级统计到达率及突发系数、输入/输出 token 的 P50/P95/P99、上下文复用、流式/批处理、质量下限、TTFT/TPOT/E2E SLO、可用性和数据/模型限制。平均 QPS 会掩盖长上下文和长尾输出，容量单位至少拆成 prefill token/s、decode token/s、KV Cache 和并发序列。

### 2. 质量先筛选

对每类任务评测大/中/小模型、量化、Prompt、RAG 和级联方案，得到任务成功、安全、最差切片与置信区间。先剔除不满足硬质量/安全门槛的配置，再优化性能；不能因为 GPU 紧张把医疗、资金等请求静默路由到不合格小模型。

对可升级任务定义：小模型先答或分类，置信不足/高风险升级大模型。级联实际成本为：

$$
E[C]=C_s+p_{upgrade}C_l
$$

还要计入两次调用延迟和误路由损失，只有端到端压测证明有收益才采用。

### 3. 建立性能画像

在目标 GPU、模型精度和引擎上，用线上长度/到达分布测不同 batch、并发、prefix cache 和并行配置，记录 TTFT、TPOT、throughput、KV/显存、错误、功耗和每请求 token。模型的服务能力不能用理论 FLOPS替代。

初步流量需求：

$$
D_{in}=\lambda E[T_{in}],\qquad D_{out}=\lambda E[T_{out}]
$$

Little 定律用于校验并发：

$$
L=\lambda W
$$

但排队延迟在高利用率附近非线性上升，所以不能把 GPU 规划到长期 100%。以压测找到满足 P99 的最大安全吞吐，并保留发布、故障和预测误差余量。

### 4. 求资源与路由方案

将 GPU 按模型池/服务等级分配。决策变量 $x_{m,g}$ 表示模型 $m$ 使用多少 GPU，在约束下最大化业务价值或成功任务：

$$
\max \sum_t value_t\cdot served_t
$$

约束包括总 GPU、各任务质量下限、pool 吞吐、KV 显存、P99、冗余和预算。可用线性/整数规划给初稿，再以离散事件模拟和压测验证，因为 batch 与排队不是线性的。

通常为核心在线大/小模型保留独立池，批任务使用剩余/谷时并可抢占；长上下文单独配额或分池。热门模型常驻，prefix cache 只在权限和版本相同的范围复用。路由器依据能力、任务、deadline、队列、预算和健康选择，低风险可降级/缩短输出，高风险转人工或排队。

### 5. 超载与高可用

预留 N+1 或可接受的单节点故障容量，并测试单 GPU/节点、模型实例和依赖故障。队列有界、token-aware 准入；超载依次使用缓存、批处理等待、非核心功能关闭、风险允许的小模型降级、限流/429，而不是无限排队。扩不了 GPU 时，必须明确业务优先级和 admission policy。

### 6. 观测和复算

核心看每池队列预计等待、运行/排队 token、TTFT/TPOT/P99、KV 命中与压力、batch size、取消、质量代理、升级率、成功任务和 GPU-hour/成功任务。流量、输出长度、模型或 Prompt 变化都会让旧容量表失效，按周/月重放真实脱敏流量并更新方案。

固定 GPU 的“成本”还包括能耗、许可、运维和机会成本。最终交付应包含正常/峰值/单节点故障三张容量表、质量与 SLO 假设、降级顺序、报警阈值和压测证据。

### 面试简答版

我先按任务统计峰值到达、输入/输出 token 分布、质量下限和 TTFT/TPOT/P99，再在目标 GPU 上对各模型、量化和 batch 做真实压测，得到满足 SLO 的安全 token/s 与 KV 容量。质量/安全不达标的配置先剔除；剩余方案把 GPU 分给大小模型和在线/批处理池，通过级联路由提高利用率，并用整数规划/模拟给初稿、压测验证。容量保留 N+1 和突发余量，队列有界且按 token 准入，超载按业务优先级缓存、抢占批任务、风险允许的降级或限流。最终以每成功任务成本而非每 token 单价优化。
