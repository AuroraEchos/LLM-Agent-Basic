> **问题：** 如何在推理服务中同时优化高并发、低延迟、高可用和低成本？

## 我的答案

这四个目标相互制约：大 batch 提高吞吐和降低单位成本，却可能增加排队与 TTFT；大量冗余提高可用性，却降低平均利用率；激进排队提高 GPU 利用率，却会造成尾延迟雪崩。因此先定义分层 SLO，再做约束下的多目标优化，而不是追求单个 GPU 利用率最大。

### 1. 建立正确指标和预算

按任务/租户定义 TTFT、TPOT、端到端 P95/P99、成功率、质量下限和每成功任务成本。将延迟拆成：

$$
T_{e2e}=T_{gateway}+T_{queue}+T_{prefill}+N_{out}\cdot T_{pot}+T_{post}
$$

分别设置预算，才能判断该扩容、限流、缩短上下文还是优化 kernel。容量规划使用输入/输出 token 分布、峰值和模型实测吞吐，不用平均 QPS 或理论 FLOPS。

### 2. 高并发与低延迟

- worker 内 continuous batching，让新请求在 decode step 加入，完成请求及时离开；按长度/模型/LoRA 分桶，降低 padding 与队头阻塞。
- 使用 paged KV Cache、prefix cache、量化和高效 attention/kernel；热点模型常驻，避免冷启动。
- 将交互式与批处理分池或分配资源保留，长上下文和超长输出设上限；队列有界并做 deadline-aware admission。
- 可在流量足够时做 prefill/decode 分离，提高阶段独立扩容能力，但仅在 KV 传输与网络开销经过压测后采用。
- 流式返回降低感知延迟，但不能改善真实 TPOT；要同时优化首 token 和持续生成速度。

### 3. 高可用

网关和路由跨可用区多副本，模型池至少 N+1 容量，发布采用滚动/金丝雀和优雅摘流。对模型池、工具和上游分别做超时、熔断、隔离舱和健康探测；保留 last-known-good 配置及回滚开关。

降级按业务风险设计：低风险可切小模型、减少采样/输出或关闭非核心 Judge；高风险请求宁可转人工或失败，也不能静默使用不满足质量/安全要求的模型。重试只针对明确瞬时且幂等的失败，并计入原始 deadline，使用退避与抖动，防止重试风暴。

### 4. 低成本

- 用复杂度分类器或级联路由：简单请求走小模型，低置信度或高风险再升级；路由收益必须扣除误路由导致的质量损失和二次调用成本。
- prefix/KV cache、精确响应缓存、prompt 压缩和 RAG 精简上下文减少 token；缓存键须包含模型、Prompt、权限和数据版本，避免跨租户泄漏。
- 对满足质量下限的模型采用量化、投机解码、适当并行与实例规格；以实际负载压测选型。
- 稳定基线用预留/自有容量，突发流量用弹性容量；离线任务填充谷时但可被在线流量抢占。
- 关注 `cost / successful task`，因为便宜模型若失败和重试更多，可能总成本更高。

### 5. 调度与扩缩容

使用 token bucket 做租户配额，采用加权公平/优先级调度，同时给低优先级 aging，避免饿死。准入估计 prefill、输出上限和 KV 占用，超出 deadline 的请求尽早拒绝或降级。

扩容信号优先用队列预计等待、运行中 token、KV Cache 压力和 SLO burn rate，而非滞后的 GPU 利用率；模型加载慢时维护 warm pool，并基于流量预测提前扩容。缩容要等请求排空和 KV 释放，设置稳定窗口防抖。

### 验证方式

建立真实长度和到达分布的负载测试，画 concurrency—throughput—TTFT/TPOT—cost 曲线，测试突发、长短混合、慢客户端、节点故障、模型发布和上游超时。上线通过按版本/任务切片的 SLO、错误预算和单位成功成本共同决策。

### 面试简答版

高并发、低延迟、高可用和低成本不能同时无限最大化。我先把延迟拆成排队、prefill、逐 token decode 和后处理，并定义 TTFT、TPOT、P99、质量及每成功任务成本。执行层用 continuous batching、paged/prefix KV Cache、长度分桶和热点常驻；队列有界、token-aware 准入，在线与离线隔离。可用性依靠跨 AZ、多模型池熔断、N+1 余量和风险感知降级。成本通过大小模型级联、量化、缓存与谷时批处理优化。扩缩容看预计等待、token 和 KV 压力，最后用真实分布压测寻找 Pareto 点，而不是只追求 GPU 利用率。
