## 我的答案

我会先确认业务的 **RTO、RPO、数据驻留、跨境限制、峰值容量和会话一致性**。大模型服务不仅有无状态推理，还有会话、配额、RAG、工具副作用与日志；不同状态的复制策略必须分开设计。

### 架构与地域模式

```text
Client → Global Traffic Manager / Anycast
             │ health + latency + residency
      ┌──────┴──────┐
      ▼             ▼
 Region A Cell   Region B Cell
 Gateway         Gateway
 Router          Router
 Model Pools     Model Pools
 Regional RAG    Regional RAG
 Tool Proxy      Tool Proxy
      └────── control/config replication ──────┘
```

每个地域是可独立运行的 cell，包含网关、路由、模型池、区域内缓存、RAG 副本和监控，避免正常请求跨地域串联。低 RTO、高利用率场景选 active-active；成本更敏感或存在单主数据时可 active-passive，但备用区要持续预热模型、验证容量，不能只有空集群。

全局流量管理同时依据健康、网络延迟、容量和数据驻留路由。DNS 健康检查可作为一层，但 TTL、客户端缓存和局部故障使它不够精细；入口还需区域级熔断、连接级重试和手动隔离开关。

### 状态与复制

- 模型、Prompt、策略和工具 Schema 作为不可变制品按 digest 异步复制，发布时只启用已完整校验的版本；区域保留 last-known-good。
- 配额、路由和 feature flag 使用版本化配置；关键变更需要一致发布或明确区域版本差异。
- 会话指定 `home_region`，短期状态留在区域内；故障切换若无法复制完整会话，就显式重新建会话并提示，而不是假装无损续接。
- RAG 文档依数据主权做区域副本或区域独占，ACL 与删除事件必须和内容一起传播。索引允许最终一致，但要暴露版本和滞后。
- 资金、邮件、删除等工具操作使用全局唯一 idempotency key、业务侧去重和事务状态，防止跨区重试产生两次副作用。

### 故障检测与切换

健康检查分层：进程存活、模型可推理、依赖可访问、合成业务请求和 SLO burn rate。只有探针连续失败并超过阈值才摘流，恢复后以小流量探测再逐步加入，避免抖动。

切换流程是停止向故障区分配新会话、优雅排空可完成请求、将流量切到有容量且满足驻留的区域。已断开的流式生成通常不能透明迁移 KV Cache；客户端收到带 `request_id/sequence_no` 的终止事件后可重试，服务端按幂等键决定重新生成或续取已持久化事件。重试受原始 deadline 和预算约束。

定期做区域故障演练，验证备用容量、制品完整、DNS/路由收敛、RTO/RPO、工具幂等和回切。回切要先同步状态、canary 验证再逐级加流，不能故障一恢复就全量反切。

### 安全的流量回放

回放用于容量、兼容和故障验证，但生产 Prompt 常含隐私。采集时默认保存结构化特征、版本、长度与脱敏/令牌化内容；完整样本需单独授权、加密、短 TTL 和访问审计。回放集按租户、语言、长度、任务和失败类型分层，并保留原到达间隔或按目标倍数整形。

回放环境固定模型、Prompt、索引快照和依赖 mock。shadow 请求禁止真实写工具、邮件和支付，改用 sandbox/canary；为每个请求生成新的 trace，但保留关联 ID。比较 TTFT/TPOT、错误、路由、成本、结构契约、质量与安全差异。非确定生成使用多次采样或 Judge/人工比较，不能要求逐字一致。

### 面试简答版

我会按 RTO/RPO、数据驻留和成本选择 active-active 或 active-passive，并把每个地域做成可独立运行的 cell。模型和配置按不可变版本复制，会话绑定 home region，RAG 内容与 ACL/删除事件一起同步；外部副作用用全局幂等键和业务事务去重。全局路由结合健康、延迟、容量和驻留，故障时停止新流量、排空并切换，流式请求明确重试语义。流量回放使用脱敏数据和固定快照，禁用真实写操作，按原流量形状比较质量、TTFT、成本与错误；通过定期区域演练验证真实 RTO/RPO。
