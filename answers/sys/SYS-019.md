## 我的答案

一体化平台的核心是将数据、基础模型、训练配方、偏好目标和评测门禁组织成一个**可追溯实验图**，而不是把三个脚本拼在一起。任何模型版本都能回答用了什么数据/代码/超参、为何被选择、在哪些切片退化。

### 平台架构

```text
Dataset/Label Registry ─┐
Base Model Registry ────┼→ Experiment Orchestrator → Train Jobs
Recipe/Code Registry ───┘          │                  │
                                   ▼                  ▼
                            Evaluation Service ← Checkpoints
                                   │
                           Model Registry / Gate
                                   │
                           Canary Deployment / Feedback
```

数据注册表区分 SFT、pairwise preference、prompt-only、reward/过程标注和 eval，记录 Schema、许可、来源、版本、去重及污染报告。实验配置引用不可变的 model/data/code/container digest、tokenizer、chat template、seed 和分布式拓扑。

### 训练阶段

**SFT** 先建立指令遵循和领域行为，支持 packing、loss mask、样本权重、全参或 LoRA。训练前检查模板、EOS、角色 mask 和长截断，监控每数据源 loss 与梯度，防止重复/高权重数据主导。

**偏好优化**根据数据和成本选择：有成对 chosen/rejected 可用 DPO/IPO 等离线方法；需要可泛化评分时训练 reward model，并在人类反馈闭环下做 PPO/其他 RL；AI 反馈必须有独立校准。无论算法，都固定 reference/base 版本，记录 KL、reward margin、长度和风格偏差，避免 reward hacking。

DPO 的典型目标可写为：

$$
-\log\sigma\left(\beta\left[\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right]\right)
$$

$\beta$ 控制相对 reference 的偏离强度。算法只是实现，是否更好仍由独立评测和人类偏好证明。

### 评测一体化

训练中进行 loss、梯度、吞吐、NaN 和小型 canary；checkpoint 后运行：

- 通用/领域能力、事实、推理、工具和结构输出；
- 人类偏好、pairwise win rate、长度控制与风格；
- 安全、越狱、隐私、偏见和过度拒答；
- 历史 Bad Case、最差语言/任务切片；
- 推理 P95、显存、吞吐和单位成功成本。

评测集与训练数据做文档/模板级污染检查。Judge 盲化模型名、随机交换顺序并由人类集校准。门禁采用关键指标硬约束+统计置信区间，不让平均提升抵消严重安全或核心任务回退。

### 模型注册与发布

每个候选保存 checkpoint、optimizer（若需续训）、训练曲线、data/model card、eval 报告和 lineage。通过门禁后进入 staging，使用固定 Prompt/Guardrail/推理配置做 shadow/canary；线上业务结果和 Bad Case 回流标注队列，但与评测集隔离，防止不断对测试集调参。

所有 job 支持分片 checkpoint、抢占恢复和配额；数据与模型按租户权限、加密和审计。平台比较的不只是最终分数，也包括 GPU-hour、碳/资源、失败率和可复现性。相同配置重跑允许随机浮动，但关键指标应在预设容差内。

### 面试简答版

我会把 SFT、偏好优化和评测建成一个版本化实验 DAG：数据、基础/reference 模型、代码、容器、模板、超参和 checkpoint 都有不可变 digest 与 lineage。SFT 关注模板、mask、packing 和分源 loss；偏好阶段按数据选 DPO、reward model+RL 等，并监控 KL、长度偏差和 reward hacking。每个 checkpoint 自动跑能力、偏好、安全、污染、历史 Bad Case、延迟和成本，关键指标设硬门禁及置信区间。通过后进入模型注册表和 shadow/canary，线上反馈回到新的训练数据版本，但不污染固定评测集。
