## 我的答案

这类系统不能把所有文件简单 OCR 成一串文本，因为表格的行列关系、图片含义、标题层级和页面坐标都会丢失。设计目标是建立**保留版面与来源坐标的统一文档中间表示（Document IR）**，再做跨模态检索与可视化引用。

### 摄取与解析

1. 上传层校验身份、租户、MIME magic bytes、大小/页数、恶意文件和重复哈希，原文件加密存入对象存储并记录版本。
2. 区分 born-digital PDF 与扫描 PDF：前者优先提取原生文本、字体和对象，后者按页渲染、方向/去噪后 OCR；混合页面按区域选择，避免重复文字。
3. 版面模型识别标题、段落、列表、页眉页脚、表格、图/图注、公式和阅读顺序；每个元素保存 page、bounding box、父子层级、解析置信度和原文偏移。
4. 表格做行列/合并单元格重建，保存结构化 cells、HTML/Markdown 视图和截图；图片/图表保存 crop、图注、附近段落，必要时用 VLM 生成可检索描述，但标注为模型派生信息。
5. 低置信 OCR、跨页表格、手写、旋转页等进入规则或人工质检；所有派生制品绑定 parser/OCR/VLM 版本。

Document IR 可表示为树：`document→section→page→block→line/cell/figure`。原始 OCR、规范化文本、表格结构和视觉区域同时保留，不能让 VLM 描述覆盖原始证据。

### 分块与索引

- 文本按标题层级和语义分块，加入祖先标题、页码和相邻上下文；表格尽量以完整表或行组为单位，并重复列头。
- 为文本/OCR、表格序列化、图片描述建立稀疏和向量索引；图片还可建立视觉 embedding。所有记录带文档/页面/元素稳定 ID、坐标、版本和 ACL。
- 对同一元素的多个表示用 `element_id` 关联，检索融合时去重，避免一个表格的 OCR、HTML 和描述占满 top-k。

### 查询与回答

查询路由先判断是普通文本事实、跨页总结、表格计算还是视觉问题。并行执行 BM25、文本向量和必要的图像向量检索，经 ACL 过滤、RRF/重排后取候选；命中表格单元时补齐行列头和表题，命中图片时连同 crop、图注及附近段落交给多模态模型。

计算型表格问题不要让模型凭文本心算：将授权的表格区域解析为结构化数据，在沙箱中执行聚合/公式，再把结果和使用的 cell 坐标返回生成器。生成答案中的每个 citation ID 映射到文档版本、页码和 bounding box，前端可打开原页并高亮证据。

### 质量、安全与更新

文档内指令视作不可信内容，不能改变系统目标或触发高权限工具。解析、索引、缓存和引用均执行 tenant/ACL；删除需清理原文件、页面图、OCR、向量和缓存。文档更新采用新版本重解析，验证后切换可见 alias，保留短期回滚。

评测要分阶段：OCR 看 CER/WER；版面看区域/阅读顺序和表格结构；检索看不同元素类型 Recall@k/nDCG；问答看事实、表格计算、视觉理解、忠实度和引用框准确率。测试集要包含扫描质量、旋转、双栏、跨页表、图例、相似页面、多语言和无答案。线上监控解析失败/低置信率、各模态召回占比、引用点击与纠错、P95 和每页成本。

### 面试简答版

我会先构建保留页码、bounding box、标题层级和阅读顺序的 Document IR：原生 PDF 优先提取文本，扫描页走 OCR，版面模型识别段落、表格、图片和公式；表格保留 cells/行列结构，图片保留 crop、图注和派生描述。文本、表格序列化与视觉 embedding 建多路索引并用 element ID 去重。查询按文本、表格或视觉意图路由，命中后补齐表头/图注，表格计算交给沙箱代码。答案 citation 映射到具体版本、页码和坐标供前端高亮；评测分别覆盖 OCR、版面、检索、计算、忠实度和引用定位。
