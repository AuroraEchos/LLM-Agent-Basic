## 我的答案

LLM-as-Judge 平台应把 Judge 当成一个需要被评测和校准的测量仪器，而不是真值。核心是**明确 rubric、盲化与随机化、对人类锚点校准、级联控制成本，并完整版本化输入和判定。**

### 任务与数据模型

评测单元保存 `task_id、输入、候选输出、reference/证据、rubric、风险、slice`。rubric 将正确性、忠实度、指令遵循、安全、风格等拆成可观察标准，定义分数锚点、硬失败和是否允许不确定；尽量一轮只评价相对单一维度，减少含糊总分。

支持 pointwise、pairwise 和 listwise：pointwise 便于绝对门槛但标尺漂移明显；pairwise 更稳定，适合版本比较；listwise 成本低但位置与长列表偏差更强。确定性可判定项如 JSON、代码测试、数学结果和引用存在应先用程序验证，不浪费 Judge。

### 执行与偏差控制

1. 隐藏模型/供应商名、价格和无关元数据，候选统一格式，避免身份与格式偏差。
2. pairwise 随机 A/B 顺序并做 swap test；若交换后赢家不随内容一致，标为位置不稳定。
3. 控制长度：rubric 明确不奖励冗长，准备质量相同但长度不同的反事实集；必要时抽取主张后评价。
4. 将候选输出以明确的数据边界传入，防止其中的注入文本指挥 Judge；Judge 不拥有工具写权限。
5. 高风险或争议样本使用多个异构 Judge、独立人审或领域专家。多数投票只降低独立噪声，不能消除共同偏见。

pairwise 可同时两次交换顺序，只有结果一致才计为有效偏好；tie 和 invalid 是合法结果，不能强迫 Judge 选边。

### 校准与质量监控

建立代表任务、语言、长度和边界的盲审人类 gold set，测 Judge 与人类的一致率、Cohen's kappa/Krippendorff's alpha、pairwise accuracy、各标签 precision/recall 和校准。定期加入隐藏 canary，监控 Judge 模型升级、Prompt 或流量漂移。

对人类分歧大的样本记录 label uncertainty；Judge 不应被要求超过标注本身的可靠性。分析最差切片和系统偏差，而不只看总相关系数。自动 Judge 发现回退后抽样人审，重要发布由人类证据最终确认。

### 成本与调度

采用级联：确定性规则→小 Judge→大 Judge/多 Judge→人工。简单高置信样本早停，低 margin、顺序不一致、高风险或版本差异大的升级。固定输入标准化和 Judge 版本后可缓存结果，缓存键包含 candidate/reference/rubric/Judge/Prompt/采样参数 digest，防止错误复用。

预算分层采样：全量跑便宜指标，代表切片和回归跑 Judge，关键/边界样本跑人审。报告每个可靠判定成本和延迟，不把减少样本导致的置信区间扩大隐藏起来。

### 可复现性与平台治理

每次 run 固定数据集 manifest、候选模型和解码、Judge 名称/版本、system prompt、rubric、few-shot、顺序随机 seed、温度、重试、代码和时间。保存结构化分数、理由的受控摘要、raw response 引用、token、错误和 trace；外部 API 模型即使同名也可能变化，因此保留 canary 漂移结果，不能承诺逐字复现。

看板展示总体与切片、置信区间、tie/invalid、顺序不稳、人类一致、成本和失败率。Judge Prompt/模型变更需像评测器代码一样评审、版本化，并在固定锚点集上通过门禁后使用。

### 面试简答版

我会把 Judge 当成待校准测量器。平台把任务、reference、证据和单维 rubric 版本化，确定性规则先判断 Schema/测试等硬指标；pairwise 评测隐藏模型名、随机 A/B 并做顺序交换，允许 tie/invalid，候选文本按数据隔离以防注入。Judge 用代表性人类 gold set 校准，报告一致率、最差切片和偏差；低置信、顺序不稳和高风险样本升级到异构 Judge 或人审。成本用规则→小模型→大模型→人工级联，缓存键绑定完整版本。每个 run 固定数据、Prompt、rubric、seed 和采样配置，展示置信区间、成本与漂移。
