## 我的答案

长期记忆不等于永久保存全部聊天。设计目标是让 Agent 在用户授权下保留**未来确实有用、可纠正、可过期、可删除且来源明确**的信息，同时避免错误摘要、注入和隐私不断累积。

### 记忆分层

| 层级 | 内容 | 生命周期 |
|---|---|---|
| 工作记忆 | 当前轮目标、临时变量、最近消息、工具结果 | 会话内，超预算后压缩 |
| 情节记忆 | 某次事件与结果，如“上周讨论了项目 A” | 有来源、时间和过期策略 |
| 语义/画像记忆 | 经确认的偏好、身份属性、长期项目事实 | 用户级，需高置信与可编辑 |
| 程序记忆 | 组织批准的流程、工具用法 | 系统/租户级，由管理员版本化 |

系统 Prompt 与组织规则不放进用户可写记忆；工具返回和外部文档也不能直接成为高可信长期事实。

### 写入链路

每轮结束由候选提取器产生结构化 `fact、type、subject、source_message_ids、confidence、sensitivity、valid_from/to`，再经过策略门禁：是否对未来有用、是否重复/冲突、是否敏感、用户是否同意。姓名、健康、财务等敏感信息默认不长期保存或要求明确确认。

记忆使用稳定 ID 与版本，保留 provenance 和提取器版本。用户明确说“以后回答简洁一些”可写偏好；一次性地址、验证码、第三方秘密不应写。模型从不直接改数据库，只提交写入提案，由确定性服务做 ACL、去重和审计。

### 检索与上下文组装

先理解当前问题，再按用户/租户硬过滤，通过时间、实体、关键词和向量混合检索候选；按相关性、重要性、新鲜度、可信度和隐私风险重排：

$$
score=w_rR+w_iI+w_fF+w_cC-w_sS
$$

只注入少量必要记忆，并标记为“历史记录，可能过期”，附来源/时间。当前用户明示信息与权威工具结果优先于旧记忆。会话摘要用于节省上下文，但需保留未决事项、约束和引用，不能取代可审计原始消息。

### 冲突、纠正与遗忘

新旧事实冲突时不静默覆盖：可按相同 subject/predicate 建版本，结合来源、时间和用户确认选择 active 版本。用户说“我已经搬家”应使旧地址失效，但审计保留受控变更记录；回答前仍可向权威资料或用户确认。

支持查看、编辑、忘记某条/某类/全部记忆，删除传播到主存、向量索引、缓存、备份策略和训练导出。TTL、时间衰减和未使用清理降低无限增长；需要法律保留的内容与产品记忆分离并透明说明。

### 安全、可靠与评估

记忆存储按用户/租户加密隔离，检索前置 ACL，第三方对话不能写入另一人的画像。防 memory poisoning：外部内容和模型推断低信任，敏感/高影响事实需用户确认；写入频率和大小限额，检测重复/恶意注入。

离线评测记忆写入 precision/recall、跨会话检索、冲突解决、时效、零跨用户泄漏和删除完成率；线上看用户纠正、记忆有用率、错误个性化、延迟和存储成本。对照组验证长期记忆是否真正提升任务成功，而不只是让回答更像“记得你”。

### 面试简答版

我会把记忆分成会话工作记忆、带时间来源的情节记忆、经用户确认的长期偏好/事实，以及管理员维护的程序规则。模型只提出结构化写入候选，记忆服务根据用途、敏感性、同意、去重和 ACL 决定落库，并保存版本与 provenance。查询时按用户硬过滤，再按相关、重要、新鲜和可信度检索少量内容；当前信息和权威工具优先于旧记忆。冲突采用版本化和确认，用户可查看、纠正、设置 TTL 或删除，删除同步向量索引与缓存。还要专门测试记忆投毒、跨用户泄漏和错误个性化。
