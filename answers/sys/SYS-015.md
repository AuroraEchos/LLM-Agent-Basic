## 我的答案

安全代码 Agent 应默认只在临时分支和隔离环境中提出、验证变更，不能把“模型生成了可运行代码”直接等同于“可以进入生产”。威胁包括仓库内间接注入、恶意依赖、秘密泄漏、沙箱逃逸、资源滥用和未经授权的发布。

### 工作流

```text
Task/Auth → Scoped Repo Snapshot → Plan → Generate Patch
                                   ↓
 Static Checks → Isolated Build/Test → Security Scan
                                   ↓
                      Diff Summary + Human Review
                                   ↓
                       PR / Approved Deployment
```

入口确认用户对仓库、目录和操作的权限，建立只包含允许范围的不可变 commit snapshot 和临时分支/worktree。Agent 先读取项目规则、依赖锁和测试命令，输出文件级计划；写入采用 patch，禁止越出允许路径、改分支保护或修改 CI/权限文件，除非任务明确授权并经过更高级审批。

仓库 README、Issue、依赖输出和网页都是不可信数据，不能改变系统权限或索取秘密。工具接口分为只读搜索、受限编辑、测试和提交提议，各自有 Schema 与 allowlist；模型只提出命令，执行代理重新校验工作目录、参数和风险。

### 执行沙箱

每个任务/租户使用一次性 microVM 或强化 sandbox；普通容器只能作为纵深的一层。关键限制包括：非 root、禁止 privilege escalation、只读基础镜像、临时可写层、禁止宿主 socket/device、seccomp/AppArmor、CPU/内存/PID/磁盘/时间配额和进程树终止。

网络默认关闭。安装依赖时只允许组织镜像/代理，锁定版本和 digest，限制 DNS/出站目标；不要把云元数据、内网和生产数据库暴露给沙箱。凭据由代理按具体操作提供短期能力，不写环境转储、Prompt 或日志；测试优先使用假数据和 mock。

### 验证链路

1. 格式、lint、类型和编译；
2. 受影响单测、集成测试及资源/超时限制；
3. SAST、依赖/SBOM、license、秘密和 IaC 扫描；
4. 对安全、并发、数据库迁移、权限和 API 契约做专门测试；
5. 展示完整 diff、测试证据、未验证项、依赖变化和风险给人审。

测试通过不证明业务正确或无漏洞。生成器不能同时成为唯一审查者；优先使用编译器、测试和安全扫描，关键变更由 CODEOWNERS/领域人员审批。Branch protection 要求必需检查通过，Agent 不能绕过或直接 push 受保护分支。

### 副作用与供应链

包安装使用锁文件、校验和和可信 registry，防 typosquatting 与 install script；必要时在无秘密的构建阶段执行。数据库迁移先 dry-run/兼容性检查，部署使用 canary、feature flag 和回滚。生产发布、密钥轮换、删除资源等单独授权，确认绑定不可变 commit digest，防审批后代码变化。

完整 trace 记录读取/修改文件列表、patch digest、经脱敏命令、沙箱镜像、依赖、测试和审批，不记录源码秘密。监控越界路径、网络阻断、资源耗尽、秘密命中、测试稳定性和修复后线上指标。保留失败样本进入安全回归。

### 面试简答版

代码 Agent 只在授权的仓库 snapshot 和临时分支上生成 patch，仓库内容视为不可信，模型不能自行扩大路径、命令或凭据权限。代码在一次性 microVM/强化沙箱执行：非 root、只读镜像、限 CPU/内存/PID/时间、默认断网，只能访问可信依赖代理，绝不接触生产秘密。变更依次通过编译、类型、测试、SAST、依赖/SBOM、秘密和 IaC 扫描，再以 diff、证据和未验证项进入人审及 branch protection。生产发布单独审批并绑定 commit digest，使用 canary 和回滚；Agent 不直接推受保护分支。
