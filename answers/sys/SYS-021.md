## 我的答案

安全网关应位于应用与模型/工具之间，统一执行版本化政策和可观测性，但不能被误认为单点万能过滤器。设计目标是：**已知攻击尽早拦截、未知注入即使影响模型也无法越权、敏感数据有明确流向、良性敏感请求尽量得到帮助。**

### 分层架构

```text
Request → Auth/Quota → Normalize & Data Classify → Intent/Risk Policy
                    → Context Manifest / Prompt Builder → Model Router
                    → Output/Claim/DLP Guard → Tool Policy or Response
                                      │
                              Human Review / Audit
```

入口保留原文的受控引用，并生成规范化副本用于分类，防止 Unicode/编码绕过；同时做文件类型、长度、速率、恶意内容、PII/秘密和越狱风险检测。认证用户、租户和业务场景来自可信会话，不能让 Prompt 自报身份。

### 越狱与 Prompt Injection

- 越狱重点是绕过内容安全。结合模型安全训练、输入意图分类、输出危害判定和多轮状态检查；最终判断是否提供了实质性危险帮助，不只匹配敏感词。
- Prompt Injection 重点是不可信内容改变指令流。为系统、用户、RAG、网页、工具结果建立 provenance manifest，外部内容始终标为数据；限制其进入长期记忆和工具参数。
- 模型只提出动作，工具执行器按真实 `subject-action-resource` 重新鉴权，使用强类型参数、最小权限和高风险确认。这样即使注入成功，现实影响仍受限。

不应把“忽略文档中的指令”当作安全边界。网关、数据层 ACL、工具策略和外部系统权限需要相互独立。

### 敏感数据处理

先建立数据分类和 source→sink 策略：哪些 PII 可进入哪个模型/地域，哪些秘密永不进入模型，哪些输出可发给当前用户或外部工具。可对必要 PII 做 tokenization/掩码，映射存入独立 vault；只在最终且授权的输出通道恢复。低熵手机号不能只用普通哈希。

第三方模型路由要检查数据驻留、保留和训练用途；日志默认只存脱敏结构、哈希和 trace 引用。输出 DLP 是最后一层，但源系统仍需行列/租户 ACL，不能让模型先读取全库再靠 DLP 拦截。

### 控制过度拒答

采用允许、敏感但允许、灰区、高风险四级路由，而不是一个关键词阈值。教育、新闻、医疗求助和防御性安全等困难良性样本用于分类器校准；灰区可追问意图、限制可操作细节、部分满足或交给更强审核器。高风险才拒绝/人工。

每项政策有类别、严重度、阈值和版本。分类器输出校准分，按风险成本选择 threshold；对允许集监控误拒率，对禁止集监控漏放率，并按语言、群体和业务切片。生成安全替代内容也要检查是否真正有帮助，而不是模板化道歉。

### 运行与评估

缓存键必须包含租户、权限、政策、模型和数据版本；安全决策 fail-open 还是 fail-closed 按场景设定，高风险工具 fail-closed，低风险聊天可降级。所有策略结果、模型/分类器版本、工具提议、授权理由和审批进入脱敏 trace，支持 tool/policy 级 kill switch。

红队覆盖直接/间接、多轮、编码、跨模态、数据外泄和工具链。发布门禁同时约束严重度加权 ASR、秘密/越权零容忍、敏感良性误拒、任务成功、P95 和成本。线上用申诉、人工推翻和事故持续校准。

### 面试简答版

安全网关我会做成分层策略执行点：入口认证、规范化、风险与 PII 分类；上下文构建保留来源并把外部内容标为不可信数据；模型输出再做危害、DLP 和引用检查；任何工具动作由后端按真实身份重新鉴权、强类型校验和审批。越狱关注安全绕过，注入关注指令流劫持，防护和指标分开。敏感数据按 source→sink 策略、地域和最小化处理。为避免过度拒答，采用允许、灰区、限制回答和高风险阻断的多级路由，同时设置严重漏放、良性误拒、最差语言切片与 P95 门禁。
