## 我的答案

企业级 RAG 的目标不是“接一个向量库”，而是让每个回答都满足：**检索得到正确且当前的证据、用户确实有权看到、生成结论可由引用验证、效果能持续评估。**

### 离线索引链路

```text
Connectors → Raw Object Store → Parse/OCR → Normalize/Deduplicate
           → Structure-aware Chunk → Metadata + ACL
           → Sparse Index + Vector Index → Versioned Alias
```

连接器读取 Wiki、网盘、数据库和工单，原文件与来源版本进入对象存储作为 SSOT。解析层保留标题层级、页码、表格、更新时间和坐标；按段落/章节语义切块，加入祖先标题但避免大量重叠。每个 chunk 使用稳定 `document_id/chunk_id/version`，并携带 tenant、owner、ACL、有效期、语言和来源 URI。

索引采用事件驱动增量更新：创建/修改生成新版本，删除写 tombstone 并从稀疏、向量、缓存和副本同步清除。embedding 模型或 chunk 策略升级时建新索引，完成回填与验证后原子切 alias，不能原地混合不同向量空间。

### 在线查询链路

1. 从可信会话得到用户、租户和群组，规范化问题并识别语言、时间、产品和实体；必要时拆成子查询。
2. **检索前施加 ACL/tenant 过滤**，并在返回内容时再次校验，不能先取未授权 top-k 再过滤，否则既可能泄漏，也会造成召回不足。
3. 并行执行 BM25/关键词和向量召回；可用 RRF 融合：

   $$
   score(d)=\sum_{r\in R}\frac{1}{k+rank_r(d)}
   $$

4. 对候选做去重、时效/权威性规则、cross-encoder rerank 和多样性选择；给上下文分配 token 预算，保留问题所需的相邻块与表格结构。
5. 生成器只能依据证据回答，为每个事实主张输出内部 `citation_id`。服务端把 ID 映射到文档版本、页码/段落和授权链接，模型不能自行拼 URL。
6. 做 Schema、引用存在、claim-evidence entailment、政策和敏感信息检查。证据不足或冲突时说明不确定、追问或转人工，不能让模型补全。

### 权限与安全

权限来自源系统并保持血缘，支持用户/群组/资源级 ACL、时间条件和 deny 优先。索引、结果缓存、embedding 缓存和日志都要包含租户与权限上下文；管理员诊断也要审计。源权限变更和删除应有可量化 SLA，紧急撤权可通过查询时权威 ACL 门禁立即生效。

外部文档是不可信数据，可能含间接 Prompt Injection。将内容与指令分区，不允许文档改变任务或工具权限；Agent 工具最小权限，高风险动作重新鉴权。对秘密、PII、恶意文件和数据投毒做检测及来源信誉控制。

### 评估与运行

离线数据集覆盖真实问题、无答案、权限差异、时间变化和多语言。检索看 Recall@k、MRR/nDCG、ACL 零泄漏和新鲜度；生成看答案正确、忠实度、引用 precision/coverage、拒答和任务成功；系统看 P95、成本和可用性。必须做组件消融，区分查询、召回、重排和生成故障。

线上先 shadow/canary，监控无结果率、文档覆盖、引用点击/支持率、纠正、人工转接和 Bad Case；用户反馈经权限和隐私处理后回流评测集。索引、检索配置、Prompt 和模型全部版本化，支持回滚与可复现 trace。

### 面试简答版

企业 RAG 我会分为版本化索引链路和在线证据链路。文档从源系统进入 SSOT，经结构化解析、去重、语义切块后，同时写 BM25 与向量索引；chunk 保存稳定 ID、版本、来源和 ACL。查询时先用可信身份做 tenant/ACL 过滤，再混合召回、RRF、重排和 token 预算组装。模型输出 citation ID，服务端映射到授权文档，并逐主张检查证据支持；无证据就拒答或转人工。评估分别覆盖 Recall/nDCG、ACL 零泄漏、忠实度、引用正确率、P95 和成本，所有模型、索引与权限变更都可追踪和回滚。
