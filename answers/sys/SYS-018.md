## 我的答案

训练数据平台首先是数据治理与可复现系统，其次才是清洗流水线。最终每个训练样本都应回答：**从哪里来、是否允许使用、经过哪些变换、为何被保留、进入了哪个版本，以及如何删除。**

### 分层架构

```text
Source Registry → Immutable Raw/Landing → Parse/Normalize
       │                    │
 License/Consent       Lineage/Event Log
                            ▼
 Filter → Exact/Near Dedup → Quality/Safety/PII → Enrichment
                            ▼
                 Curated Datasets / Mixture Manifest
                            ▼
                  Training + Evaluation Registry
```

源注册表记录 owner、采集方式、许可证/同意、地域、数据分类、保留期、禁止用途和删除渠道。原始层只追加、加密并按内容哈希寻址；任何转换都生成新 artifact，不覆盖原数据。每个样本携带 source id、document id、时间、语言、权限和 transformation lineage。

### 清洗与规范化

按模态和来源解析编码、正文、布局与元数据；语言识别、Unicode/空白规范化、模板/导航/广告去除，保留原文引用以便审计。质量规则处理过短、乱码、机器生成、低信息密度、重复模板和异常语言，但规则按语言/领域分别校准，防止系统性删除低资源群体。

安全与合规层检测 PII、凭据、恶意代码、有害内容、版权/许可证不兼容和评测集污染。策略可以删除、脱敏、隔离或降低采样权重；每个决定有 reason code。秘密与高风险个人数据不应只靠模型分类器“降权”。

### 去重

分层处理成本和粒度：

1. 文件/样本内容哈希做 exact dedup；
2. 规范化文本的 n-gram MinHash/LSH、SimHash 做近重复候选；
3. 语义 embedding 只用于难例或同簇分析，避免高成本和误删同主题但不同事实的样本；
4. 训练/验证/评测之间做跨 split 去重，且切分按文档/站点/作者等 group，而非随机 chunk。

保留哪份副本依据来源权威、许可、质量、时间与元数据完整度。记录 dedup cluster 和 canonical id，使删除一条来源时能重新判断剩余副本的合法性。

### 质量、采样与标注

质量不是一个全局模型分。组合语言、完整性、事实/来源、教育价值、毒性、格式和领域规则，并通过人工分层抽检校准 precision/recall。对 SFT/偏好数据还检查指令可解、回答正确、引用/工具轨迹、标注者一致性和模板泄漏。

构建训练 mixture 时保存各数据集版本、过滤策略和目标 token 比例：

$$
p_i=\frac{w_iN_i^\alpha}{\sum_j w_jN_j^\alpha}
$$

$\alpha<1$ 可降低大语料独占，$w_i$ 表示业务权重，但最终需通过消融和下游评测选择。采样器记录 seed、epoch 和实际 token 分布。

### 版本与可复现

一个 dataset version 是不可变 manifest：样本/分片哈希、Schema、源快照、代码/容器、规则与模型版本、统计、许可、父版本和质量报告。大数据使用 manifest 引用对象存储，不复制整份。发布前验证行数/token、语言/来源/PII 分布、去重率、污染和抽样质量；签名后只读。

删除请求根据 lineage 找到原始及所有派生版本，生成 tombstone、阻止未来训练并按策略物理删除；已训练模型的处置由单独风险流程决定，不能声称删数据就自动从模型中遗忘。

### 面试简答版

我会用不可变 raw layer 和全链路 lineage 建平台：源注册时先记录许可、同意、用途与删除渠道，再做解析规范化、精确哈希、MinHash/LSH 近重复、质量/PII/秘密/安全过滤和分层抽检。去重按文档/来源跨训练与评测 split 进行，保留 dedup cluster 而非只删记录。训练 mixture 保存数据版本、采样权重、seed 和实际 token 分布。每个发布版是带对象哈希、代码/规则/模型版本、统计和质量报告的只读 manifest，支持差异比较、重放和沿 lineage 删除所有派生数据。
