## 我的答案

并行策略不是越多越好。我会先根据模型参数量、序列长度、global batch、精度、GPU 显存、节点内 NVLink/节点间网络和目标 MFU，计算单卡能否容纳模型状态与 activation，再从通信最少的方案逐步增加并行维度。

### 内存与并行选择

以 Adam 混合精度训练粗略估算，参数、梯度和优化器状态常需十几 bytes/parameter，外加 activation、临时 buffer 和碎片。准确值取决于 master weight、优化器与实现，应由 estimator+小规模 profiling 验证。

- **Data Parallel / DDP**：每卡完整模型、切 batch、梯度 all-reduce。模型能放单卡且 batch 足够时最简单高效。
- **ZeRO/FSDP**：沿 data-parallel 组分片 optimizer、gradient，最终可分片 parameter；显著降模型状态显存，但每层 all-gather/reduce-scatter 增加通信。模型接近或超过单卡时优先考虑。
- **Tensor Parallel (TP)**：单层矩阵按 hidden/head 切分，解决单层权重/activation 过大；每层有 collective，要求高速互联，通常把 TP 组放同一节点/NVLink 域。
- **Pipeline Parallel (PP)**：按层分 stage，适合很深、跨节点模型；需要 micro-batch 填流水线，存在 bubble 和 stage 负载不均。
- **Context/Sequence Parallel (CP/SP)**：切序列/activation，长上下文 attention 内存成为瓶颈时使用；会引入 token/attention 通信。
- **Expert Parallel (EP)**：MoE 专家分布到不同卡，需 all-to-all token dispatch，要处理专家负载不均和网络热点。

混合并行满足近似关系：

$$
WorldSize=DP\times TP\times PP\times CP\times EP
$$

具体框架的维度组合可能有约束，不能机械相乘。选择顺序通常是：能用 DDP/FSDP 解决就先不用 TP；单层放不下再加同节点 TP；整体仍放不下再 PP；长序列加 CP；MoE 才加 EP，剩余卡做 DP 提升吞吐。

### 系统架构与拓扑

控制面负责作业、资源配额、镜像/代码/数据/超参版本、gang scheduling 和弹性重排；训练数据从分片对象存储经本地缓存/预取进入 worker。rank placement 感知 NVLink、PCIe、NIC、机架：高频 TP/EP 通信放高速域，DP/PP 再跨节点，并为 NCCL collective 使用独立拓扑验证。

训练使用 BF16/FP8（需数值验证）、activation checkpoint、FlashAttention/融合 kernel、通信与计算 overlap、梯度累积。global batch 为：

$$
B_{global}=B_{micro}\times N_{micro}\times DP
$$

调整并行度时保持优化超参语义，关注 tokens/update 而非只看 micro-batch。

### 数据、Checkpoint 与容错

数据清单和样本顺序版本化，分片 sampler 在 DP rank 间不重复并支持恢复。Checkpoint 保存 sharded model/optimizer、scheduler、RNG、dataloader cursor、训练步、并行拓扑和代码版本，通过临时目录+完成 manifest 原子发布。异步保存要确保权重快照一致。

大规模 collective 中一个 rank 消失通常会终止整组；调度器重新 gang 启动，从最近 checkpoint 恢复。checkpoint 间隔按写入成本和预期故障损失权衡：

$$
ExpectedLoss\approx \frac{CheckpointInterval}{2}
$$

还需校验 checkpoint 可恢复，定期做节点/NIC/存储故障注入。

### 可观测与调优

监控 tokens/s、samples/s、MFU、step time 分解、bubble、collective 时间、通信 overlap、GPU 显存/利用率、dataloader stall、专家负载、loss/grad norm、NaN 和 checkpoint 时间。先以少量节点做 correctness baseline，再逐级 scale，画 strong/weak scaling；若增加 GPU 后 tokens/s 几乎不涨，应定位通信、输入或负载不均，而不是继续扩容。

### 面试简答版

我会先估算参数/梯度/优化器与 activation 显存，再按最少通信原则选并行：模型放得下先 DDP；状态太大用 FSDP/ZeRO；单层放不下在节点内做 TP；层数多且仍超内存再 PP；长上下文加 CP/SP；MoE 使用 EP，剩余维度做 DP。TP/EP 放高速互联域，调度采用 topology-aware gang scheduling。global batch 保持 `micro_batch × accumulation × DP`。Checkpoint 保存分片模型、优化器、RNG 和数据游标并原子提交，通过故障注入验证恢复；调优看 MFU、bubble、collective、数据 stall 和 scaling efficiency。
