> **问题：** GRPO 中所有候选奖励相同或方差接近零时如何处理？

## 我的答案

GRPO 的核心优势是：

\[
\hat A_i=\frac{r_i-\bar r}{s_r+\epsilon}
\]

若所有候选 reward 相同，则分子全为 0；若方差只接近 0，则除法可能把微小评估噪声放大。二者应分别处理，不能强行制造 winner。

### 一、所有奖励完全相同

#### 全错

二元 verifier 下所有回答得 0，说明当前策略对该 Prompt 的成功轨迹覆盖不足。这组没有方向信息，正确处理通常是 advantage=0 并跳过 policy gradient，而不是随机选一个“相对最好”。

改善手段：

- 先做 SFT/rejection sampling warm start；
- 使用难度 curriculum，从能偶尔成功的问题开始；
- 增大 G、temperature 或合理探索空间，提高命中成功轨迹概率；
- 提供部分分、单元测试子项、过程 reward 或工具反馈；
- 把过难 Prompt 暂存，待策略能力提高后重放。

#### 全对

所有回答得 1 也没有相对信号，且继续强化可能无必要。可减少该类 Prompt 采样、提高难度、加入效率/简洁性/鲁棒性等次级但可靠的判别，或将其用于能力保持。不能为获得梯度而随意惩罚一个正确答案。

### 二、方差接近零

若 rewards 为 `0.5001, 0.5000, 0.4999`，直接除以极小 \(s_r\) 会把 RM 数值噪声标准化成约 \(-1,0,1\)，让模型过度学习无意义排序。

可选策略：

1. **标准差阈值**：\(s_r<\tau\) 时整组 advantage=0；
2. **Variance floor**：分母用 \(\max(s_r,\tau)\)，避免放大；
3. **只中心化**：\(A_i=r_i-\bar r\)，保留真实小幅度；
4. **全局/分桶 scale**：用跨 batch 的稳健标准差，不对每个微小组强制单位方差；
5. **Rank advantage**：reward 可信排序但尺度不可信时使用 rank，不过 tie 和微差仍需阈值；
6. **多评审/重复执行**：降低 stochastic verifier 噪声后再比较。

这些选择会改变梯度标尺和 bias，应固定总 rollout token 做消融。

### 三、增加 G 何时有效

若单样本成功率 \(p\) 不是极端值，增加 G 会降低全同 reward 概率 \(p^G+(1-p)^G\)。但当 \(p\approx0\) 时，哪怕 G 很大仍全错且生成成本激增；此时 curriculum 或更密集 reward 比盲目增 G 更有效。

还要去重候选。如果 16 条输出其实是同一答案的轻微格式变化，有效 group size 远小于 16。

### 四、改善 Reward 的分辨率

- 数学：最终答案正确之外，加入可验证的关键中间量，但避免主观过程规则；
- 代码：按隐藏单测通过比例、编译、复杂度和安全分开给分；
- 工具：schema、调用选择、参数、执行结果分阶段验证；
- PRM：给步骤级 reward，但必须评估 PRM hacking 和错误标注；
- 主观任务：使用 RM ensemble、不确定性和人类主动标注边界样本。

Dense reward 不等于随意堆 shaping。每个子奖励都可能产生新捷径，必须有独立端到端 outcome 护栏。

### 五、监控与实现

记录：全同 reward 组比例、近零 std 比例、跳过 token 数、有效 group size、每题 pass rate、reward unique values、advantage 分位数与梯度贡献。分布式实现中，组统计必须只在同一 Prompt 的候选间计算，不能误把不同题目的 reward 混在一起。

若跳过大量组，实际 global batch 会缩水；应按有效 token 归一化 loss，并调整采样，而不是用零梯度样本填满 nominal batch 后误以为学习率合理。

### 面试简答版

所有候选奖励相同时，组内中心化 advantage 必然为 0，应跳过该组或令其零梯度，不能随机制造 winner。全错说明探索/能力不足，应使用 SFT warm start、curriculum、更大但有上限的 G 或部分/过程 reward；全对则提高难度或降低采样。方差接近零时直接标准化会放大 RM 噪声，可设 std 阈值/floor、只中心化或用跨 batch 稳健尺度。持续监控全同组、近零方差、有效 group size 和实际有效 token，按固定 rollout 预算选择策略。
