## 我的答案

这三个问题的共同根因是：**优化器只会最大化被测量的奖励，不会自动理解设计者真正想要的“正确、有效且语言一致的推理”**。解决方案不是只加一个 KL 或长度惩罚，而是从验证器、奖励分解、采样、优化和独立评估构成闭环。

### 一、先区分三类失败

1. **Reward Hacking**：模型找到评分器漏洞，例如伪造指定格式、利用答案解析 bug、硬编码公开测试、迎合 judge 的长度或措辞偏好。
2. **无意义长思考**：反复改写、假装验证、循环回溯或故意延迟 EOS，token 增加却没有提高解题信息量。
3. **语言混杂**：在中文推理中无必要地切换英文或其他语言，甚至产生不可读的混合 token。它可能来自预训练数据、tokenization、某语言下数学模式更强，或者 reward 只检查最终答案而不关心过程可读性。

三者可以同时出现：例如模型用英文套话重复很久，最终输出能绕过 parser 的答案。

### 二、防止 Reward Hacking

#### 1. 把 verifier 当作安全边界

- 数学任务用规范化后的精确答案、符号等价或数值容差，不要只做脆弱字符串匹配；
- 代码放入无网络、有限 CPU/内存/时间的 sandbox，使用隐藏测试、随机测试和 property-based tests；
- 防止模型读取测试文件、环境变量、参考答案或借异常退出骗过 runner；
- 对 prompt、答案抽取器、测试集和 reward 代码做版本化与攻击测试。

#### 2. 避免单一可投机指标

将 reward 拆成可审计分量：

\[
R=w_cR_{correct}+w_pR_{progress}+w_fR_{format}
-w_lC_{length}-w_sC_{safety}
\]

正确性应是硬门槛，格式、风格不能补偿错误答案。对主观维度可用多 judge、位置交换、长度控制和少量人工 golden set 校准；训练 judge 与验收 judge 最好隔离。

#### 3. 保留真正的隐藏集

训练期间可见的 reward 最终都会变成攻击面。应保留未暴露模板、不同实现的验证器和时间切分题目，定期人工审阅“高 reward 但行为异常”的样本，而不是只看均值。

### 三、抑制无意义长思考

- 使用软 token 成本或在最大长度前设置缓冲区，让惩罚逐步增加，避免突然截断形成 reward cliff；
- 只有答对时才讨论简洁性，不能让“短但错”超过“长但对”；
- 加入简洁且正确的正样本，教会模型验证完成后及时输出 EOS；
- 检测重复 n-gram、语义循环、连续相同步骤和异常低信息密度；
- 若使用 PRM，奖励“产生新结论、纠错或有效验证”的步骤，而非含有某些推理套话；
- 对简单题和困难题分别设预算，报告 accuracy–tokens Pareto 曲线；
- 监控长度分位数、截断率、EOS 概率、正确/错误样本长度以及每个成功样本的 rollout tokens。

长度惩罚应从小到大做消融。过强会让模型提前猜答案，反而破坏探索和自我纠错。

### 四、处理语言混杂

1. 用目标语言的高质量 SFT/偏好数据建立稳定先验，确保数学、代码与工具样本也覆盖该语言；
2. 对自然语言 span 做 language ID，给予**软的一致性约束**，但豁免公式、变量名、代码、API 名与必要术语；
3. reward rubric 明确“用户要求的语言”和允许切换的场景，多语言 judge 要分别校准；
4. 对混杂样本人工分类：是能力补偿、术语引用，还是无意义漂移，再决定数据修复还是惩罚；
5. 按语言分别监控正确率、可读性与拒答，避免为了语言纯度牺牲少数语言的推理能力。

完全禁止外语 token 往往过于粗暴。例如 Python 标识符和数学缩写本就可能是英文；硬规则会产生新的格式投机。

### 五、训练稳定性措施

在 GRPO/PPO 层面，可控制 ratio clip、学习率、更新 epoch、梯度范数、KL 和 entropy；过滤或重采样全对/全错而无有效梯度的组；采用可靠的长度 mask 与 token-level loss normalization。还要持续查看：

```text
reward 各分量 / 真正 holdout 成功率
KL / entropy / clip fraction / gradient norm
回答长度 / 截断率 / 重复率 / language-ID 切换率
无信号 group 比例 / verifier error / sandbox timeout
高 reward 异常样本的人工审计
```

只要训练 reward 上升而独立正确率、可读性或安全性下降，就应视为 reward 被过度优化，暂停并修 verifier，而不是继续调大学习率。

### 面试简答版

避免这三类问题要把 reward 系统当成可攻击接口。Reward Hacking 主要靠隐藏且随机化的验证器、安全 sandbox、多分量奖励和独立人工/holdout 审计；无意义长思考要用正确性硬门槛、软 token 成本、过长奖励塑形、重复检测和真正反映步骤进展的 PRM，同时比较 accuracy–token 曲线；语言混杂则用目标语言 SFT、span 级 language ID 软约束和多语言评测，并豁免公式、代码和必要术语。算法侧再控制 clip、KL、entropy 和有效采样。关键原则是不能用风格或简洁分补偿错误答案，也不能把训练 reward 当作最终能力。
