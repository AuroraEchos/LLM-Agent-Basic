## 我的答案

选择这三类方法，核心要看四件事：**数据是不是固定的、能否在线探索、反馈是标量偏好还是教师分布、能承担多少生成与判分成本**。它们不是互斥的，成熟项目通常按“离线冷启动 → on-policy 修正分布 → RL 探索和突破”组合使用。

### 一、三种路线分别在做什么

#### 1. Online RL

当前或稍旧版本的策略自己生成回答，再由 Reward Model、规则验证器或环境给奖励，最后用 PPO、GRPO 等算法更新策略：

\[
y\sim\pi_{old}(\cdot|x),\qquad r=R(x,y),\qquad
\theta\leftarrow\theta+\eta\widehat{\nabla J(\theta)}
\]

它的关键优势是训练数据随策略变化，模型能探索离线数据里没有的轨迹，尤其适合数学、代码、工具调用和游戏等有可靠验证器的任务。代价是 rollout、判分和分布式同步昂贵，而且会有高方差、策略坍缩与 Reward Hacking。

#### 2. Offline Preference Optimization

先固定偏好数据 \((x,y_w,y_l)\)，再用 DPO、IPO、CPO 等目标直接提高 chosen 相对 rejected 的概率。以 DPO 为例，它学习的是相对 reference 的隐式奖励差：

\[
\mathcal L_{DPO}=-\log\sigma\left(\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}
\right]\right)
\]

它不需要在线 rollout、显式 RM 和 Critic，训练简单、稳定、容易复现，适合已有高质量成对数据的风格、安全和通用偏好对齐。但它只能重加权数据覆盖到的行为，不能主动试错；数据若来自旧策略，还会有 distribution mismatch。

#### 3. On-Policy Distillation

学生策略先生成自己的轨迹，教师再对**学生实际访问的 token 前缀**给出完整概率分布或其他细粒度反馈：

\[
y\sim\pi_S(\cdot|x),\qquad
\mathcal L_{OPD}=\mathbb E_{(x,y)\sim\pi_S}
\sum_t D_f\!\left(
\pi_T(\cdot|x,y_{<t})\,\|\,\pi_S(\cdot|x,y_{<t})
\right)
\]

这里“on-policy”指**状态/前缀由学生生成**，不是教师生成完整答案后让学生模仿。教师会直接纠正学生自己造成的错误状态，因此比固定 teacher-forcing 数据更能缓解训练—推理分布不一致。代表性方法可参考 [On-Policy Distillation / GKD](https://arxiv.org/abs/2306.13649)。

它的监督比单一标量 reward 稠密，通常比 RL 低方差；但每个学生 token 可能都要教师前向，成本高，而且性能受教师能力、校准和可访问 logits 限制。若教师只能返回文本或 API 不开放分布，标准 token-level distillation 就难以实施。

### 二、横向比较

| 维度 | Online RL | Offline Preference Optimization | On-Policy Distillation |
|---|---|---|---|
| 轨迹来源 | 当前/旧策略在线生成 | 固定数据集 | 学生在线生成 |
| 监督信号 | 标量 reward、process reward、环境回报 | chosen/rejected 或离线偏好 | 教师 token 分布或稠密反馈 |
| 主动探索 | 强 | 基本没有 | 访问学生状态，但目标主要受教师约束 |
| 训练稳定性 | 较难，高方差 | 通常最好 | 通常较稳，取决于 divergence 和采样 |
| 主要成本 | 多次 rollout、验证器/RM、分布式 RL | 偏好数据与普通反向传播 | 学生 rollout + 大教师推理 |
| 能否超越教师/数据 | 有可能借环境真值突破 | 很受数据覆盖限制 | 通常受教师上限限制 |
| 典型风险 | Reward Hacking、坍缩、训练不稳 | 过拟合、长度偏差、分布陈旧 | 教师偏差、反向 KL 模式收缩、推理成本 |

### 三、如何选择

1. **有可靠可验证奖励，且需要搜索新解法**：优先 Online RL。例如代码 hidden tests、数学答案验证、工具任务成功率。
2. **只有一批高质量偏好对，希望低成本稳定训练**：优先 DPO/IPO 等 Offline 方法。主观风格与安全偏好往往更适合这条路线。
3. **有明显更强的教师，目标是压缩能力且能访问教师分布**：优先 On-Policy Distillation，尤其适合纠正学生推理时会进入、离线教师数据却未覆盖的错误前缀。
4. **reward 很容易写但不完整**：不要直接把它交给 RL 大规模优化。先红队验证器，或用教师/人工偏好补充不可形式化维度。
5. **预算有限**：先 SFT + Offline Preference；收益到顶后，仅在高价值、可验证子域加入 On-Policy 或 Online 阶段。

### 四、常见混合管线

```text
高质量示范 SFT
→ 离线 DPO/IPO 建立基本风格与安全边界
→ 学生 on-policy 采样，教师纠正自身错误状态
→ 在可验证任务上用 GRPO/PPO 探索
→ 独立人工集和隐藏验证器验收
```

混合训练时必须版本化数据来源、采样策略、教师、reference、reward 与 chat template。否则实验即使算法名字相同，也无法解释效果究竟来自方法还是数据分布变化。

### 面试简答版

Offline Preference Optimization 用固定 chosen/rejected 数据训练，便宜稳定但没有探索，适合已有高质量偏好数据的风格与安全对齐。Online RL 让当前策略采样并由 RM、验证器或环境打分，能探索并适应当前分布，适合数学、代码和工具等可验证任务，但 rollout 贵且容易 Reward Hacking。On-Policy Distillation 则让学生生成轨迹、教师在学生访问的前缀上给 token-level 分布，能纠正学生自己的错误状态，监督稠密但受教师上限和教师推理成本限制。工程上通常是 SFT/离线偏好冷启动，再按需要加入 on-policy 蒸馏或可验证 RL。
