> **问题：** GRPO 与 PPO、REINFORCE 的目标和资源占用有何差异？
>
> **分类：** RLHF、偏好优化与推理强化学习
>
> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

三者都可做在线 policy gradient，但 baseline 和限制更新的方法不同：REINFORCE 是最直接的蒙特卡洛策略梯度；PPO 用 Critic/GAE 降方差并用 ratio clip 限制更新；GRPO 保留 PPO-style clip，却用同 Prompt 的组均值代替 Critic。

### 一、目标对比

#### REINFORCE

\[
\nabla J=\mathbb E[(R-b)
\sum_t\nabla\log\pi_\theta(a_t|s_t)]
\]

最简单版本整条序列共享 outcome return，baseline 可为空、全局移动平均或 leave-one-out。实现简单且无需 Critic，但稀疏长序列 reward 方差很高，一批 rollout 通常只更新一次或少量次。

#### PPO

\[
J_{PPO}=\mathbb E_t[
\min(\rho_tA_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t)]
\]

Critic 估计每前缀 value，GAE 生成 token-level advantage；ratio 和 clip 允许同一 rollout 做多个 minibatch epoch，同时抑制大步更新。通常另有 Reference KL、value loss 与 entropy。

#### GRPO

\[
\hat A_i=\frac{r_i-\operatorname{mean}(r_{1:G})}
{\operatorname{std}(r_{1:G})+\epsilon}
\]

然后把 \(\hat A_i\) 代入 PPO-style token ratio/clip，并加 Reference KL。它用同题多个回答的相对 reward 代替 \(V_\psi(s_t)\)，不训练 Critic。

### 二、资源占用

| 资源 | REINFORCE | PPO | GRPO |
|---|---|---|---|
| Policy/Actor | 需要 | 需要 | 需要 |
| Old log-prob | 实现而定 | 需要 | 需要 |
| Critic + optimizer | 不需要 | 需要 | 不需要 |
| Reference | 可选 | RLHF 中常用 | 常用 |
| 每 Prompt 候选 | 可为 1 或多条 | 可为 1 或多条 | 必须多条才有组信号 |
| Rollout 成本 | 较低起点 | 高 | 随 G 增长，可能很高 |
| 激活/显存 | 最低起点 | Critic 最重 | 无 Critic但需缓存 G 条轨迹 |

GRPO 节省的是 Critic 训练，不保证总 FLOPs 最少；长 CoT 下生成 G 条回答可能比 Critic 前向更贵。

### 三、方差和 Credit Assignment

- REINFORCE：裸 outcome return 方差最高，对所有 token 归因粗；好的 baseline/leave-one-out 会使它与组相对方法更接近。
- PPO：Critic 能跨 Prompt 和前缀泛化，并用 GAE 给不同 token 不同 advantage；若 Critic 不准，反而引入 bias 和训练不稳。
- GRPO：同题难度被组均值消除，不需要学习 Critic；但 outcome 模式下同一回答所有 token 常共享 advantage，过程归因仍粗，且组内全同 reward 时无信号。

### 四、On-policy 与样本复用

REINFORCE 的经典估计直接用当前策略轨迹；PPO/GRPO 保存 \(\pi_{old}\) log-prob，用 importance ratio 在有限范围复用 rollout。更新太多 epoch 后 ratio 与 KL 变大，clip 并非万能，轨迹应丢弃并重新采样。

三者都不同于 DPO 的固定离线 pair：它们能从当前 policy 探索新输出，代价是 rollout 和 reward 服务成本。

### 五、选型

- 验证算法/小模型、reward 稳定、能容忍高方差：REINFORCE 是最清晰基线；
- 通用主观奖励、需要 token value 和成熟稳定控制：PPO 更完整，但成本最高；
- 同题可并行采多条、结果可验证、Critic 太贵：GRPO 很合适；
- 若成功率极低且所有组全错，GRPO 也学不到，需要 SFT/curriculum、更大探索或过程奖励。

### 面试简答版

REINFORCE 直接用序列 return 乘 token log-prob 梯度，不需 Critic、资源最省但方差和 credit assignment 最差。PPO 训练 Critic，用 GAE 得到 token advantage，再用 old-policy ratio clip 复用 rollout，稳定性更强但要额外 Value Model 及 optimizer。GRPO 删除 Critic，对同一 Prompt 采 G 条回答，以组内标准化 reward 为 advantage，再沿用 PPO clip 和 Reference KL；它省 Critic 显存，却增加多样本 rollout 成本，且全组同奖时无信号。
