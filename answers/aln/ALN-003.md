> **问题：** PPO 用于 LLM 对齐时 Actor、Critic、Reward Model 和 Reference Model 分别做什么？
>
> **分类：** RLHF、偏好优化与推理强化学习

> **来源：** [INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md](../../INTERVIEW_QUESTIONS_AGENT_HARNESS_EXPANDED.md)

## 我的答案

在 LLM PPO 中，一条轨迹是完整回答：**state 是 Prompt 加已生成前缀，action 是下一个 token**。Actor 决定生成什么，Critic 估计当前前缀未来能获得多少回报，Reward Model 评价最终回答，Reference Model 约束策略不要偏离 SFT 分布。

### 一、Actor：当前可训练策略

\[
a_t=y_t\sim\pi_\theta(\cdot|s_t),
\qquad s_t=(x,y_{<t})
\]

Actor 从 prompt 自回归采样回答，是最终要部署的模型。PPO 根据 advantage 调整已采样 token 的 log-prob：高于预期的动作概率上升，低于预期的动作概率下降。它通常从 SFT checkpoint 初始化。

### 二、Critic：估计每个前缀的 Value

\[
V_\psi(s_t)\approx
\mathbb E\left[\sum_{k=t}^{T}\gamma^{k-t}r_k\mid s_t\right]
\]

Critic 用于计算 \(A_t=Q(s_t,a_t)-V_\psi(s_t)\)，是降低 policy-gradient 方差的 baseline，不负责定义“什么回答好”。它用 rollout return/GAE target 回归训练；可与 Actor 共享 backbone 加 value head，也可独立部署。

### 三、Reward Model：给偏好代理分数

\[
r_{RM}=r_\phi(x,y)
\]

RM 从人类 pairwise preference 学来，通常对完整回答在终止位置给 sequence-level scalar reward，并在 PPO 阶段冻结。RM 不等于 Critic：RM 学人类更偏好哪个完整回答，Critic 学当前策略从某个 token 前缀出发的期望训练回报。

### 四、Reference Model：提供 KL 锚点

Reference 通常是冻结 SFT 策略 \(\pi_{ref}\)，对 Actor 采样的 token 计算：

\[
k_t=\log\pi_\theta(a_t|s_t)-\log\pi_{ref}(a_t|s_t)
\]

并构造 shaped reward：

\[
r_t^{total}=r_t^{task}-\beta k_t
\]

它限制 Actor 进入 RM 未覆盖的异常分布，也帮助保留语言质量和通用能力。Reference 不判断回答好坏，且不更新梯度。

### 五、还存在一个 Old Policy

PPO 中的 \(\pi_{old}\) 不应与 Reference 混淆：

- \(\pi_{old}\)：本轮 rollout 时 Actor 的快照，计算 importance ratio \(\pi_\theta/\pi_{old}\)，每轮更新；
- \(\pi_{ref}\)：长期冻结的 SFT 锚点，用于 KL regularization。

有些实现只缓存 rollout 的 old log-prob，而不保留完整 old model；Reference 仍需计算 reference log-prob。

### 六、一次迭代的数据流

```text
Prompt
  → Actor rollout（保存 token、old logprob）
  → RM 给终端偏好分数
  → Reference 给每 token KL
  → Critic 给每 token value
  → 构造 reward、GAE advantage 和 return
  → 多个 minibatch epoch 更新 Actor/Critic
  → 进入下一轮 rollout
```

训练中监控 RM reward、KL、entropy、value loss、explained variance、clip fraction、ratio、长度和独立人评。只看总 reward 上升无法判断是偏好改善还是钻 RM/长度漏洞。

### 七、资源边界

逻辑上可能同时有 Actor、Critic、RM、Reference 四个大模型。可用 PEFT、模型共享、冻结模型量化、offload 和并行降低显存，但共享 backbone 可能造成 Actor/Critic 梯度干扰；量化也会改变 reward/KL 数值。每种优化都要保持模型版本和 log-prob 一致。

### 面试简答版

Actor 是可训练语言策略，按 token 生成回答；Critic 对每个 Prompt+前缀估计未来总回报，用作 advantage baseline；Reward Model 从人类偏好学到，冻结后给完整回答任务奖励；Reference Model 是冻结 SFT 副本，提供逐 token KL 锚点。还要区分 old policy：它是本轮采样快照，用来算 probability ratio，而 reference 是长期对齐锚点。一次迭代是 rollout、RM/KL/value 打分、GAE，再更新 Actor 和 Critic。
