## 我的答案

PPO 不稳定可能来自 prompt、Reward Model、rollout、GAE、Actor/Critic 优化或分布式实现。排查时应先验证一条轨迹的逐 token 数学，再看小规模 overfit，最后扩大并行；直接调学习率容易掩盖 mask 或 log-prob bug。

### 一、数据与 Mask

- Prompt 是否来自目标分布，是否重复、过长、全是某任务或含训练/评估泄漏；
- tokenizer、Chat Template、BOS/EOS 与 SFT/RM/Reference 是否一致；
- response、prompt、padding、tool result 的 masks 是否正确；
- 截断是正常 terminal 还是 time-limit truncation，GAE 是否错误跨样本传播；
- 每个 prompt 是否能采到有区分度的输出，而不是全相同或全无效；
- 不同长度/任务在 token-average 和 whitening 后的实际权重。

第一步应打印一个极小 batch 的 tokens、old/actor/ref log-prob、reward vector、value、return、advantage 和 loss mask，手算核对。

### 二、奖励指标

分别记录而非只报总和：

- 原始 RM/task reward 的均值、方差、分位数和各任务切片；
- 每 token/每序列 reference KL、KL penalty 和净 reward；
- EOS、长度、格式、安全等 shaping reward；
- reward clipping/normalization 前后分布；
- reward 与长度、重复率、正确率、人评的相关性；
- 高 reward 样本人工审计和 RM ensemble disagreement。

若 reward 方差近零，策略没有学习信号；极端 outlier 会主导 advantage；RM reward 快速上升而独立质量下降说明 hacking，而非 PPO“收敛很好”。

### 三、采样与 Rollout

- temperature、top-p、max/min length、stop token 是否让探索过窄或噪声过大；
- entropy、token 多样性、重复率、EOS rate 和长度直方图；
- rollout 是否真由保存的 \(\pi_{old}\) 生成，old log-prob 是否在采样时冻结并与 token 对齐；
- rollout 太陈旧时 Actor 已变化，importance ratio 会失真；
- RM/Reference 是否以 eval mode 运行，dropout 是否意外开启；
- Actor、Reference、RM 的模板或 response slicing 是否不同。

可先固定一批 prompt/rollout，检查一次 PPO epoch 内 ratio 如何变化，再进入在线循环。

### 四、Actor/PPO 指标

重点看：

- policy loss、approximate old-policy KL、reference KL；
- ratio 的均值、标准差、最大/最小和 clip fraction；
- entropy、token log-prob 和梯度范数；
- 每个 minibatch PPO epoch 后的 KL 增长；
- 学习率、optimizer state、gradient accumulation、clipping 和 loss scale；
- NaN/Inf、BF16/FP16 overflow、全局梯度裁剪前后数值。

若 ratio 初始就不接近 1，通常是 old log-prob、权重版本、dropout、mask 或 tokenizer bug；若一个 epoch 后 KL 暴涨，减少 actor LR、PPO epochs、clip range，检查 advantage scale。

### 五、Critic 与 GAE

- value loss、value mean/std、return mean/std、explained variance；
- advantage 在 whitening 前后是否有限、均值/方差是否合理；
- \(\gamma,\lambda\)、terminal mask 和 bootstrap 是否正确；
- Critic LR、value clipping、loss coefficient 是否过大或跟不上；
- Actor/Critic 共享 backbone 时 value loss 是否破坏 policy；
- sparse terminal reward 下不同长度的 return scale。

Critic 输出常数时 explained variance 接近 0；严重负值说明可能比均值 baseline 更差。Critic 学太快也可能过拟合 rollout，使 advantage 失真。

### 六、KL 控制与 Reward Scale

- 固定 \(\beta\) 是否与 RM reward 量级匹配；
- 自适应 controller 的 target、更新方向、horizon 和 clip 是否正确；
- KL 是按 token 还是 sequence，是否被长度重复累计；
- reward whitening 是否跨不同 task 混合，导致语义标尺改变；
- RM checkpoint 更新后 reward scale 是否跳变。

同时监控“原始 reward、KL、净 reward”，否则可能净 reward 几乎全由 KL 决定。

### 七、分布式和系统问题

- DP rank 的 prompt、reward normalization 统计是否正确 all-reduce；
- padding side、sequence length 和跨 rank mask 是否一致；
- Actor 更新后 rollout worker 是否同步到同一权重版本；
- gradient accumulation 除数、world size 与 global batch 是否重复缩放；
- checkpoint 恢复时 optimizer、KL controller、sampler 和 RNG 是否恢复；
- 量化/offload 是否让不同 worker 的 logits 有系统差异。

### 八、推荐排查顺序

1. 单样本逐 token 手算；
2. 极小固定 batch 上验证 reward/GAE/PPO 能按预期过拟合；
3. 关闭自适应 KL、复杂 shaping 和分布式，建立最小基线；
4. 逐项加入 Critic、KL controller、多 GPU 和在线 rollout；
5. 每次只变一个因素，并保存高 reward 文本；
6. 最终用独立质量而非 PPO 内部 reward 选 checkpoint。

### 面试简答版

我会先逐 token 核对 prompt/response/padding mask、old/actor/ref log-prob、reward、value、GAE 和 terminal，尤其检查 PPO 开始时 ratio 是否接近 1。奖励侧看 RM、KL、净 reward 的分布和与长度/真实正确率的相关性；采样侧看 entropy、EOS、长度和 rollout 新鲜度；Actor 看 ratio、clip fraction、old/ref KL、梯度；Critic看 value loss、return、advantage 和 explained variance。再排查学习率、PPO epoch、reward scale、KL controller，以及分布式权重同步和归一化。先单卡小 batch 复现，再逐项扩大。
