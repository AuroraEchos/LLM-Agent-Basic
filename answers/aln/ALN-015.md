## 我的答案

GRPO（Group Relative Policy Optimization）由 [DeepSeekMath](https://arxiv.org/abs/2402.03300) 提出。它保留 PPO 的在线采样、importance ratio、clip 和 reference KL，但用**同一 Prompt 下多个回答的组内相对奖励**代替训练一个 Value/Critic Model。

### 一、PPO 为什么需要 Critic

PPO 用：

\[
A_t\approx Q(s_t,a_t)-V_\psi(s_t)
\]

Critic \(V_\psi\) 通常与 Policy 规模相近，要为每个 token 前缀估计 value。它增加模型权重、optimizer、激活和通信显存；而 LLM reward 常只在回答末端出现，使 token-level value 本身也难学准。

GRPO 观察到：若同一个问题采样多个回答，可以直接用它们彼此比较来构造 baseline，不必用神经网络预测 value。

### 二、组内采样和相对优势

对一个 prompt \(q\)，从 old policy 采样 \(G\) 个回答：

\[
o_1,\ldots,o_G\sim\pi_{old}(\cdot|q)
\]

通过 RM、规则或 verifier 得到：

\[
r_1,\ldots,r_G
\]

计算组均值和标准差：

\[
\mu_q=\frac1G\sum_{j=1}^{G}r_j,
\qquad
\sigma_q=\sqrt{\frac1G\sum_j(r_j-\mu_q)^2}
\]

常见 outcome-level 相对优势：

\[
\hat A_i=\frac{r_i-\mu_q}{\sigma_q+\epsilon}
\]

组内高于平均的回答为正优势，低于平均为负优势。若只有终端 outcome reward，通常回答 \(o_i\) 的所有有效 token 共享 \(\hat A_i\)；若有 process reward，可按步骤/位置构造更细优势。

### 三、GRPO Objective

对第 \(i\) 条回答第 \(t\) 个 token：

\[
\rho_{i,t}=\frac{
\pi_\theta(o_{i,t}|q,o_{i,<t})
}{
\pi_{old}(o_{i,t}|q,o_{i,<t})
}
\]

核心目标可概括为：

\[
J_{GRPO}=\frac1G\sum_i\frac1{|o_i|}\sum_t
\left[
\min(\rho_{i,t}\hat A_i,
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i)
-\beta D_{KL}(\pi_\theta\|\pi_{ref})
\right]
\]

具体实现可能对 advantage、KL estimator、长度归一化与多次更新有所变体，但核心是“PPO-style policy update + group-relative baseline，无 Critic”。

### 四、为什么可以不训练 Critic

组均值 \(\mu_q\) 近似该 prompt 下当前策略的 expected reward baseline：

\[
V(q)\approx\frac1G\sum_i r_i
\]

减去只依赖 prompt、与具体 sampled action 无关的 baseline，可以降低 policy-gradient 方差而不需要学习 value network。按同一 Prompt 标准化还会消除部分题目难度差异：难题的 0.5 分和易题的 0.5 分不再被当成完全相同的绝对信号。

### 五、优势

- 去掉 Critic 的参数、优化器、激活和训练不稳定性，显著节省显存；
- 与“同题多个候选相互比较”的 reward/verification 结构自然匹配；
- 对数学、代码等可一次采多条并自动验证的任务很实用；
- 不必等 Critic 学会稀疏终端回报，即可产生相对信号。

### 六、代价和边界

1. **Rollout 成本**：每个 Prompt 必须生成 \(G\) 个回答，省掉 Critic 不等于总计算一定更低；长推理的 Decode 成本很高。
2. **全组同奖无信号**：若所有回答都错得 0 分或都得 1 分，\(r_i-\mu=0\)，该组几乎没有学习信号；需要合适难度、探索和更细 reward。
3. **小方差放大噪声**：组内真实差异极小却除以很小标准差，会把 reward 噪声放大；需 epsilon、阈值、去标准化或 robust normalization。
4. **相对而非绝对质量**：一组全是差答案，也会有“相对最好者”获正优势；reward 本身必须可靠，并可设绝对门槛。
5. **Credit Assignment 粗**：outcome advantage 仍赋给整条回答，不知道具体哪一步正确；Critic 被省掉，但过程归因问题没消失。
6. **样本相关**：同组优势相互依赖，batch/组划分、重复答案和 reward tie 会显著影响方差。
7. **仍会 Hacking**：规则测试、RM、长度和格式均可能被利用，reference KL 也不是万能防线。

### 七、工程监控

除 PPO 的 ratio、clip fraction、KL、entropy 和梯度外，还要记录每个 Prompt 的 reward mean/std、全同 reward 组比例、组内正确率、多样性、重复率、有效 group size 和每个正确样本消耗的 rollout tokens。调大 \(G\) 会改善 baseline 和命中成功轨迹的概率，却线性增加采样成本，需做质量—成本曲线。

### 面试简答版

GRPO 对同一 Prompt 从 old policy 采样 \(G\) 个回答，用 verifier/RM 得到奖励，再以 \((r_i-\bar r)/({std}(r)+\epsilon)\) 作为组内相对优势，因此无需训练与 Policy 同规模的 Critic。随后仍用 PPO-style token ratio、clip 和 reference KL 更新策略。它节省 Critic 显存，适合数学代码等可验证任务；但每题要生成多条，组内全同奖励时没有信号，小方差会放大噪声，且 outcome advantage 仍无法精确定位推理步骤，所以必须监控 group reward 分布、多样性、KL 和 rollout 成本。
