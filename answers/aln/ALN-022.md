## 我的答案

Function Calling 不是一个“JSON 合法率”任务，而是从用户意图到环境结果的多阶段决策。奖励应覆盖：**是否需要工具、选哪个工具、参数是否语义正确、执行是否成功、最终回答是否使用结果完成任务，以及成本与安全约束。**

### 一、分解轨迹

```text
用户请求
→ 决定直接回答或调用工具
→ tool name
→ arguments / call_id
→ 环境执行与 observation
→ 是否重试/调用下一工具
→ 最终回答或状态变更
```

每个阶段都可能失败。只奖励最终答案时信号太稀疏；只奖励格式时又会学会“合法但无用”的调用。

### 二、奖励组件

#### 1. 格式与协议

- tool call 能被 parser 解析；
- 符合 JSON Schema、类型、必填字段和枚举；
- call ID、并行调用和结束 token 与协议一致。

格式 reward 应是前置门槛而非高额主奖励，否则模型会输出空但合法 JSON 刷分。

#### 2. 工具选择

- 该问题是否真的需要工具；
- 在候选工具中选择语义正确且权限允许者；
- 不该调用时能直接回答或澄清；
- 多工具任务的顺序和依赖正确。

需要包含 no-tool、ambiguous、unavailable 和 adversarial tool description 样本，防止模型形成“总调用最热门工具”的捷径。

#### 3. 参数

- schema 合法只是基础；
- 实体、单位、时区、日期范围、过滤条件与用户意图一致；
- 缺少关键参数时先询问，不可擅自编造；
- 敏感字段、权限 scope 和注入内容经过校验。

可用参考参数 exact/semantic match、约束求解或真实环境结果判断。多个参数等价表达时不能只做字符串 exact match。

#### 4. 执行结果

- API/工具是否成功，返回状态和环境状态是否达到目标；
- 对瞬时失败是否合理重试，对永久失败是否停止并说明；
- 写操作是否幂等、是否获得确认、是否避免重复副作用；
- 不允许把模型自己伪造的“tool result”当执行成功。

#### 5. 最终回答

最终答案应基于 observation，正确概括结果、引用必要字段、不泄露敏感数据，也不能声称未执行的动作已完成。对写操作，真正的环境 state transition 比自然语言自报更可信。

#### 6. 成本和安全

惩罚无效调用、重复调用、token、延迟和付费 API 成本：

\[
C=\lambda_nN_{calls}
+\lambda_tT_{latency}
+\lambda_mC_{money}
\]

但不能让成本惩罚导致模型为省一次必要调用而胡答。越权、危险写操作、Prompt Injection 成功等应作为硬约束。

### 三、组合方式

一种带 gating 的形式：

\[
R=
\mathbf1[format\_valid]\cdot
\left(
w_sR_{selection}+w_aR_{args}
+w_eR_{execution}+w_fR_{final}
\right)-C
\]

安全违规可令整条轨迹 reward 为强负或直接拒绝执行。相比简单加权，gating/lexicographic 规则能避免“执行失败却靠漂亮 final answer 抵消”。

### 四、训练数据与评估

- 构造正确工具、易混淆工具、无需工具、缺参数、工具报错、恶意 observation 和多步依赖；
- 在可回滚 sandbox 中执行，写操作使用 mock/事务；
- 对同一意图做参数改写、工具名扰动和 schema 版本变化；
- 分别报告 parse、selection、argument semantic match、execution success、end-to-end task success、安全违规、平均 calls/成本；
- 以 end-to-end 成功为主指标，各中间分数用于诊断。

### 五、常见 Hacking

- 重复调用直到偶然成功；
- 选择永远返回 200 但不完成任务的工具；
- 伪造 observation 或把用户文本当 tool result；
- 利用 validator 忽略额外字段、重复 key 或单位；
- 为获得“调用工具”分而对简单问题也调用；
- 跳过确认直接执行高风险动作。

因此奖励服务必须读取可信 execution trace，而不是只解析模型最终文本。

### 面试简答版

Function Calling reward 要分层：格式/schema 是门槛；工具选择要包括“是否需要调用”；参数既验类型也验实体、单位和用户语义；执行以可信环境状态和错误恢复为准；最终回答必须忠实使用 observation；同时惩罚无效调用、延迟和费用，并把越权/危险写操作设为硬约束。可用 gating 让格式或安全失败不能被其他高分抵消。评估应分别报 parse、selection、args、execution 和 end-to-end success，训练在沙箱中覆盖 no-tool、缺参数、失败、注入和多步场景。
