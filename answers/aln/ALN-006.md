## 我的答案

PPO 中通常有两种“离得不要太远”的机制：PPO clip 限制当前更新相对 rollout old policy 的变化；RLHF 的 KL 惩罚则约束 Actor 长期不要远离冻结的 SFT Reference。题目中的 KL 通常指后者。

### 一、为什么需要 Reference KL

Reward Model 只是有限偏好数据上训练的代理。若只优化：

\[
\max_\theta\;\mathbb E_{y\sim\pi_\theta}[r_\phi(x,y)]
\]

表达能力很强的策略会寻找 RM 的漏洞，进入其训练分布之外，出现怪异格式、无意义冗长、迎合 judge 或通用能力下降。加入：

\[
\max_\theta\;
\mathbb E[r_\phi(x,y)]
-\beta D_{KL}(\pi_\theta(\cdot|x)\|\pi_{ref}(\cdot|x))
\]

相当于用 SFT policy 作为先验/行为锚点，在偏好收益和分布漂移之间权衡。它能减缓 reward hacking、语言退化和遗忘，也使 RM 少做分布外外推，但不能保证完全消除代理过优化。

### 二、逐 Token 实现

对 Actor 采样 token \(a_t\)，常用 sampled KL 估计：

\[
k_t=\log\pi_\theta(a_t|s_t)-\log\pi_{ref}(a_t|s_t)
\]

把它加入 reward：

\[
r_t^{total}=r_t^{task}-\beta k_t
\]

完整 expectation 下 KL 非负，但单条样本的 log-ratio 可以为负；不能因某个 token 出现“负 KL penalty”就断言实现错误。也可以对全词表精确计算 categorical KL，成本更高但方差更小。

回答越长，逐 token KL 累积通常越大，因此监控时要同时看 sequence KL、每 token KL 和长度分布，明确 loss 是按 token 还是 sequence 归一化。

### 三、固定 KL 系数

固定 \(\beta\) 在整个训练中不变。

优点：

- 目标函数固定，实验容易解释与复现；
- 实现简单，没有控制器振荡；
- 负载和 reward scale 稳定、已有成熟经验时足够。

缺点：

- 训练早期和后期需要的约束强度可能不同；
- reward normalization、回答长度或 prompt 分布变化后，同一 \(\beta\) 的实际作用会改变；
- 太小导致 KL 失控，太大则策略几乎不学习。

应通过 KL—独立质量 Pareto 曲线搜索，而不是只选 RM reward 最大的系数。

### 四、自适应 KL 控制

先设目标 \(K_{target}\)，根据观测 KL 更新 \(\beta\)。一种概念性更新为：

\[
\beta_{t+1}=\beta_t
\exp\left(\eta\left(\frac{K_t}{K_{target}}-1\right)\right)
\]

- \(K_t>K_{target}\)：增大 \(\beta\)，加强约束；
- \(K_t<K_{target}\)：减小 \(\beta\)，允许更多学习。

实践会 clip 更新幅度并用滑动平均，避免单个异常 batch 让控制器剧烈振荡。目标 KL 要明确是每 token、每 sequence、哪个长度归一化以及相对哪个 reference。

优点是能在训练动态和长度分布变化时维持近似稳定的 KL budget；缺点是新增 controller gain、horizon、target 等超参数，而且反馈有延迟。若 reward 或策略突然变化，控制器可能过冲，\(\beta\) 也可能塌到极小/极大。

### 五、如何选择

- 小规模、分布稳定、需要严格可复现实验：先用固定 \(\beta\) 建基线；
- 长训练、策略变化大、在线 prompt mix 波动明显：自适应 KL 更易维持预算；
- 无论哪种，都要设置 KL hard alarm/early stop，不能完全依赖 controller；
- 针对不同任务和长度可分桶监控，防止平均 KL 正常但长回答或某语言已经漂移。

### 六、工程监控

同时记录 RM/task reward、KL penalty、净 reward、reference KL、old-policy approximate KL、clip fraction、entropy、长度、EOS、通用能力和独立人评。若 RM reward 上升、reference KL 持续扩大而独立质量下降，就是典型过优化信号；调大 \(\beta\) 只是一个手段，还需修 RM 数据、加入 hard negatives 或提前停止。

### 面试简答版

Reference KL 把 Actor 锚定在 SFT 分布附近，避免策略为了最大化不完美 Reward Model 而产生 reward hacking、语言退化和遗忘。常把每 token 的 \(\log\pi_\theta-log\pi_{ref}\) 乘 \(-\beta\) 加入 reward。固定 \(\beta\) 目标稳定、易复现，但难适应不同训练阶段和长度分布；自适应 KL 根据观测值相对目标 KL 增减 \(\beta\)，能维持近似 KL budget，但可能振荡且新增控制超参数。两者都要同时监控每 token/每序列 KL、独立质量和 RM reward。
