## 我的答案

PRM（Process Reward Model）的目标是在推理步骤边界评估前缀质量。高质量 PRM 的难点不在加一个 scalar head，而在于定义“步骤”、标注语义和覆盖模型实际会生成的错误路径。

### 一、先定义步骤与标签语义

将解答切成：

```text
问题 x
步骤 z1
步骤 z2
...
最终答案 a
```

步骤边界可来自换行、显式分隔 token、工具调用或结构化 AST。切得太细，标签只是在评 token 文法；太粗，又退化成 outcome supervision。

标签必须说明是在判断：

1. **局部正确性**：本步推导自身是否成立；
2. **前缀有效性**：到此为止是否存在错误；
3. **可完成性/Value**：从此前缀继续得到正确答案的概率；
4. **Progress**：本步相对上一步是否提高成功概率。

不能混用这些标签后训练一个含义不明的分数。

### 二、人工步骤级标注

流程通常是：

1. 从当前/多阶段 Policy 采样大量完整解答，覆盖正确、常见错误与边界策略；
2. 可靠地切分步骤，保留原始 token span；
3. 专家逐步标注 correct/incorrect/uncertain，并指出 first error 和原因；
4. first error 之后的步骤可能建立在错误前提上，可标为 invalid/不可判，而不是机械都当独立错误；
5. 多标与仲裁，监控步骤类别、难度和标注员一致性；
6. 用 active learning 优先标 PRM 不确定、多个 verifier 分歧或搜索高访问的前缀。

[PRM800K / Let's Verify Step by Step](https://arxiv.org/abs/2305.20050) 是大规模人工步骤监督的代表。Train/Test 要按题目家族隔离，不能把同题不同轨迹拆到两侧。

### 三、自动/弱监督标注

当最终答案可验证时，可对步骤前缀 \(z_{\le k}\) 采样 \(M\) 条 continuation：

\[
\hat V(z_{\le k})=
\frac1M\sum_{j=1}^{M}
\mathbf 1[\text{continuation}_j\text{ succeeds}]
\]

它把“从该前缀还能否成功”作为软 value 标签。也可用符号验证器、代码执行、定理证明器、强模型 judge 或规则检查局部步骤。[Math-Shepherd](https://arxiv.org/abs/2312.08935) 展示了自动构造步骤监督并用于验证和 RL。

边界是：失败 continuation 可能源于生成器弱，而非前缀错误；成功 continuation 也可能纠正早期问题或猜中答案。M 小时方差高，M 大时数据成本高。自动 judge 与待训练 Policy 还可能共享盲点。

### 四、训练 PRM

输入为问题加截至第 k 步的前缀，在步骤结束 token 的 hidden state 上接分类/标量 head：

\[
p_k=\sigma(w^Th_{end(k)})
\]

可用 BCE、ordinal loss、pairwise ranking 或对 rollout success rate 的回归。训练要：

- 对 correct/first-error/uncertain 和题目难度做平衡；
- 防止模型只看步骤长度、格式、关键词和最终答案泄漏；
- 用“格式漂亮但推理错”“简短但正确”的 hard negatives；
- 在新 Policy、新题型和不同步骤位置上评估校准；
- 报 first-error detection、step AUROC/accuracy、prefix value calibration 和端到端搜索收益。

### 五、用于训练 Generator

1. **数据过滤/拒绝采样**：只用 PRM 全程高分的轨迹做 SFT；
2. **Step-level RL**：在步骤结束位置加入 reward，用 PPO/GRPO 将信号传给步骤内 token；
3. **过程蒸馏**：用 PRM 选出高质量推理路径，再训练较小模型；
4. **错误修复数据**：截取 first-error 前缀，生成并监督正确分支。

要保留 outcome verifier 作为最终约束，否则 Policy 可能学习写 PRM 喜欢的过程而答案仍错。

### 六、用于推理搜索

- **Best-of-N**：生成 N 条完整轨迹，以 final outcome、PRM 最小步分、平均 log score 或组合分数 rerank；
- **Beam Search**：每扩展一个步骤用 PRM 打分，保留 top beams；
- **MCTS**：PRM 作为 node value/heuristic，指导 selection 与 pruning；
- **Backtracking**：PRM 发现低分步骤时回退到此前高分前缀，尝试新分支。

聚合方式会改变偏好：乘积/累加 log-prob 惩罚长轨迹，取最小值对单个误判极敏感，平均值可能掩盖致命错误。应在固定 test-time token budget 下比较最终正确率，而非只看 PRM score。

### 七、主要风险

- PRM 本身可被 hacking：冗长、显式“检查”、标准格式可能骗分；
- 局部正确不等于有用进展，搜索可能困在漂亮但死路的分支；
- 强制显式步骤可能惩罚正确的跳步或非传统解法；
- 训练 Policy 后分布变化，旧 PRM 需要用新轨迹持续校准；
- 隐式思考不一定可安全暴露，PRM 数据和产品输出策略要分离。

### 面试简答版

PRM 数据先把模型解答切成稳定步骤，明确标签是局部正确、前缀无错、可完成性还是进展。人工方案逐步标 correct/first-error/uncertain，并用 active learning 标难例；自动方案可从每个前缀采多条 continuation，以最终成功率估计 value，但受生成器能力和采样方差影响。PRM 通常在步骤结束 hidden state 上做分类/回归。训练时可用于轨迹过滤或 step-level PPO/GRPO；推理时可做 Best-of-N rerank、beam pruning、MCTS 和回退。必须用最终 outcome verifier 护栏，并防长度、格式和推理风格 hacking。
