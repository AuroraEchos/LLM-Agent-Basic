> **问题：** DPO 与 PPO 在数据、计算成本、在线探索和稳定性上有何差异？

## 我的答案

DPO 和 PPO 都能利用偏好信号，但训练范式不同：**DPO 是固定偏好 pair 上的离线策略学习；PPO 是当前策略在线采样、Reward Model 打分后进行 on-policy/near-on-policy 强化学习。**

### 一、整体对比

| 维度 | DPO | PPO-based RLHF |
|---|---|---|
| 数据 | 离线 \((x,y_w,y_l)\) | Prompt + 当前 Actor rollout + RM/规则奖励 |
| 显式 RM | 不需要 | 通常需要，或使用可验证 reward |
| Critic | 不需要 | 通常需要 |
| Reference | 通常需要 | 通常需要做 KL |
| 在线采样 | 训练时不需要 | 每轮需要 |
| 计算/显存 | 类似 pairwise SFT，较低 | Actor/Critic/RM/Reference 与 rollout，较高 |
| 探索 | 仅学习数据中已有回答 | 能发现数据中未出现的新回答 |
| 稳定性 | 训练链路简单，但会过拟合 pair | 组件多且敏感，但可持续适应新分布 |
| Reward 类型 | 主要是偏好比较 | 标量 RM、规则、执行器、过程奖励可组合 |

### 二、数据差异

DPO 需要同一 Prompt 的 chosen/rejected pair，质量取决于候选覆盖和标签。如果数据由旧模型生成，DPO 只能重新分配这些轨迹附近的概率，不能主动发现全新策略。

PPO 只需 prompt 分布和可调用 reward function。Actor 每轮生成当前策略输出，reward 看到的是最新分布；这使它能探索，也使 RM 不断面对分布漂移。若 reward 是数学答案、代码测试等在线 verifier，PPO/GRPO 能从大量新采样中寻找未标注的正确路径。

### 三、计算成本

DPO 每个 pair 要对 policy 跑 chosen/rejected；reference log-prob 可预计算。没有 rollout server、Critic、GAE 和 PPO 多轮同步，工程成本接近双序列 SFT。

PPO 一轮通常涉及：

```text
Actor 生成
+ Reward Model/Verifier 打分
+ Reference logprob
+ Critic value
+ Actor/Critic 多 epoch 更新
```

生成是串行 Decode，且四个逻辑模型占大量显存；虽可共享、量化和 offload，复杂度仍显著更高。

### 四、在线探索的利弊

PPO 优势：

- 能针对当前 policy 的失败持续采样；
- 可优化不可微但可执行的结果 reward；
- 有机会发现 preference dataset 未包含的更优答案；
- 可做 curriculum、动态难题和环境交互。

代价是探索噪声、低成功率样本成本、reward hacking 和训练/采样版本同步问题。DPO 没有在线探索，因此更安全可控，但受离线 coverage 限制。

### 五、稳定性不是绝对结论

DPO 没有 value、advantage、ratio 和 adaptive KL，通常更容易跑通、复现；但它仍可能：

- 记忆有限 pair，margin 无限增大；
- 降低 rejected 概率而未提高 chosen；
- 受长度/模板/label noise 强烈影响；
- 离线分布与部署分布错配。

PPO 容易因 reward scale、Critic、GAE、old log-prob、KL controller 和并行同步不稳，但在实现正确、reward 可靠且需要探索时更具表达力。不能把“DPO 简单”误说成“质量一定更高”。

### 六、如何选

- 已有高质量偏好 pair、预算有限、主要做聊天风格/安全偏好：先用 DPO 建基线；
- 任务可验证、需要探索新推理轨迹或持续与环境交互：优先考虑 PPO/GRPO 类在线 RL；
- 可先 DPO 建立稳定行为，再用在线 RL 在可验证任务上提升；
- 无论哪种，都要固定 reference、独立测试 reward hacking、监控 KL/长度/通用能力。

### 面试简答版

DPO 在固定 chosen/rejected pair 上离线训练，不需要显式 RM、Critic 和在线 rollout，计算与工程成本接近 pairwise SFT，通常更稳定易复现，但只能利用数据已有轨迹，容易过拟合或受长度偏置。PPO 让当前 Actor 在线采样，由 RM/Verifier 给 reward，再用 Critic、GAE 和 KL 更新；成本和不稳定因素更多，却能探索偏好集之外的回答，特别适合数学、代码、工具等可验证任务。高质量静态偏好和有限预算先选 DPO，需要在线探索与环境 reward 则选 PPO/GRPO。
