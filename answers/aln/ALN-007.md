## 我的答案

完整回答只有一个序列级奖励时，策略梯度仍能训练每个 token，因为序列概率可分解为 token 概率乘积；但它只能把最终结果粗粒度地归因给整条轨迹，这就是 credit assignment 难题。

### 一、从序列概率到 Token 梯度

\[
\pi_\theta(y|x)=\prod_{t=1}^{T}
\pi_\theta(y_t|x,y_{<t})
\]

因此：

\[
\nabla_\theta\log\pi_\theta(y|x)
=\sum_{t=1}^{T}
\nabla_\theta\log\pi_\theta(y_t|x,y_{<t})
\]

REINFORCE 给出：

\[
\nabla J(\theta)=
\mathbb E\left[
(R(y)-b)\sum_t
\nabla_\theta\log\pi_\theta(y_t|s_t)
\right]
\]

最朴素做法是给所有 token 同一个终端 return：好回答中的所有动作整体增概率，坏回答整体降概率。它无偏但方差高，而且无法知道正确答案中是否夹杂错误步骤。

### 二、Critic 与 Advantage

Critic 为每个前缀估计：

\[
V(s_t)\approx\mathbb E[R|s_t]
\]

用 return 减 baseline 得到 \(A_t\)，再通过 GAE 混合不同跨度 TD residual。这样最终奖励会从末端向前传播，但不同 token 获得的 advantage 会因前缀 value 不同而不同，方差比整条序列共享裸 reward 更低。

PPO 的 token 级 actor loss为：

\[
L_t^{clip}=\min(
\rho_tA_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t)
\]

只在有效 response token 上聚合。

### 三、Reward Shaping

常见 reward vector：

```text
t=1 ... T-1：逐 token KL penalty
t=T：KL penalty + sequence RM/task reward
```

即：

\[
r_t=-\beta k_t,quad t<T
\]

\[
r_T=-\beta k_T+r_{outcome}
\]

还可加入 EOS、格式、工具执行或安全 penalty。但 shaping 改变优化目标，若规则可被钻空子就会产生新 hacking；理论上 potential-based shaping 更容易保持原最优策略，工程规则奖励则必须做对抗测试。

### 四、Outcome Reward 与 Process Reward

- **Outcome Reward Model（ORM）**：只评完整答案/最终结果，标注便宜、适用广，但 credit assignment 粗；
- **Process Reward Model（PRM）**：对每个推理步骤或中间状态打分，可更准确定位错误步骤，但标注和校准更困难，错误过程监督也可能被策略利用；
- **可验证奖励**：代码测试、数学答案、工具执行结果通常比主观 RM 更可靠，但仍可能有测试覆盖漏洞。

若有 step boundaries，可在步骤结束处放 process reward，再由 GAE 传播到步骤内 token。不能简单把 sequence reward 均匀除以 token 数：这会改变长度依赖，却仍没有获得真正的因果归因。

### 五、边界处理

- Prompt token 是条件，一般不计算 actor loss；
- padding 必须 mask，packed sequence 在边界 reset return/GAE；
- 正常 EOS 是 terminal，`max_length` 截断是否 bootstrap 要按环境定义；
- 缺失 EOS 的 penalty 不应错误加到 padding；
- 按 token 平均会让长回答贡献更多 action，按 sequence 归一化会改变长度权重，需要明确；
- reward normalization/whitening 只能用有效样本，并避免把不同任务的绝对标尺错误混合。

### 六、根本限制

GAE 和 Critic 只是统计估计，不能从一个终端分数推断某个具体推理 token 的因果贡献。缓解方法包括增加多样 rollout、step-level verifier、分段 reward、反事实/分支比较和更好的 value model。最终仍要看可验证正确率与独立人评，而不能把 advantage 图当成真实解释。

### 面试简答版

序列概率是各 token 概率的乘积，所以 \(\nabla\log\pi(y)=\sum_t\nabla\log\pi(y_t|s_t)\)，一个序列 reward 可以通过 policy gradient 更新所有生成 token。朴素 REINFORCE 给每个 token 同一 return，方差和归因误差很大；PPO 用 Critic、GAE 得到每 token advantage。实践中逐 token 放 reference KL，末端再加 RM/可验证 outcome reward；若有 PRM，可在步骤边界加入过程奖励。Prompt/padding 要 mask，EOS/截断和样本边界要正确处理，但仅凭终端奖励仍无法精确知道哪个推理步骤有功。
