## 我的答案

Perplexity（困惑度，PPL）是平均 token 负对数似然的指数。对包含 $T$ 个有效预测 token 的序列：

$$
\operatorname{PPL}(x)
=\exp\left(-\frac{1}{T}\sum_{t=1}^{T}
\log p_\theta(x_t\mid x_{<t})\right)
$$

若交叉熵使用自然对数，则 $\mathrm{PPL}=e^{\mathcal{L}}$；若使用以 2 为底的对数，则为 $2^{\mathcal{L}_{bits}}$。它可以直观地理解为模型在每一步面对的“等效分支数”，但这只是解释，不是说模型真的在 PPL 个 token 中均匀选择。

例如平均 NLL 为 $\ln 10$，PPL 为 10；平均 NLL 从 2.4 降到 2.3，PPL 从约 11.02 降到 9.97。因为指数变换单调，在相同评测协议下比较 PPL 和比较平均 NLL 排序相同。

### 正确计算方式

应先把所有有效 token 的 NLL 求和，再除以总有效 token 数：

$$
\operatorname{PPL}_{corpus}
=\exp\left(\frac{\sum_i\operatorname{NLL}_i}
{\sum_iT_i}\right)
$$

不能直接平均各文档的 PPL，因为指数是非线性的，也不能让短文档和长文档在未说明的情况下等权。PAD、SFT prompt 等被 mask 的位置不得进入分母。

评估长于 context window 的文档时，独立不重叠切块会让每块开头失去真实历史，PPL 偏高。应使用滑动窗口/stride，仅对拥有约定上下文的目标 token 计分，并明确 BOS 与跨文档边界处理。

### 为什么不同 Tokenizer 的 PPL 不能直接比较

PPL 的单位是 token。Tokenizer A 可能把一个词编码成 1 个 token，B 编成 3 个，两者的样本空间和每步条件概率不同。因此只有在相同 Tokenizer、相同文本、相同 mask 和相同上下文协议下，token PPL 才可直接比较。

跨 Tokenizer 更适合报告 bits per byte：

$$
\operatorname{BPB}
=\frac{-\sum_t\log_2p(x_t\mid x_{<t})}
{\text{原始文本 byte 数}}
$$

即便如此，若 normalization 已改变原文，也要先统一评测契约。

### 为什么 PPL 不能完整反映生成质量

#### 1. 它只评价参考文本的似然

开放式问题有很多合理回答。模型可能给参考答案概率不高，却生成另一个正确、清晰的答案；也可能对常见措辞概率很高，却事实错误或没有完成指令。

#### 2. 强烈依赖评测数据分布

新闻 PPL 低不代表代码、中文、数学或对话表现好。数据重复或 benchmark 污染还会让 PPL 异常低。必须按领域、语言、长度和时间切片。

#### 3. 不直接衡量任务目标

PPL 不能直接测：

- 事实正确性和引用忠实度；
- 数学/代码可执行正确率；
- 指令遵循、格式和工具调用；
- 安全拒答、无害性与偏见；
- 长上下文检索和多步规划；
- 人类偏好、简洁性和帮助程度。

#### 4. 平均值会掩盖长尾

大量容易 token 可掩盖实体、数字、否定词等关键位置的高 Loss。一处数字错就可能使整个答案错误，但只占平均 Loss 的很小部分。因此还要看分位数、关键 span Loss 和任务级 exact/execution metrics。

#### 5. 生成由解码策略共同决定

PPL 衡量模型分布，实际输出还受 temperature、top-p、重复惩罚和约束解码影响。低 PPL 模型配不当解码仍可生成重复或保守文本。

### 应该怎样使用

PPL 很适合做同模型族的预训练进度、过拟合、数据域适配和回归监控，因为它便宜、连续且方差较小。最终评估则应组成指标矩阵：PPL/held-out Loss + 任务正确率 + 代码/工具执行 + 事实与引用 + 安全 + 人评/偏好 + 延迟成本。

### 面试简答版

PPL 是平均 token NLL 的指数：$\exp(-\frac1T\sum_t\log p(x_t\mid x_{<t}))$，越低表示模型对该评测文本分配的平均概率越高。语料级计算要先汇总所有有效 token 的 NLL 再取指数。它依赖 Tokenizer、Normalization、context 和数据域，不同词表的 token PPL不能直接比，可考虑 bits/byte。PPL 只评价参考文本似然，无法完整衡量开放式多答案、事实性、指令遵循、代码执行、安全和解码后的体验，所以适合监控预训练，不应作为生成质量的唯一指标。
