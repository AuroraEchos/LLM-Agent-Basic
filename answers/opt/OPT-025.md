## 我的答案

随机种子只决定伪随机数流的起点，不保证所有算子、线程、设备和通信按相同顺序消费这些随机数，也不保证浮点 reduction 顺序相同。因此“设置了 seed”只是复现的必要条件之一，不是充分条件。

### 需要控制哪些随机源

- Python、NumPy、框架 CPU RNG；
- 每张 GPU 的 CUDA RNG；
- dropout、随机初始化、数据增强；
- dataloader worker 的派生 seed；
- distributed sampler 的 shuffle seed/epoch；
- tensor/model parallel 中专用 RNG stream；
- MoE routing noise、随机丢 token；
- 数据混合、Packing 和在线采样器。

各 rank 不应简单使用完全相同 seed：数据采样通常需要确定但不同的 rank 子流；Tensor Parallel 某些 dropout 则可能要求逻辑副本共享 mask。成熟框架的 RNG tracker 会按用途管理 stream。

### 算子为何不确定

GPU 大量并行线程使用 atomic add 或不同归约树。浮点加法不满足结合律：

$$
(a+b)+c\ne a+(b+c)
$$

线程调度或 kernel 算法变化会导致最后几位不同。某些 cuDNN/cuBLAS/Attention、scatter、embedding backward 和稀疏操作存在非确定性实现；编译器 autotune、融合和动态 shape 也可能选择不同 kernel。

开启 deterministic algorithms 可强制使用确定实现或在无实现时报错，但通常降低吞吐、增加显存，并非所有算子/硬件都有确定版本。TF32、FP8、快速 reduction 和异步执行也会影响数值轨迹。

### 分布式并行带来的差异

- Data Parallel 的 all-reduce 树和 bucket 顺序可能随 world size/网络拓扑变化；
- 梯度累积与 microbatch 切分改变求和顺序和 dropout mask；
- TP/PP/CP 改变矩阵分块、通信 reduction 和 pipeline 调度；
- MoE 不同容量、路由 ties 和并行拓扑会改变 token 分派；
- 某 rank 数据耗时不同可能影响异步系统顺序；
- elastic restart 或 world size 变化会改变 sampler 和 shard 边界。

即使所有结果初期只差 $10^{-7}$，非凸训练数万步后权重也可能明显不同；这不一定是 bug。更重要的是指标分布是否在可接受范围。

### 三个复现目标

#### Bitwise Reproducibility

要求参数逐位相同。通常需要相同硬件、驱动、库、world size、拓扑、kernel、数据顺序、RNG 和确定性模式，成本最高，适合单元测试和短程 debug。

#### Numerical Reproducibility

允许很小的 Loss/权重差异，短程轨迹在定义容差内。适合验证 checkpoint resume 和实现重构。

#### Statistical Reproducibility

多次独立 run 的均值、方差和结论一致。对大模型实验更现实：报告多个 seed、小规模代理实验、置信区间或至少关键结论的重复验证，而不是要求最终权重相同。

### 工程实践

1. 固定并记录 seed 层级、数据 manifest、样本顺序和 Tokenizer；
2. 锁定代码 commit、容器、驱动、库、硬件和编译配置；
3. checkpoint 保存每 rank RNG、sampler/cursor 和 optimizer/scheduler；
4. debug 模式开启 deterministic algorithms、同步执行和非有限断言；
5. 性能模式允许已验证的非确定性 kernel，但建立短程数值容差和最终指标容差；
6. 记录首批 sample IDs、初始权重 hash、每隔若干步的 Loss/grad/parameter checksum；
7. world size 或 batch 改变时，将其视为新实验配方，不宣称 bitwise 复现。

### 常见误区

- 只设置一个 global seed，却没设置 dataloader workers 和每 rank RNG；
- resume 恢复权重但未恢复 RNG/数据 cursor；
- 不同 GPU 数仍期望完全相同的数据顺序和 reduction；
- 把单次 run 的小幅指标差异都归因于代码回归；
- 为了 bitwise 确定性牺牲大量训练性能，却没有明确业务需要；
- 只说“结果差不多”，却未预先定义 Loss 和任务指标容差。

### 面试简答版

Seed 只固定伪随机流起点，还要控制 Python/NumPy/CPU/CUDA、dataloader worker、每 rank sampler 和模型并行 RNG。GPU atomic/reduction 因浮点加法不结合而可能非确定，DP/TP/PP/MoE 又会改变归约和数据顺序，所以 world size 或 kernel 变化后很难逐位一致。工程上区分 bitwise、数值容差和统计复现：debug 时锁定硬件软件并启用确定性算子；大规模训练则保存完整 RNG/数据 cursor，记录 checksum，并用多次 run 的指标分布验证结论。设置 seed 不是复现保证。
