## 我的答案

梯度裁剪主要有按值和按范数两类。大模型训练通常优先使用**全局 L2 范数裁剪**，因为它保留完整梯度方向；按值裁剪适合已知个别元素离群的特殊场景，但会独立截断坐标，更明显地改变方向。

### 按值裁剪

对每个梯度元素：

$$
g_i' = \operatorname{clip}(g_i,-c,c)
$$

优点是简单，能直接阻止单元素极值；缺点是可能大量坐标都被截断，无法控制整个向量的总长度，参数量很大时即使每个元素不超过 $c$，全局范数仍可很大。

### 按全局范数裁剪

先计算所有参与训练参数的全局 $p$-norm，通常 $p=2$：

$$
G=\sqrt{\sum_i\|g_i\|_2^2}
$$

再统一缩放：

$$
g_i'=g_i\cdot\min\left(1,\frac{c}{G+\epsilon}\right)
$$

当 $G>c$ 时所有参数乘同一系数，方向不变，仅限制长度。也可按层裁剪或做 Adaptive Gradient Clipping，但会改变层间相对权重，需明确目的。

### 正确执行顺序

混合精度、梯度累积下的典型顺序是：

```text
for each microbatch:
    forward
    scaled_loss / accumulation normalization
    backward accumulate

after final microbatch:
    unscale gradients
    detect NaN/Inf
    compute distributed global norm
    clip gradients
    optimizer.step()
    scheduler.step()   # 具体前后按框架约定
    zero_grad()
```

关键点：

- 必须在 FP16 loss scaling **unscale 后**裁剪，否则阈值也被 scale 放大；
- 应在全部 microbatch 累积完成后裁剪一次，才能等价限制 global batch 梯度；每个 microbatch 分别裁剪会改变最终方向；
- 必须在 optimizer step 前；Adam moments 应接收裁剪后的梯度；
- 分布式场景要对所有参数 shard 计算真正的全局 norm，不能每个 rank 独立用局部 norm；
- 若检测到 non-finite，动态 loss scaler 通常跳过整个 optimizer step，不能把 Inf 裁成有限值后继续。

### 分片训练中的细节

Data Parallel 梯度 all-reduce 后，各 rank 拥有相同梯度，可直接一致裁剪；FSDP/ZeRO/TP 中参数和梯度分片，需用框架提供的 distributed clip API，通过 all-reduce 聚合平方和。自己调用普通 `clip_grad_norm_` 可能只得到局部范数。

### 阈值如何选

阈值取决于模型、Loss reduction、batch/token 数和优化器。先记录不裁剪时的 global norm 分布，再选一个只处理异常尾部的起点，并监控：

- clipping 触发比例；
- 缩放系数分布；
- 裁剪前后 update norm；
- Loss spike、吞吐和最终验证质量。

如果几乎每步都强裁剪，模型的有效学习率已被隐式改变，应优先检查 LR、warmup、Loss 分母或数据。不同实验只有在梯度按相同有效 token 归一化时，阈值才可比较。

### 面试简答版

按值裁剪把每个梯度元素限制到 $[-c,c]$，能压单点异常但会改变方向且不控制总范数；LLM 通常用全局 L2 范数裁剪，超阈值时所有梯度乘同一系数，保留方向。正确顺序是所有 microbatch backward 累积完成后，先 unscale 并检查 NaN/Inf，再按所有 rank/分片的真实全局范数裁剪，随后 optimizer step。不能每个 microbatch 单独裁剪，也不能在 scaled gradients 上直接裁剪；若持续触发，应查学习率、数据和 Loss 归一化，而不是把 clipping 当根治。
