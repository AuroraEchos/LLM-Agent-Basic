## 我的答案

可精确断点续训的 checkpoint 不是只有模型权重，而是训练状态的完整快照。目标是恢复后下一个 batch、随机操作、学习率和参数更新都与未中断轨迹一致；仅能重新开始微调的“weights-only checkpoint”不能称为精确 resume。

### 通常需要保存的状态

#### 模型与优化器

- 模型参数、buffer、共享/tied weight 关系；
- FP32 master weights；
- Adam/AdamW 的 $m,v$、step counter 和参数组；
- 梯度状态：通常只在 optimizer step 边界保存；若在累积中途保存，还要保存已累计梯度和 microstep；
- EMA/SWA 权重（若使用）。

#### 调度与数值状态

- LR scheduler 的 current step、阶段和总计划；
- dynamic loss scaler 的 scale、growth tracker、overflow 历史；
- AMP/FP8 的 scale、amax history 等配方状态；
- gradient accumulation index、global tokens/updates 计数。

#### 随机与数据状态

- Python、NumPy、框架 CPU RNG；
- 每个 GPU/rank 的 CUDA RNG，以及 model/tensor parallel RNG tracker；
- distributed sampler epoch、随机排列、当前位置；
- dataloader/shuffle buffer、数据 shard、样本 offset；
- curriculum/混合采样器权重和内部状态。

#### 配置与血缘

- 模型/Tokenizer/chat template 版本；
- 训练代码 commit、依赖和容器镜像；
- 数据 manifest、过滤/打包版本和内容哈希；
- DP/TP/PP/EP/FSDP 拓扑、world size 和分片格式；
- 超参数、环境变量、硬件类型和编译/kernel 配置。

### 为什么数据状态最容易漏

如果恢复后从 epoch 开头重新 shuffle，样本会重复或跳过；总 token 相同也不等于数据顺序相同。流式数据、在线 Packing、多数据源 temperature sampling 还需要保存各源 cursor 和 shuffle buffer。

可复现设计应让每个样本有稳定 ID，并能从 `(data_version, global_sample_index, seed)` 恢复。若 dataloader 状态过大，可保存确定性计数器并快速跳过，但跳过过程中不能额外消费不同 RNG。

### 原子保存与完整性

多 rank 分片 checkpoint 的安全流程通常是：

1. 所有 rank 在约定 step 边界完成更新；
2. 各 rank 写入临时、唯一目录；
3. fsync/上传后记录每个 shard 的大小和 checksum；
4. rank 0 写 manifest，验证所有 shard 到齐；
5. 最后原子发布 `COMMITTED` 标记或重命名；
6. 只有 committed checkpoint 才允许恢复。

不能边覆盖“latest”边写，进程中断会留下半个 checkpoint。保留最近多个版本，并定期做异地/不同故障域副本。删除旧 checkpoint 前应先实际加载并验证新 checkpoint。

### 恢复时的检查

- manifest、checksum、参数名/shape/dtype 完整；
- optimizer 参数组与模型参数一一对应；
- tied weights 和 shard 映射正确；
- scheduler/LR、global step/tokens 与日志一致；
- sampler 的下一个样本 ID 是预期值；
- 所有 rank 恢复一致的 loss scale 和 collective 状态；
- 先运行一个 dry step，比较未中断 reference 的 Loss、grad checksum 和更新后参数。

若 world size 或并行拓扑改变，需要 reshard 工具；并非所有 optimizer state 格式都支持直接转换。应在灾难发生前演练，而不是届时才发现 checkpoint 只能在原集群加载。

### 可复现的层级

- **精确/bitwise resume**：相同硬件、软件、拓扑和确定性算子下逐位一致；
- **数值等价 resume**：有微小浮点差异，但 Loss 轨迹和最终指标在容差内；
- **统计复现**：不同种子或拓扑下指标分布一致。

大规模异构环境中 bitwise 很难，但至少应保证不丢/重样本、LR 和 optimizer 状态正确，并定义数值与指标容差。

### 面试简答版

精确 resume 要保存模型、FP32 master weights、Adam moments/step、scheduler、loss scaler/FP8 scale、global step/tokens、梯度累积位置、每个 rank RNG，以及 sampler、shuffle buffer 和数据 cursor；还要固定 Tokenizer、数据 manifest、代码版本和并行拓扑。多 rank checkpoint 应先写临时 shard和 checksum，manifest 验证齐全后再原子提交。恢复时校验 shape/dtype、参数组、下一个样本、LR 和各 rank 状态，并用一个 reference step 比较 Loss、梯度和参数。只保存模型权重只能重新启动训练，不能保证无缝续训。
