> **问题：** 梯度累积与增大全局 Batch Size 是否等价，哪些因素会破坏等价性？

## 我的答案

在理想条件下，梯度累积 $K$ 个 microbatch 后更新一次，可以得到与一次性把它们组成大 batch 相同的平均梯度。设每个 microbatch 有 $n_k$ 个有效 token、Loss 总和为 $S_k$：

$$
g=\nabla_\theta
\frac{\sum_{k=1}^KS_k}{\sum_{k=1}^Kn_k}
$$

若各 microbatch 的 $n_k$ 相同，可对每个 mean loss 除以 $K$ 再 backward。若长度和 loss mask 不同，简单除 $K$ 不严格等价，必须按全局有效 token 数加权。

全局 batch 的常见定义是：

$$
B_{global}=B_{micro}\times K\times N_{data\ parallel}
$$

对语言模型更准确的是 global non-pad loss tokens/update。

### 严格等价需要的条件

- 所有 microbatch 在同一组参数上 forward/backward，中间不 optimizer step；
- 梯度按相同样本/token 目标归一化；
- 最后才 all-reduce、unscale、clip 和更新一次；
- dropout/随机增强等随机操作等价或只比较期望；
- 不存在依赖 batch 统计的层；
- 数值加法顺序和精度影响可忽略。

即使满足目标等价，浮点求和顺序不同也可能产生微小数值差异，之后被非凸训练放大，所以通常说“数学上等价/统计上近似”，不保证 bitwise 相同。

### 会破坏等价性的因素

#### Loss reduction 错误

可变长度 packing、assistant-only mask 下，每个 microbatch 有效 token 数不同。平均 microbatch mean 会让短 microbatch 权重过大。应累计 loss sum 并按总有效 token 归一化，分布式也要计入所有 rank。

#### 每个 microbatch 做非线性操作

若每次 backward 后分别 gradient clipping，再相加：

$$
\operatorname{clip}(g_1)+\operatorname{clip}(g_2)
\ne\operatorname{clip}(g_1+g_2)
$$

同理，per-micro overflow 跳过、梯度噪声注入或压缩也会改变结果。裁剪应在最终累计和 unscale 后做一次。

#### Optimizer 或 scheduler 误按 micro-step 前进

Adam moments、weight decay、EMA 和 LR scheduler 应每个 optimizer update 更新一次。若每个 microbatch 都 step，等价的 global batch 已被拆成 $K$ 次参数更新，训练动力学完全不同。

#### 随机层与 batch 统计

不同 microbatch 的 dropout mask 与一次大 batch 可能不同，但分布上通常可接受；BatchNorm 的均值方差则直接随 microbatch 改变，明显不等价。LLM 常用 LayerNorm/RMSNorm，不依赖 batch 统计，因此少一个主要障碍。

#### 通信与数据顺序

DDP 可在前 $K-1$ 个 microbatch 使用 `no_sync`，最后一次 all-reduce；若每次都同步，结果近似相同但通信效率差。流水并行、MoE token routing、动态 batching 和样本 packing 可能因 microbatch 划分改变负载、capacity drop 或执行顺序，进一步破坏等价。

#### 有效 batch 变大本身改变优化

梯度累积确实实现了更大的优化 batch，梯度噪声下降，但每个 epoch 的 optimizer updates 也减少。学习率、warmup 和 decay 应按 update steps 或 tokens 重新设计，不能保持所有 step 配置不变后声称只节省显存。

### 工程代价

梯度累积降低单次激活显存，但需要 $K$ 次串行 forward/backward 才更新，增加参数读取和 kernel launch，wall-clock 未必等同一次真正的大 batch；它也不能减少模型权重、optimizer state 或累计梯度显存。优点是可以在有限显存下达到目标 global tokens/update，并减少 DDP 同步频率。

### 面试简答版

理想情况下，$K$ 个 microbatch 在同一参数上累积梯度、最后只更新一次，等价于一个更大 batch；全局 batch 是 microbatch × 累积步数 × 数据并行数。严格等价要求按全局有效 token 归一化，尤其是可变长和 loss mask 数据；unscale、全局裁剪、Adam/weight decay、scheduler 都只能在累积完成后执行一次。Dropout、浮点求和、BatchNorm、MoE routing、per-micro clipping/overflow 和错误 scheduler 会破坏等价。它节省激活显存但增加串行计算，不减少模型和 optimizer state 显存。
