## 我的答案

三者都试图减少单个训练 step 的参数噪声，但方式不同：EMA 在训练中维护参数的指数滑动平均；普通 Weight Averaging 对若干参数点做算术平均；Checkpoint Averaging 是后者的工程实现——读取多个已保存 checkpoint 后平均。它们可用于 LLM，但不是必然提升，也不是大模型预训练的默认必需项。

### EMA

每次 optimizer update 后：

$$
\theta_t^{EMA}=\beta\theta_{t-1}^{EMA}
+(1-\beta)\theta_t
$$

$\beta$ 越大，平均窗口越长；有效窗口粗略约为 $1/(1-\beta)$ 个 update。也可按训练进度使用 decay schedule，并对初期偏差做校正。

优点是在线平滑，不需要保存很多 checkpoint，常能降低 SFT、小数据或噪声训练的参数波动。代价是额外保存一整份权重，超大 LLM 即使分片也会显著占用显存/主存和通信；若模型持续快速学习，EMA 会滞后于当前分布。

训练时通常仍用原始参数继续优化，评估/导出时临时换成 EMA 参数。不能把 EMA 权重与原 optimizer moments 随意组合后继续训练，因为二者不对应同一优化轨迹。

### Weight / Checkpoint Averaging

对 $K$ 个 checkpoint：

$$
\bar\theta=\frac1K\sum_{k=1}^{K}\theta^{(k)}
$$

可取训练后期相邻 checkpoint、学习率周期中的多个点，或赋予不同权重。若这些参数位于同一宽平 basin，平均点可能有更平滑的 Loss、更稳定的泛化；若来自距离很远的训练阶段或不同 basin，线性中点可能 Loss 很高。

Checkpoint averaging 的优势是不增加训练时显存，只增加离线读取、FP32 累加和写出成本。平均时应：

- 模型架构、Tokenizer、参数名和 shape 完全一致；
- 处理 tied weights，平均后保持共享关系；
- 用 FP32/更高精度累加，再转目标 dtype；
- 只平均模型权重，不把 Adam moments 简单平均；
- 对量化模型先在高精度权重上平均，再重新校准/量化；
- 在分片 checkpoint 中正确匹配 shard，避免一次聚合导致 CPU OOM。

### 为什么同一路径较安全

同一模型连续训练的 checkpoint 参数语义和隐藏单元排列一致，平均通常有意义。独立随机初始化的两个模型存在神经元/通道置换对称，即使各自性能好，直接逐元素平均也可能破坏功能。所谓 model soup 通常选择从同一预训练初始化微调出的模型，并用验证集筛选组合；不同架构或不同词表不能直接平均。

### 在 LLM 中何时可能有效

- 小规模 SFT/领域微调，训练后期 checkpoint 有波动；
- 学习率较高、验证指标在相邻保存点震荡；
- 多任务微调希望平滑局部过拟合；
- 维护 teacher/target 网络，EMA 提供更稳定目标；
- LoRA adapter 来自同一 base、相同结构且轨迹接近，可先验证 adapter 平均。

### 为什么预训练中未必值得

- 模型巨大，EMA 多一份参数的内存、带宽与 checkpoint I/O 昂贵；
- 长预训练配合 decay 后，最后 checkpoint 本身可能已很稳定；
- 模型在训练后期仍沿数据 curriculum 移动，旧 checkpoint 代表不同分布，平均会稀释新能力；
- 权重平均提高平均 Loss 不代表事实、代码或安全指标都提升；
- 与 checkpoint averaging 相比，延长训练或设计更好的 LR decay 可能更直接。

### 如何验证

先选择训练后期若干 checkpoint，计算参数距离和它们之间线性插值的验证 Loss：

$$
\theta(\alpha)=(1-\alpha)\theta_a+\alpha\theta_b
$$

若中间 Loss 没有明显 barrier，再尝试平均。最终同时比较 held-out Loss、分领域下游任务、校准、安全、生成风格和推理吞吐；EMA/平均不会改变架构，所以推理成本通常不变。

还应保留原始 checkpoint，平均是派生产物而非不可逆覆盖。若平均模型要继续训练，应新建 optimizer state并使用短 warmup，或从某个原 checkpoint 的完整状态续训。

### 面试简答版

EMA 用 $\theta_{EMA}\leftarrow\beta\theta_{EMA}+(1-\beta)\theta$ 在线平滑，适合噪声较大的 SFT，但要额外保存一份大模型权重且会滞后。Checkpoint Averaging 离线平均训练后期若干 checkpoint，不增加训练显存；只有参数来自同一初始化、同一结构且位于相近 basin 时通常才安全，独立模型不能随便逐元素平均。平均时用 FP32、保持 tied weights，只平均模型参数而非 Adam moments，量化应在平均后重做。LLM 是否受益必须以 Loss 和多维下游评测验证，预训练中其存储成本可能高于收益。
