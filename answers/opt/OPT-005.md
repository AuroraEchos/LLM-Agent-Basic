## 我的答案

Loss Mask 决定哪些目标 token 产生监督；Attention Mask 决定每个 token 能看见哪些上下文。多轮对话与 Packing 同时出现时，两种 mask 都必须正确：前者防止模型学习不该预测的角色内容，后者防止不同样本互相泄漏。

### 多轮对话的目标

假设模板序列是：

```text
<system> S </system>
<user> U1 </user>
<assistant> A1 </assistant>
<user> U2 </user>
<assistant> A2 </assistant>
```

常见 assistant-only SFT 规则是：

```text
token 区域             loss mask
system / user 内容        0
角色开始标记              0（取决于模板）
assistant 回答 A1/A2      1
assistant 结束/EOS        1
padding                   0
```

让回答结束符参与 Loss 很重要，否则模型没学到何时结束。assistant 角色起始标记是否监督要看推理协议：若它由服务端模板固定插入，通常不要求模型生成；若模型需要在多角色序列中生成该标记，则应监督。规则必须和线上模板一致。

有些任务会监督全部文本做“full-sequence loss”，这能保留语言建模信号，但模型也会学习生成 user/system 内容，且大量 prompt token 可能淹没回答监督。选择应作为训练目标明确配置，不能由数据整理脚本偶然决定。

### 正确处理 shift

模型在位置 $t$ 的 logits 预测 `input_ids[t+1]`。推荐先构造与输入等长的 labels：

```python
labels = input_ids.clone()
labels[not_assistant_or_padding] = -100

loss = cross_entropy(
    logits[:, :-1, :].reshape(-1, vocab_size),
    labels[:, 1:].reshape(-1),
    ignore_index=-100,
)
```

若 assistant 的第一个内容 token 位于位置 $j$，监督它的是位置 $j-1$ 的 logits。直接在 `logits` 位置上画 mask 很容易错一位。应通过已 tokenized 的角色边界或模板返回的 span 构造 mask，不要对解码后的字符串用脆弱的子串搜索。

### 工具调用与 observation 怎么处理

一种常见策略是：

- assistant 生成的 tool call：mask=1；
- tool/environment 返回的 observation：mask=0，但允许后续 assistant attend；
- 最终 assistant 回答：mask=1；
- system 和 user：mask=0。

如果目标是训练模型模拟工具结果，才监督 observation；普通 Agent 模型不应学习编造本应由外部工具提供的返回值。工具错误消息也通常作为输入上下文，而非模型输出标签。

### Packing 多个样本

将样本 A、B、C 放入同一物理 block 后，需要 segment IDs，例如：

```text
tokens:   [A A A EOS | B B EOS | C C C PAD]
segment:  [0 0 0  0  | 1 1  1  | 2 2 2  -1]
```

Loss Mask 由每段内部的角色规则拼接，PAD 为 0；但这还不够。若不希望 B 看到 A，应使用 block-diagonal causal mask：

$$
M_{ij}=1
\iff \operatorname{seg}(i)=\operatorname{seg}(j)
\ \text{且}\ j\le i
$$

或向 varlen Attention 内核提供每段 cumulative lengths。仅插入 EOS 并不能阻止跨文档 Attention。

position IDs 可在每个 segment 内从 0 重置，使 packed 结果更接近独立训练；也可以连续位置训练位置泛化，但必须与模型设计和推理一致。无论哪种选择，都要对每段 BOS/EOS、RoPE position 和最大长度做测试。

### 文档拼接式预训练的不同选择

通用预训练有时故意允许随机文档在 EOS 后跨文档可见，此时普通 causal mask 合法；它与“样本隔离的 packing”是两个不同目标。SFT、偏好数据和 benchmark 样本一般应隔离，否则可能出现：

- 后一样本从前一样本答案获得提示；
- 一个用户会话读取另一个会话的敏感内容；
- 训练 Loss 虚低，线上独立请求无法复现；
- 梯度错误地学习跨样本关系。

### 截断策略

截断可能留下半个 assistant 回答或丢失 EOS。可选策略包括丢弃超长样本、保留完整的最后若干轮、按消息边界切块，或明确训练 continuation。不能只按 token 长度硬切后仍把残缺片段当完整答案。

若一个 packed block 没有任何有效 assistant token，应丢弃或跳过 Loss，防止分母为 0。对超长 prompt + 极短回答，还应限制其比例，避免耗费大量 Attention 却只产生少量监督 token。

### Reduction 与验证

Loss 应除以全局有效 label token 数：

$$
\mathcal{L}=\frac{\sum m_{b,t}\ell_{b,t}}{\sum m_{b,t}}
$$

分布式训练和梯度累积要汇总 numerator/denominator，不能简单平均每个 packed block 的 mean。

建议构造极小 golden case，逐 token 打印：token 字符串、role、segment ID、position ID、label、loss mask，并验证：

1. user/system/PAD 不产生梯度；
2. assistant 首 token 和 EOS 被正确预测；
3. 不同 segment 的 Attention 权重严格不可达；
4. 单独训练与 pack 后的有效 token Loss 在 dropout 关闭时一致；
5. 不同 batch/rank 划分后的全局 Loss 一致。

### 面试简答版

多轮 SFT 通常只监督 assistant 生成的回答和结束 token，system/user 以及工具 observation 只作为可见上下文、不计算 Loss；tool call 若由 assistant 生成则要监督。先在与 `input_ids` 等长的 labels 上把非监督位置设为 `-100`，再用 `logits[:, :-1]` 对齐 `labels[:, 1:]`，避免错一位。Packing 时按 segment 拼接 loss mask，并额外使用 block-diagonal causal attention 或 varlen 边界隔离样本，必要时每段重置 position IDs；EOS 不能代替隔离 mask。最终 Loss 按全局有效 token 数归一化，并用逐 token golden test 验证 pack 前后结果一致。
