## 我的答案

Label Smoothing 不把真实类别的目标分布设为严格 one-hot，而是把一小部分概率质量分配给其他类别。词表大小为 $V$、真实 token 为 $y$ 时，一种定义是：

$$
q'_k=(1-\varepsilon)\mathbf{1}[k=y]+\frac{\varepsilon}{V}
$$

此时真实类概率为 $1-\varepsilon+\varepsilon/V$。另一种实现只在 $V-1$ 个错误类别间分配 $\varepsilon$；两种约定略有不同，使用框架接口时要确认定义。

损失变成：

$$
\mathcal{L}_{LS}
=-\sum_{k=1}^{V}q'_k\log p_k
=(1-\varepsilon)(-\log p_y)
+\varepsilon\left(-\frac1V\sum_k\log p_k\right)
$$

对 logit $z_k$ 的梯度仍是：

$$
\frac{\partial\mathcal{L}}{\partial z_k}=p_k-q'_k
$$

所以模型不再被推动到 $p_y\to1$、其他 $p_k\to0$ 的极端 one-hot 分布。

### 可能的收益

- 抑制过度自信，改善部分分类任务的校准；
- 作为正则化减少有限标签数据上的过拟合；
- 标签有噪声时，降低把单个观测标签当成绝对真值的强度；
- 防止 logits 无限制拉开，某些训练设置下更稳定。

在机器翻译、图像分类和中小规模监督任务中，这些收益较常见。

### 为什么 LLM 预训练中不总使用

#### 1. 语言模型的词表很大

当 $V$ 为数万到十几万时，把平滑质量均匀分给所有错误 token，等于同时奖励大量在当前上下文中不可能、语法错误甚至是控制符的 token。这种先验缺乏语言结构。

例如真实 next token 是数字 `4`，将概率平均分给 `<pad>`、中文、代码符号和所有 byte token，并不能表达“另一个合理答案”。自然语言的多解性应由数据条件分布或教师软标签表达，而不是均匀噪声。

#### 2. 它有意阻止真实 token 概率接近 1

标准 NLL/PPL 正是预训练的优化和评测目标。Label smoothing 引入偏置，常会使训练/验证 NLL 和 PPL 变差，即使某些下游泛化可能改善。大规模预训练本身有海量多样数据，传统小数据正则化收益可能较弱。

#### 3. 会改变生成概率和蒸馏信号

平滑后的模型概率可能更平、校准含义改变，并影响 sampling、beam search 和知识蒸馏。若后续需要用 logits 做置信度、reranking 或 speculative verification，应单独验证。

#### 4. 稀疏高效 Loss 可能变复杂

普通 one-hot cross entropy 只需要目标 token ID，易用融合 kernel 和词表并行计算。均匀 smoothing 仍可代数化高效实现，但自定义非均匀软标签会增加显存、通信和实现复杂度。

### 什么时候仍值得尝试

- SFT 数据较小、标签有噪声或模型明显过拟合；
- 输出是有限类别/特殊 token，而不是开放词表建模；
- 观察到严重过度自信，且校准是产品目标；
- 使用知识蒸馏的教师分布，提供比均匀分配更有语义的 soft targets；
- 通过消融确认任务质量收益大于 PPL 和生成锐度损失。

更有结构的替代方案包括：置信度加权、样本质量权重、教师 logits 蒸馏、只在合理候选集合内平滑，或用 dropout、weight decay、更多去重数据做正则化。

### 需要避开的实现坑

- `ignore_index` 的 PAD/prompt token 不能参与平滑项；
- 特殊控制 token 是否进入均匀分布要明确；
- 混合精度下使用稳定的 log-softmax；
- 日志中区分 smoothed training loss 与原始 hard-label NLL，否则 PPL 不可解释；
- 比较实验要保持数据、token 数、学习率和训练计算一致。

### 面试简答版

Label Smoothing 将 one-hot 目标改成 $(1-\varepsilon)$ 的真实类质量加少量其他类质量，使梯度从 $p-y$ 变成 $p-q'$，可抑制过度自信并正则化小数据训练。LLM 预训练中不总使用，因为词表巨大，均匀奖励所有错误 token 缺乏语义；它还会有意压低真实 token 概率，使 NLL/PPL 变差，而海量预训练数据已提供较强多样性。它更适合小规模有噪 SFT、有限标签任务或校准场景，使用时应屏蔽 PAD/prompt，并另外记录未平滑 NLL。
