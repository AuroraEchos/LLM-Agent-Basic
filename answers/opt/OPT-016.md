> **问题：** Batch Size、学习率和训练 token 数之间通常如何联动调整？

## 我的答案

三者通过“每次更新用了多少 token、总共做多少次更新”联系起来。设每个 optimizer step 的全局有效 token 数为 $B_{tok}$，总训练 token 为 $D$，则更新步数约为：

$$
S=\frac{D}{B_{tok}}
$$

其中：

$$
B_{tok}approx
N_{DP}\times B_{micro}\times K_{acc}\times
\text{每条样本平均有效 token 数}
$$

对变长 Packing 和 SFT，应使用真正参与 Loss 的 non-pad token 数，而不只是 sequence 数。

### Batch Size 改变了什么

增大 batch 会降低随机梯度方差，让方向更稳定，并提高数据并行吞吐；但固定总 token 时，optimizer update 次数会减少。超过问题相关的 critical batch size 后，继续增大 batch 的样本效率收益很小，只是用更多硬件换更短 wall time，甚至可能降低泛化或优化效率。

小 batch 梯度噪声大、更新次数多；大 batch 梯度更准，但每个样本获得的参数反馈频率下降。因此不能只改 batch 而保持“以 step 为单位”的 warmup、decay、保存和评测配置不变。

### 学习率如何随 Batch 调整

常见启发式有：

#### 线性缩放

$$
\eta' = k\eta,\qquad B'=kB
$$

它希望一个大 batch 更新近似替代 $k$ 个小 batch 更新的累计幅度，常配合更长 warmup。适用于一定范围，不是无限成立。

#### 平方根缩放

$$
\eta'=\sqrt{k}\eta
$$

更保守，来自梯度噪声随 batch 增大约按 $1/\sqrt{B}$ 下降的直觉。Adam/AdamW 的自适应尺度使理论关系更复杂，LLM 配方通常从已有缩放规律和 LR sweep 决定，而非机械选择一条公式。

当 batch 已超过 critical batch，学习率继续线性放大容易 loss spike；应固定或缓慢提高 LR，并接受样本效率下降。

### 总训练 token 变化时

增加 $D$ 通常意味着：

- 模型会看到更多独立数据，允许更充分收敛；
- scheduler 的训练终点、stable/decay 区间需要延长；
- 数据重复 epoch 和过拟合风险需要重新计算；
- weight decay 的累计作用与 $\sum_t\eta_t$ 变化；
- 若模型规模也变化，应结合 scaling law 重新分配参数和数据。

若只把训练 token 翻倍，却沿用原 cosine 总步数，学习率可能在一半数据时已经接近 0；若直接把 cosine 拉长，前半段 LR 轨迹又与旧实验不同。WSD 的 stable 阶段更便于追加 token，但最终仍要重新设计 decay。

### 一个具体例子

原配置每步 2M effective tokens，总计 200B tokens：

$$
S=200B/2M=100{,}000\text{ steps}
$$

若 global batch 增到 4M、总 token 不变，只剩 50,000 次更新。原来 2,000-step warmup 对应 4B token；若仍用 2,000 step，新 warmup 变成 8B token。要保持相同的 token 进度，应改为约 1,000 step。评测、checkpoint 和 decay milestone 也应按 token 重新换算。

### 还会破坏简单缩放的因素

- 序列长度改变了 Attention 计算和每样本 token 数；
- variable-length batch 的有效 token 波动；
- 梯度累积与真正大 batch 在 dropout、MoE routing、clipping 上不完全等价；
- Adam 的 $\beta_1/\beta_2$ 以 update step 计时，batch 变化后每个时间常数覆盖的 token 量变化；
- 每步 weight decay、EMA 和 scheduler 都随 update 次数改变；
- 数据分布、重复度和难度随训练阶段变化。

因此更稳妥的实验单位是：global loss tokens/update、累计训练 tokens、真实 FLOPs 和 optimizer updates 四者同时记录。

### 调参流程

1. 先在硬件上选吞吐/显存较优的 microbatch 与并行方式；
2. 以目标 global tokens/update 设置梯度累积；
3. 从成熟配置按线性或平方根规则给 peak LR 初值，做短程 sweep；
4. 按 warmup tokens 而不是只按百分比设计 warmup；
5. 对齐总训练 token，重算 scheduler、评测和保存间隔；
6. 观察训练/验证 Loss、梯度噪声、clip 率、update/weight ratio 和下游质量；
7. 对大 batch 检查是否已过 critical batch，比较达到同 Loss 所需的总 token/FLOPs。

### 面试简答版

全局有效 batch 应按每个 optimizer update 的 non-pad loss tokens 计算，总更新数是 $S=D/B_{tok}$。增大 batch 会降低梯度噪声但减少固定 token 预算下的更新次数；学习率可先尝试线性缩放或更保守的平方根缩放，再用 LR sweep 验证，超过 critical batch 后不能继续机械放大。Batch 改变时，warmup、decay、Adam 时间常数、weight decay 和 checkpoint 间隔都应按 token 进度重算；训练 token 增加时也要延长有效学习率区间并检查重复数据。工程上应同时记录 tokens/update、总 tokens、updates 和 FLOPs。
