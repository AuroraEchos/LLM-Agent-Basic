## 我的答案

Decoder-Only LLM 用左侧上下文预测下一个 token。给定序列：

$$
x=(x_0,x_1,\ldots,x_{T-1})
$$

自回归分解为：

$$
p_\theta(x)=\prod_{t=1}^{T-1}p_\theta(x_t\mid x_{<t})
$$

训练目标是最大化真实序列的似然，等价于最小化逐 token 负对数似然，也就是 one-hot 标签下的交叉熵。

### 从 logits 到损失

模型输入整个序列，经过 causal mask 后，在每个位置 $t$ 输出对词表大小 $V$ 的 logits：

$$
Z\in\mathbb{R}^{B\times T\times V}
$$

$Z_{b,t}$ 只能利用 $x_{b,\le t}$，因此它应预测 $x_{b,t+1}$。训练时需要 shift：

```text
input:   [BOS, 我, 爱, AI, EOS]
logits:    ↓    ↓   ↓   ↓
label:   [我,   爱, AI, EOS]
```

也就是：

```python
shift_logits = logits[:, :-1, :]   # [B, T-1, V]
shift_labels = input_ids[:, 1:]    # [B, T-1]
```

对单个有效标签 $y_{b,t}$：

$$
\ell_{b,t}
=-\log\frac{\exp Z_{b,t,y_{b,t}}}
{\sum_{v=1}^{V}\exp Z_{b,t,v}}
$$

实现通常使用融合的 cross-entropy/log-softmax，通过减去最大 logit 或 log-sum-exp 保持数值稳定，不应先显式 `softmax` 再取 `log`。

### Loss Mask 与归一化

并非所有位置都参与损失。令 $m_{b,t}\in\{0,1\}$ 表示该标签位置有效，则：

$$
\mathcal{L}
=\frac{\sum_{b,t}m_{b,t}\ell_{b,t}}
{\sum_{b,t}m_{b,t}}
$$

常见被屏蔽位置包括 padding、SFT 中的 system/user prompt，以及不希望监督的工具返回。通常给对应 label 写 `ignore_index=-100`，cross entropy 会跳过它。

注意 mask 要与**预测目标**对齐。若原始 `input_ids[:, j]` 是需要学习的 assistant token，那么参与损失的是 `logits[:, j-1]`。最安全的方式是先为每个 input token 构造 label/ignore mask，再统一做 shift，避免 off-by-one。

EOS 通常要参与 Loss，使模型学会结束；PAD 要屏蔽。BOS 没有前一位置预测它，通常自然落在被移除的第一个 label 外。

### Causal Mask 和 Loss Mask 不一样

- causal/attention mask 决定某个位置能**看见哪些输入**；
- loss mask 决定某个位置预测错了是否**产生梯度**。

一个 user token 可以不计算 Loss，但后面的 assistant token仍应能关注它。只做 loss mask 不会阻止不同 packed 样本互相看见；隔离样本需要额外的 block-diagonal attention mask 或 varlen 边界。

### 分布式与梯度累积中的正确 reduction

不同 microbatch 或 GPU 的有效 token 数可能不同。若每个 rank 先独立取 mean，再平均各 rank Loss，会让“有效 token 少的 rank”权重过大。正确目标是全局 token 加权：

$$
\mathcal{L}_{global}
=\frac{\sum_r S_r}{\sum_r M_r}
$$

$S_r$ 是该 rank 的有效 token loss 总和，$M_r$ 是有效 token 数。梯度累积同理：应使各 microbatch 最终按有效 token 数贡献，而不是不加区分地平均 microbatch mean。

### 训练和日志中的常见坑

- logits 与 labels 没有 shift，模型被训练成复制当前 token；
- PAD 与 EOS 共用 ID 后，按 ID 屏蔽导致真实 EOS 也不参与 Loss；
- 整段 prompt 误算 Loss，SFT 模型更倾向复述用户；
- 所有 label 都被 mask，分母为 0 产生 NaN；
- 长序列按 token mean 时自然贡献更多 token；若先按序列 mean 再平均，优化目标会改变；
- 记录 Loss 时分母包含 padding，导致指标虚低；
- tensor parallel 的 vocab shard 未正确合并全局 log-sum-exp。

### 面试简答版

Decoder-Only LLM 将序列概率分解为 $\prod_t p(x_t\mid x_{<t})$，在位置 $t$ 的 logits 预测位置 $t+1$ 的 token，所以训练要用 `logits[:, :-1]` 对齐 `input_ids[:, 1:]`。每个有效 token 用 log-softmax 负对数似然，最后除以有效 loss token 数；PAD、prompt 等位置用 loss mask/ignore index 屏蔽，EOS 通常保留监督。Attention mask 决定能看什么，loss mask 决定哪里产生梯度，二者不能混淆。分布式和梯度累积时应做全局 token 加权 reduction，避免不同 rank 有效 token 数不同造成偏差。
