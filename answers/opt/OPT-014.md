## 我的答案

混合精度训练让大部分矩阵计算使用 FP16/BF16 提高吞吐、降低显存，同时把容易累积误差或决定更新的状态保留在 FP32。Master Weight、Loss Scaling 和溢出检测分别解决“小更新被舍入”“小梯度下溢”和“错误更新污染参数”三个问题。

### FP32 Master Weight

假设模型 forward 使用 FP16 参数副本 $\theta_{16}$，优化器维护 FP32 主权重 $\theta_{32}$：

```text
FP16/BF16 model weight → forward/backward
gradient → unscale / cast to FP32
update FP32 master weight and optimizer moments
cast updated master weight back to low precision
```

若参数值约为 1，而单步更新远小于 FP16/BF16 在该数量级的间隔，直接做低精度加法可能完全舍入掉。FP32 master weight 能累积这些小更新。Adam 的 $m,v$ 通常也用 FP32，避免长时间移动平均误差。

现代实现可能没有显式“双份可见权重”，而由 optimizer/框架维护高精度状态；某些 BF16 配方直接以 FP32 参数做更新、计算时 autocast。关键是更新累加精度，而不是 API 名称。

### Loss Scaling

FP16 的小梯度可能在表示或算术中下溢为 0。将 Loss 乘 scale $S$：

$$
\mathcal L'=S\mathcal L,qquad
g'=\nabla\mathcal L'=Sg
$$

使梯度进入 FP16 可表示范围。optimizer 前再除回去：

$$
g=g'/S
$$

数学上更新不变。静态 scaling 固定 $S$，简单但难兼顾所有阶段；动态 scaling 自动调节，常从较大值开始：若连续若干步无溢出则增大，检测到溢出则减小并跳过该步。

BF16 指数范围接近 FP32，一般不需要 loss scaling；FP8 则使用更细粒度的张量 scale/amax 机制，不能简单等同于一个全局 Loss scale。

### 溢出检测与正确顺序

backward 后检查所有参数梯度是否包含 NaN/Inf。典型流程：

1. scaled loss backward，跨 microbatch 累积；
2. 所有 rank 汇总 found-inf 状态；
3. 用 $S$ unscale gradients；
4. 若任一 rank 非有限，所有 rank 一致跳过 optimizer/scheduler step，并降低 $S$；
5. 否则在未缩放梯度上做 global norm clipping；
6. optimizer 更新 FP32 master weights/moments，再更新低精度计算权重；
7. 按规则增长 scale，并清空梯度。

若某 rank 跳步、其他 rank 更新，会使模型副本立刻分叉。scheduler 是否在 overflow 跳步时前进也要统一；通常只有真实 optimizer update 才前进。

### 常见错误

- scaled gradient 未 unscale 就 clipping，阈值失真；
- 每个 microbatch 都 unscale/更新 scaler，破坏累积；
- 检测到 Inf 仍更新 Adam moments，使 optimizer 状态永久污染；
- 只检查总 Loss，不检查梯度；Loss 有限时 backward 仍可能 overflow；
- BF16 因范围大就把 softmax、norm、reduction 全降成 BF16；
- resume 只载模型，丢失 master weights、moments 和 scaler 状态，无法精确续训。

### 面试简答版

Master Weight 用 FP32 保存并累积参数更新，避免小更新在 FP16/BF16 权重上被舍入掉；Adam moments 也常保留 FP32。FP16 Loss Scaling 先把 Loss 和梯度乘 $S$ 防止小梯度下溢，optimizer 前再 unscale，数学更新不变。动态 scaler 若检测任一 rank 的梯度有 NaN/Inf，就让所有 rank 跳过 optimizer/scheduler 更新并降低 scale；正常时先 unscale、再全局范数裁剪、最后更新主权重。BF16 通常不需 loss scaling，但关键 reduction 和状态仍需高精度。
