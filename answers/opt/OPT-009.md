> **问题：** Warmup 为什么有助于大模型稳定训练，步数应如何选择？

## 我的答案

Warmup 是在训练最初一段时间把学习率从较小值逐步升到 peak learning rate。最常见的线性形式为：

$$
\eta_t=\eta_{\max}\frac{t}{T_w},qquad 0\le t\le T_w
$$

之后再进入恒定、cosine、linear 或 WSD 阶段。Warmup 的作用不是提高最终理论表达能力，而是降低训练初始状态与大步长不匹配造成的不稳定。

### 为什么初期最危险

#### Adam 的统计量尚未稳定

训练开始时 $m_0=v_0=0$，虽有 bias correction，但 mini-batch 梯度分布、不同层尺度和二阶矩估计仍处于快速变化期。直接使用 peak LR 可能在少数坐标产生过大的 update/weight ratio。

#### 随机初始化的激活和残差还未自适应

深层 Transformer 各层的激活、Attention logits 和残差尺度在早期可能不均衡。大更新会放大异常层，形成 loss spike、梯度爆炸或低精度 overflow。Warmup 让模型在小步长下先进入较稳定区域。

#### 大 batch 配方需要更高 peak LR

增大全局 batch 后常相应提高 peak LR；若从第 1 步直接应用，高相似梯度会产生一次很大的确定性更新。Warmup 让优化器逐渐适应新的 batch 和步长尺度。

#### 低精度和并行会放大故障代价

BF16/FP16、深网络和大规模数据并行下，一次异常更新可能使多个 rank 同时产生 Inf/NaN。Warmup 提供了观察梯度、激活和数据异常的缓冲期，但它不能修复错误 mask、坏数据或数值 bug。

### Warmup 步数如何选择

没有固定的“必须 5%”。应从成熟配方起步，再根据以下量调整：

1. **按优化器更新步或训练 token 定义**：同样 2000 step，在 global batch 改大 8 倍后已看过 8 倍 token；跨实验最好同时报告 warmup steps 和 warmup tokens；
2. **模型规模与深度**：更深、初始化更敏感的模型可能需要更保守 warmup；
3. **peak LR 与 batch size**：峰值越激进，通常需要更长或更平滑的升温；
4. **优化器参数**：较长 $\beta_2$ 记忆、不同 epsilon 会改变早期尺度估计；
5. **训练总时长**：短 SFT 若 warmup 占比过大，模型大部分时间都没到有效 LR；超长预训练则用少量百分比也可能太长；
6. **初始化与架构**：Pre-Norm、残差缩放、已有 checkpoint 微调通常比从零 Post-Norm 更稳定；
7. **Loss/梯度曲线**：用小规模试跑观察 peak 前是否出现 update norm 或 clipping 激增。

实践起点常是总更新步的低个位数百分比或固定的数百到数千步，但这只是搜索起点。更可靠的选择是做短程 sweep：例如不同 warmup token 数，在相同 peak LR 下比较早期 Loss、梯度范数、被裁剪率、最大 update/weight ratio 和吞吐故障。

### 太短与太长的表现

Warmup 太短：

- 初期 Loss spike 或瞬间 NaN；
- 梯度裁剪频繁触发；
- 某些层权重范数突然漂移；
- 多次随机种子稳定性差。

Warmup 太长：

- 前期学习率过低，浪费 token 预算；
- 短训练尚未充分学习就开始 decay；
- 虽然曲线平滑，最终验证 Loss 反而较高。

若延长 warmup 才能掩盖持续的周期性 spike，应继续排查数据、精度、梯度同步和优化器，而不是无限延长。

### Resume 和继续预训练的边界

从 checkpoint 精确断点续训时，应恢复 optimizer 和 scheduler 状态，不能重新 warmup，否则学习率轨迹改变。若只加载模型权重开启新的 DAPT/SFT，优化器状态被重置，通常使用新的短 warmup；但预训练好的权重也可能被过大的初始 LR 破坏，因此 warmup 仍有价值。

改变 global batch、序列长度或数据混合时，即使恢复权重，也应评估是否需要短暂的 LR transition，而不是机械复用原 schedule。

### 面试简答版

Warmup 在训练初期把学习率从小值升到 peak LR，给 Adam moments、各层激活和残差尺度一个稳定过程，降低深层模型、大 batch 和低精度下的早期大更新、loss spike 与 NaN 风险。步数没有固定比例，要结合 peak LR、global batch、模型深度、$\beta_2$、初始化和总训练时长选择，并同时按 steps 与 tokens 报告。用短程 sweep 看 Loss、梯度裁剪和 update/weight ratio：太短会不稳，太长会浪费 token。精确 resume 应恢复 scheduler 而非重新 warmup；只载权重的新阶段通常重新设计一个较短 warmup。
