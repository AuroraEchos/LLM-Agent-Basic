## 我的答案

Activation Checkpointing（也叫 Gradient Checkpointing）用额外计算换显存：前向时不保存所有中间激活，只保存若干检查点；反向需要某段激活时，从最近检查点重新执行该段 forward，再计算梯度。

它与训练 checkpoint 文件不是一回事：前者是单个训练 step 内的显存优化，后者是用于故障恢复的模型/优化器持久化状态。

### 为什么训练要保存激活

反向传播计算某层参数梯度和输入梯度时，需要该层 forward 的输入、Attention/MLP 中间量等。若网络有 $L$ 层，全部保存的 activation memory 粗略随：

$$
M_{act}=O(B\cdot S\cdot H\cdot L)
$$

增长，其中 $B$ 是 microbatch、$S$ 是序列长度、$H$ 是隐藏维。Attention 是否物化 $S^2$ 矩阵、使用何种 fused kernel 会改变常数。长上下文下，激活经常比参数本身更快成为瓶颈。

### Checkpointing 的过程

以连续若干层为一段：

```text
Forward:
  保存段输入 h0
  执行 layer 1..k，但丢弃段内中间激活
  保存段输出/下一个检查点

Backward:
  从 h0 重算 layer 1..k forward
  取得临时激活并立即反向
  释放这一段
```

极端情况下每层只保存输入，反向时每层重算一次；也可每 $k$ 层设检查点。经典链式网络采用约 $\sqrt L$ 个分段时，保存的边界和单段临时激活都约为 $O(\sqrt L)$ 层量级，但现代 Transformer 实际收益取决于层内算子和框架调度。

### 能省什么、不能省什么

能省：Attention、MLP、Norm 等用于 backward 的中间 activation，以及部分临时 buffer。

不能直接省：

- 模型参数和梯度；
- Adam 的一阶、二阶状态与 master weights；
- 通信 buffer、CUDA context 和不可重算的长期状态；
- 当前检查点边界及重算段所需的临时激活。

所以模型连权重/optimizer state 都放不下时，需要 FSDP/ZeRO、offload 或低精度优化器，Activation Checkpointing 单独不够。

### 计算与系统代价

- backward 前要额外执行部分 forward，step 时间上升；全层重算常带来显著但非简单固定比例的开销；
- 重算增加 GEMM、通信或随机状态管理，可能降低 MFU；
- 分段太细会增加框架/kernel launch 开销，太粗则显存节省有限；
- 与流水并行结合时，重算可能改变 stage 时间和 bubble；
- CPU offload、FlashAttention、sequence parallel 同时使用时，瓶颈可能转移，收益需实测。

由于 forward 通常比完整 forward+backward 便宜，重算并非让总计算翻倍。真实开销应测 tokens/s，而不是仅用理论 FLOPs 判断。

### 随机性和正确性

重算必须与原 forward 在数学上相同。Dropout 等随机算子要保存/恢复 RNG 状态，否则 backward 使用的 mask 与原 forward 不一致。框架的 checkpoint API 通常能 preserve RNG，但会有额外开销。

还应避免 checkpoint 段内有不可重复副作用，例如：

- 修改全局状态或缓存；
- 计数器/日志重复写入；
- 有状态随机采样未保存 RNG；
- in-place 修改重算输入；
- 第一次和重算时依赖不同的 autocast/context。

不同框架还有 reentrant/non-reentrant 实现、提前停止重算等差异，需用梯度一致性测试验证。

### 选择粒度

常见策略：

- 每个 Transformer block checkpoint：简单、节省大；
- 只 checkpoint MLP 或 Attention：对显存热点做 selective recomputation；
- 不重算便宜但占存小的 Norm，重算占存大的激活；
- 根据层、序列长度和并行 stage 做异构策略。

可以比较每个候选张量的“保存字节数 / 重算 FLOPs”，优先重算高显存、低计算成本的部分。最终在目标长度与 microbatch 上画吞吐—峰值显存 Pareto 曲线。

### 验证方法

关闭 dropout 或固定 RNG，在小模型上比较开启/关闭 checkpointing 的 Loss、逐参数梯度和一次更新结果；再测峰值 allocated/reserved memory、tokens/s、通信时间和不同长度下的 OOM 边界。允许浮点重排导致微小误差，但不应出现系统性差异。

### 面试简答版

Activation Checkpointing 前向只保留若干层边界，丢弃段内激活；反向时从边界重算 forward，再立即反传，用额外计算换取原本随层数增长的激活显存。它不减少参数、梯度和 Adam 状态，所以常与 FSDP/ZeRO 配合。代价是额外 forward、吞吐下降和更复杂的 RNG/副作用管理；Dropout 重算必须恢复相同随机状态。粒度应按“节省字节/重算 FLOPs”选择，并用开启前后的梯度一致性、峰值显存和 tokens/s 实测。
