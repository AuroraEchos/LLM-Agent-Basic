## 我的答案

估算 FLOPs 前必须先统一口径。本答案按高性能计算中常见的约定：**一次乘法和一次加法计为 2 FLOPs**。因此 $[M,K]$ 乘 $[K,N]$ 的主要 FLOPs 约为 $2MKN$。有些资料把一次 MAC 计为 1，结果会差 2 倍，比较时必须先对齐口径。

设：

- Batch Size 为 $B$；
- 序列长度为 $S$；
- 层数为 $L$；
- hidden size 为 $d$；
- FFN 中间维度为 $m$；
- 词表大小为 $V$。

### 单层、单次前向 FLOPs

#### Attention 线性投影

标准 MHA 有 Q、K、V、O 四个 $d\times d$ 矩阵。每个矩阵处理 $BS$ 个 token：

$$
F_{proj}=4\times2BSd^2=8BSd^2
$$

GQA/MQA 中 K/V 输出维度更小，应将对应的两个 $d^2$ 项替换为 $d(h_{kv}d_h)$。

#### Attention score 与 Value 聚合

$QK^T$ 和 $AV$ 各需约：

$$
2BS^2d
$$

两者合计：

$$
F_{attn}=4BS^2d
$$

Softmax、Mask、RoPE、Norm 和激活函数的逐元素 FLOPs 通常比大矩阵乘小，粗略估算时可忽略；做 kernel 性能分析时则不能忽略它们的内存读写和 launch 开销。

#### FFN

标准两矩阵 FFN：

$$
F_{ffn}^{standard}=4BSdm
$$

SwiGLU/GEGLU 有两个上投影和一个下投影：

$$
F_{ffn}^{gated}=6BSdm
$$

#### 单层总量

对标准 MHA + 标准 FFN：

$$
\boxed{F_{layer}^{fwd}\approx8BSd^2+4BS^2d+4BSdm}
$$

若 $m=4d$：

$$
F_{layer}^{fwd}\approx24BSd^2+4BS^2d
$$

对 MHA + SwiGLU，若 $m\approx8d/3$，FFN 也约为 $16BSd^2$，所以仍有相同的主要估算形式。

### 完整模型一次前向

$L$ 层主体：

$$
F_{stack}^{fwd}=L\,F_{layer}^{fwd}
$$

训练时如果对所有 token 计算词表 logits，LM Head 还需：

$$
F_{lm}=2BSdV
$$

Embedding lookup 是内存查表，不是 $Vd$ 的密集矩阵乘。LM Head 即使与 Embedding 权重绑定，也只是不重复存参数，前向的 $hE^T$ 计算仍然存在。

### 用参数量快速估算

对以大矩阵乘为主、注意力 $S^2$ 项不占主导的稠密模型，每个 token 使用每个参数做一次乘加，因此前向可粗估为：

$$
F_{fwd}\approx2P\times N_{tokens}
$$

$P$ 是实际激活的主要参数，$N_{tokens}=BS$。这个 $2PN$ 法则很方便，但会弱化或漏掉：

- Attention 的 $S^2$ 项；
- 绑定参数被在多处使用的额外计算；
- MoE 中“总参数”与“每 token 激活参数”的差异；
- 逐元素算子、通信和内存读写。

### 训练一步 FLOPs

对矩阵乘，反向通常需同时计算输入梯度和权重梯度，总 FLOPs 约是前向的 2 倍。因此“前向 + 反向”约为纯前向的 3 倍：

$$
F_{train\ step}\approx3F_{fwd}
$$

结合 $F_{fwd}\approx2PN_{tokens}$，得到常用粗估：

$$
\boxed{F_{train}\approx6P N_{tokens}}
$$

这不包含或只粗略包含 optimizer update、数据处理、梯度通信和逐元素算子。Activation Checkpointing 会在反向时重算部分前向，因此实际 FLOPs 会高于不重计算时的 3 倍前向。

### 生成一个 token：带 KV Cache

假设 Batch Size 为 1，当前 Cache 长度为 $S$，只处理一个新 token。对标准 MHA + 标准 FFN，每层约为：

$$
F_{decode,layer}
\approx
8d^2+4Sd+4dm
$$

其中：

- $8d^2$：Q/K/V/O 投影；
- $4Sd$：当前 Q 与 $S$ 个历史 K 点积，再对 $S$ 个 V 加权；
- $4dm$：标准 FFN，SwiGLU 则为 $6dm$。

完整模型还要乘以 $L$，并加上当前 token 的 LM Head：

$$
F_{decode}\approx
L F_{decode,layer}+2dV
$$

对 Batch Decode 再乘以当前 active sequence 数。GQA/MQA 会减少当前 token 的 K/V 投影，但每个 Query head 仍需与共享 Key 做点积，所以主要收益常来自 KV Cache 容量和读带宽，而非 $4Sd$ 理论 FLOPs 按 KV head 比例同步减少。

### Prefill 与 Decode 必须分开

- **Prefill** 一次处理整个 prompt，使用前面的 $B,S$ 公式，矩阵大、并行度高，更可能 compute-bound。
- **Decode** 每步只处理一个 token，虽然 FLOPs 较少，却要为少量 token 读取整个模型权重和全部 KV Cache，常更容易 memory-bandwidth-bound。

如果不使用 KV Cache，为生成每个新 token 都重新前向整个前缀，会重复计算历史 token 的投影和 Attention，单步开销不再是上述“单 Query”估算。

### FLOPs 不等于时间

将 FLOPs 除以 GPU 峰值算力只能得到不可达的理论下界。真实时间还受：

- 内存带宽与 KV Cache 读写；
- Tensor/Pipeline/Data Parallel 通信；
- kernel 形状、融合程度和硬件利用率；
- Padding、请求长度分布和 Batch 调度；
- 数据类型、量化、稀疏性和投机解码接受率

影响。工程上应同时报告理论 FLOPs、实测 tokens/s、MFU、TTFT 和 TPOT。

### 面试简答版

我会先声明一次乘加计 2 FLOPs。对 $B\times S$ token、hidden size $d$、FFN 维度 $m$ 的标准 MHA 层，前向约为 $8BSd^2+4BS^2d+4BSdm$；SwiGLU 把 FFN 项改为 $6BSdm$。完整模型乘层数 $L$，训练所有 token 还要加 LM Head $2BSdV$。反向约是前向的 2 倍，所以前向+反向约为 3 倍前向，常用粗估是每 token 训练约 $6P$ FLOPs。带 KV Cache 生成一个 token 时，每层约为 $8d^2+4Sd+4dm$，再加 LM Head。最后必须强调 FLOPs 不等于时间：Prefill 常更偏计算密集，Decode 则常受权重和 KV Cache 内存带宽限制。
