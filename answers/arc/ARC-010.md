> **问题：** Padding Mask、Causal Mask 和 Attention Bias 有什么区别，如何正确广播？

## 我的答案

Padding Mask、Causal Mask 和 Attention Bias 都会修改 Attention logits，但它们解决的问题不同：

- **Padding Mask**：屏蔽为了对齐 Batch 而补入的无效 token。
- **Causal Mask**：屏蔽自回归模型中的未来 token。
- **Attention Bias**：为某些 Query-Key 对加上额外先验或结构性偏置，不一定完全屏蔽它们。

### 统一视角

设 Attention logits 为：

$$
S=\frac{QK^T}{\sqrt{d_h}}
\in\mathbb{R}^{B\times H\times L_q\times L_k}
$$

最终计算可写成：

$$
A=\operatorname{Softmax}(S+M_{pad}+M_{causal}+B_{attn})
$$

从数学上看，Mask 也可表示为只取 $0$ 和 $-\infty$ 的加法 Bias。但工程上通常将“硬性禁止关注”称为 Mask，将“改变关注倾向”称为 Bias。

### Padding Mask

同一 Batch 中序列长度不同时，需使用 Padding token 对齐：

```text
[A, B, C, D]
[E, F, PAD, PAD]
```

第二个样本的有效 Query 都不应读取 `PAD` 位置的 Key/Value。常见 Key Padding Mask 的原始形状为 $[B,L_k]$，为了与 logits $[B,H,L_q,L_k]$ 广播，应变形为：

$$
[B,1,1,L_k]
$$

它在 head 维和 Query 位置维上广播，表示同一样本的所有 head、所有 Query 都不读取 Padding Key。

需区分两件事：Key Padding Mask 阻止有效 Query 关注 Padding Key；Padding 位置自身作为 Query 产生的输出，则常由输出掩码或 Loss Mask 忽略，不一定仅靠 Key Padding Mask 解决。

### Causal Mask

Causal Mask 表示 Query-Key 位置之间的时序关系。无 Cache 的等长 Self-Attention 中，其原始形状可为 $[L_q,L_k]$，广播形状为：

$$
[1,1,L_q,L_k]
$$

它在 Batch 和 head 维上共享。对普通 Decoder Self-Attention，只允许 $j\le i$ 的 Key 位置；有 Prefix Cache 或 Chunked Prefill 时，还需加 Query 的绝对位置偏移。

Encoder 的双向 Self-Attention 通常不使用 Causal Mask。普通 Encoder-Decoder 的 Cross-Attention 通常也不使用下三角 Mask，因为 Decoder 可以关注完整源序列。

### Attention Bias

Attention Bias 是加到 logits 上的额外值，可用于表达：

- 相对位置偏置；
- ALiBi 中与距离成比例的线性惩罚；
- 图结构、文档边界或局部窗口先验；
- 自定义的注意力约束。

其形状取决于是否区分 Batch、head 和 Query：

| 形状 | 含义 |
|---|---|
| $[L_q,L_k]$ | 所有 Batch 和 head 共享 |
| $[1,H,L_q,L_k]$ | 每个 head 有不同偏置 |
| $[B,1,L_q,L_k]$ | 每个样本不同，head 共享 |
| $[B,H,L_q,L_k]$ | 完全自定义，显存开销最大 |

### 如何正确广播和合并

假设：

```text
scores.shape      = [B, H, Lq, Lk]
padding_mask      = [B, Lk]       # 1 表示有效 token
causal_mask       = [Lq, Lk]      # True 表示允许关注
position_bias     = [1, H, Lq, Lk]
```

可统一转换成加法形式：

```python
pad_allowed = padding_mask[:, None, None, :]     # [B, 1, 1, Lk]
causal_allowed = causal_mask[None, None, :, :]   # [1, 1, Lq, Lk]

allowed = pad_allowed & causal_allowed
scores = scores.masked_fill(~allowed, negative_infinity)
scores = scores + position_bias
weights = softmax(scores, dim=-1)
```

关键是在运算前明确每一维的语义，不要只看“形状能跑通”。错误广播有时不会报错，却会将一个样本或一个 Query 的 Mask 用到错误维度上。

### 常见坑点

- **布尔语义相反**：不同库中 `True` 可能表示“允许”或“屏蔽”，必须确认 API 约定。
- **掩码错维**：将 $[B,L_k]$ 误变形为 $[B,L_k,1,1]$，没有对齐最后的 Key 维。
- **整行被屏蔽**：若某 Query 的所有 Key 都被屏蔽，对全 $-\infty$ 做 Softmax 可能得到 NaN。
- **左 Padding 错位**：除 Attention Mask 外，位置 ID 和 RoPE 位置也必须按真实 token 对齐。
- **遗漏 Loss Mask**：Padding Key 不被关注，不代表 Padding 位置会自动从训练 Loss 中消失。

### 面试简答版

Padding Mask 用来屏蔽 Batch 对齐产生的 PAD Key，通常从 $[B,L_k]$ 扩展为 $[B,1,1,L_k]$。Causal Mask 用来屏蔽未来位置，通常从 $[L_q,L_k]$ 扩展为 $[1,1,L_q,L_k]$。Attention Bias 则对某些 Query-Key 对增加有限的正负偏置，可按 Batch 或 head 变化。它们最终都要广播到 logits 的 $[B,H,L_q,L_k]$ 语义上。实现时最需注意布尔 Mask 语义、广播维度、全屏蔽行的 NaN 以及 Padding 位置的 Loss Mask。
