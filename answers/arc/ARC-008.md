## 我的答案

GQA（Grouped-Query Attention）的核心是：**Query head 数量多，KV head 数量少，若干个 Query head 共享同一组 Key 和 Value。**

### 形状和分组关系

设输入 $X\in\mathbb{R}^{B\times T\times d_{model}}$，Query head 数为 $h_q$，KV head 数为 $h_{kv}$，head dimension 为 $d_h$。必须满足：

$$
h_q\bmod h_{kv}=0
$$

每个 KV head 对应的 Query head 数为：

$$
g=\frac{h_q}{h_{kv}}
$$

线性投影后：

$$
Q\in\mathbb{R}^{B\times h_q\times T\times d_h}
$$

$$
K,V\in\mathbb{R}^{B\times h_{kv}\times S\times d_h}
$$

$T$ 是 Query 长度，$S$ 是 Key/Value 长度。Self-Attention 训练时通常 $T=S$；带 KV Cache 的单 token 解码时通常 $T=1$。

### Query head 如何映射到 KV head

若采用连续分组，第 $i$ 个 Query head 对应的 KV head 编号为：

$$
\operatorname{kv\_head}(i)
=
\left\lfloor\frac{i}{g}\right\rfloor
$$

例如 $h_q=8$、$h_{kv}=2$，则 $g=4$：Query head 0–3 共享 KV head 0，Query head 4–7 共享 KV head 1。Query head 自身仍然有独立的 $W_i^Q$ 和独立的注意力分布。

### 一个直观的 PyTorch 式伪代码

```python
def grouped_query_attention(x, attention_mask=None, past_kv=None):
    # x: [B, T, d_model]
    batch_size, query_len, _ = x.shape

    q = q_proj(x).view(batch_size, query_len, h_q, d_h)
    k = k_proj(x).view(batch_size, query_len, h_kv, d_h)
    v = v_proj(x).view(batch_size, query_len, h_kv, d_h)

    # [B, heads, sequence, d_h]
    q = q.transpose(1, 2)
    k = k.transpose(1, 2)
    v = v.transpose(1, 2)

    if past_kv is not None:
        past_k, past_v = past_kv
        k = concat([past_k, k], dim=2)
        v = concat([past_v, v], dim=2)

    # 缓存仍保持 h_kv 个头，不保存展开后的 K/V
    new_past_kv = (k, v)
    group_size = h_q // h_kv

    # 教学写法：在 head 维复制，使 K/V 头数与 Q 对齐
    k_for_attention = k.repeat_interleave(group_size, dim=1)
    v_for_attention = v.repeat_interleave(group_size, dim=1)

    scores = q @ k_for_attention.transpose(-2, -1)
    scores = scores / sqrt(d_h)
    if attention_mask is not None:
        scores = scores + attention_mask

    # 混合精度中常用 FP32 完成 softmax 再转回
    weights = softmax(scores, dim=-1)
    output = weights @ v_for_attention

    output = output.transpose(1, 2).contiguous()
    output = output.view(batch_size, query_len, h_q * d_h)
    return o_proj(output), new_past_kv
```

`repeat_interleave` 适合说明语义，但可能真正复制 K/V，产生额外显存开销。高效实现会利用 reshape、broadcast 或专门的 Attention kernel，让多个 Query head 直接共享 KV 数据，而不物理复制 KV Cache。

### 不显式复制 K/V 的思路

可将 Query 多拆出一个 group 维：

$$
Q\in\mathbb{R}^{B\times h_{kv}\times g\times T\times d_h}
$$

而 K 保持 $[B,h_{kv},S,d_h]$，在每个 KV head 内让 $g$ 个 Query head 通过广播与同一个 K 计算点积：

$$
\text{scores}_{b,k,g,t,s}
=
\sum_d Q_{b,k,g,t,d}K_{b,k,s,d}
$$

这样能表达真正的共享语义，而不需物理复制 K/V。

### KV Cache 的正确处理

推理时只缓存原始的 $h_{kv}$ 个 K/V head：

$$
K_{cache},V_{cache}
\in
\mathbb{R}^{B\times h_{kv}\times S\times d_h}
$$

不应把 K/V 扩展到 $h_q$ 个头后再缓存，否则会丢失 GQA 最主要的 KV Cache 收益。对新 token，先计算 $K_{new}$ 和 $V_{new}$，再沿 sequence 维追加。真正服务引擎会向预分配或分页缓存写入，而不是每步用 `concat` 重新分配整块内存。

### 常见错误

- $h_q$ 不能被 $h_{kv}$ 整除，却直接做等长分组。
- `view` 后没有正确 `transpose`，将 sequence 维和 head 维混淆。
- 缓存复制到 $h_q$ 个头的 K/V，导致显存节省消失。
- 带 KV Cache 分块解码时仍使用从 0 开始的下三角 Mask，没考虑 Query 位置偏移。
- Tensor Parallel 切分后，每张卡分到的 Query/KV head 数与分组关系不合法。

### 面试简答版

实现 GQA 时，先将 Q 投影为 $h_q$ 个头，将 K、V 投影为较少的 $h_{kv}$ 个头，并保证 $h_q$ 能被 $h_{kv}$ 整除。每 $g=h_q/h_{kv}$ 个 Query head 共享一个 KV head，第 $i$ 个 Query head 通常映射到 $\lfloor i/g\rfloor$ 号 KV head。教学实现可将 K/V `repeat_interleave` 到 Query head 数，高效实现则应使用广播或专用 kernel，避免真实复制。推理时必须只缓存 $h_{kv}$ 个 K/V head，这才能保留 GQA 的显存和带宽收益。
