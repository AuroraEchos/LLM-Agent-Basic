## 我的答案

三类架构的核心差别在于注意力可见范围和输入/输出的建模方式：Encoder-Only 使用双向 Self-Attention 理解整个输入，Decoder-Only 使用因果 Self-Attention 续写前缀，Encoder-Decoder 则先双向编码源序列，再通过 Cross-Attention 条件生成目标序列。

### Encoder-Only

Encoder 中每个 token 可以关注输入内所有其他 token：

$$
h_i=f(x_1,\ldots,x_T)
$$

它通常使用 Masked Language Modeling、对比学习或其他表征学习目标预训练。由于一个 token 的表示同时融合左右上下文，特别适合：

- 文本分类、意图识别、情感分析；
- 序列标注，如 NER、词性标注；
- 抽取式问答；
- 句子/文档 embedding、语义检索和 reranking；
- 需要对完整输入做理解或判别的任务。

局限是原生结构不是自回归生成器，不能直接像 Decoder 一样逐 token 生成任意长度文本。

### Decoder-Only

Decoder-Only 使用 Causal Mask，位置 $t$ 只能关注 $\le t$ 的 token，并通常使用 Next-Token Prediction：

$$
p(x_{1:T})=\prod_{t=1}^{T}p(x_t\mid x_{<t})
$$

它适合：

- 开放式文本生成、对话、代码生成；
- 通过 prompt 统一表达的问答、摘要、翻译和信息抽取；
- In-Context Learning、工具调用与 Agent 决策；
- 需要将多种任务统一为“给定前缀，生成后续”的通用模型。

优点是预训练目标与自回归推理完全对齐，架构统一，大量原始文本都可直接作为训练数据。局限是输入 token 之间也只有单向可见性；对纯表征任务，同规模的双向 Encoder 可能更高效。

### Encoder-Decoder

Encoder 先使用双向注意力得到源序列表示 $H_{src}$，Decoder 再使用两类注意力：

1. Causal Self-Attention：关注已生成的目标前缀；
2. Cross-Attention：Query 来自 Decoder，Key/Value 来自 $H_{src}$。

它直接建模条件概率：

$$
p(y\mid x)=\prod_t p(y_t\mid y_{<t},x)
$$

特别适合输入和输出语义明确分离的 Seq2Seq 任务：机器翻译、摘要、语音识别后文本生成、结构化转换和条件生成。Encoder 可一次完整理解源序列，源端不必遭受因果 Mask 限制。

代价是结构包含两个 stack 和 Cross-Attention，实现、并行和服务缓存更复杂，多任务统一性也不如单一 Decoder 直接。

### 综合对比

| 架构 | 可见性 | 常见预训练目标 | 优势任务 |
|---|---|---|---|
| Encoder-Only | 输入内双向 | MLM/表征学习 | 理解、分类、标注、检索 |
| Decoder-Only | 因果单向 | Next-Token Prediction | 通用生成、对话、代码、Agent |
| Encoder-Decoder | 源端双向 + 目标端因果 | Denoising/Seq2Seq | 翻译、摘要、条件生成 |

这些是架构偏好而不是绝对能力边界。Decoder-Only 也可做分类，Encoder-Decoder 也可做对话，最终选择要同时考虑数据、延迟、参数预算、输入/输出长度和是否需要通用 In-Context Learning。

### 面试简答版

Encoder-Only 使用双向 Self-Attention，能为每个 token 融合完整上下文，适合分类、序列标注、检索和抽取式问答。Decoder-Only 使用 Causal Attention 和 Next-Token Prediction，预训练与生成推理对齐，适合通用文本/代码生成、对话和 Agent。Encoder-Decoder 先双向编码源序列，再用因果 Decoder 和 Cross-Attention 生成目标，适合翻译、摘要等输入输出明确分离的 Seq2Seq 任务。
