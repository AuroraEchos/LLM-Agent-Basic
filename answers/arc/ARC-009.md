## 我的答案

Causal Mask（因果掩码）用于保证位置 $i$ 的 token 只能关注自己和它之前的 token，不能看到未来信息。这使 Decoder-Only 模型满足自回归分解：

$$
p(x_1,\ldots,x_T)=\prod_{t=1}^{T}p(x_t\mid x_{<t})
$$

### 为什么训练时必须有 Causal Mask

训练时通常一次将整个序列输入 Transformer，并行预测所有位置的下一个 token：

```text
输入：<BOS>  我  喜欢  学习
标签：我     喜欢  学习  <EOS>
```

如果没有 Causal Mask，某个位置可以直接关注后面已出现的目标 token，造成标签泄漏。训练 Loss 看似很低，但推理时没有未来 token 可看，模型就无法正常生成。Causal Mask 让训练在保持因果约束的同时，仍能并行计算整个序列。

### 训练时如何构造

设 $S=QK^T/\sqrt{d_h}$，对长度 $T$ 的 Self-Attention，定义加法掩码：

$$
M_{i,j}=
\begin{cases}
0,&j\le i\\
-\infty,&j>i
\end{cases}
$$

然后计算：

$$
A=\operatorname{Softmax}(S+M)
$$

以长度 4 为例：

$$
M=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}
$$

Softmax 后，右上三角区域的权重为 0。Mask 可保存为 $[T,T]$ 并广播到 $[B,H,T,T]$，无需为每个 Batch 和 head 真实复制。

### 推理时如何处理

#### 不使用 KV Cache

如果每一步都把完整前缀重新输入模型，就需要对整个前缀使用普通下三角 Causal Mask。

#### 单 token 解码并使用 KV Cache

假设 Cache 中已有 $S$ 个 token，当前只输入一个新 token。Query 长度为 1，Key/Value 是“过去 $S$ 个 token + 当前 token”。因为缓存中根本没有未来 Key，这一行可以关注所有现有 Key，通常无需再显式构造三角 Mask。因果性此时由“Cache 中只存在过去和当前 token”自然保证。

#### Chunked Prefill 或多 token 解码

若 Cache 中已有 $P$ 个 token，当前一次处理 $T$ 个新 Query，则 Query 的绝对位置是 $P,ldots,P+T-1$，Key 的绝对位置是 $0,ldots,P+T-1$。正确条件是：

$$
M_{i,j}=0\quad\text{iff}\quad j\le P+i
$$

因此不能不加偏移地直接使用一个 $T\times(P+T)$ 的普通下三角矩阵，否则新 Query 可能无法关注完整历史前缀。

### Causal Mask 与 Loss Mask 的区别

- Causal Mask 作用在 Attention logits 上，决定 token **能看到哪些 token**。
- Loss Mask 作用在 token-level loss 上，决定哪些位置 **参与梯度优化**。

例如 SFT 中可以让 Assistant token 看到前面的 System 和 User token，但只对 Assistant token 计算 Loss。

### 常见工程问题

- 不同 API 对布尔 Mask 的 `True` 定义可能相反：有的表示“保留”，有的表示“屏蔽”。
- Padding Mask 和 Causal Mask 合并错误，导致模型关注 Padding token。
- 某一行所有 Key 都被设为 $-\infty$，Softmax 可能产生 NaN。
- 左 Padding、KV Cache 和分块 Prefill 组合时，没有正确处理位置偏移。

### 面试简答版

Causal Mask 阻止当前 token 关注未来 token，从而保证自回归建模的因果性。训练时将 Attention logits 右上三角部分加上 $-\infty$，Softmax 后这些位置权重为 0，这样既防止标签泄漏，又能并行训练整个序列。单 token 带 Cache 解码时，因为只存在过去和当前 Key，通常不需要显式三角 Mask；但多 token 解码或 Chunked Prefill 必须根据 Cache 长度加上正确的位置偏移。
