## 我的答案

目标不是单纯追求最小 MB，而是同时做到**依赖可复现、缓存有效、运行面最小、无秘密、能正确接收信号**。一个简化骨架如下：

```dockerfile
# syntax=docker/dockerfile:1
FROM python:3.12-slim@sha256:<经审核的实际摘要> AS builder
WORKDIR /build
COPY requirements.lock ./
RUN --mount=type=cache,target=/root/.cache/pip \
    python -m venv /opt/venv && \
    /opt/venv/bin/pip install --require-hashes -r requirements.lock

FROM python:3.12-slim@sha256:<同系列经审核的实际摘要> AS runtime
ENV PATH=/opt/venv/bin:$PATH \
    PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1
RUN groupadd --system app && useradd --system --gid app --home /app app
WORKDIR /app
COPY --from=builder /opt/venv /opt/venv
COPY --chown=app:app src/ ./src/
USER app
EXPOSE 8000
CMD ["python", "-m", "src.server"]
```

摘要需替换为真实值并由自动更新 PR 定期升级；固定 digest 保证同输入可追踪，但不会自动获得安全修复。Python、CUDA、driver、PyTorch 和 GPU architecture 必须形成经过测试的兼容矩阵，不能为小体积随意换 Alpine/musl 或删运行库。

关键实践：

1. 使用可信、最小的基础镜像和 multi-stage build，编译器/header 只留 builder；只安装必要 OS 包，同一层更新/安装/清理。
2. 先 COPY lockfile 安装依赖，再复制高频变化源码以利用缓存；依赖固定版本/hash，使用私有 index 时校验证书和制品来源。
3. `.dockerignore` 排除 `.git`、测试缓存、虚拟环境、数据、模型和密钥；秘密用 BuildKit secret mount，只在该 RUN 可见，不能用 `ARG/ENV/COPY` 烘进 layer。
4. 最终用非 root 用户、只读 rootfs（运行时配置）、drop capabilities；缓存/临时目录显式创建并只授予所需写权限。
5. exec-form CMD 让服务成为正确 PID/收到 TERM；应用实现 readiness、drain 和有界退出。不要用 shell wrapper 吞信号，确需多子进程时使用能转发/reap 的 init。
6. 在 CI 对最终 image 做 SBOM、漏洞/secret/license 扫描、签名与 provenance，启动容器跑 smoke/health test，并按 digest 发布，避免部署浮动 `latest`。

模型权重可做独立不可变 artifact，通过 digest 校验后挂只读卷；若必须随 image 发布，应拆独立稳定 layer，并评估 registry、节点拉取时间和许可证。可复现还要求构建输入、平台和生成步骤受控，而不仅是“本机第二次能命中 cache”。

### 面试简答版

我会用可信且固定 digest 的基础镜像、多阶段构建和 lockfile/hash 固定依赖；先复制依赖文件利用 cache，最终镜像只留运行时与源码。用 `.dockerignore` 缩小 context，secret 通过 BuildKit mount 而非 ARG/ENV，运行用户非 root、最小 capability、可只读 rootfs，CMD 用 exec form 并支持 SIGTERM。模型权重按 digest 作为独立 artifact/只读卷或稳定 layer。CI 对最终镜像做 smoke test、SBOM、漏洞/secret 扫描、签名，并用自动更新流程获得安全修复。
