> **问题：** `P0` Docker Image、Container、Layer、Volume 和 Network 分别是什么？

## 我的答案

- **Image**：创建容器的不可变模板，由 manifest/config 和一组只读 filesystem layers 组成，包含程序、运行时与元数据。tag 是可移动名字，digest 才标识具体内容。
- **Container**：image 的一个运行实例，本质是受 namespace/cgroup 等约束的宿主进程，加 image 只读层之上的可写层和运行配置。停止的容器仍可能保留可写层，但删除容器通常会删除它，所以不应用它保存持久数据。
- **Layer**：Dockerfile 某些指令产生的内容差异层，可被镜像复用和构建缓存。下层不可变；上层“删除”下层大文件通常只加 whiteout，并不会从旧层抹去体积或秘密。
- **Volume**：生命周期独立于容器的持久数据存储，由 Docker/CSI 等管理并挂载到容器；不同于 image layer。bind mount 则把宿主明确路径映射进容器，耦合更强、权限风险更高。
- **Network**：给容器提供隔离的网络环境、地址、路由、DNS 与连接策略。Docker bridge、host、overlay 等 driver 语义不同；发布端口是宿主/入口到容器端口的映射，`EXPOSE` 主要是镜像元数据，不会自动对外开放。

```text
Image read-only layers
        + container writable layer   <- 临时运行状态
        + mounted volume             <- 持久/共享数据
        + network namespace          <- 通信视图
```

模型服务通常把应用和固定运行时放 image，把日志送 stdout/集中系统，把缓存/权重按策略放只读 volume 或外部对象存储。把超大权重烘进 image 能获得启动确定性，却会增加分发、漏洞修复和版本存储成本；运行时下载则要校验 digest、有并发锁、原子落盘和可观测的预热。

安全上 image 不是秘密容器：构建参数、删除前的文件可能留在历史 layer。volume 也不自动备份/加密；network 隔离也不等于访问控制，仍需最小端口、认证、TLS 和网络策略。

### 面试简答版

Image 是按 digest 标识、由只读 layer 组成的容器模板；Container 是 image 加可写层和运行时隔离后的进程实例；Layer 是可复用的文件系统差异；Volume 独立于容器生命周期保存数据，bind mount 则直接绑定宿主路径；Network 提供容器网络视图和连接。容器可写层是临时的，EXPOSE 不等于发布端口，删除上层文件不会抹掉旧 layer 中的秘密或体积，模型权重放镜像还是外部存储需权衡启动确定性与分发成本。
