## 我的答案

容器配置应把**镜像中的不可变程序**和**部署时的环境差异**分开，并明确宿主、容器和编排器三层语义。

### 端口与网络

服务在容器内通常监听 `0.0.0.0:<container_port>` 或 `[::]`；只监听 `127.0.0.1` 会导致端口映射后外部仍不可达。`EXPOSE 8000` 是文档元数据，真正发布由 `-p host_ip:host_port:container_port`、Compose ports 或 Kubernetes Service/Ingress 完成。数据库和 metrics 不应无条件绑定所有宿主接口；只开放需要的端口，并配认证、TLS、NetworkPolicy/防火墙。

### 环境变量与秘密

环境变量适合小型非敏感配置，例如 log level、feature 开关和服务地址；启动时做 schema/范围校验并输出脱敏后的有效配置。密钥优先用 secret manager 或只读文件挂载，避免进入 image、Compose 文件、命令行、日志和 crash dump。修改环境变量不会自动改变已运行进程，通常需要受控重启；动态配置则需显式 reload/version 机制。

### 挂载与权限

- 配置、权重尽量 `read-only`；缓存、临时文件、输出分别挂可写 volume，并设置容量/清理策略。
- bind mount 强依赖宿主路径和 UID/GID，且可能覆盖 image 中同路径内容；启动前验证路径类型、owner 和 SELinux label。
- 容器使用固定非 root UID/GID，volume 预置匹配 ownership 或由受控 init 步骤设置。不要为了修权限运行 privileged 或递归 `chmod 777`。
- 原子下载模型到临时文件，校验 digest 后 rename；多副本共享缓存需锁或内容寻址，避免读到半文件。

### GPU

GPU 必须由运行时/编排器以 device request 分配，并安装兼容的 host driver 与 NVIDIA Container Toolkit/device plugin；镜像包含匹配的用户态 CUDA/框架。`CUDA_VISIBLE_DEVICES` 主要改变进程可见/编号，单独设置它不等于设备安全隔离或资源配额。Kubernetes 中申请 GPU resource，结合 MIG/专用调度实现所需隔离，并校验容器内可见设备、显存、compute capability。不要把 `/dev` 整体映射或使用 privileged 作为捷径。

最终还要设置 CPU/memory/pids/ephemeral-storage 限制、ulimit、只读 rootfs、tmpfs 和优雅退出。部署 smoke test 应验证端口可达、挂载只读/可写边界、以预期 UID 运行、secret 不出现在 image/env dump，以及 GPU 推理真实成功。

### 面试简答版

容器内服务要监听 0.0.0.0，EXPOSE 只是元数据，外部访问靠端口映射或 Service。非敏感小配置可用 env 且启动校验，秘密优先文件/secret manager；权重和配置只读挂载，缓存/输出单独可写 volume，并让非 root UID/GID 与卷权限匹配。GPU 由 runtime/Kubernetes resource 分配并匹配 host driver、CUDA 和框架；只设 CUDA_VISIBLE_DEVICES 不等于隔离。最后用资源限制、最小设备/端口、只读 rootfs 和 smoke test 验证实际边界。
